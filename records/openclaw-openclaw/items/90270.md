## Summary

Keep open: current main improved managed service-env install/repair handling, but the direct macOS LaunchAgent restart path still restages the existing generated service env rather than rebuilding it from the edited state-dir `.env`, so the central user problem remains a product/security decision.

## What This Changes

The issue requests making the global state-dir `.env` the user-facing source of truth for managed Gateway environment variables, or at least documenting/warning when generated service env overrides it.

## Best Possible Solution

Maintainers should define one managed Gateway environment contract, then align restart, install/doctor repair, docs, and focused service-env tests so key rotation is either refreshed from `.env`/SecretRefs or clearly warned.
