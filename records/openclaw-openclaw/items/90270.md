## Summary

Keep open: current main and v2026.6.11 still preserve daemon/process environment precedence over the state-dir `.env`, and the macOS restart path restages existing LaunchAgent environment instead of rebuilding managed values from `.env`. The remaining change is a credential-precedence product/security decision, not a safe stale cleanup close.

## What This Changes

Request that state-dir `.env` become the user-facing source of truth for gateway/provider environment variables, or that OpenClaw warn/document when generated service-env values override it.

## Best Possible Solution

Maintainers should define the daemon environment contract, then align restart, install/doctor repair, docs, and service-env tests around that choice.
