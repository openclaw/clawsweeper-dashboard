## Summary

Keep open: current main still does not make state-dir `.env` the single source of truth on ordinary Gateway restart. Install, doctor, and repair paths have stronger service-env handling now, but restart still mostly reuses existing supervisor metadata, and changing that policy affects credential precedence and secret preservation.

## What This Changes

Requested behavior is to make `~/.openclaw/.env` the single user-facing source for managed Gateway environment variables, or warn/document when service-managed values override it.

## Best Possible Solution

Define one daemon environment contract: either restart safely re-stages managed provider keys from state-dir `.env`, or status/doctor warns about drift and offers a visible fix path without silently changing preserved service secrets.
