## Summary

Keep open: current main still does not make the state-dir `.env` the single source of truth for managed Gateway service env values. The recent merged service-env preservation work fixes an adjacent SecretRef/token wipe, but plain macOS restart still restages the existing generated LaunchAgent environment instead of rebuilding it from `.env`, so this remains a product/security contract decision.

## What This Changes

The issue asks OpenClaw to make state-dir `.env` authoritative for managed Gateway service environment variables, or warn/document when generated `service-env` values override it.

## Best Possible Solution

Maintainers should choose one managed-Gateway credential contract, then align restart, install/doctor repair, conflict diagnostics, docs, and focused service-env tests around that contract.

Options:

- **Warn and repair explicitly (recommended):** Keep the current installed service-env precedence, but add diagnostics/docs/doctor guidance that detects conflicts and tells users how to restage from `.env`.
- **Make `.env` authoritative on restart:** Rebuild managed service env from state-dir `.env` during restart, accepting the upgrade and credential-precedence change with focused migration proof.
- **Document current behavior only:** Clarify the precedence chain without changing runtime behavior, leaving users to run force install or doctor when they intentionally rotate `.env` secrets.

## Solution Assessment
