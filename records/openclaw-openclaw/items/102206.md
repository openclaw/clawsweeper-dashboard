## Summary

Keep open: current main and the latest release still contain the source-level Codex app-server binding and outbound-policy behavior described by the report, so the silent heartbeat notification loss is not proven fixed.

## What This Changes

The issue reports a regression where Codex app-server heartbeat/internal turns inherit `webchat` as the current provider, causing Discord message-tool notifications to be denied and masked by heartbeat success.

## Best Possible Solution

Keep the cross-provider guard for real chat-bound turns, but make Codex heartbeat/internal turns avoid a deliverable `webchat` provider binding and ensure failed message sends cannot be masked by a later heartbeat success.

Yes, at source level: current main binds Codex dynamic-tool context from `messageChannel`, and the outbound policy denies a Discord send when that binding is `webchat`. I did not perform a live Discord heartbeat replay.

## Solution Assessment

Yes, the best direction is a focused runtime repair rather than asking users to globally allow cross-provider sends, because the problematic origin is an internal heartbeat turn rather than a real webchat conversation.
