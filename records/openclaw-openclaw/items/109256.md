## Summary

Keep open: this is a fresh, detailed regression report with a plausible current auth/session-state boundary failure. Current main contains generic cooldown skipping and model-failover handling, but that does not prove an automatically persisted session override is cleared when its selected OAuth profile becomes unavailable, and no merged fix provenance establishes that the reported sequence is resolved.

## What This Changes

Clear or replace an automatically generated auth-profile override when its OAuth profile becomes unavailable so subsequent events can create agent sessions through another usable provider.

## Best Possible Solution

Treat user-selected auth-profile pins as authoritative, but when an override marked source="auto" references a cooldowned or unavailable profile, remove it from the prepared session state and continue through the existing auth-profile and model-fallback machinery; add coverage for repeated channel events, fallback, and recovery after cooldown expiry.
