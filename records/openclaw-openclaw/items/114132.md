## What This Changes

The PR adds nine command-carrier executables to OpenClaw’s opaque dispatch-wrapper list so approval and allowlist policy blocks them instead of evaluating only the wrapper executable.

## System Context

OpenClaw turns an exec argv into an execution target and a policy target before applying approvals or allowlists. Parser-backed transparent wrappers expose their child command, while unmodeled wrappers stop the trust plan so policy cannot accidentally authorize an unseen child executable.

## Architecture Diagram

flowchart LR
  A[Agent tool argv] --> B[Exec wrapper trust plan]
  B --> C{Dispatch wrapper known?}
  C -->|Parser-backed| D[Resolve child executable]
  C -->|Opaque carrier| E[Block policy evaluation]
  D --> F[Approval or allowlist check]
  E --> G[Deny execution]
  F --> H[Execute or deny]

## Best Possible Solution

Keep opaque blocking for the verified unmodeled command carriers, document the intentional approval/allowlist behavior change in the PR context, and land only after the owner confirms the compatibility tradeoff and a redacted live policy-resolution run demonstrates the denial path.
