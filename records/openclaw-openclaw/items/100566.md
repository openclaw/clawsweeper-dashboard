## Summary

Keep open: the report is source-reproducible on current main and v2026.6.11. OpenClaw already treats `gemini-flash-latest` as a Gemini 3 Flash alias for thinking, but the Google transport's tool-call signature guard only checks for `gemini-3`, so replayed unsigned tool calls for that alias can omit both the original signature and the existing skip-validator fallback required by Google's function-calling contract. ([ai.google.dev](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures))

## What This Changes

The issue asks OpenClaw to fix `google/gemini-flash-latest` tool-call turns that fail with a missing `thought_signature` 400 on version 2026.6.11.

## Best Possible Solution

Align the Google transport's tool-call thought-signature requirement with the existing Gemini 3 latest-alias predicates, then add focused regression coverage for `gemini-flash-latest` and related latest aliases without changing broader signature retention policy.
