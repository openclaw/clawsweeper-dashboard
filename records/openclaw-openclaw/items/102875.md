## Summary

Keep open: current main mitigates the operator-facing exec display path, but the exported stage splitter still lacks heredoc awareness and this issue is paired with open closing PRs for that remaining boundary.

## What This Changes

The issue reports that shell heredoc body text is split and rendered as phantom failed exec command stages in channel tool-status footers.

## Best Possible Solution

Review and land one narrow helper-level PR that teaches the top-level shell scanner to skip heredoc bodies, then close this issue after the merged fix reaches main.

## Solution Assessment

Yes for the remaining gap. Moving heredoc skipping into `scanTopLevelChars` is the narrowest durable fix because stage and pipe splitting share that helper, while the current display-only compaction is only a partial mitigation.
