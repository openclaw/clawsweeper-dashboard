## Summary

Keep open: current main still lacks a supported cron tag/category field, tag-aware cron.list/API filtering, CLI list exposure, and Control UI tag filters. The overlapping Reminders issue is narrower, and the earlier opaque metadata PR was closed unmerged after a maintainer design concern.

## What This Changes

The issue requests optional cron job tags/categories that persist, appear in CLI/UI list output, and support tag filtering or bulk actions.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, protocol filters, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.
