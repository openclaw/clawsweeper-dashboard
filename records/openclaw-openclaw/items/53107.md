## Summary

Keep open: current main still lacks a supported cron tag/category field, tag-aware cron.list filtering, CLI list exposure, and Control UI tag filters. The related Reminders issue overlaps only on classification, and the prior opaque metadata PR was closed unmerged after maintainer API/protocol design concerns.

## What This Changes

Request an optional cron job tags/categories contract with persistence, filtering, UI/CLI exposure, and possible tag-based bulk actions.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

## Solution Assessment

Unclear as proposed. Freeform tags are plausible, but maintainers should first choose the shared cron classification/display metadata model so reminders, plugin scheduling, CLI, API, and UI do not diverge.
