## Summary

Keep open: current main and the latest release still lack a supported cron tag/category/purpose field, tag-aware cron.list filtering, CLI list exposure, and Control UI tag filters; the overlapping Reminders issue is narrower and the related opaque metadata PR was closed unmerged pending owner-reviewed API design.

## What This Changes

Request adds optional freeform cron job tags/categories that persist across upgrades and are exposed for organization, filtering, and bulk operations in the API, CLI, and Control UI.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.
