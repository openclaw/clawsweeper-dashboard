## Summary

Keep open: current main and v2026.6.11 still lack a supported cron tag/category field or tag-aware list/UI filter. The existing bundled plugin scheduled-turn tag path is name-prefix cleanup only, and the related Reminders issue plus closed opaque-metadata PR do not supersede this broader cron organization request.

## What This Changes

Request to add optional cron job tags/categories for persisted organization, list/UI filtering, and possible tag-based bulk enable/disable.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

## Reproduction Assessment

Yes. Source inspection of current main reproduces the capability gap: cron job storage, protocol/list params, service filtering, and the Control UI filter panel have no supported tag/category field or filter.

## Solution Assessment

Unclear as proposed. Freeform tags are plausible, but maintainers should first choose the shared cron classification/display metadata model so reminders, plugin scheduling, CLI, API, and UI do not diverge.
