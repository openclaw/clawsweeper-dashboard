## Summary

Keep open: current main still lacks a supported cron tag/category field, tag-aware cron listing, CLI exposure, and Control UI tag filters; the related Reminders issue overlaps but is narrower, and the prior metadata PR was closed unmerged pending owner-reviewed API design.

## What This Changes

Requested behavior is optional cron job tags/categories so cron jobs can be grouped, filtered, and surfaced in CLI, UI, and API output.

## Best Possible Solution

Define one additive cron classification/display contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

Options:

- **Use typed metadata (recommended):** Design a narrow purpose/display metadata contract that can cover reminders and system/user/project jobs without creating opaque plugin-owned blobs.
- **Add freeform tags:** Add an optional normalized tags array to cron jobs and expose tag filtering consistently across storage, RPC/API, CLI, UI, tests, and docs.
- **Defer to plugin seam:** Keep the core cron schema lean and first extend plugin hooks/API only if classification can be owned outside core without losing filtering support.

## Solution Assessment

Unclear as proposed. Freeform tags are plausible, but maintainers should choose the shared cron classification/display metadata model first so reminders, plugin scheduling, CLI, API, and UI do not diverge.
