## Summary

Keep open: current main still lacks a supported cron tag/category/classification field, tag-aware cron.list filtering, CLI list exposure, and Control UI tag filters; the related Reminders issue is narrower and the opaque metadata PR was closed unmerged after an owner-review design concern.

## What This Changes

The issue requests optional cron job tags/categories for grouping, filtering, UI display, export/upgrade survival, and possible tag-based bulk operations.

## Best Possible Solution

Define one additive cron classification/display contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

Unclear as proposed. Freeform tags are plausible, but maintainers should first choose the shared cron classification/display metadata model so reminders, plugin scheduling, CLI, API, and UI do not diverge.
