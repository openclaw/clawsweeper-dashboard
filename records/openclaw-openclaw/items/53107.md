## Summary

Keep open: current main and v2026.6.11 still lack supported cron tags/categories, tag-aware cron.list filtering, CLI list exposure, and Control UI tag filters. The overlapping Reminders issue is narrower, and the prior opaque metadata PR was closed unmerged after a maintainer requested an owner-reviewed API design slice.

## What This Changes

The issue requests optional cron job tags/categories that persist across upgrades and exports, appear in CLI/UI output, and support filtering or bulk operations.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, cron.add/update/list validation, tag or purpose filtering, CLI/UI presentation, bulk operations if accepted, tests, and docs around that shared model.
