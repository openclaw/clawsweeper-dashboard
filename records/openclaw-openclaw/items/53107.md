Keep open: current main still lacks a supported cron tag/category field, tag-aware cron.list filtering, CLI list exposure, and Control UI tag filters; the related Reminders issue is narrower and the opaque metadata PR was closed unmerged for design and validation reasons.

## What This Changes

Add optional cron job tags or categories that persist, appear in CLI/UI lists, and support organization and filtering.

## Best Possible Solution

Define one additive cron classification/display metadata contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

Unclear as proposed. Freeform tags are plausible, but maintainers should first choose the shared cron classification/display metadata model so reminders, plugin scheduling, CLI, API, and UI do not diverge.
