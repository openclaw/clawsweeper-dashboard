## What This Changes

The issue requests optional cron job tags/categories plus list, UI, and API filtering so larger scheduled-job sets can be organized.

Define one additive cron classification/display contract, then wire persistence, RPC/API filtering, CLI/UI presentation, accepted bulk operations, tests, and docs around that shared model.

## Solution Assessment

Unclear as proposed. Freeform tags are plausible, but maintainers should choose the shared cron classification/display metadata model first so reminders, plugin scheduling, CLI, API, and UI do not diverge.
