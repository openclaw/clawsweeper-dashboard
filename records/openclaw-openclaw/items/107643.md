## Label Justifications

- `P2`: The affected workflow continues, but a bounded routing path can silently execute on the wrong model and fallback chain.
- `impact:auth-provider`: The session selects global provider/model defaults instead of the configured per-agent route.
- `impact:session-state`: The mismatch is introduced during initialization of the fresh session created by `/new`.

## Summary

The report is actionable and should remain open: the shipped reset path clears cached runtime model fields, while the model resolver still falls back to global configuration whenever the routed agent id is absent, and the current-main Telegram caller chain was not proven to preserve that id.

## What This Changes

Fix Telegram `/new` sessions so the first new turn uses the routed agent’s configured primary model and per-agent fallback chain rather than global agent defaults.

## Best Possible Solution

Carry the resolved session agent id through the Telegram `/new` first-turn model and fallback resolver, then add a regression covering `agent:main:main` with different global and per-agent primary/fallback settings while preserving explicit session overrides.
