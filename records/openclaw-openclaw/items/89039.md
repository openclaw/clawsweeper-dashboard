## Summary

The prior configured-retry blocker remains: the branch correctly keeps SDK retries out of the released prompt-lock window, but it replaces configured provider retry behavior with a single hard-coded outer retry. That can reduce retries for existing configured embedded-agent users, so this PR needs a focused repair before merge.

## What This Changes

The PR makes embedded steering writes fence-aware, disables in-window SDK retries during prompt-lock release, adds takeover resend guidance, and adds outer retry handling and regression coverage for connection and timeout failures.

## Best Possible Solution

Keep the in-window SDK retry pin at zero, but move the effective configured provider retry budget to the outer whole-attempt owner and add focused coverage for configured, unconfigured, and explicit per-call retry precedence.
