## Summary

Keep this PR open: the prior P1 compatibility blocker remains. The branch deliberately forces embedded prompt-window SDK retries to zero, but the replacement outer retry is only one-shot and does not preserve an existing configured provider retry budget; configured users therefore lose their selected retry behavior on this path.

## What This Changes

The branch makes embedded-session steering writes fence-aware, disables SDK retries during released prompt locks, forwards retry options through OpenAI transports, restores selected transient retries at the outer runner, and surfaces session-takeover resend guidance.

## Best Possible Solution

Keep SDK retries pinned to zero inside the released prompt-lock window, then preserve the configured provider retry budget at the outer attempt owner so every configured retry reacquires the session lock; add focused default and configured-budget regression coverage.
