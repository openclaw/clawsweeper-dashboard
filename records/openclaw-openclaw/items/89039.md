## Summary

This PR addresses a credible P1 message-loss path, but the final design repurposes the configured provider retry budget as a whole fallback-cycle budget. That can change configured multi-model behavior, and the supplied final-head proof does not demonstrate the affected configured contract; keep the PR open for a targeted semantic repair and redacted final-head behavior evidence.

## What This Changes

The branch makes embedded-agent session takeovers fence-aware, prevents SDK retries during the released prompt-lock window, retries eligible transport failures outside that window, and returns resend guidance instead of silently losing a reply.

## System Context

An embedded agent turn releases its session-write lock while a model stream runs, then reacquires it before committing transcript work. The reply runner classifies provider and coordination failures and turns the resulting outcome into the message delivered to the originating channel.

## Best Possible Solution

Keep SDK retries disabled inside the released prompt-lock window, but restore configured retries at a lock-reacquiring provider-candidate boundary rather than by replaying the entire fallback cycle; add final-head redacted live output for a configured primary-plus-fallback scenario and the takeover resend path.
