## Summary

This PR addresses a credible P1 reply-loss path and includes substantial loopback/process proof, but its final change moves an existing configured provider retry budget from SDK request scope to the outer primary-to-fallback reply cycle. That can change retry ordering, provider attempts, latency, and usage for existing configured installations, so a maintainer needs to explicitly accept that compatibility contract before merge.

## What This Changes

The branch makes embedded-agent transcript steering fence-aware, disables provider-SDK retries while the session lock is released, restores retry attempts in the outer reply orchestrator, and returns resend guidance after a session takeover.

## System Context

OpenClaw’s auto-reply path receives an inbound message, runs an embedded agent against a persisted session transcript, and turns the result into a channel reply. The embedded prompt phase releases the session write lock around provider I/O, so retry placement and transcript-write ownership affect both session fencing and whether the user gets a reply.

## Best Possible Solution

Keep SDK retries pinned to zero during the released-lock window, but preserve the documented meaning of configured provider retries through an explicitly approved outer retry policy with focused single-model and fallback-chain upgrade coverage; otherwise narrow the change to the unconfigured one-shot recovery path.
