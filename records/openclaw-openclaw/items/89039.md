## Summary

This PR addresses a valid silent-message-loss bug and contains useful fencing, lifecycle, and failure-copy work, but the current head still permits configured provider retries inside the released prompt-lock window, preserving the race it is intended to eliminate.

## What This Changes

The PR adds owned transcript fencing for steering, changes embedded provider retry ownership, forwards OpenAI retry options, handles takeover failures in the reply lifecycle, and adds focused regression coverage.

## Best Possible Solution

Pin every embedded provider SDK call to zero retries while the prompt lock is released, then honor configured retry policy through bounded outer attempts that reacquire the session lock before each provider call.

## Solution Assessment

No. The steering fence and resend handling are useful, but retry ownership remains split; the narrow safe fix gives the released-lock SDK call zero retries and performs all configured resilience after lock reacquisition.
