## Summary

Keep this PR open for maintainer review: it has credible real-process proof for the silent-loss path, but its latest change repurposes an existing provider retry setting from SDK-local retries into retries of the entire primary-to-fallback cycle. That can change provider ordering, request count, latency, and billing for existing configured installations, so the compatibility contract needs an explicit decision before merge.

## What This Changes

The branch makes embedded-session steering writes fence-aware, disables SDK retries while the session lock is released, retries selected transient failures at the reply orchestrator, and returns resend guidance after a genuine session takeover.

## System Context

The auto-reply runner accepts an inbound channel message, runs an embedded agent while coordinating ownership of its session transcript, then emits reply payloads back to the channel. The changed code sits between model-provider transport retries and the session-lock/fallback loop, so it affects both transcript consistency and whether a failed turn is retried or surfaced to the user.
