## Summary

Keep this PR open, but it is not merge-ready: the branch prevents in-window SDK retries and adds takeover guidance, yet it relocates the existing configured provider retry budget to a whole fallback-cycle counter. That can give later fallback candidates fewer retries than the configured per-provider behavior. The prior review identified the same blocker and the current diff still implements the shared outer counter. Likely related people: `steipete` and `vincentkoc` were explicitly brought into the PR discussion; ownership confidence is low because the local read-only command environment could not provide additional history.

## What This Changes

The branch makes embedded-session steering writes fence-aware, disables SDK retries while the prompt lock is released, retries transient failures from the reply orchestrator, and returns resend guidance instead of silently losing a reply after session takeover.

## System Context

The embedded-agent runner releases a session write lock around a model call, while the auto-reply pipeline owns model fallback and the final user-visible reply. This PR changes how model-call retries, transcript ownership, and terminal error mapping interact across that boundary.

## Best Possible Solution

Keep SDK retries disabled inside the released-lock window, but restore configured retries at the provider-candidate boundary with a full lock reacquisition before each retry; then add exact-head live output covering a configured multi-model fallback route.
