## Summary

The PR addresses a real silent-reply failure and supplies meaningful live-process proof, but its current retry pin still changes the existing configured provider-retry contract. The prior blocker remains: configured retry budgets must be restored at the outer attempt owner, where every retry reacquires the session lock, before this can merge safely.

## What This Changes

The branch makes embedded steering writes fence-aware, pins SDK retries to zero during the released prompt-lock window, retries selected failures at the outer runner, and returns resend guidance for session takeovers.

## Best Possible Solution

Keep SDK retries disabled only inside the released-lock window, then have the outer attempt owner honor the existing configured provider retry policy with each full retry reacquiring the session lock; cover configured, unconfigured, and explicit per-call retry precedence.
