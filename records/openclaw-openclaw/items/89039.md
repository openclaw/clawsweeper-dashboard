## Summary

Keep this PR open: current main does not yet have the silent-loss fix, and the proposed branch is a plausible, well-tested implementation candidate for the linked session-takeover bug. I found no discrete line-level correctness finding, but merge still needs maintainer acceptance because the patch intentionally changes embedded session ownership, user-visible takeover recovery, and unconfigured provider retry timing.

## What This Changes

The PR wraps embedded steering writes in owned transcript-write handling, adds takeover-specific resend recovery, forwards provider `maxRetries`, moves unconfigured embedded SDK retries out of the prompt-lock window into a bounded outer retry gate, and adds regression coverage.

## Best Possible Solution

Land this only after session/provider/message-delivery owners explicitly accept the new embedded retry and takeover recovery policy; otherwise split the owned-write fix from the retry-policy changes for narrower review.
