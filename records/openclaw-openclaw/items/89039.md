## Summary

Keep this PR open for one remaining P1 compatibility repair: it correctly keeps SDK retries out of the released embedded prompt-lock window, but it replaces existing configured provider retry behavior with a single hard-coded outer retry. The fix should preserve the configured retry budget at the full-attempt owner, where each retry reacquires the session lock. Likely related people: `steipete`, `vincentkoc`, and `aaron-he-zhu` were explicitly included in the early review routing; ownership confidence is low without a stronger current-main history signal.

## What This Changes

The branch makes embedded steering writes fence-aware, pins SDK retries to zero during released prompt locks, forwards OpenAI retry options, and turns session-takeover failures into visible retry guidance.

## Best Possible Solution

Keep the released-window SDK retry default at zero, but carry the existing configured provider retry budget into a bounded full-attempt retry loop that reacquires the session lock before every retry and covers the same transport-error classes.
