## Summary

This PR addresses a real P1 silent-reply-loss path and includes meaningful live-style proof, but it still replaces configured provider retry counts with a single generic outer retry. Keep it open for the narrow repair already identified in prior review: retain the zero-retry released-lock invariant while honoring configured retry policy at the full-attempt owner.

## What This Changes

The branch makes embedded steering writes fence-aware, disables SDK retries while the prompt lock is released, forwards retry options through OpenAI transports, and surfaces takeover/retry failures as user-visible replies.

## Best Possible Solution

Keep SDK retries at zero only inside the released prompt-lock window, then have the outer full-attempt orchestrator honor the configured provider retry budget while reacquiring the session lock for every attempt.
