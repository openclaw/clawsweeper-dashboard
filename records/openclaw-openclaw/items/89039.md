## Summary

Keep this PR open, but it is not ready to merge. The current head still repurposes the existing provider retry setting as a budget for repeating the entire fallback cycle, which changes configured retry semantics; its supplied real-process proof also predates that final configured-retry behavior.

## What This Changes

The branch makes embedded-agent session takeovers fence-aware, disables SDK retries during the released prompt-lock window, retries eligible transport failures outside that window, and returns resend guidance instead of silently losing a reply.

## System Context

Embedded agent turns release a session-file lock while a model request is in flight, then reacquire and validate a fence before continuing. The reply runner maps model and lock failures into fallback decisions and user-facing reply payloads for the originating channel.

## Architecture Diagram

flowchart LR

  B --> C[Released prompt lock]
  C --> D[Model provider request]
  D --> E[Retry and fallback decision]
  E --> F[Session fence reacquire]
  F --> G[Reply payload]
  G --> H[Channel delivery]

## Best Possible Solution

Keep SDK retries disabled during the released lock window, but implement configured retries at a lock-owning provider-candidate boundary so each attempt reacquires the session lock without replaying unrelated fallback routing; then publish redacted live output from the final head.
