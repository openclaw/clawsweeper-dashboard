## Summary

This remains necessary: the current supported macOS 15 CLI release can fail before `main`, and the current universal-build path still creates and signs only a standalone executable without a visible compatibility-runtime packaging or runtime-dependency verification step.

## What This Changes

The issue reports that the v3.9.6 macOS CLI binary dynamically requires `libswiftCompatibilitySpan.dylib`, which is absent from the release artifact and prevents launch on macOS 15.

## Best Possible Solution

Publish a replacement CLI artifact that runs on a clean macOS 15 host, preferably by eliminating the undeclared runtime dependency when supported by the Swift toolchain, and add a release-artifact smoke check that runs `peekaboo --version` outside the build toolchain.
