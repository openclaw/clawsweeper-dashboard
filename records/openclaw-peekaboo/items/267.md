## Summary

Keep this PR open, but do not merge the current head: the underlying cancellation bug is valid, yet the unchanged patch still converts cancellation into ordinary misses in three helpers, allowing the top-level verifier to continue and potentially report a normal verification failure. Green CI does not exercise this behavior, and the updated PR body still lacks an after-fix real cancellation run.

## What This Changes

The PR adds cancellation exits after seven swallowed polling sleeps in the CLI menu-bar click verifier.

## Best Possible Solution

Preserve cancellation as `CancellationError` through the complete `verifyClick` call path—either make all affected wait helpers throwing or add immediate top-level cancellation checks—then add focused regression coverage and demonstrate prompt cancellation in a real macOS run.

## Reproduction Assessment

Yes, at source level. Cancel while `waitForFocusedWindowChange`, `waitForOwnerWindow`, or `waitForMenuExtraMenuOpen` is sleeping; the proposed check returns an ordinary miss, after which `verifyClick` continues rather than immediately propagating cancellation.

## Solution Assessment

No. Checking every swallowed sleep is necessary, but the current return values do not preserve the throwing API's cancellation contract; typed propagation plus focused tests is the narrower complete fix.
