## Summary

Keep open for product direction: current main is explicitly Cloudflare-native and does not provide a supported Docker or non-Cloudflare production runtime, while the requested portability would require replacing several authoritative runtime services rather than adding packaging alone.

## What This Changes

Request a supported Docker-based self-hosting deployment path that does not depend on Cloudflare.

## Best Possible Solution

Define a portability RFC and conformance contract for request execution, strongly consistent policy authority, budget ledgers, queues, secret storage, content retention, and administrator identity; then implement a supported Docker target only if maintainers sponsor equivalent non-Cloudflare backends without weakening the hot path.
