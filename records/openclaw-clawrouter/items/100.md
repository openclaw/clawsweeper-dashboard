## Label Justifications

- `P1`: One user's spending can exhaust the shared production quota and block the authenticated maintainer workflow for everyone assigned to that policy.
- `impact:auth-provider`: The issue concerns authenticated principal attribution, policy-bound access, and proxy credential issuance.
- `impact:security`: Allowing signed-in users to create durable proxy credentials changes a credential and authorization boundary.

## Summary

Keep open: current main confirms that assignment-rule users sharing a policy also share its monthly budget window, while durable proxy-key issuance remains administrator-only. The requested isolation and self-service flow are not implemented, but maintainers must define the human-versus-service accounting and credential-authority boundary before implementation.

## What This Changes

Requests per-principal budget isolation for assignment-rule policies and session-authenticated self-service proxy-key issuance.

## Best Possible Solution

Use principal-aware monthly budget subjects for verified human assignment identities while retaining shared policy budgets for service credentials, then expose a constrained session endpoint that issues only caller-bound credentials under server-derived effective policies with limits, expiry, rotation, and revocation.
