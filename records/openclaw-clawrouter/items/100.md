## Label Justifications

- `P1`: Before the fixes, one maintainer could exhaust the shared quota for every maintainer, while obtaining a usable proxy key required administrator intervention.

## Summary

Close as implemented: the shared-budget failure was resolved by the merged per-principal accounting change, and the remaining administrator dependency was resolved by the subsequent self-service credential change now at the supplied current-main SHA.

## What This Changes

The issue requests isolated per-principal maintainer budget windows and session-authenticated self-service proxy-key issuance.

## Best Possible Solution

Keep principal scoping opt-in so service policies retain shared-budget compatibility, while self-issued keys remain bound to the authenticated principal and already-held policies with atomic limits, same-origin mutation checks, and one-time secret handling.

Required: false

## Reproduction Assessment

Yes at source and production-evaluation level: the original ledger key shared one policy window, and credential mutation was restricted to administrator routes. This is not a remaining current-main failure because both gaps are now implemented.

## Solution Assessment

Yes. The split implementation preserves existing shared service-policy semantics while adding an explicit principal scope and narrowly constrained session credential authority rather than broadening administrator APIs.
