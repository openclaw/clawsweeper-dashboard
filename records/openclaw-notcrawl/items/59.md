## What This Changes

The issue requests that API sync treat unsupported `ai_block` block-children 400 validation errors as nonfatal warnings so the rest of the workspace can continue syncing.

## Best Possible Solution

Yes from source inspection: `walkBlocksAt` returns any `/blocks/{id}/children` request error, `ingestPage` returns `walkBlocks` errors, and `Sync` returns `ingestPage` errors. I did not use a live Notion workspace because that requires the reporter's token and workspace content.

## Solution Assessment

Yes: the narrow repair path is to classify this specific unsupported block-children error as nonfatal, surface it through existing API warnings, and avoid marking or retiring page blocks after a partial walk.
