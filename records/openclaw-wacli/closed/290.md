## Summary

Keep open: current main still only reconnects follow mode on disconnect-like events or whatsmeow `KeepAliveTimeout`, while this current-release report describes message ingestion going stale with no disconnect, reconnect, or stale event. The earlier keepalive-bound fix and the v0.11.2 presence/socket change are relevant context, but they do not fully cover the reported failure shape.

## What This Changes

The issue reports that `sync --follow --stale-threshold` on v0.11.2 stops ingesting WhatsApp messages while remaining connected, and asks for freshness-based reconnect or stale health reporting.

## Best Possible Solution

Define a follow-mode health contract that distinguishes healthy quiet sessions from connected-but-not-ingesting sessions, then implement tested reconnect or unhealthy doctor behavior in the sync/app layer with redacted live proof.

## Reproduction Assessment

No, we do not have a high-confidence live reproduction in this checkout. Source inspection does confirm that current main cannot react to the reported shape unless whatsmeow emits `KeepAliveTimeout`, `Disconnected`, or `StreamReplaced`, and the reporter supplied detailed current-release operational evidence.

## Solution Assessment

Unclear: a freshness-based reconnect may be the right repair, but current main intentionally made `--stale-threshold` keepalive-only. Maintainers should decide whether to broaden that flag, add a separate health/watchdog surface, or change `doctor` semantics.
