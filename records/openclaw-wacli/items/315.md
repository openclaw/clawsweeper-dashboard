The new receipt and chat-presence paths are otherwise a focused extension of the existing sync webhook flow.

## What This Changes

This PR adds an opt-in `--webhook-events` flag so `wacli sync --follow` can POST receipt and per-chat typing-presence events as well as messages.

## System Context

`wacli sync --follow` receives live WhatsApp events, stores messages locally, and can asynchronously POST selected events to an operator-provided webhook. This change extends that outbound webhook boundary from stored messages to receipt and chat-presence events while keeping the queue and HTTP delivery worker shared.
