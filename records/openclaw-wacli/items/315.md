## Summary

Keep this PR open. The latest commit fixes the earlier event-selection bug, but the default webhook payload now unconditionally gains `EventType`; that changes the established legacy JSON contract for every existing `sync --webhook` consumer. It also still lacks redacted after-fix runtime proof for receipt and chat-presence delivery.

## What This Changes

This PR adds `--webhook-events` so `wacli sync --follow` can optionally POST message receipts and per-chat typing-presence events to the existing webhook endpoint.

## System Context

Continuous sync receives WhatsApp events, persists live messages, and uses a bounded worker to POST selected events to a configured webhook. This PR changes the event-selection and serialization boundary between runtime events and webhook consumers.

## Best Possible Solution

Keep the no-flag/default webhook body byte-for-byte compatible, make the expanded discriminated event contract explicitly opt-in, remove the release-owned changelog edit, and attach redacted live receiver output covering a message, receipt, and typing-presence event.
