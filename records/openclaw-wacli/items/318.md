## Summary

Keep this PR open. The opt-in CLI surface also needs maintainer direction, and the supplied evidence remains unit-level rather than an after-fix follow-daemon run.

## What This Changes

Adds an opt-in `sync --follow --send-spacing <min>[-<max>]` flag that spaces serialized delegated WhatsApp sends by a fixed or randomized delay.

## System Context

`sync --follow` starts a long-lived WhatsApp daemon that receives local delegated `wacli send` requests through a Unix socket. The daemon serializes those requests before dispatching them through the WhatsApp client, and this PR adds an optional delay at that serialized dispatch point.

## Best Possible Solution

Keep the default unchanged, but bind the delegate socket deadline and the pacing/send context to one effective request deadline, add a regression test for an interval beyond five minutes, and provide redacted real-daemon evidence showing two delegated sends are paced and acknowledged.
