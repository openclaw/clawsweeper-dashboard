## Summary

The core failure is convincingly reproduced and the recovery design is promising, but two correctness defects remain: mute operations synchronize the wrong app-state collection, and one-shot catch-up can consume deltas without persisting them locally.

## What This Changes

The PR adds context-bounded app-state catch-up, recovery-snapshot requests, exponential backoff, and regression tests before archive, pin, mute, and read-state writes.

## Best Possible Solution

Make recovery collection-aware for each mutation and route pre-write catch-up through the established app-state persistence handler so whatsmeow state and wacli.db advance together.

## Solution Assessment

No, not in its current form. Waiting for keys and requesting one recovery snapshot is appropriate, but the helper must target the collection written by each operation and preserve fetched events through the normal database update path.
