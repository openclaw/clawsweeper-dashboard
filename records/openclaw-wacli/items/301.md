## Summary

This issue remains necessary: current main still constructs outbound reply context with only the referenced stanza ID and an optional participant, without the quoted message payload needed to preserve the visible quote. The detailed live report matches that source path, and neither current main nor v0.12.0 contains evidence that the silent degradation was fixed.

## What This Changes

Fix `send text --reply-to` so delivered messages retain their requested WhatsApp quoted-reply context instead of silently arriving as plain text.

## Best Possible Solution

Construct the quoted payload from the locally stored target message using the established whatsmeow representation, resolve the correct participant for incoming and own outgoing targets, and fail before sending when a valid quote cannot be built.
