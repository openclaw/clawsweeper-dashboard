This is substantively duplicated by the broader open multi-account proposal at https://github.com/openclaw/wacrawl/issues/46, but the repository’s conservative onboarding profile only permits automatic issue closure when the exact change is certainly implemented on current `main`. ## What This Changes

Add profile-scoped, concurrent Wacrawl backup and sync for multiple named wacli accounts, with isolated archives, source validation, and per-profile failure handling.

## System Context

Wacrawl imports WhatsApp Desktop data into a local archive, then exposes that archive to search and encrypted backup/restore workflows. This request would add an alternative read-only wacli source and coordinate separate archive and backup lifecycles for several accounts on one host.

## Architecture Diagram

  D --> E[Per-profile archive and media]

  F --> G[Encrypted per-profile backups]

## Best Possible Solution

Consolidate the concurrent-wacli-profile scope under https://github.com/openclaw/wacrawl/issues/46, then define a narrow profile/storage contract that preserves existing single-account Desktop imports before implementing a read-only wacli adapter.
