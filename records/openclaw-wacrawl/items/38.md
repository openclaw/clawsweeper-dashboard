## Label Justifications

- `P2`: This is a meaningful archive-retention and search improvement, but it is a broad new capability rather than an urgent regression.
- `impact:data-loss`: Messages absent from a newer WhatsApp snapshot are removed from the active searchable archive, even when an older backup commit still retains them.

## Summary

Current main still models the archive as one point-in-time snapshot, so older messages can remain recoverable in Git backups without being searchable in the active database. The request is still necessary, but it combines cumulative storage semantics with first-class account profiles and therefore needs an explicit product/data-model decision before implementation.

## What This Changes

Add isolated multi-account profiles and cumulative, deduplicated import and search across historical WhatsApp archive snapshots.

## Best Possible Solution

Define an account-scoped cumulative archive that reconciles new imports without discarding older messages, while preserving Git commits as immutable point-in-time backups and delivering named profiles as a separately scoped layer.

- **Snapshot federation:** Keep replacement imports and build a query or indexing layer over selected historical backup commits.
- **Defer first-class support:** Continue using separate source, database, and backup configuration paths and document that manual isolation workflow.

## Reproduction Assessment

Yes for the stated limitation: current source deterministically clears prior archive rows during replacement, and search only queries the resulting active database. This verifies the gap, although the requested behavior is a new capability rather than a broken existing contract.

## Solution Assessment

Unclear as one combined implementation: cumulative merging, cross-snapshot federation, and named profiles have different boundaries. A maintainer-approved cumulative archive contract followed by separately scoped profile UX is the narrowest maintainable direction.
