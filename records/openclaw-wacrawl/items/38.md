## Summary

This remains necessary: current main still replaces the live archive during import, searches only that database, and restores historical snapshots as separate point-in-time archives. The request is valid but combines two substantial product directions—cumulative historical retention and first-class account profiles—that need an explicit storage and UX decision before implementation.

## What This Changes

Requests isolated multi-account profiles and deduplicated search or merging across all retained historical WhatsApp snapshots.

## Best Possible Solution

Keep the ordinary archive as the latest point-in-time view, add a read-only historical snapshot catalog with federated deduplicated search, and separately define named profiles that isolate source, database, media, identity, and backup configuration.

- **Keep manual isolation only:** Retain --db and --source as the multi-account mechanism and scope this issue solely to historical snapshot search.
