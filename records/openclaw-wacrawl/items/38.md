- `impact:data-loss`: Messages omitted from a later WhatsApp Desktop snapshot leave the active archive and normal search unless an older snapshot is manually restored.

## Summary

Current main still replaces the active archive during import and searches only that archive. The request remains necessary, but cumulative retention and first-class account profiles require an explicit storage, identity, compatibility, and UX direction rather than a narrow bug fix.

## What This Changes

Add isolated WhatsApp account profiles and make messages retained only in historical snapshots searchable through federation or a deduplicated cumulative archive.

## Best Possible Solution

Define a stable account identity, retain immutable point-in-time snapshots, add named profiles that own source/database/media/backup paths, and initially provide read-only federated search with account-scoped deduplication before considering a cumulative materialized archive.

Options:

- **Federate snapshots, split profiles (recommended):** Keep current snapshot and restoration semantics, design account-scoped identity, deliver cross-snapshot search first, and track named account profiles separately.
- **Build cumulative archive model:** Retain and reconcile historical rows during import, with explicit migrations and compatibility proof for backup, restoration, deletion, and existing setups.
- **Profiles and federation together:** Design a unified profile registry whose search spans every profile and snapshot, accepting a larger multi-area implementation and migration effort.
