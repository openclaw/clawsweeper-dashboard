## Label Justifications

- `P2`: This is a valid but substantial archive and account-management improvement with limited current blast radius and no demonstrated emergency regression.
- `impact:data-loss`: Messages that disappear from a later WhatsApp Desktop snapshot are removed from the searchable live archive even though an older encrypted snapshot may still retain them.

## Summary

Keep this issue open: current main still replaces the live archive during each import, searches only the configured archive database, and restores historical backups as separate point-in-time archives; path overrides allow manual isolation but do not provide first-class account profiles.

## What This Changes

Add isolated WhatsApp account profiles and cumulative, deduplicated search or storage across current and historical archive snapshots.

## Best Possible Solution

Split the work into two coordinated designs: add an explicit per-account profile namespace, then add an opt-in historical import that merges into a cumulative archive using account-scoped stable identities and snapshot provenance while preserving existing point-in-time backup pull behavior.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should wacrawl first implement a per-account cumulative archive with explicit historical imports and track first-class profile UX separately, or should both capabilities be designed as one combined storage migration?

Rationale: The current replacement archive, backup restore contract, message identity, media layout, and global path defaults all need a consistent product boundary before code can safely choose merge semantics or profile configuration.

Likely owner: steipete

Owner confidence: high

Options:

- **Split cumulative history first (recommended):** Design an account-scoped cumulative archive and explicit historical merge command first, while tracking named profile UX as a separate follow-up that reuses the same namespace.
- **Design one combined migration:** Introduce profiles, account-scoped schema identity, backup configuration, media layout, and cumulative history together as one larger coordinated storage migration.
- **Keep manual isolation only:** Retain the existing --db, --source, and --config path workflow and defer cumulative retention and named profiles.

## Reproduction Assessment

Yes at source level: import a snapshot containing an older message, then import a newer source snapshot without it; ReplaceAll deletes the existing message and FTS rows before loading the newer snapshot. A live WhatsApp dataset was not exercised during this read-only review.

## Solution Assessment

No, implementing cumulative history and first-class multi-account profiles as one undifferentiated feature is not the narrowest safe path. The storage identity and historical merge contract should be designed first, with profile UX split into a coordinated follow-up.
