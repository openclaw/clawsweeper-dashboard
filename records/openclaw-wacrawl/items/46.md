## Summary

This issue remains necessary: the merged cumulative-import foundation keeps account archives bound and separate, but it explicitly did not add concurrent multi-account profiles, a read-only `wacli` source, or searchable ingestion from older snapshots. The broad request also overlaps with a narrower open multi-account report, so a maintainer should choose the supported product boundary before implementation.

## What This Changes

Add isolated Wacrawl profiles with a read-only `wacli` account source for concurrent backups, plus a safe way to expose history retained only in older matching-account snapshots.

## System Context

Wacrawl imports WhatsApp data into an account-bound local archive, then backs that archive and copied media into encrypted Git snapshots. This request would add a source/profile layer before ingestion and a historical-retrieval path after snapshot storage, while preserving strict account separation.

  D --> E[Cumulative message ingestion]
  E --> F[Encrypted backup snapshots]
  F --> G[Current and historical search]

## Best Possible Solution

First define and sponsor a narrow profile/source contract that preserves the existing account-binding and Desktop workflows; then implement concurrent read-only `wacli` ingestion and historical snapshot reconciliation as separately validated follow-up slices.
