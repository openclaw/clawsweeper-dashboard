## Summary

This issue remains necessary. Current Wacrawl supports one WhatsApp Desktop source/archive and exact historical snapshot restore, while the merged cumulative-import work intentionally stopped short of multi-account profiles, a `wacli` source contract, and federated historical search; the overlapping open requests need a maintainer-owned scope decision before implementation.

## What This Changes

Add isolated multi-account Wacrawl profiles with a read-only named `wacli` source, concurrent per-profile sync/backup, and a way to make matching-account historical snapshot data searchable without replacing newer data.

## System Context

Wacrawl snapshots a local WhatsApp Desktop SQLite source into its own archive, then serves search and creates encrypted Git backups of that archive. This request would add a source/profile layer ahead of archive ingestion and make sync, backup, and historical recovery operate safely per account.

## Architecture Diagram

flowchart LR
  A[WhatsApp Desktop source] --> C[Source snapshot and import]
  B[wacli named account store] --> D[Profile and source validation]
  D --> C
  C --> E[Account-scoped Wacrawl archive]
  E --> F[Search and local viewer]
  E --> G[Encrypted Git backup]
  G --> H[Historical restore or future federation]

## Best Possible Solution

Choose a phased core design: first define an account-scoped, read-only source-adapter/profile contract with strict archive and media isolation for the multi-account goal, then separately decide whether historical refs should be merged into an archive or queried through an explicitly federated search surface.
