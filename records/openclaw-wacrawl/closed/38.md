## Label Justifications

- `P2`: The request addresses meaningful archive retention and search limitations but proposes new product capability rather than an urgent established-behavior regression.
- `impact:data-loss`: Messages absent from a later WhatsApp Desktop source are removed from the active archive during replacement import, even though an older encrypted snapshot may still retain them.

## Summary

This remains necessary: current main preserves point-in-time encrypted backups, but imports and restores replace one configured archive, and search is against that single archive. The requested cumulative-history and account-profile behaviors therefore remain unimplemented and need a maintainer decision on the storage and UX boundary before work begins.

## What This Changes

Add isolated WhatsApp account profiles plus cumulative, deduplicated history import or cross-snapshot search without losing newer archive data.

## Best Possible Solution

Split the work into a profile-scoped archive model and a separately specified cumulative-history feature; preserve immutable snapshot restores while adding explicit provenance, deterministic deduplication, and either a materialized aggregate archive or a read-only federated search index.

Options:

- **Split and design cumulative history first (recommended):** Define an account-independent snapshot provenance and deduplication contract first, then track multi-account profile isolation as a separate follow-up.
- **Build one profile-aware archive program:** Adopt profile namespaces, profile-scoped backup state, and cumulative history together, accepting a larger schema and migration program.
- **Keep snapshot restore only:** Document point-in-time restore to an alternate `--db` as the supported recovery path and decline aggregate-history behavior for now.

## Solution Assessment

No: implementing the combined request as one undifferentiated change would make identity, deduplication, backup, and migration behavior ambiguous. A separately specified cumulative archive plus a distinct profile-isolation decision is the more maintainable path.
