## Summary

The focused patch appears correct and current main still lacks containment for intrinsically wide Markdown tables; the PR should remain open for normal merge review, with the failing TypeScript check resolved before landing.

## What This Changes

The PR wraps rendered GFM tables in a sanitized horizontal-scroll container and adds native-layout table styling within web message Markdown.

## Best Possible Solution

Land the dedicated scroll wrapper as the single overflow boundary while retaining native table layout and the existing DOMPurify sanitization path.

## Maintainer Decision

## Reproduction Assessment

Yes, at source level: current main renders native GFM tables without a dedicated overflow container, so a table wider than a narrow message surface can exceed that surface.

## Solution Assessment

Yes. Wrapping the native rendered table is narrower and safer than applying block overflow directly to the table because it contains width without replacing the browser's table layout model.
