## What This Changes

Adds an idempotent managed-channel reconciliation API that creates, updates, archives, or reopens one externally identified channel across SQLite, Postgres, OpenAPI, and the TypeScript SDK.

## System Context

ClickClack integrations use workspace-bound bot credentials to manage durable collaboration channels. This change accepts an external provider/reference identity, reconciles it to one stored channel, and returns the canonical channel plus any durable state-change event.

## Architecture Diagram

flowchart LR
  A[External integration webhook] --> B[Workspace-bound bot request]
  B --> C[Managed channel reconcile API]
  C --> D[Provider and reference identity]
  D --> E[SQLite or Postgres channel store]
  E --> F[Created updated or unchanged result]
  F --> G[Durable channel event when state changes]

## Best Possible Solution

If maintainers want ClickClack to own a provider-neutral durable-channel primitive, merge this narrowly scoped API with its migration and compatibility tests while keeping provider-specific synchronization outside core.
