## Summary

Current main has managed-channel primitives but not the proposed GitHub App adapter. This is a broad optional integration with credential, webhook, deployment, and privacy policy choices, so it should remain open for maintainer product-direction review.

## What This Changes

Add a reference GitHub App integration that reconciles one externally managed ClickClack channel per pull request and records bounded lifecycle updates.

## System Context

ClickClack’s managed-channel API lets authorized bots attach a durable channel to an external work item and archive or restore that conversation. The proposed adapter would receive GitHub pull-request events, fetch canonical GitHub state, and use that API to keep the related ClickClack conversation current without giving ClickClack authority over GitHub.

## Architecture Diagram

flowchart LR
  A[GitHub pull request events] --> B[Reference GitHub App receiver]
  B --> C[Signature and repository checks]
  C --> D[Fetch current pull request state]
  D --> E[Managed-channel reconciliation]
  E --> F[Deduplicated lifecycle messages]
  F --> G[ClickClack channel and archive state]

## Best Possible Solution

First settle and, if accepted, land the provider-scoped reconciliation contract; then implement the GitHub adapter as a separately deployable reference package with explicit GitHub App permissions, secret handling, allowlisting, lifecycle proof, and no server-side credential storage.
