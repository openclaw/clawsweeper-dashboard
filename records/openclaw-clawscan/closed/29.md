## Summary

Keep this active for maintainer review. The member-authored PR adds a narrow Windows host-shell command-injection guard, but it deliberately makes some previously runnable target paths fail and therefore needs explicit acceptance of that compatibility change.

## What This Changes

The PR rejects user-defined scanner targets containing `%`, `!`, or double quotes when ClawScan executes them through the Windows host `cmd.exe` path, while retaining existing Docker and POSIX execution paths.

## System Context

User-defined scanners are declared in a ClawScan profile, rendered with a scan target, and then executed by either Docker or a host shell. This change sits between shell selection and command rendering so unsafe Windows host targets become a failed scanner result rather than reaching `cmd.exe`.
