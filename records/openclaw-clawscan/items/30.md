## What This Changes

This PR changes profile-defined scanner execution so host runs use a disposable working directory and Docker runs do not derive their working directory from the scan target, with tests for the workspace lifecycle.

## System Context

Profiles can define external scanner commands, which ClawScan resolves into scanner adapters and executes through either the host runner or Docker sandbox. The adapter passes the scan target to the command and records its raw JSON evidence, so the sandbox must let the scanner read that target without granting writable access to neighboring files.

## Best Possible Solution

Keep the disposable host cwd, and give Docker scanners a dedicated read-only mount of the exact scan target at a stable container path while rendering that container path into the scanner command; add an end-to-end Docker test that reads the target and proves writes to it or its parent fail.
