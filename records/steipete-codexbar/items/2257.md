## Summary

Keep open: current main exposes provider-scoped model breakdowns but not canonical cross-provider model aggregation, and the distinct remaining work requires an explicit product and data-contract decision.

## What This Changes

Requests a model-centric token and cost view that groups usage across providers while addressing model identity, currencies, double-counting, and UI density.

## Best Possible Solution

Introduce a provider-safe Models surface first: preserve provider-qualified identities, aggregate tokens only when an authoritative canonical mapping exists, retain costs by provider and currency, expose uncertain aliases rather than guessing, and add cross-provider controls only after provenance and double-counting rules are defined.

## Risks / Open Questions

- Provider model aliases do not currently supply a trustworthy canonical identity, so aggregation could merge unrelated models or leave equivalent models split.

- Adding model rows to existing provider cards could worsen the Overview density problem tracked by https://github.com/steipete/CodexBar/issues/2107.
