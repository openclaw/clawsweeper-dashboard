## What This Changes

Requests a model-centric token and cost view that aggregates usage across providers while handling canonical model identity, currencies, and duplicate accounting.

## Best Possible Solution

Define a shared aggregation contract with canonical model IDs, provider/source provenance, currency-specific cost buckets, and duplicate-exclusion rules, then use it for a dedicated Models view and CLI output rather than expanding already-dense provider cards.

## Risks / Open Questions

- Canonical aliases could merge distinct provider products or split equivalent models, producing misleading totals.
- Combining actual billing data with local API-rate estimates could present a false precision unless provenance remains visible.
- Cross-provider costs cannot be safely collapsed into one figure when currencies or pricing bases differ.
- The same underlying request may appear in local tool logs and provider billing APIs, causing double counting without source identity or explicit exclusions.
- Adding model rows to existing provider cards could worsen the Overview density problem tracked at https://github.com/steipete/CodexBar/issues/2107.
