## What This Changes

The PR distinguishes direct percentage fields from computed usage ratios in the OpenCode and OpenCode Go parsers, then adds Linux regression tests for sub-one-percent computed values and fractional direct fields.

## Best Possible Solution

Merge the narrow origin-aware normalization guard after the existing Linux and macOS test matrix completes successfully, keeping direct fractional-field normalization unchanged.

## Reproduction Assessment

Yes. On current main, a parsed payload with `used: 1` and `limit: 100` reaches `(used / limit) * 100 == 1`, then the unconditional `<= 1` heuristic changes it to 100; the same path exists in both providers.

## Solution Assessment

Yes. Tracking whether the selected percent came from a direct field is the narrowest maintainable correction because it preserves the existing direct-fraction contract while leaving computed percentages in their native 0–100 range.
