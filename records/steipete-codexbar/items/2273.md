## Summary

Keep this PR open: the new configurable label modes are a reasonable feature direction and the PR now includes redacted live CLI output for metadata and fallback behavior, but it can attach a descriptive title from one session to another process when multiple Codex sessions share the same working directory. The existing review discussion identifies a concrete P2 correctness gap that should be repaired before merge, while the new preference itself still needs product sponsorship.

## What This Changes

This PR adds Project, Descriptive, and Descriptive + project agent-session label modes, sourcing optional Codex thread and subagent metadata from local state SQLite files and carrying it through remote session JSON.

## Best Possible Solution

Retain Project as the compatibility default and only show rollout-derived descriptive labels when the rollout can be correlated unambiguously to the specific process; preserve project-name fallback otherwise, then land the setting only with explicit product sponsorship.
