## Summary

The patch correctly addresses a reproduced Codex fork-accounting bug and includes strong real-corpus proof, but the changed cache-reuse path performs potentially expensive parent indexing before a known priority-rescan rejection; that low-risk efficiency defect should be fixed before landing.

## What This Changes

The PR prefers leaf fork identities, tracks parent-file dependencies for cached fork baselines, rotates the parser hash, documents cache versioning, and adds focused scanner regressions.

## Best Possible Solution

Keep leaf-ID precedence and direct-parent fingerprint invalidation, while preserving the existing cheap cache-rejection gates ahead of parent index work so correctness does not add unnecessary refresh cost.
