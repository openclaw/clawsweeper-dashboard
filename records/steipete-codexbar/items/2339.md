## Summary

Keep this PR open: it advances the configurable-cap portion of the related request, but the new value does not participate in merged-menu invalidation, so an already-rendered Overview can retain the old row count until another settings change or restart. The requested 1–12 persistent setting also needs a maintainer product decision because the canonical request frames the cap and compact-density behavior together.

## What This Changes

The PR adds a persistent 1–12 Settings stepper for the merged Overview provider cap and changes the menu limit lookup from a fixed constant to a `UserDefaults`-backed value.

## Best Possible Solution

If a maintainer sponsors a configurable cap, model it in `SettingsStore`’s observed defaults state, invalidate or rebuild the merged menu when it changes, add focused regression coverage, and validate the chosen range in a freshly built app bundle.
