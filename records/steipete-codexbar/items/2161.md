## Summary

The patch is focused, technically coherent, and supported by live workflow evidence with no actionable correctness finding. Keep it open for the repository owner to confirm that a green aggregate check may intentionally represent deferred macOS validation on drafts, because that branch-protection policy cannot be settled by tests alone.

## What This Changes

The PR defers macOS Swift shards for code-changing draft pull requests, exposes the deferral through the aggregate CI gate, reruns CI on draft-state transitions, and makes a Kiro detached-child timing fixture return parseable context output.

## Best Possible Solution

Adopt the explicit deferred state only if ready-for-review and merge-queue policy reliably require a fresh aggregate result backed by both macOS shards; otherwise use a distinct readiness guard that cannot be satisfied by the earlier draft run.
