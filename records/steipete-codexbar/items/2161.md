## Summary

The patch is correct, focused, and strongly validated, but it intentionally allows the aggregate required check to pass before macOS validation runs on code-changing drafts. That repository-level CI policy needs explicit owner approval before merge.

## What This Changes

The PR defers macOS Swift shards for code-changing draft pull requests, reruns CI on draft-state transitions, reports deferral as aggregate success, and repairs a Kiro detached-child timing fixture.

## Best Possible Solution

Adopt the explicit deferred-state design only if the repository owner confirms that green aggregate status on drafts is desired, while retaining mandatory fresh macOS validation when a pull request becomes ready for review.
