## Summary

The current head addresses the prior cache-version, oversized-complete-record, and changelog feedback, but it remains blocked by a newly introduced oversized incomplete-tail correctness defect and absent real behavior proof.

## What This Changes

The PR changes incremental JSONL scanning to retain incomplete EOF records, invalidates older cost caches, and adds regression coverage for append and oversized-record cases.

## Best Possible Solution

Track JSON completion independently of retained line bytes so complete oversized EOF records can be emitted while oversized incomplete records preserve the prior committed offset, with regression and live upgrade proof for both paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: current main flushes the final buffer and returns EOF, so appending the remainder of an incomplete JSON object makes the next incremental scan begin after its prefix. The added ordinary-tail test captures that path, while the new EOF condition exposes the analogous oversized-tail failure.

## Solution Assessment

No, not fully: validating complete small tails while committing every truncated tail conflates size clipping with JSON completeness. The scanner needs completion-aware state that continues working after retained bytes reach `maxLineBytes`.
