## Summary

Keep this PR open: its re-import action can clear a working cached cookie without being allowed to read Chromium cookies back, so the advertised recovery path can leave OpenCode or OpenCode Go unauthenticated. It also expands a user-initiated retry into an all-browser cookie scan contrary to the repository’s Chrome-first guidance. Real after-fix behavior proof is still required before merge.

## What This Changes

The PR adds trailing re-import cookie buttons to the OpenCode and OpenCode Go settings pickers, clears cached cookies, attempts a browser import, and refreshes the selected provider.

## Best Possible Solution

Scope both actions as user-initiated retries, retain Chrome-first browser selection unless a provider-specific override is necessary, add focused gate/refresh coverage for both providers, then attach redacted after-fix UI or runtime proof.
