## What This Changes

This PR lets an explicit Grok cookie refresh import and cache a validated browser session, then reuse that session for later Grok usage fetches without allowing ordinary CLI imports.

## System Context

CodexBar’s provider fetch pipeline chooses a Grok CLI or web strategy for usage data. The web strategy can read a Chrome session on macOS, validates it against Grok billing, and returns usage to the menu-bar app or CLI while cache state avoids unnecessary browser and Keychain access.

## Architecture Diagram

flowchart TD
    A[CLI or app usage request] --> B[Grok provider strategy]
    B --> C{Cached validated session?}
    C -->|Yes| D[Fetch Grok billing]
    C -->|No| E{Browser import permitted?}
    E -->|Explicit refresh or app| F[Read and validate browser session]
    E -->|Routine CLI| G[Use auth file or report unavailable]
    F --> H[Store validated session cache]
    H --> D
    D --> I[Usage result for app or CLI]

## Best Possible Solution

Preserve the explicit-refresh repair while documenting and testing the interaction-context contract: only deliberate refresh actions may enable browser-cookie import, and normal CLI/background fetches must remain unable to do so on a cache miss.
