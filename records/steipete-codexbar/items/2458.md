## Summary

This PR remains necessary: current main still blocks Grok browser-cookie import for CLI work unless the environment override is set, while the proposed path enables it only for an explicit refresh and reuses the validated cache. The latest head also addresses the earlier stale team-cookie concern, but its new fallback path lacks current-head real-behavior proof, so it should stay open for contributor evidence and maintainer review rather than be auto-closed.

## What This Changes

The PR lets an explicitly initiated `codexbar cookie refresh --provider grok` import and cache a validated Chrome session, preserves ordinary CLI/background gating, evicts only authentication-failed cached sessions, and documents and tests the flow.

## System Context

CodexBar’s Grok usage provider first resolves a fetch strategy, then reads a cached browser session or—when permission allows—imports Chrome cookies to call Grok billing. A validated session is cached for later app and CLI usage requests, while authentication failures evict only the cache entry that was actually used.
