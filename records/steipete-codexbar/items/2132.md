## Summary

This remains a valid but unsponsored product-direction request: current main supports four manually selected static display modes, while automatic cycling, interval settings, unavailable-mode skipping, and menu-open pausing are all new behavior that needs UX approval before implementation.

## What This Changes

Add an optional, configurable rotation that cycles selected menu-bar display modes for the current provider and usage window.

## Best Possible Solution

If maintainers sponsor the idea, introduce one shared disabled-by-default rotation policy that derives eligible states through the existing display-text seam, pauses during menu tracking, resets after manual selection, and initially keeps interval and mode-selection UX deliberately narrow.
