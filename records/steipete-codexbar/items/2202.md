## Summary

Keep this draft PR open. The fix remains necessary because current main only serializes Claude Keychain reads and does not coalesce the completed outcome across same-refresh callers; the proposed direction and deterministic coverage are credible, with no established line-level defect, but the authentication-path change still lacks required real Keychain proof and the repository’s full test/check results.

## What This Changes

The PR adds refresh-scoped outcome sharing for Claude OAuth Keychain reads and regression tests covering concurrent callers, cancellation, expired credentials, and delegated refresh retries.

## Best Possible Solution

Keep one interactive Keychain read and exact outcome per user-triggered refresh, preserve prompt suppression for background work, and allow delegated OAuth reloads and later independent refreshes to retry, with focused tests plus redacted packaged-app proof of those boundaries.
