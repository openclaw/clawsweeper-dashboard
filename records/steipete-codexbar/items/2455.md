## Summary

This PR addresses a real remaining Grok late-cycle pace gap, but it still drops reset-only weekly windows during the final half-day because its label heuristic rounds the remaining time to whole days. It also needs redacted after-fix runtime evidence before merge; the supplied tests are useful but do not show a live Grok billing/menu result.

## What This Changes

The PR derives a Grok web billing period length from protobuf timestamps and uses that duration to retain weekly or measured-monthly pace projections near a credit-window reset.

## System Context

CodexBar fetches Grok billing information, normalizes it into a shared usage window, and passes that window to the menu-card model for a human-readable cycle label and pace projection. The changed parser supplies duration data when possible, while the provider descriptor decides whether a reset-only window is weekly and eligible for pace.

## Architecture Diagram

flowchart LR

  B --> C[Shared usage window]
  C --> D[Weekly or monthly classification]
  D --> E[Pace eligibility]
  E --> F[Menu-bar usage card]

## Best Possible Solution

Classify reset-only weekly windows using the unrounded remaining interval against the seven-day horizon, add a sub-day regression case, and attach redacted after-fix evidence showing the late-cycle menu card retains its Weekly label and pace details.
