## Summary

Keep open: current main still stores the named UI preferences in UserDefaults, and the only portable-preferences prototype was closed unmerged because the storage contract was unsafe and incomplete.

## What This Changes

The issue requests a dotfiles-syncable JSON storage path for general CodexBar UI preferences such as refresh cadence, launch-at-login, merged overview selection, and display settings.

## Best Possible Solution

Approve a separate opt-in portable preferences.json for a narrow non-secret allowlist, then wire SettingsStore import/export or dual-write behavior with upgrade tests and diagnostics.
