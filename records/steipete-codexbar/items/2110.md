## Summary

The final head still has both correctness blockers from the prior review: metadata-only caching can remain stale behind a stable wrapper, and nonempty diagnostic output can be cached without confirmed command success. The installed-CLI transcript improves the evidence, but it starts a fresh test process and does not show zero warm subprocesses plus exactly one in-process reprobe across the real upgrade.

## What This Changes

The PR adds a lock-protected, single-flight in-memory cache for Claude CLI version probes keyed by resolved executable metadata, with focused cache, invalidation, concurrency, failure, benchmark, and live-executable tests.

## Best Possible Solution

Retain single-flight caching, but add bounded freshness or wrapper-target revalidation, cache only a version from a confirmed successful command completion, keep live-Claude tests explicitly opt-in, and provide redacted final-head process or runtime logs showing one cold probe, zero warm probes, and exactly one reprobe after a real in-process executable update.
