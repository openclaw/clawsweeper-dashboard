## Summary

Keep this issue open because the linked draft implementation PR, https://github.com/steipete/CodexBar/pull/2462, explicitly targets it and has not merged. The reported Chrome-only import order conflicts with the requested Firefox fallback, while repository guidance says Chrome-only imports are preferred by default; a maintainer should confirm the narrow LongCat exception before landing the paired change.

## What This Changes

Add Firefox as a Chrome-first fallback when LongCat automatically imports browser cookies, so an existing Firefox session can supply usage data.

## System Context

CodexBar providers obtain authenticated usage data from configured cookie sources. In Automatic mode, provider metadata selects which browser stores the shared cookie importer probes, and any discovered LongCat session feeds the LongCat usage refresh.
