## Summary

Keep this PR open but do not merge it yet: the proposed command is useful, but it creates a second cookie-cache workflow, reports a successful refresh when most providers are only cleared for a later fetch, and lacks the focused tests and real terminal proof needed for credential-sensitive behavior. The linked feature request also explicitly leaves the CLI shape for maintainer decision.

## What This Changes

Adds `codexbar cookie refresh` commands that clear provider cookie caches and directly re-import OpenCode-family browser sessions.

## Best Possible Solution

Extend the existing cookie-cache command with an explicit re-import option backed by the shared provider fetch/import pipeline, returning an accurate refreshed, deferred, unsupported, or failed result for every provider.

- **Keep cookie refresh:** Retain the new namespace only after implementing truthful provider-wide result semantics and documenting its distinction from cache clearing.
- **Document two commands:** Close this implementation and document cache clearing followed by a normal usage fetch as the supported recovery workflow.

## Solution Assessment
