## Summary

Current main still supports only rolling day-count cost windows, and no linked pull request or canonical issue owns the requested calendar-month mode. The request fits CodexBar’s spend-reporting vision, but its persisted cross-surface contract requires maintainer product sign-off before implementation.

## What This Changes

Add a saved month-to-date cost reporting mode alongside the existing rolling-day window across app, widgets, and CLI.

## Best Possible Solution

Introduce one typed semantic cost-period abstraction, resolved against a per-operation clock and shared by filtering, provider aggregation, cache identity, settings, app/widget labels, and CLI output, while preserving rolling days as the default and retaining legacy JSON aliases.
