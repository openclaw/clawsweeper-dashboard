## Summary

Keep this PR open because the prior P1 authorization blocker remains on the unchanged reviewed head: narrowing the default to fresh installs does not prevent existing Adaptive users from acquiring recurring local metadata scans after upgrade. Maintainer approval of the privacy boundary and stronger packaged-runtime proof are still required.

## What This Changes

The PR makes Adaptive the persisted cadence for fresh installs and uses bounded local Codex/Claude session metadata to pull slower Adaptive refresh timers forward to five minutes.

## Best Possible Solution

Separate cadence selection from local metadata authorization: preserve existing Adaptive users’ no-scan behavior, enroll only a maintainer-approved fresh-install cohort or explicit preference, and validate fresh and upgrade paths in the packaged app.
