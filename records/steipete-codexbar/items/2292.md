Keep this PR open for a focused regression-test correction: the renderer replacement is targeted and the supplied before/after runtime evidence is useful, but the new byte-value assertion can pass for an all-black RGBA image because opaque alpha bytes add a second sampled value.

## Best Possible Solution

Keep the `ImageRenderer` implementation and revise the regression test to compare sampled visible RGB pixel values while ignoring alpha, so an all-black export cannot pass solely due to its alpha channel.
