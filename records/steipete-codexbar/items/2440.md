## Summary

Keep this PR open for a maintainer UX decision. The implementation correctly reaches generic Claude scoped-weekly windows and the supplied screenshot shows the new token working, but its visible and accessibility labels always identify the value as Fable even though the resolver intentionally accepts future non-Fable scoped windows.

## What This Changes

This PR adds a custom macOS menu-bar layout token that renders the most-constrained active Claude model-scoped weekly quota and refreshes the title when that quota changes.

## System Context

Claude usage fetchers place model-scoped weekly quota carve-outs in the usage snapshot as extra rate windows. The menu-bar layout path selects a window, combines it with the saved layout tokens, and renders the result into the status-item title.

## Architecture Diagram

flowchart LR
    A[Claude usage snapshot] --> B[Extra quota windows]
    B --> C[Scoped weekly selector]
    D[Saved layout tokens] --> E[Menu-bar render data]
    C --> E
    E --> F[Status-item title]

## Best Possible Solution

Keep the scoped-weekly token model-neutral in its palette label, visible prefix, and accessibility text, or explicitly carry the selected model name through rendering if maintainers prefer a dynamic identity.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should the new token remain model-neutral across all Claude scoped-weekly promotions, or should it dynamically identify the selected model?

Rationale: The implementation intentionally supports any future scoped model window, while the proposed static Fable branding would become inaccurate once the provider rotates the promotion; choosing the durable user-facing contract requires product intent.

Likely owner: konon4

Owner reason: Their merged provider parsing work defines the model-neutral scoped-window contract that the menu-bar token should represent.

Owner confidence: medium

Options:

- **Use a neutral scoped token (recommended):** Rename the palette, visible prefix, and accessibility wording to describe a generic scoped-weekly quota, preserving the current generic resolver.
- **Show the selected model dynamically:** Extend render data to carry the selected scoped window title or model name so the menu bar identifies the actual active carve-out.
- **Ship Fable-only branding:** Constrain the resolver and documentation to Fable-only behavior, accepting that later scoped promotions will not use this token.
