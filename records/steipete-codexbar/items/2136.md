## Summary

Keep this PR open for normal review: current main still allows spawned CLIs to inherit the calling thread’s signal mask, while the narrowly scoped patch directly addresses a reproduced authenticated Kiro timeout with strong two-machine live proof and no identified correctness defect.

## What This Changes

The PR configures both pipe and PTY `posix_spawn` paths to start children with an empty signal mask and adds a regression test for the pipe-launch path.

## Best Possible Solution

Ensure both shared CLI launch modes explicitly start with an empty signal mask and retain focused regression coverage for the pipe and PTY attribute paths.

## Reproduction Assessment

Yes. The regression test creates the inherited SIGTERM mask directly, and released CodexBar reproduced the authenticated Kiro timeout on two Macs before the patched build succeeded repeatedly.

## Solution Assessment

Yes. Explicitly setting an empty child signal mask at both `posix_spawn` boundaries addresses the isolated OS-process state leak without changing Kiro parsing, credentials, deadlines, or provider routing.
