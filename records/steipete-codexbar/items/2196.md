## Summary

The earlier RPC buffer blocker remains at the current head: valid newline-delimited output can be classified as overflow based on an arbitrary read-chunk size. The branch is active and contains meaningful, narrowly repairable reliability work, so it should remain open for correction and process-level proof.

## What This Changes

The PR caps PTY and cached Codex/Claude CLI output at 1 MiB, adds bounded newline-delimited buffering for Codex and Grok RPC, adds regression tests, and includes Linux CI and platform-gating stabilization changes.

## Best Possible Solution

Drain complete RPC records incrementally, enforce the cap only on the retained unterminated line, cover large same-chunk output and true overflow, and attach redacted process-level proof of normal and cleanup behavior.
