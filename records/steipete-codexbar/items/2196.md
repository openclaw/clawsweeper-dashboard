## Summary

The current head still has the previously reported shared line-buffer defect: it can terminate valid Codex or Grok RPC streams when one read coalesces enough complete JSONL records to exceed the remaining buffer budget. The bounding direction is worthwhile, but the PR also lacks required after-fix process-level proof, so it is not merge-ready.

## What This Changes

The PR adds 1 MiB limits to PTY, cached Codex/Claude CLI, Codex RPC, and Grok RPC output, terminates overflowing processes, adds focused buffer tests, and retries Linux CI package installs.

## Best Possible Solution

Drain complete newline-delimited records from each incoming chunk first, cap only the retained unterminated partial line, preserve termination for a genuinely oversized partial record, and demonstrate overflow cleanup plus normal RPC success with redacted process-level output.
