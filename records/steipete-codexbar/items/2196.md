## Summary

Current main still has the unbounded-output problem, so this hardening remains useful; however, the proposed shared line buffer can reject valid newline-delimited output solely because of an arbitrary read-chunk boundary, and the PR has test-only rather than real behavior proof.

## What This Changes

Bounds accumulated CLI and newline-delimited RPC output, terminates overflowing child processes, and adds focused buffer tests.

## Best Possible Solution

Keep one shared bounded-buffer implementation, but parse newline-delimited chunks segment by segment so only the current unterminated line is capped, add chunk-partition-invariance tests, and demonstrate overflow cleanup with a synthetic CLI/RPC child.
