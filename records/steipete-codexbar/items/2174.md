## Label Justifications

- `P2`: This is a bounded, useful cost-visibility improvement for organization API-key users, but it is not an urgent regression or blocked core runtime.
- `impact:ux-friction`: Affected users can obtain local costs through the CLI, but the menu’s managed-account scoping obscures the available local estimate and creates avoidable workflow friction.

## Summary

Current main already scans local Codex sessions, but it deliberately scopes menu cost history to the selected managed account’s `CODEX_HOME`; the requested independent system-local ledger remains a real product change. Keep this issue paired with the open closing PR, with explicit sign-off on attribution and privacy behavior before landing.

## What This Changes

Add an independently configurable local Codex session ledger showing recent token, estimated-cost, conversation, and model totals even when remote organization billing data is unavailable.

## Best Possible Solution

Provide a separately labeled “Local Codex sessions” ledger sourced from the system `CODEX_HOME` or `~/.codex`, keep managed-account quota and identity fields siloed, preserve account-scoped behavior by default or through an explicit mode, and show remote quota failures independently from valid local estimates.
