## Summary

The proposal remains necessary if CodexBar wants to own quota-gating policy: current main exposes the required quota and pace data but has no guard command or headroom-based exit semantics. Because VISION.md requires sign-off for new features and no maintainer has approved this contract, the issue should remain open for a focused product decision.

## What This Changes

Proposes a `codexbar guard` CLI command that converts provider quota headroom into deterministic exit codes for scripts and agent loops.

## Best Possible Solution

Approve a minimal single-provider `--need` command only if CodexBar intends to own the policy, evaluate raw remaining percentage through a pure typed helper, preserve existing operational exit meanings, return structured JSON, and defer projection-duration rules until provider-independent semantics are specified.
