## Summary

The new console-session source addresses Groq standard-account usage, and the earlier availability blocker is fixed. However, `auto` now silently replaces the shipped Enterprise Prometheus view whenever browser credentials are present, so the PR needs an explicit source-selection decision and upgrade proof before merge.

**Likely related people**

## What This Changes

The PR adds Groq console-session spend and token-history fetching through browser cookies and Stytch refresh, retains Enterprise Prometheus as fallback, and updates dashboard rendering, settings, tests, and documentation.

## Best Possible Solution

Make `auto` credential-aware—preserve Prometheus-first behavior when an API key is configured and prefer the console source when no key exists—while retaining explicit `web` and `api` modes and testing both fresh and upgrade scenarios.
