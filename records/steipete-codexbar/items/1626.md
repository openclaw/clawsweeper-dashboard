## Summary

Keep open: current main still discovers multiple OpenCode Go workspace identifiers but selects only one for the usage snapshot. The merged owner-authored decision brief defines the intended bounded fan-out but explicitly does not implement it.

Likely related people: @steipete is the high-confidence product and architecture owner through the merged decision brief; @mohkg1017 is a medium-confidence recent contributor to the parser and snapshot behavior that multi-workspace support must preserve.

## What This Changes

Add automatic multi-workspace OpenCode Go usage fan-out under shared credentials, with separate workspace cards and the existing workspace override retained as an exact single-workspace filter.

## Best Possible Solution

Implement the accepted fan-out with shared in-memory credentials, deterministic identifier ordering, a 20-workspace visible cap, four drained concurrent pipelines, per-workspace failure isolation, stacked cards, and exact override filtering; use identifier-safe labels unless redacted evidence proves stable display names, and preserve optional weekly windows per workspace.
