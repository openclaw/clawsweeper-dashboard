## Summary

Keep open for maintainer review: the feature is useful and bounded, but it creates a durable automation API, the generic window contract is incorrect for providers without session/weekly windows, and the live proof exercises only the unknown-quota path.

## What This Changes

Adds a `codexbar guard` CLI subcommand that evaluates provider quota headroom and returns automation-friendly text, JSON, and exit codes.

## Best Possible Solution

Ship an explicitly approved guard contract that uses provider-native window metadata or unambiguous `primary`/`secondary` selectors, reuses existing account/source selection behavior, documents stable exit and JSON semantics, and includes redacted live proof for safe, blocked, and unknown outcomes.
