## Summary

The known cookie-name and non-Chrome fallback fixes are shipped in v0.42.0, but this current-release report still fails with active Safari and Brave sessions. The issue remains necessary because browser discovery, access, decryption, and cookie-recognition failures collapse into the same sign-in message, leaving the current cause and recovery path unresolved.

## What This Changes

Improve Ollama browser-session detection and troubleshooting when CodexBar reports no session cookie despite an active Safari or Brave login.

## Best Possible Solution

Keep the Chrome-first importer, add an in-product Doctor or Fix flow that safely identifies attempted browser profiles and failure classes, then implement focused Safari or Brave store coverage for the confirmed cause.
