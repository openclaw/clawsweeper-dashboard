## Summary

Keep open for product review. Current behavior intentionally reports local token-price estimates in USD while Claude account spend can carry its API-reported currency; changing or converting the estimate is a new financial-display feature rather than a bug fix.

## What This Changes

Add a way to display locally estimated Claude costs in a non-USD currency such as GBP.

## System Context

CodexBar’s local cost scanner reads Claude and Codex session logs, applies API token pricing, and passes the resulting estimates into the menu and CLI. Separately, provider usage snapshots can carry account-reported spend limits and extra-usage amounts with their native currency.

## Architecture Diagram

flowchart LR
    A[Claude session logs] --> B[Local cost scanner]
    B --> C[API-rate USD estimate]
    C --> D[Cost formatter]
    D --> E[Menu and CLI cost display]
    F[Claude usage API] --> G[Account currency and spend data]
    G --> E

## Best Possible Solution

Choose one explicit policy for local estimates—preferably a display-only currency preference backed by a documented exchange-rate source and an “estimated from USD API rates” label—while leaving provider-reported Claude spend in its API currency.

- **Keep local estimates in USD:** Preserve the current API-price denomination and improve the explanatory copy so it is not mistaken for account billing.
