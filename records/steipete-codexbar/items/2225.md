## Label Justifications

- `P2`: This addresses a real but limited-scope unexpected Keychain prompt without evidence of data loss, outage, or a broadly unusable workflow.
- `merge-risk: 🚨 compatibility`: Background Chromium re-import changes from conditionally allowed to always blocked, so existing automatic-cookie users can require manual recovery after cache loss or expiry.
- `merge-risk: 🚨 auth-provider`: The shared gate controls browser-cookie authentication across multiple providers and could suppress deliberate CLI or fallback auth paths if interaction context is not propagated correctly.

## Summary

The patch is narrow and consistent with CodexBar’s established rule that prompt-capable credential access belongs behind user action. It should remain open because the external PR supplies only test-seam validation; packaged macOS behavior and the deliberate CLI path remain unproven.

## What This Changes

Blocks Chromium browser-cookie imports during background refresh before Keychain preflight while retaining user-initiated imports and updating two gate tests.

## Best Possible Solution

Keep the early host gate, but land it only after packaged-app evidence shows automatic refresh never reaches Chromium Keychain access, manual refresh still performs the pre-alert/import flow, cached-cookie refresh remains usable, and deliberate CLI web imports are unaffected or explicitly covered.
