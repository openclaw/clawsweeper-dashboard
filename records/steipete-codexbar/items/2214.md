## Summary

Keep this issue open for an explicit product and architecture decision. Current main has shared host-level credential helpers plus provider-specific prompt modes and cooldowns, but it does not implement the proposed provider-neutral contract across Security.framework, browser imports, and app-launched processes; the proposal is coherent, security-relevant, and broader than the linked provider-specific reports.

## What This Changes

Proposes a provider-neutral three-mode credential policy spanning Keychain operations, browser credential access, provider overrides, cooldown state, and app-launched external processes.

## Best Possible Solution

If maintainers approve the direction, introduce a shared internal operation/risk vocabulary and policy evaluator first, preserve existing Standard behavior during migration, then route each Keychain, browser, and subprocess boundary through it with deterministic compatibility tests before exposing stronger user-facing guarantees.

- **Keep provider-specific policies:** Continue fixing individual provider and credential-path bugs without adding a common user-facing policy or migration program.
