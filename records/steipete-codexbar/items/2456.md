## What This Changes

This PR adds a local-only Codex Workspaces foundation that indexes local Codex sessions into a v11 cost cache and SQLite sidecar, then exposes project, session, model, daily, and CSV analytics models for a later UI PR.

## System Context

CodexBar’s local usage pipeline scans Codex rollout logs, then persists parsed data for fast refreshes. This change adds read-only catalog enrichment and a SQLite sidecar so a future menu and inspector can show project- and session-level analytics without querying Codex services.

- **[P2] Surface degraded catalog state on a cached refresh:** `Sources/CodexBarCore/CodexLocalProjectUsageIndexer.swift:75`
  - body: When a previously indexed catalog later becomes missing, locked, corrupt, or incompatible, the cached fast path can return the old `.complete` payload without revalidating the catalog.   - confidence: 0.96

  - body: The fallback `created_at` and `updated_at` columns are Unix seconds, but the result exposes them as `*UnixMs`. Multiply these fallback values by 1,000 or normalize according to the selected column so older thread rows do not sort as January 1970 activity.

  - body: A complete catalog read currently upserts returned entries without removing old ones, so deleted rows can indefinitely override rollout-derived cwd, title, or model metadata. Delete rows not observed in a successful complete generation while retaining last-good rows only for unavailable catalog reads.
  - confidence: 0.95
