## Summary

The prior regression-test blocker is fixed: the PR head now asserts LongCat’s metadata directly and confirms Chrome-first Firefox fallback. The remaining blocker is product/compatibility intent: it changes Automatic imports from the repository’s Chrome-only default to probing Firefox for every existing LongCat Automatic setup, so this needs an explicit maintainer decision before merge.

## What This Changes

This PR changes LongCat Automatic cookie discovery from Chrome-only to Chrome first then Firefox, and updates the provider metadata regression test accordingly.

## System Context

CodexBar’s provider metadata determines which browser cookie stores Automatic account discovery consults before it makes authenticated provider usage requests. LongCat’s order therefore controls which local browser session data is considered during a normal refresh.

## Best Possible Solution

Keep Automatic imports Chrome-only by default and expose Firefox through the existing browser-selection path, unless the repository owner explicitly approves a documented LongCat-specific exception with upgrade behavior accepted.
