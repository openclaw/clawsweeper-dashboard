## Summary

This is a credible current-main bug with a distinct stale-rebound failure mode, but the linked draft pull request is still open and explicitly owns the fix, so the issue should remain open until that implementation is reviewed and merged.

## What This Changes

Prevent one Claude weekly quota refill from producing duplicate confetti when stale usage briefly rebounds above the reset threshold.

## Best Possible Solution

Review and land a narrowly scoped per-account persisted recovery state that requires sustained post-reset usage before re-arming, preserves boundary-independent Claude refills, and covers stale rebounds, restarts, migration, account isolation, and a later genuine refill.
