  - body: When a deleted cached fork triggers the sibling-rescan path, rebuilding `scanState` discards keys from retained parent or earlier contributors whose totals remain in cache.   - confidence: 0.94

  - body: This removal path only schedules the removed entry's own `forkedFromId`; a real parent has none. If that parent disappears, cached children referencing its session ID are not reparsed to reclaim the now-unowned prefix, leaving usage undercounted until a force rescan.

  - body: A non-nil `turnID` is not sufficient proof that a row belongs to the replayed parent: child token rows can retain the old parent turn after a `turn_context` without a new `task_started`. Parent-scoping those rows can deduplicate legitimate child work across siblings, so derive ownership from a copy-stable provenance signal instead.
