## Summary

This PR remains necessary because current main allows Codex historical pacing to bypass an explicit work-day schedule. The branch provides a focused, well-tested correction, but maintainer confirmation of the precedence model and real app proof are still needed before merge.

## What This Changes

The PR makes explicit 4-, 5-, and 7-day schedules override Codex historical pace predictions, renames the nil schedule to Automatic, and updates tests and documentation.

## Best Possible Solution

Make explicit schedules authoritative if maintainers confirm that precedence, phrase the tracking subtitle as an eligibility condition, and demonstrate both explicit and Automatic modes in a freshly built app.
