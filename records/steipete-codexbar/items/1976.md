## Summary

Keep open for maintainer product direction. The current supported remote surface is a localhost-only `codexbar serve` API, while this request adds a new iOS target, LAN discovery, CloudKit transport, background delivery, pairing/privacy policy, and release-capability ownership; the related implementation PR was closed unmerged and does not resolve the request.

## What This Changes

The issue requests a native iOS usage companion that mirrors Mac-collected provider data through opt-in Bonjour LAN sync and private iCloud/CloudKit delivery.

## Best Possible Solution

First make an explicit product decision on whether CodexBar should own an iOS companion; if approved, define a small, opt-in paired-device protocol with authenticated LAN transport, a visible Settings toggle, data-minimization rules, and separate capability/release validation before reintroducing the mobile target.
