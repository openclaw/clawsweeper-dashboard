## Summary

The report matches a current Claude credential-access failure mode that prior mitigations intentionally reduced but did not eliminate; because it reproduces on v0.42.1 and no newer main fix is established, this issue remains necessary.

## What This Changes

Prevent recurring macOS Keychain authorization prompts for the `Claude Code-credentials` item during normal and background CodexBar activity.

## Best Possible Solution

Make every background, availability, wake, and scheduled Claude credential probe strictly non-interactive, reserve authorization UI for a visible user-invoked action, and add an in-app Diagnose/Fix path that identifies prompt policy, cache state, and the attempted credential source without exposing secrets.

Yes in direction, but the exact repair is not yet proven; the narrow maintainable fix is to close any remaining interactive background read while retaining explicit user-triggered authorization and existing fallback behavior.
