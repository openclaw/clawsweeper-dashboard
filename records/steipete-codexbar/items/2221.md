## Summary

Keep this PR open. The contributor’s redacted live output and menu screenshot now provide sufficient real-behavior proof, and the earlier API-source separation and AK/SK restoration concerns are addressed. However, the unchanged current head still places ambient arkcli SSO ahead of configured credentials in auto mode, so existing users can silently see usage from a different account; that compatibility decision must be resolved before merge.

## What This Changes

The branch adds arkcli SSO retrieval for Doubao Coding and Agent Plan usage, retains signed AK/SK and bearer-key API paths, groups both plans in the menu, replaces the provider icon, and expands focused tests.

## Best Possible Solution

Make explicit cli and api modes remain strict, while auto mode uses a credential-aware policy: honor configured provider credentials without silently changing identity and use arkcli as the zero-configuration path when no account-specific credentials are configured; cover mixed-account routing with focused tests and retain the submitted live UI proof.

- **Require explicit source selection:** Avoid mixed-source auto routing and require users with multiple available identities to choose cli or api in settings.
