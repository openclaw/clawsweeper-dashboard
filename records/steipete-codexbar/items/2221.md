## Label Justifications

- `P1`: The proposed default routing can silently switch the provider account used by existing Doubao installations.
- `merge-risk: 🚨 compatibility`: Auto mode changes established credential precedence for users upgrading with stored AK/SK or Ark API keys.
- `merge-risk: 🚨 auth-provider`: A successful ambient arkcli session can override the identity represented by explicitly stored provider credentials.

## Summary

The latest head resolves the two prior findings by restoring AK/SK support and registering arkcli as a real CLI strategy, but it still needs a compatibility fix because auto mode silently prefers ambient arkcli SSO over an existing user's configured API credentials; only mock-based proof is available.

## What This Changes

The PR adds arkcli-based Doubao Coding and Agent Plan usage, preserves signed and bearer API strategies, groups both plan types in the menu, replaces the provider icon, and expands provider tests.

## Best Possible Solution

Make auto selection credential-aware so configured API credentials retain precedence while arkcli serves credential-free or explicitly selected CLI setups, then document the source behavior and prove both fresh arkcli setup and existing-credential upgrade paths in a freshly built app.

Owner confidence: medium

Options:

- **Preserve configured credentials (recommended):** Prefer valid stored AK/SK or Ark API credentials in auto mode and use arkcli when credentials are absent or fail, preserving upgrade behavior.
- **Adopt CLI-first auto mode:** Keep ambient arkcli ahead of configured credentials, but explicitly document the account-switching upgrade behavior and provide live proof for mixed-account setups.
- **Require explicit CLI selection:** Leave auto mode on the existing API path and expose arkcli only through the existing explicit CLI source selection.

## Reproduction Assessment

Yes for the merge defect: configure Doubao credentials, leave source mode on auto, and authenticate arkcli to another account; the resolver's CLI-first order selects the ambient SSO identity before the configured API strategy. The actual runtime result still needs live proof.

## Solution Assessment

No. Splitting CLI and API strategies is maintainable, but unconditional CLI-first auto routing is not the safest upgrade behavior; selection should account for explicitly configured credentials.
