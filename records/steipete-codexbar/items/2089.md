## Summary

This is a well-specified current bug: main still allows a non-forced fetch to receive the scanner’s recently cached report and then records that successful result under UsageStore’s one-hour freshness TTL. No current fix or canonical open PR was found, and the bounded source path plus existing temporary-directory fixtures make it suitable for a focused repair.

## What This Changes

Prevent non-forced cost refreshes from treating a scanner-debounced stale report as fresh for the full token usage TTL.

## Best Possible Solution

Give each explicit CostUsageFetcher request a current incremental view of the session files while retaining the scanner’s existing file-level cache optimizations, and lock the contract down with a non-forced append regression test for native and applicable Pi history.
