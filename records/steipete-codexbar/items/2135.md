## Summary

The earlier browser-host API blocker is fixed, but the current head still has a merge-blocking account-isolation defect: a preserved legacy DeepSeek Platform token can enrich whichever API-key account is active, so one account’s detailed usage can appear beside another account’s balance. The screenshots demonstrate the new UI but do not prove the multi-account credential boundary.

## What This Changes

This PR adds DeepSeek Platform detailed usage and browser-only balance support, Chrome-profile session discovery and selection, credential-scoped profile settings, stable refresh presentation, documentation, localization, and extensive tests.

## Best Possible Solution

Keep Platform-session access behind the shared browser host, bind every detailed-usage session to the selected DeepSeek account scope, and allow an unscoped legacy token only for browser-only balance or require explicit profile re-selection before combining it with an API-key account.
