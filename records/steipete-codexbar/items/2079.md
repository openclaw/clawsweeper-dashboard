## Summary

## What This Changes

The PR prevents ordinary overlapping Agent Sessions remote refresh calls from scheduling a duplicate pass while preserving settings-generation invalidation, stale-result suppression, and one settings-driven retry.

## Best Possible Solution

Merge the minimal gate correction and focused regression tests after required checks complete, retaining the intentionally documented next-cycle retry behavior after a shared failure.

## Reproduction Assessment

Yes. Current main deterministically sets pending retry state for any overlapping refresh call, so `finish()` requests another pass even when settings remain unchanged; the provided live harness exercises the same overlap path.

## Solution Assessment

Yes. Reserving pending state for settings changes is the narrowest maintainable fix because it preserves stale-generation suppression and exactly one current-generation retry without adding another scheduler or configuration surface.
