## Summary

Keep this owner-authored PR open for a focused correction: the new `nil` TTL disables Manual-mode cache freshness as well as its timer, so non-forced refreshes can rescan token/cost history despite a freshly hydrated snapshot.

## What This Changes

The PR replaces the fixed hourly token/cost refresh cadence with the global refresh frequency, clamps automatic runs to five minutes, disables the Manual-mode timer, and updates tests, widget documentation, and localized preference copy.

## Best Possible Solution

Separate timer scheduling from cache-freshness eligibility: keep Manual mode free of automatic timer wakeups while preserving bounded reuse of hydrated or recently fetched token snapshots, with a dedicated Manual-mode regression test.

Yes, from source: set the refresh setting to Manual, hydrate or fetch a token snapshot, then take a non-forced token-refresh path; the optional TTL is nil and the changed predicate rejects the fresh cache.

## Solution Assessment

No. Deriving timer enablement directly from the cache-freshness TTL conflates two behaviors; the narrower solution disables only periodic scheduling in Manual mode and preserves cache reuse.
