## Summary

Current main writes snapshots atomically, waits for the write, calls `reloadAllTimelines()`, and constructs each requested Usage or Burn Down entry from the latest shared snapshot. The report therefore identifies a credible remaining failure after CodexBar’s normal data handoff rather than the token-row bug fixed earlier; keep it open for a macOS VM reproduction correlating the rendered widget with the exact timeline payload.

## What This Changes

Investigate desktop Usage and Burn Down widgets that continue displaying old values after a new shared snapshot is written and WidgetKit accepts freshly generated timelines.
