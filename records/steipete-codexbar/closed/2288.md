## Summary

This remains a necessary, bounded dashboard correctness fix: the supplied current-main path filters enabled providers by token-cost support before the UI can show a truthful unavailable state. The open tracker treats this as an isolated production-correctness item, not as work already completed or superseded.

## What This Changes

Make Usage & Spend represent every enabled provider with a truthful capability state, including OpenRouter when token-cost history is unavailable.

## Best Possible Solution

Replace the spend-only eligibility gate with a capability-aware provider roster and render an explicit non-fabricated state for enabled providers that lack token-cost history, with focused regression coverage for OpenRouter and existing spend-capable refresh paths.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, at source level: the reported current-main eligibility filter excludes any descriptor whose token-cost capability is false, and OpenRouter is identified as such a descriptor. A focused model test can verify the omission without invoking live provider or Keychain access.

## Solution Assessment

Yes. A capability-aware roster is the narrow maintainable fix because it keeps unsupported metrics unavailable rather than inventing comparable token or spend values, while preserving the existing token-cost pipeline for providers that support it.
