## Summary

The report remains necessary: the reviewed main revision enters Commander/Foundation-backed CLI setup without a Linux timezone bootstrap, while the merged localization fix addresses a separate `Bundle(for:)` crash. The detailed NixOS reproduction covers both v0.42.1 Linux artifacts and an unmodified build of the reviewed main SHA, so the unidentified duplicate marker is insufficient grounds to close.

## What This Changes

Make Linux CLI startup derive a usable default timezone from `/etc/localtime` on non-FHS systems when `TZ` is unset, while preserving explicit `TZ` values and other platforms.

## Best Possible Solution

Add a small Linux-only pre-Foundation bootstrap that leaves nonempty `TZ` untouched, safely derives a zone identifier or usable zoneinfo path from `/etc/localtime` on non-FHS systems, and falls back without trapping, with isolated tests for unset, explicit, invalid, and conventional layouts.
