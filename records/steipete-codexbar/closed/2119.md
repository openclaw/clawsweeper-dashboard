## Summary

Current main has substantial generic token-account plumbing, but OpenRouter is not conclusively enabled through the requested Settings workflow. The broader provider-instance issue overlaps without superseding this bounded slice, and repository policy requires product sign-off for provider authentication and stored-credential changes.

Likely related people: @chountalas introduced the OpenRouter provider, @ratulsarna carried major follow-up work, and @steipete is the clearest product-direction owner.

## What This Changes

Requests multiple labeled OpenRouter API-key accounts with isolated usage, errors, selection, and backward-compatible single-key behavior.

## Best Possible Solution

Approve OpenRouter as an existing-model token-account provider, add only the missing catalog and Settings integration, and cover credential isolation, selection, removal, stacked refresh, label association, and legacy single-key compatibility.
