## Summary

Keep open. This is a concrete reliability bug: a killed local review can leave durable feature state that blocks later reviews until an operator manually clears it; the report provides a focused failure mode and a conservative reclaim rule.

## What This Changes

Reclaim a feature lock automatically when its recorded host is local and its recorded process is no longer alive, while preserving conflicts for live or remote holders.

## System Context

`clawpatch review` selects features, claims an on-disk per-feature lock before work, and records review results in the local workflow state. The lock claim protects concurrent reviews, so stale-lock handling must distinguish a dead local process from an active or remote run before allowing the next review to proceed.

## Architecture Diagram

flowchart TD
  A[Review command] --> B[Select features]
  B --> C[Read feature lock]
  C --> D{Lock holder valid?}
  D -->|No lock| E[Claim feature]
  D -->|Local host and dead process| E
  D -->|Live or remote holder| F[Report feature conflict]
  E --> G[Run feature review]
  G --> H[Persist review result]

## Best Possible Solution

Add conservative local stale-lock reclamation at claim time, expose the same rule through a safe `clean-locks --stale-only` path, and preserve successful per-feature results when another feature remains legitimately locked.

## Repair Work Prompt

Fix stale per-feature lock recovery for `clawpatch review`. At claim time, inspect existing lock metadata and reclaim only when the recorded hostname is the current host and the recorded PID is definitively not alive; retain the existing conflict for a live PID, an unknown liveness result, or a different host. Add a safe `clean-locks --stale-only` mode using the identical predicate if the command structure permits it, without changing unconditional cleanup semantics unless explicitly requested. Preserve existing successful review results when a legitimately locked feature is encountered, but keep a non-zero final status and clear per-feature reporting. Add focused regression tests for dead local, live local, remote-host, malformed/unknown liveness, and mixed-feature review behavior. Do not add a cross-host TTL or a new configuration setting in this repair. No changelog edit is needed for this normal PR.
