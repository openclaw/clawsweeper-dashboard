## Summary

Current main still places a real Node-specific discovery barrier ahead of all mapper execution, so the performance concern remains actionable. The suggested lazy context shape needs refinement because Node-family mappers always run and would still trigger the same scans; the repair should improve scheduling and prove any I/O skip preserves nested and polyglot Node discovery.

## What This Changes

Reduce Node-specific discovery overhead so non-Node repository mapping is not delayed by Node project and Turbo task scanning.

## Best Possible Solution

Start root-only mappers without awaiting Node context, then use one memoized Node-context computation for Node-family mappers and reduce discovery work only through a signal that demonstrably preserves nested and polyglot Node project mapping.
