## What This Changes

Change `clawpatch review --since <base>` so mapped features owning changed files are reviewed regardless of their prior review status, while preserving status-based narrowing for unscoped backlog review.

## System Context

`clawpatch review` turns a feature map into review tasks. With `--since`, a base ref produces changed files that should be intersected with feature ownership so a pre-push or CI gate evaluates the code the diff actually changes.

## Architecture Diagram

  C[Feature map and status] --> D[Candidate selection]

## Best Possible Solution

Make file-scoped review selection start with all features in the chosen project and intersect them with changed-file ownership, retain status filtering only for unscoped backlog review, and distinguish “no owning feature changed” from “owning features excluded by status.”
