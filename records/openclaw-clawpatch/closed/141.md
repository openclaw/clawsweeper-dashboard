## Summary

Keep open: current main still runs write-mode patch providers and validation in the caller checkout, while Crabbox is only adjacent hydration infrastructure. The latest discussion also identifies an explicit owner product/security decision before choosing an opt-in Crabbox-style executor.

## What This Changes

The issue asks for patch agents and validation to run in an isolated, forkable per-task execution box instead of the caller checkout.

## Best Possible Solution

Define an opt-in isolated repair executor contract that forks a clean pinned checkout per patch attempt, runs the provider and validation there, returns verified patch artifacts and proof metadata, and keeps local execution as the default until maintainers approve a broader rollout.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Not as a runtime bug, but yes by source inspection: fix providers and validation both run against loaded.root on current main.

## Solution Assessment

Is this the best way to solve the issue? Unclear until maintainers choose the backend and policy; the proposed opt-in Crabbox boundary is a plausible narrow first implementation but still needs product and security approval.
