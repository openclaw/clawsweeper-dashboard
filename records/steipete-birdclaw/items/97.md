## Summary

This PR addresses a real wrong-account initialization problem, but the proposed default behavior makes `birdclaw init` perform an implicit live xurl lookup. That conflicts with Birdclaw’s local-first policy and creates unexpected API-credit and account-selection behavior during setup; the change should remain open for a narrow revision and real runtime proof.

## What This Changes

Adds authenticated xurl account selection to `birdclaw init`, including an optional `--account` flag, seeded-account replacement safeguards, external X user ID persistence, and regression tests.

## Best Possible Solution

Keep `init` offline by default, resolve and adopt an xurl identity only after explicit user intent such as `--account`, replace only a verifiably untouched demo seed, and prove both fresh and existing-database behavior with a redacted live transcript.
