## Summary

Keep this issue open for maintainer direction. Current main has official archive and Birdclaw-backup import paths but no supported Scrollmark or twitter-web-exporter importer; the concept fits Birdclaw’s local-first vision, while adopting third-party schemas as permanent core compatibility contracts requires an explicit scope decision.

## What This Changes

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical local store with provenance, validated collection semantics, and structured reporting.

## Best Possible Solution

Approve a narrow core importer for Scrollmark canonical bundle v1 first, implemented through a producer-specific normalization adapter and explicit provenance records; create only relationships proven by the bundle, reuse canonical persistence and FTS paths, enforce archive-grade ZIP limits, prohibit live X access, and defer legacy Scrollmark and twitter-web-exporter shapes to separately reviewed adapters.
