## Summary

Current main does not import third-party passive-capture exports. The proposal aligns with Birdclaw’s local-first direction, but the supported producer/version contract, provenance model, completeness semantics, and legacy-format policy require explicit product direction before implementation.

## What This Changes

Add an idempotent CLI path that imports Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical tweets, profiles, relationships, media metadata, and search indexes.

## Best Possible Solution

Approve a narrow first contract for validated Scrollmark canonical bundle v1 imports, store explicit producer/schema/provenance and partial-completeness metadata, and defer legacy or twitter-web-exporter auto-detection until fixtures and version guarantees are available.
