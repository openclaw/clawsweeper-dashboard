Keep this issue open for maintainer direction. Current main supports official archive ZIP ingestion and Birdclaw backup import, but not Scrollmark or twitter-web-exporter captures; the proposal fits Birdclaw’s local-first SQLite vision while creating a new durable third-party source contract for provenance, account binding, collection semantics, schema versions, and untrusted-file handling. citeturn584468view0turn768738view0turn333902view0

## What This Changes

Add an idempotent CLI importer that normalizes Scrollmark bundles and supported twitter-web-exporter JSON/JSONL captures into Birdclaw’s canonical tweets, profiles, collection edges, FTS, and media metadata.

## Best Possible Solution

Approve a staged core importer that starts with validated Scrollmark canonical bundle v1, records explicit source/provenance metadata, reuses the bounded archive ZIP and canonical repository paths, and defers legacy auto-detection until fixtures prove stable mappings.
