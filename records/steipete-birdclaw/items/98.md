## Summary

Current main does not import Scrollmark or twitter-web-exporter captures, and the request is directionally aligned with Birdclaw’s local-first archive vision. Keep it open for maintainer direction because accepting third-party capture formats creates a durable data-source contract whose provenance, account binding, completeness, schema-version, and backup semantics require approval before implementation.

## What This Changes

Add an additive, idempotent CLI import path that normalizes supported Scrollmark and twitter-web-exporter files into Birdclaw’s canonical local store.

## Best Possible Solution

Approve a Scrollmark canonical-bundle-v1-first additive importer with explicit import-run provenance, account binding for proven semantic edges, partial-completeness markers, backup round-trip coverage, bounded ZIP handling, deterministic reports, and no live network activity; defer legacy format autodetection until representative fixtures establish stable mappings.
