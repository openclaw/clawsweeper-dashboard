## Summary

Current main does not support these third-party capture formats. The proposal fits Birdclaw’s local-first direction, but it would establish durable contracts for provenance, account binding, collection completeness, backups, and untrusted-file handling that require maintainer product direction before implementation.

## What This Changes

Add idempotent import of Scrollmark bundles and confidently detected Scrollmark or twitter-web-exporter JSON/JSONL into Birdclaw’s canonical SQLite store.

## Best Possible Solution

Establish a source-neutral capture-import contract, then implement Scrollmark canonical bundle v1 as the first adapter with additive canonical upserts, explicit producer/schema/run provenance, account binding, partial-completeness markers, bounded validation, deterministic reports, FTS refresh, and backup round-trip coverage; add legacy formats only for confidently recognized shapes.

## Risks / Open Questions

- Separate format adapters added before a shared provenance and source-run model could create incompatible ownership and backup semantics.
- Captured route presence does not necessarily prove bookmark, like, timeline, search, or list membership, so incorrect mapping could silently invent account-scoped edges.
- ZIP bundles and large mixed JSONL files are untrusted inputs requiring traversal protection, decompression limits, bounded parsing, and row-level failure behavior.
- Fresh-database and upgrade behavior must prove that capture imports do not replace richer archive/live data or bind records to the wrong account.
