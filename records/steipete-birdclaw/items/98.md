## Summary

Keep this issue open: current main does not import third-party passive-capture formats, and the request fits Birdclaw’s local-first direction, but its durable provenance, completeness, account-scoping, migration, backup, and initial-format contracts need explicit product direction before implementation.

## What This Changes

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical local SQLite store.

## Best Possible Solution

Start with a phased Scrollmark canonical-bundle-v1 importer that reuses canonical repository APIs, records explicit source/import provenance, preserves unknown completeness, includes migration and backup compatibility, and proves ZIP safety and idempotency before considering legacy shapes or twitter-web-exporter.
