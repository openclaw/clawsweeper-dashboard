## Summary

Current main has the canonical ingestion architecture needed for this idea but no supported Scrollmark or twitter-web-exporter import path. The feature fits Birdclaw’s local-first direction when narrowed, while adopting an external producer schema as a maintained compatibility contract requires explicit owner approval.

## What This Changes

Add idempotent, source-aware imports for Scrollmark and twitter-web-exporter capture files into Birdclaw’s canonical SQLite, FTS, collection-edge, and media-metadata model.

## Best Possible Solution

Approve a first version limited to Scrollmark canonical bundle v1, implemented as an Effect-based strict parser and normalizer feeding the transactional canonical repository, with durable import provenance, explicit partial-collection semantics, backup round-trip coverage, deterministic JSON reporting, and a hard no-network guarantee.
