Keep this issue open: current main supports official X archives and Birdclaw backups, not third-party passive-capture formats; the proposal aligns with Birdclaw’s local-first direction, but the supported producer and durable provenance, completeness, migration, and backup contract require maintainer direction first.

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical SQLite store.

## Best Possible Solution

Define one versioned capture-import contract and implement Scrollmark canonical bundle v1 first, with additive canonical upserts, explicit unknown completeness, durable import provenance included in backups, bounded ZIP handling, deterministic reports, and no live X access.
