## Summary

Keep this issue open: current main has no third-party passive-capture importer, and the requested local, attributable ingestion path fits Birdclaw’s vision, but the multi-format and provenance scope needs a maintainer product decision before implementation.

## What This Changes

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical SQLite store.

## Best Possible Solution

Implement a source-specific importer for Scrollmark canonical bundle v1 first, using additive transactional writes, explicit provenance/import metadata, strict ZIP and record limits, deterministic reports, and canonical FTS/backup coverage; defer heuristic legacy formats until versioned fixtures and mappings are agreed.
