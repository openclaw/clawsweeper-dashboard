## Summary

Keep this feature request open for maintainer direction. Current main has archive and backup import paths but no importer for third-party passive-capture formats, while the repository vision supports additional durable local sources only after their source-attribution, freshness, completeness, and storage contracts are defined. The prior ClawSweeper review identified the same unresolved product boundary, and no later human discussion or implementation now owns the work.

## What This Changes

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical local database.

## Best Possible Solution

Define a narrow first contract around Scrollmark canonical bundle v1, with versioned fixtures, import-run provenance, explicit partial-collection semantics, additive canonical upserts, ZIP limits, backup coverage, and deterministic reports; defer legacy and twitter-web-exporter shapes until each has stable samples and a separately approved mapping.
