## Summary

Keep this feature request open for maintainer direction. Current main supports official archive, backup, and live-transport ingestion but not the requested passive-capture formats, and Birdclaw's vision requires source attribution, completeness, freshness, backup, and CLI contracts to be settled before accepting a new durable data surface. ([raw.githubusercontent.com](https://raw.githubusercontent.com/steipete/birdclaw/main/VISION.md))

## What This Changes

Add an idempotent importer for Scrollmark and twitter-web-exporter captures that normalizes supported records into Birdclaw's canonical local database.

## Best Possible Solution

Approve a narrow Scrollmark canonical-bundle-v1 importer first, backed by a reusable source-normalization contract, explicit partial-collection semantics, durable provenance, deterministic backup coverage, bounded ZIP processing, and fixture-based idempotency tests; defer legacy auto-detection until representative formats are stable.
