## Summary

Keep this issue open: current main does not support third-party passive-capture imports, and the proposal fits Birdclaw’s local-data direction, but adopting external schemas and durable provenance semantics requires explicit product direction.

## What This Changes

Add an idempotent CLI importer that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical local database.

## Best Possible Solution

Start with one explicitly versioned Scrollmark canonical bundle format, normalize through existing canonical repositories, store producer and observation provenance separately from account ownership, treat collection completeness as partial by default, and defer legacy or second-producer detection until the contract is proven.

- **Decline capture imports:** Retain official archives and Birdclaw live transports as the only supported ingestion sources.
