## Summary

Keep this issue open for maintainer direction: current main has no third-party capture importer, and the idea fits Birdclaw’s local-first vision, but the initial producer contract and durable provenance, completeness, account-scoping, migration, and backup semantics must be approved before implementation.

## What This Changes

Add an additive, idempotent CLI importer that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical tweets, profiles, collection edges, FTS, and media metadata.

## Best Possible Solution

Start with an explicitly sponsored Scrollmark canonical bundle v1 importer, persist import/source provenance separately, reuse additive canonical entity writers, create only proven account-scoped edges, include migration and backup round-trip coverage, and defer legacy shape autodetection until real fixtures establish stable contracts.
