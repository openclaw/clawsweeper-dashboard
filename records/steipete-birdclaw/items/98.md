## Summary

Keep this issue open: current main still supports official X archives and Birdclaw backups rather than third-party passive-capture bundles, so the requested capability remains useful, but adopting external producer schemas and durable provenance/completeness semantics requires explicit product direction before implementation.

## What This Changes

Add an idempotent CLI import path that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical SQLite store.

## Best Possible Solution

Adopt one versioned format first—preferably Scrollmark canonical bundle v1—behind a typed normalization adapter, persist explicit import-run and record provenance without changing existing ownership semantics, include the new metadata in backups, and add idempotency, partial-collection, malformed-row, ZIP-safety, offline-search, and no-network regression coverage before considering legacy formats.
