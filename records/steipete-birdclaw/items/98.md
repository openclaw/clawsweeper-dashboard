Keep this issue open: current main imports official X archives and Birdclaw-owned backups, not third-party passive-capture formats; the request fits Birdclaw’s local-first vision, but producer support and the durable provenance, completeness, migration, and backup contract require maintainer direction first.

## What This Changes

Add an idempotent CLI importer that normalizes Scrollmark and twitter-web-exporter captures into Birdclaw’s canonical tweets, profiles, collection edges, media metadata, and search index.

## Best Possible Solution

Start with a maintainer-approved Scrollmark canonical bundle v1 importer that records versioned provenance and partial-completeness semantics, uses additive canonical writes and bounded ZIP parsing, survives backup round trips, and defers legacy and twitter-web-exporter formats until fixtures prove a stable mapping.

- ZIP bundles and large JSONL payloads create an untrusted-input boundary requiring traversal protection, decompression limits, bounded parsing, and row-level validation.
