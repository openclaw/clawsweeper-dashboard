## Summary

Current main has reusable live-transport and canonical ingestion boundaries but no FxTwitter/FxEmbed implementation. The proposal fits Birdclaw’s local-first read architecture, while making core responsible for a public third-party endpoint, its privacy disclosure, reliability, capability limits, and support policy requires explicit repository-owner approval.

## What This Changes

Add an explicit opt-in FxTwitter/FxEmbed transport for credential-free public post, thread, profile, timeline, and search ingestion with self-hosting and capability guardrails.

## Best Possible Solution

If core adoption is approved, implement one explicit opt-in Effect-native adapter behind the existing gateway, advertise only supported public-read capabilities, normalize into canonical storage with source/completeness metadata, validate HTTPS base URLs, and cover decoding, pagination, rate limiting, idempotency, and unsupported operations with recorded fixtures.
