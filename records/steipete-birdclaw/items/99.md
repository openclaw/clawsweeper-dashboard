## Summary

Current main has a bounded live-transport gateway and canonical local ingestion paths, but it does not implement FxTwitter/FxEmbed. The proposal aligns with Birdclaw’s local-first read architecture in principle, while adopting a public third-party endpoint and configurable host requires explicit repository-owner product approval.

## What This Changes

Add an explicit opt-in FxTwitter/FxEmbed transport for public post, thread, profile, timeline, and search reads, with canonical persistence and capability-specific boundaries.

## Best Possible Solution

If approved, add one explicit-only FxTwitter adapter behind the existing live gateway, initially limited to well-defined public operations, with canonical persistence, capability errors before network access, safe HTTPS endpoint configuration, provenance and completeness metadata, fixture-based tests, and no automatic fallback.

## Risks / Open Questions

- The public FxTwitter service receives requested post IDs, handles, search terms, and caller network metadata, so opt-in and disclosure semantics must be product-approved.
- A configurable service URL introduces endpoint-trust and request-safety obligations, including strict HTTPS validation, rejection of embedded credentials, and protection against unsafe hosts or redirects.
- Availability, response compatibility, rate limits, and operational support depend on a third-party service outside Birdclaw's control.
- FxTwitter lacks authenticated account capabilities; an overly broad integration could misrepresent public results as bookmarks, likes, mentions, home-timeline membership, or other account-scoped data.
