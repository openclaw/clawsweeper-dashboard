## Summary

Current main has a bounded live-transport gateway and canonical local ingestion paths, but no FxTwitter/FxEmbed implementation. The proposal fits Birdclaw’s local-first read architecture in principle, while adoption of a public third-party endpoint creates privacy, endpoint-trust, reliability, configuration, and support obligations that require repository-owner approval before implementation.

## What This Changes

Requests an opt-in, read-only FxTwitter/FxEmbed transport for public post, thread, profile, timeline, and search ingestion with explicit capability and privacy boundaries.

## Best Possible Solution

Adopt a bounded experimental core adapter only after owner approval: require explicit per-command opt-in, keep automatic fallback disabled, validate self-hosted endpoints against a strict outbound-URL policy, expose a capability matrix, normalize through the existing canonical ingestion path, and initially limit support to post, thread/conversation, profile, public-status, and search reads with recorded fixtures and provenance metadata.

## Risks / Open Questions

- The public service receives requested IDs, handles, search terms, caller network metadata, and potentially sensitive research intent; explicit disclosure and opt-in semantics need owner approval.
- A configurable base URL expands the outbound-request trust boundary and needs strict HTTPS URL parsing, credential rejection, redirect policy, and protection against private-network or loopback access.
- Public endpoint stability, undocumented response changes, rate limits, availability, and service terms could create an ongoing support burden that the repository has not yet accepted.
- FxTwitter cannot represent authenticated account membership such as bookmarks, likes, mentions, home timelines, or DMs, so capability errors must prevent misleading normalization or silent fallback.
