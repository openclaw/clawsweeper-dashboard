## Summary

Keep this recent, well-specified feature request open for an explicit product decision. Current main still limits live transport selection to `auto`, `bird`, and `xurl`; the adapter architecture can accommodate another attributable source, but adopting FxTwitter in core creates a new third-party privacy, reliability, configuration, and support contract that repository history does not establish automatically.

## What This Changes

Add an explicit opt-in FxTwitter transport for credential-free public post, thread, profile, timeline, and search reads with canonical persistence, pagination, source attribution, and capability-aware failures.

## Best Possible Solution

If sponsored, implement a narrow explicit-opt-in adapter behind the existing transport and capability abstractions, initially covering post lookup, threads/conversations, profiles, public statuses, and search while preserving canonical persistence, source metadata, safe HTTPS endpoint validation, and a strict prohibition on implicit fallback or account-private operations.
