## Summary

Keep this issue open as the phased tracker for the remaining FxTwitter proposal. The maintainer accepted and merged the secure first phase—explicit, fixed-origin single-tweet import—but threads, profiles, timelines, search, and pagination remain intentionally deferred and need a new owner-approved scope decision before implementation.

## What This Changes

Add an explicitly opted-in FxTwitter transport for public X/Twitter reads, including lookup, threads, profiles, and search, while keeping private and write operations unavailable.

## System Context

Birdclaw imports explicitly requested live X/Twitter data through selected read transports, normalizes it into local canonical records, and serves later local queries from its database. The FxTwitter path is currently a narrowly scoped public, fixed-origin import path with provenance and disclosure safeguards rather than a general live-read provider.

## Architecture Diagram

  B --> C{Capability and URL checks}
  C -->|allowed public lookup| D[Fixed FxTwitter public API]
  C -->|private or unsupported| E[Capability error]
  D --> F[Normalize canonical tweet]
  F --> G[Local database and source provenance]
  G --> H[Offline local query surfaces]

## Best Possible Solution

Retain the merged fixed-origin, explicit opt-in tweet-import path and approve any next FxTwitter capability as a separately bounded phase that preserves disclosure, capability rejection, canonical provenance, and local-first reads.
