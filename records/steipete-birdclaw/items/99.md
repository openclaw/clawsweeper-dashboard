## Summary

Keep this issue open for an explicit product decision. Current main supports only the authenticated `bird` and `xurl` live transports, while Birdclaw’s vision supports bounded live-source interfaces; the unresolved question is whether core should adopt and support an external public FxTwitter service plus its configuration and privacy contract.

**Likely related people**
- `steipete` — repository owner and likely product-direction owner for the transport boundary; medium confidence.

## What This Changes

Requests an explicitly selected, read-only FxTwitter transport for public post, thread, profile, timeline, and search retrieval, including a configurable self-hosted endpoint.

## Best Possible Solution

If sponsored, add an experimental, explicitly selected adapter through the existing gateway, initially limited to post and thread retrieval with canonical persistence, capability-specific failures, source attribution, URL safety, and clear hosted-service consent; defer search, timelines, and social-graph pagination until that contract proves stable.

## Risks / Open Questions

- The hosted public service would receive requested IDs, handles, search terms, and caller network metadata, requiring a deliberate consent and documentation policy.
- FxTwitter availability, rate limits, response compatibility, and operational continuity are outside Birdclaw’s control unless users self-host.
- Mapping public-only results into surfaces associated with authenticated timelines, likes, bookmarks, mentions, or account state could produce misleading provenance unless capabilities fail closed.
- The requested MVP spans configuration, HTTP transport, decoding, normalization, persistence, pagination, capability reporting, privacy documentation, and fixtures, so implementation should not begin before scope is narrowed.
