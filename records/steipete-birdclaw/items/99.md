## Summary

Keep this recent feature request open for a maintainer product decision. Current main has only the authenticated `bird` and `xurl` live transports, while the repository vision permits additional bounded, attributable data sources; the unresolved question is whether Birdclaw core should assume the privacy, availability, configuration, and support contract of a third-party FxTwitter service. citeturn577574view0turn442265view1

## What This Changes

Add an explicit, opt-in FxTwitter read transport for public post, thread, conversation, profile, timeline, and search ingestion into Birdclaw’s canonical local model.

## Best Possible Solution

If sponsored, implement a narrow read-only adapter behind explicit per-command selection, with no automatic fallback, safe HTTPS base-URL validation, canonical persistence, source and completeness metadata, bounded cursor pagination, capability-specific failures, and recorded-fixture coverage.
