## Summary

Current main has a bounded live-transport gateway and canonical local ingestion paths, but no FxTwitter/FxEmbed transport. The request is recent, detailed, and compatible with Birdclaw’s local-first direction in principle; it should remain open until the repository owner decides whether core should assume the privacy, endpoint-trust, reliability, configuration, and support obligations of an opt-in public third-party service.

## What This Changes

Add an optional, explicitly selected FxTwitter read transport for public tweet, thread, conversation, profile, timeline, and search operations, with canonical local persistence and capability-aware failures.

## Best Possible Solution

If core sponsorship is granted, implement a narrow explicit-opt-in read-only adapter through the existing live gateway and canonical ingestion path, initially limiting it to public lookup, thread/conversation, profile/statuses, and search with capability prechecks, safe HTTPS endpoint policy, source/privacy metadata, bounded pagination, fixture-based tests, and no automatic fallback.

## Risks / Open Questions

- Using the public default endpoint discloses requested IDs, handles, search terms, and caller network metadata to a third party whose availability, rate limits, retention, and API compatibility Birdclaw does not control.
- A configurable self-hosted endpoint adds URL-validation, redirect, credential-leakage, and trust-boundary requirements that need an explicit supported policy.
- Mapping public-only results into existing authenticated concepts could misrepresent bookmarks, likes, mentions, home timelines, or account identity unless capability checks are enforced before network access.
- The proposed MVP spans several endpoints and cursor/error variants, so accepting it creates ongoing fixture, normalization, documentation, and compatibility maintenance beyond a single lookup adapter.
