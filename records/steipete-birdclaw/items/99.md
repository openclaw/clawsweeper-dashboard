## Summary

Keep this recent feature proposal open for repository-owner direction. Current main has reusable transport, HTTP, ingestion, and persistence boundaries but no FxTwitter provider; the proposal fits Birdclaw’s conditional vision for new data surfaces while adding a third-party service commitment whose capability, privacy, endpoint-safety, and support policies require explicit approval.

## What This Changes

Add an explicitly opted-in, read-only FxTwitter transport for public X lookups, threads, profiles, timelines, and search, including self-hosted endpoint support and capability/privacy guardrails.

## Best Possible Solution

Approve a staged, explicit-opt-in provider only after defining its capability matrix and outbound-endpoint policy, then implement it through the existing gateway, HTTP service, canonical ingestion, and persistence paths with recorded fixtures, provenance metadata, privacy documentation, and no implicit fallback.
