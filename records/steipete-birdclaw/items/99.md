## Summary

Keep this recent issue open for repository-owner direction. Current main has reusable live-transport, ingestion, and HTTP boundaries, but FxTwitter is not implemented and adopting it creates a new third-party provider commitment with privacy, endpoint-safety, reliability, and support implications; the related issues address distinct behavior and do not supersede this proposal.

## What This Changes

Add an explicitly selected, read-only FxTwitter transport for public post, thread, profile, timeline, and search ingestion, including configurable self-hosted endpoints.

## Best Possible Solution

If sponsored, begin with a narrow explicit-opt-in MVP for post lookup, threads, profiles, and public search; reuse canonical ingestion, advertise an exact capability matrix, forbid automatic fallback and credential forwarding, define self-hosted endpoint safety, and require fixtures plus a redacted live CLI transcript before expanding pagination-heavy surfaces.
