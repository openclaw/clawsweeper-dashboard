Keep this recent, well-specified feature request open for an explicit product decision. ## What This Changes

Add an explicitly selected, read-only FxTwitter transport for public post, thread, profile, timeline, and search operations.

## Best Possible Solution

If sponsored, implement a bounded explicit-opt-in adapter through existing command surfaces, with capability-specific rejection before network access, safe HTTPS endpoint configuration, canonical persistence, source and completeness attribution, bounded pagination, fixture coverage, and no automatic fallback.

## Risks / Open Questions

- The public FxTwitter endpoint would receive requested post IDs, handles, search terms, and caller network metadata, creating a privacy disclosure and consent obligation.
- A core adapter would make Birdclaw responsible for third-party uptime, schema drift, rate limits, abuse controls, and deprecation behavior outside the repository's control.
- A configurable self-hosted endpoint needs a clear trust model and URL-safety policy so credentials, unsafe schemes, redirects, and unexpected hosts are not accepted silently.
- FxTwitter cannot satisfy authenticated account operations, so incomplete capability gating could produce misleading results or unintended fallback behavior.
