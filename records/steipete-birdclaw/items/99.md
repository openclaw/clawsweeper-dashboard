## Summary

Current main has reusable Effect-based transport and canonical-ingestion boundaries but no FxTwitter implementation. The request aligns with Birdclaw’s local-first vision, but supporting a public third-party API in core introduces a new privacy, reliability, and compatibility commitment that requires explicit repository-owner approval.

## What This Changes

Add an explicitly selected FxTwitter read transport for public post, thread, profile, timeline, and search ingestion into Birdclaw’s canonical local store.

## Best Possible Solution

After owner approval, begin with an explicit opt-in MVP for post lookup and thread or conversation ingestion, including safe HTTPS endpoint validation, source and privacy metadata, canonical persistence, and no automatic fallback; expand to profiles and search only after that normalization contract proves stable.
