## Summary

Keep open for maintainer ownership. Current `main` has partially addressed local-auth capacity by moving the shard to a 16-vCPU runner and emitting pressure diagnostics, but the required HTTP gate still exercises GitHub-repository publish cases and local-auth helpers still contain broad reload/retry paths; the remaining scope needs a CI reliability decision rather than auto-close.

## What This Changes

Harden the HTTP and local-auth CI gates against transient GitHub lookup failures, runner under-capacity, and retry-driven local Convex saturation.

## Best Possible Solution

Keep the capacity diagnostics and runner upgrade, then use a maintainer-approved split that adds bounded retry only for classified transient GitHub failures and replaces generic page-reload loops with backend-readiness polling plus focused UI assertions.
