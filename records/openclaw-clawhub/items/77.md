## Summary

Keep open. Current main and v0.23.1 still accept any non-empty skill display name across shared publish validation, schema, web publish, GitHub import, and CLI/API payloads, so the requested title-length policy remains unresolved.

## What This Changes

The issue asks for a product policy limiting skill display-title length so skill titles stay short and concise.

## Best Possible Solution

Define the public skill display-name policy first, then enforce the chosen limit consistently in shared backend validation, web publish/import UI, GitHub import, CLI/API schemas, docs, and tests with explicit legacy handling.

## Reproduction Assessment

Yes, at source level: current main accepts any non-empty displayName through the shared publish helper, schema, web publish form, GitHub import path, and CLI/API schema. I did not run a live publish because the validators and entry points already show the missing policy.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
