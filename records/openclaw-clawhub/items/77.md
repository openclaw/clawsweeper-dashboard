## Summary

Keep open. Current main and the latest v0.23.1 release still only require a non-empty skill display name across the inspected publish paths, so the requested skill title-length policy remains unresolved product work.

## What This Changes

The issue requests a maximum length policy for skill titles so published skills use short, concise display names.

## Best Possible Solution

Define the public display-name maximum and legacy behavior, then enforce it in shared backend validation with aligned publish/import UI, CLI/API schemas, docs, and regression tests.

## Reproduction Assessment

Yes, at source level: current main accepts any non-empty displayName through the shared backend publish helper, web publish form, GitHub import path, and CLI/API schema. I did not run a live publish because this read-only review found the missing policy in the validators and entry points.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
