## Summary

Keep open. Current main and the latest v0.23.1 release still only require skill display names to be non-empty, so the requested title-length policy remains unresolved and needs maintainer product direction.

## What This Changes

The issue asks for a maximum length policy for skill titles so published skill titles stay short and concise.

## Best Possible Solution

Define the public skill display-name policy first, then enforce the chosen limit consistently in shared backend validation, web publish/import UI, CLI/API schemas, docs, and tests.

## Reproduction Assessment

Yes, at source level: current main accepts any non-empty displayName through the shared backend publish helper, web publish form, GitHub import path, and CLI/API schema. I did not run a live publish because this read-only review found the missing policy directly in the validators and entry points.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
