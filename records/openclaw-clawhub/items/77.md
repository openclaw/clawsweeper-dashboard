## Summary

Keep open. Current main and the latest v0.23.1 release still accept any non-empty skill display name across the shared publish, web publish, GitHub import, CLI, and request-schema paths, so the requested title-length policy remains unresolved maintainer product work.

## What This Changes

Request a maximum length policy for public skill titles/display names so skill names stay short and concise.

## Best Possible Solution

Define the public skill display-name maximum and legacy policy, then enforce it in shared backend validation with aligned web publish, GitHub import, CLI/API schema, docs, and regression tests.

## Reproduction Assessment

Yes, at source level. Current main accepts any non-empty displayName through the shared publish helper, schema, web publish form, GitHub import path, and CLI/API schema; I did not run a live publish because this review is read-only.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
