## Summary

Keep open. Current main and the latest v0.23.1 release still accept any non-empty skill display name across the backend publish, GitHub import, web publish, and CLI publish paths, so the requested title-length policy remains unresolved maintainer product work.

## What This Changes

The issue requests a product policy limiting skill titles so public skill names stay short and concise.

## Best Possible Solution

Define the public skill display-name policy first, then enforce the chosen limit in the shared backend publish/import validation and mirror it in web, CLI/API schemas, docs, and tests with explicit legacy handling.

## Reproduction Assessment

Yes, at source level: current main accepts any non-empty displayName through the shared publish helper, schema, web publish form, GitHub import path, and CLI schema. I did not run a live publish because this read-only review cannot create fixture data and the validators already show the missing policy.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
