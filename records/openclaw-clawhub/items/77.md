## Summary

Keep open. Current main and the latest v0.23.1 release still accept any non-empty skill display name, so the requested title-length policy remains unresolved product work rather than an implemented cleanup.

## What This Changes

The issue requests a maximum length or policy for skill display names/titles so public catalog entries stay concise.

## Best Possible Solution

Define the public skill display-name policy first, then enforce the chosen limit consistently in shared backend validation, web publish/import UI, GitHub import, CLI/API schemas, docs, and tests with explicit treatment for already-published long names.

## Reproduction Assessment

Yes, at source level: current main accepts any non-empty displayName through backend publish, GitHub import, web publish, and CLI/API schema paths. I did not run a live publish because the validators and entry points expose the missing policy directly.

## Solution Assessment

Unclear until maintainers choose the maximum length and legacy handling. The maintainable solution is a shared backend rule with UI/API/CLI/docs/test alignment, not a presentation-only clamp.
