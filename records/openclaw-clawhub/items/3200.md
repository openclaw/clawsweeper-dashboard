## Label Justifications

- `impact:other`: The reported impact is release-management recoverability for published skills, which does not fit the more specific owned impact categories.

## Summary

This issue remains necessary: current main still exposes an owner tag mutation whose authorization only accepts the legacy direct owner or a platform moderator, while the documented version-delete path does not provide an owner-controlled way to select and repoint `latest` for an organization-owned skill. The narrow recovery behavior needs a maintainer decision on the supported public command shape before implementation.

## What This Changes

Add an organization-owner-authorized recovery path that can move a skill’s `latest` tag to an existing valid version and withdraw an accidentally published higher version.

## Best Possible Solution

Add a narrow, transactional owner rollback operation—preferably an explicit replacement-version argument on version withdrawal—that requires organization publisher-admin access, validates an existing available replacement for the same skill, and synchronizes all latest-derived state; expose it through the CLI with focused regression coverage.
