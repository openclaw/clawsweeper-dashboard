## Summary

This remains necessary: the documented delete flow still disallows deleting the current latest version, while the requested org-owner rollback/tag path is not documented as an available recovery mechanism. The report identifies a bounded product and authorization gap, but the permanent rollback semantics need maintainer direction before implementation.

## What This Changes

Add an organization-owner-authorized recovery flow to repoint `latest` to an existing version or replace the current latest safely after an accidental higher-version skill publish.

## Best Possible Solution

Define a narrow, audited owner/admin rollback operation that selects an existing eligible version as `latest`, authorizes through publisher membership for organization-owned skills, preserves version history, and exposes the same operation through a documented CLI/API path.
