## Summary

Keep open. Current main and v0.23.1 still install or update skill files and metadata without injecting an active-session system event, and a collaborator has already signaled that this should be prioritized.

## What This Changes

Request to notify an active OpenClaw session after `clawhub install` or `clawhub update` so the agent reads the installed skill's `SKILL.md` setup instructions.

## Best Possible Solution

Define a consent-aware ClawHub/OpenClaw install-update handoff contract with explicit session targeting, inspectable setup guidance, approval before consequential actions, docs, and CLI/session tests.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` install or update skill files and metadata and print success without an active-session system event or `SKILL.md` onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not exactly as proposed. A notification may be appropriate, but unconditional instructions to execute setup from `SKILL.md` should be replaced by a maintainer-approved consent, session-targeting, trust, and failure-handling contract.

- Automatically injecting newly installed or updated `SKILL.md` guidance into an active session could let publisher-controlled content steer an agent without a settled consent boundary.
- The ClawHub CLI does not currently expose a deterministic active OpenClaw session target, so a CLI-only implementation could misroute, spoof, or silently fail the handoff.
