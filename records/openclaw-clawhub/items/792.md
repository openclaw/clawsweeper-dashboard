## Summary

Keep open: the requested active-session handoff remains a cross-product feature with a meaningful execution and session-security boundary, and a collaborator explicitly supported prioritizing it. Current review context does not establish that current main or v0.23.1 delivers a consented, targeted post-install/update event.

## What This Changes

Add a post-install and post-update event that tells the active agent session to read a newly installed or updated skill's `SKILL.md` and perform its setup guidance.

## Best Possible Solution

Define a narrow, consented install/update handoff contract: report the installed package and version to an explicitly selected active session, require visible approval before consequential actions, and preserve successful package installation when follow-up guidance cannot run.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ClawHub introduce a consented, session-targeted post-install/update handoff for package-authored setup guidance, and what actions may that handoff request without further user approval?

Rationale: The implementation crosses the boundary between a registry install operation and an agent session that may change local configuration, install plugins, or restart services; source-level work cannot safely choose that authority and failure contract alone.

Likely owner: Patrick-Erichsen

Owner reason: Their collaborator comment is the clearest available evidence of ownership of the pending prioritization and product-boundary decision.

Owner confidence: medium

Options:

- **Approve a consented handoff contract (recommended):** Emit a structured install/update event only to an explicitly active session, with visible approval for consequential setup actions and a non-blocking failure path.
- **Keep setup manual:** Continue treating `SKILL.md` guidance and lifecycle steps as user-initiated instructions rather than automatically delivering them into an agent session.
- **Limit the scope to registration diagnostics:** Address missing hook or plugin registration warnings separately without creating a general agent-session execution handoff.

## Reproduction Assessment

No live current-main reproduction was established in this read-only review, but the prior source review provides a medium-confidence path: install or update a skill and observe that completion does not hand off its `SKILL.md` to an active session.

## Solution Assessment

Unclear: a raw system-message injection is not yet the best safe solution because it lacks an approved consent, session-targeting, and failure contract; a structured, non-blocking handoff with visible approval is the safer direction.
