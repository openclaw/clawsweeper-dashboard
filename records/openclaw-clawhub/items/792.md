## Summary

Keep open: current main and v0.23.1 still lack post-install/update active-session handoff, and the collaborator discussion says this should be prioritized rather than cleaned up as obsolete.

## What This Changes

The issue requests that `clawhub install` and `clawhub update` inject a system event into the active session so the agent reads the installed skill's `SKILL.md` and finishes setup or onboarding.

## Best Possible Solution

Define a consent-aware ClawHub/OpenClaw install-update handoff contract with explicit session targeting, inspectable setup guidance, approval before consequential changes, docs, and CLI/session tests.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` install or update skill files and metadata and print success without an active-session system event or `SKILL.md` onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as an unconditional instruction to execute setup from `SKILL.md`. A notification may be appropriate, but the maintainable solution needs maintainer-approved consent, session targeting, trust, and failure-handling rules.
