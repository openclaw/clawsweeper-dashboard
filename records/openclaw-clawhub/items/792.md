## Summary

Current main still installs and updates skill files without handing completion to an active agent session, and the collaborator discussion explicitly supports prioritizing the idea. The request remains necessary, but unconditional execution of newly installed SKILL.md instructions would cross session and security boundaries that require a maintainer-approved contract.

## What This Changes

Add a post-install and post-update handoff that informs an active agent session about the changed skill and initiates its onboarding guidance.

## Best Possible Solution

Make native OpenClaw skill installation the session-aware surface: refresh the skill snapshot, emit a structured informational event to the invoking session when one exists, require explicit user confirmation before privileged onboarding actions, and document the trust, targeting, failure, and headless behavior in a focused spec.

Rationale: The repository cannot safely infer an active session from the standalone ClawHub CLI, and automatically following third-party instructions can perform privileged agent actions; maintainers must define the cross-product trust boundary before implementation.

Likely owner: Patrick-Erichsen

Owner confidence: medium

Options:

- **Consent-gated OpenClaw handoff (recommended):** Have native OpenClaw installs notify the invoking session, refresh available skills, and ask for confirmation before executing onboarding steps.
- **Informational notification only:** Refresh the skill snapshot and announce the changed skill without interpreting or executing its onboarding instructions.
- **Automatic onboarding execution:** Automatically follow installed SKILL.md setup guidance, accepting the larger prompt-injection and operator-control risk.

## Reproduction Assessment

Yes, from source inspection: run either ClawHub install or update and observe that the command extracts files, records metadata, and exits after its success message without any gateway or session handoff. This establishes the missing behavior on current main without requiring a particular third-party skill.

## Solution Assessment

No, not as an unconditional system directive to execute SKILL.md instructions. A structured OpenClaw-owned notification with deterministic session targeting, skill refresh, explicit consent, and bounded failure behavior is safer and avoids coupling the registry CLI directly to arbitrary active sessions.

- A standalone `clawhub` process has no reliable, authenticated definition of which running gateway or session should receive the event.

- The implementation likely spans ClawHub and OpenClaw contracts, so adding a ClawHub-only side channel could create a second installation source of truth beside native `openclaw skills` commands.
