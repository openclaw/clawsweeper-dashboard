- `impact:security`: The requested handoff would let newly installed or updated publisher-controlled skill content influence an active agent session.

## Summary

Keep open. Current main and v0.23.1 still install or update skill files and local metadata without injecting an active-session event, and the live issue discussion includes collaborator support for prioritizing the request.

## What This Changes

Request a post-install/update handoff that tells the active agent session to read the installed skill's SKILL.md and complete setup guidance.

## Best Possible Solution

Define a consent-aware ClawHub/OpenClaw install-update handoff contract with explicit session targeting, inspectable setup guidance, approval before consequential actions, docs, and CLI/session tests.

## Reproduction Assessment

Yes, at source level. Current cmdInstall and cmdUpdate install or update files and metadata and print success without an active-session system event or SKILL.md onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as unconditional injection. A notification may be appropriate, but the maintainable solution needs maintainer-approved consent, session targeting, trust, and failure-handling boundaries before implementation.

## Risks / Open Questions

- Automatically injecting newly installed or updated SKILL.md guidance into an active session could let publisher-controlled content steer the agent without a settled consent boundary.
- The ClawHub CLI does not currently expose a deterministic active OpenClaw session target, so a CLI-only implementation could misroute, spoof, or silently fail the handoff.
- The related hook-registration work at https://github.com/openclaw/clawhub/issues/2295 should be aligned so hook registration and SKILL.md onboarding do not become competing setup mechanisms.
