## Summary

Current main and v0.23.1 still finish skill installation and updates without notifying an active session, so the requested onboarding continuation remains missing. Collaborator discussion supports prioritizing the idea, but automatic execution would reverse an approved no-direct-handoff boundary and requires a maintainer-defined authentication, consent, session-selection, and failure contract.

## What This Changes

Add a post-install/update active-session notification that prompts the agent to read and act on the installed skill’s onboarding instructions.

## Best Possible Solution

Define an OpenClaw-owned authenticated notification carrying bounded skill identity, version, path, and operation data, then present inspectable, explicitly approved setup actions rather than automatically executing SKILL.md instructions.

Owner confidence: high

Options:

- **Consent-gated runtime handoff (recommended):** Send bounded install/update metadata to OpenClaw and require explicit approval before commands, configuration changes, plugin activation, health fixes, or restarts.
- **Improve explicit setup prompts:** Keep ClawHub and active sessions separated while making install and update completion guidance consistently visible, inspectable, and copyable.
- **Automatic onboarding execution:** Inject a system directive that immediately reads and executes installed skill instructions in the selected active session.

## Reproduction Assessment

Yes, at source level. Current main and v0.23.1 complete installation and updates through filesystem, metadata, telemetry, and terminal output without any active-session handoff; a live gateway/session run was not performed.

## Solution Assessment

No, not exactly as proposed. An unconditional execute-on-install directive is too broad; an authenticated typed notification with inspectable, consent-gated actions is the safer and more maintainable solution.
