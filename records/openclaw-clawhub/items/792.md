- `P2`: This is a meaningful setup reliability and ergonomics feature with security implications, but not an emergency outage, data loss, or confirmed bypass.
- `impact:security`: The requested handoff would let newly installed or updated publisher-controlled skill instructions influence active agent behavior.
- `impact:session-state`: The feature explicitly injects new trusted context into an active session and can affect immediate agent behavior.
- `impact:ux-friction`: The current CLI install/update flow can appear complete while setup guidance remains undiscovered unless the user knows to use the copyable prompt or read SKILL.md manually.

## Summary

Keep open. Current main and the latest release still lack post-install/update active-session event injection; the existing install-and-setup prompt is a user-copied workaround, and a collaborator has already signaled this should be prioritized rather than cleaned up.

## What This Changes

The issue requests an active-session system event after `clawhub install` or `clawhub update` so the agent reads the installed skill's SKILL.md and completes onboarding or post-update setup.

## Best Possible Solution

Define a consent-aware ClawHub/OpenClaw install-update handoff contract with explicit session targeting, inspectable setup guidance, approval before consequential actions, docs, and focused CLI/session tests.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` install or update skill files and metadata and print success without an active-session system event or SKILL.md onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not exactly as proposed. A handoff may be appropriate, but unconditional instructions to execute setup from SKILL.md should be replaced by a maintainer-approved consent, session-targeting, trust, and failure-handling contract.
