## Summary

Keep open. Current main and v0.23.1 still install or update skill files and metadata without an active-session post-install/update handoff, while the existing web prompt flow only helps users start a guided install before the CLI action.

## What This Changes

Request to notify the active OpenClaw session after ClawHub skill install/update so the agent reads SKILL.md and performs setup, onboarding, or post-update steps.

## Best Possible Solution

Design an explicit, consent-gated OpenClaw/ClawHub handoff that surfaces verified SKILL.md metadata after install/update without hiding security decisions from the user.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ClawHub/OpenClaw add an automatic active-session post-install/update handoff, and if so what consent and trust gate must run before the agent reads or acts on the newly installed SKILL.md?

Rationale: The requested behavior is useful setup UX, but it changes the authority boundary between registry install/update and an active agent session that can run commands or modify configuration.

Likely owner: Patrick-Erichsen

Owner reason: They already engaged on this issue and have recent history in the install UX and CLI surfaces that define the boundary under discussion.

Owner confidence: high

Options:

- **Design consent-gated handoff (recommended):** Add a post-install/update handoff only after a visible trust prompt or explicit user action, and constrain the agent to verified ClawHub metadata and the installed skill path.
- **Keep prompt-only flow:** Continue using copyable OpenClaw install/setup prompts and do not inject events from the ClawHub CLI until a stronger runtime contract exists.
- **Allow automatic injection:** Treat install/update as sufficient consent for an active-session system event, accepting the higher security and surprise-cost burden.

## Reproduction Assessment

Yes from source inspection: the current ClawHub install and update commands complete file/lock metadata changes and success output without any active-session event or SKILL.md onboarding handoff. I did not run a live OpenClaw session, but the absence is clear in the command path and docs.

## Solution Assessment

Unclear until maintainers choose the handoff contract. The narrowest maintainable path is not silent auto-execution; it should be an explicit, consent-gated event or OpenClaw-owned install/update flow that preserves the security boundary.
