## Summary

Keep open. Current main and v0.23.1 still do not inject a post-install/update event into an active session, and Patrick-Erichsen’s maintainer comment says this should be prioritized rather than cleaned up as obsolete.

## What This Changes

The issue requests a post-install/update active-session event so agents read the installed skill's SKILL.md and complete onboarding steps.

## Best Possible Solution

Define a consent-aware ClawHub/OpenClaw install-update handoff contract with explicit session targeting, inspectable setup guidance, approval before consequential actions, docs, and CLI/session tests.

## Reproduction Assessment

Yes, at source level. Current cmdInstall and cmdUpdate install or update skill files and metadata and print success without an active-session system event or SKILL.md onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not exactly as proposed. A notification may be appropriate, but unconditional instructions to execute setup from SKILL.md should be replaced by a maintainer-approved consent, session-targeting, trust, and failure-handling contract.

## Risks / Open Questions

- Automatically injecting newly installed or updated SKILL.md guidance into an active session could let publisher-controlled content steer an agent without a settled consent boundary.
- The ClawHub CLI does not currently expose a deterministic active OpenClaw session target, so a narrow CLI-only patch could misroute, spoof, or silently fail the handoff.
- The approved install surface currently chooses inspectable copyable prompts over direct handoff, so implementing this request requires an explicit product decision.
- The related hook-registration work at https://github.com/openclaw/clawhub/issues/2295 should be aligned so hook registration, declarative metadata, and SKILL.md onboarding do not become competing setup mechanisms.
