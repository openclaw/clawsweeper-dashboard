## Summary

Keep open. The issue requests a new install/update-to-active-session handoff and current main still only installs skill files plus manifest-defined lifecycle commands; collaborator feedback says this should be prioritized, and the remaining design has security and session-state implications that need maintainer direction.

## What This Changes

The issue asks for `clawhub install` and `clawhub update` to notify the active agent session so newly installed or updated skills can be read and acted on immediately.

## Best Possible Solution

Define a maintainer-approved, consent-aware install/update handoff that can surface SKILL.md onboarding to the active agent without automatically executing untrusted instructions, and coordinate it with the hook-registration contract tracked separately.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection supports the gap: the current installer handles files and lifecycle scripts, but no active-session notification path was found. I did not execute a live install/update session, so this is source-reproducible rather than directly reproduced.

## Solution Assessment

Is this the best way to solve the issue? Unclear: an active-session event may be the right product shape, but maintainers still need to define consent, trust, and whether the session should only notify/read or also execute setup actions.
