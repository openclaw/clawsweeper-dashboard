## Summary

Keep open. Current main and v0.23.1 still install or update skill files and metadata without injecting an active-session event, and the remaining work needs product and security direction around consent and session targeting.

## What This Changes

Request to notify the active agent session after `clawhub install` or `clawhub update` so the agent reads the installed skill's `SKILL.md` and completes setup guidance.

## Best Possible Solution

Define a user-consented OpenClaw/ClawHub install-update handoff contract, or explicitly keep the current inspectable copy-prompt flow as the supported setup path.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` update skill files and metadata and print success without an active-session system event or SKILL.md onboarding read; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as unconditional injection. A notification may be appropriate, but maintainers need to define consent, session targeting, trust boundaries, and failure handling before this becomes an implementation task.
