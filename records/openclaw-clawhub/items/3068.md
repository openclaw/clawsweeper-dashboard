## Summary

Current main still statically combines redirect, loader, metadata, nested-route, and heavy skill-detail UI responsibilities in the shared owner/slug route, so the proposed measurement-first investigation remains necessary. The issue is repository-member-authored and its accepted implementation depends on a maintainer-controlled stop/go decision after bundle and navigation measurements.

## What This Changes

Measure the shared route preload closure, extract one route’s loader/head/data contracts from UI imports, and expand only if the A/B proves a material reduction without navigation regressions.

## Best Possible Solution

Run one narrowly scoped contract extraction against an identical baseline, preserve SSR, metadata, redirects, hydration, and navigation behavior, and stop with a documented no-go result if preload bytes do not materially improve.
