## Summary

Keep open: current main intentionally limits trusted provenance to server-resolved GitHub sources, while ordinary skill publish still accepts client-declared source metadata without a clear retention, visibility, or deprecation contract. Resolving that mismatch requires an explicit product and security decision.

## What This Changes

Clarify whether CLI-declared skill source metadata should become verified provenance, remain visibly untrusted attribution, or be documented as non-visible metadata.

## Best Possible Solution

Preserve the current trust boundary, record the permanent contract in `specs/`, immediately clarify CLI help and public docs, and expose trusted provenance only through a server-verified flow that validates repository authority and artifact identity.
