## Summary

Keep open: the report identifies a real trust-boundary ambiguity, not an already-solved defect. Current behavior intentionally distinguishes client-declared publish source from server-resolved GitHub provenance, but maintainers still need to choose the permanent retention and visibility contract before a safe documentation or implementation change can be scoped.

## What This Changes

Define whether CLI-supplied GitHub source metadata is server-verified provenance, separately visible untrusted attribution, or intentionally non-visible metadata.

## Best Possible Solution

Choose and document a two-tier model: keep verified GitHub import provenance authoritative for trust decisions, and either retain CLI data only as explicitly unverified attribution or remove/deprecate source flags that cannot have a user-visible effect.
