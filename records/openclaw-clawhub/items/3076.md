## Summary

Keep open: the report identifies an unresolved contract boundary between accepted client-declared source fields and server-trusted GitHub provenance. Current documentation separates ordinary skill publishing from GitHub-backed package publishing, but it does not settle whether skill source flags should be rejected, retained as explicitly untrusted attribution, or become server-verified provenance.

## What This Changes

Clarify the contract for source metadata supplied to `clawhub skill publish`, or add a safe provenance/attribution path for CLI-published skills.

## Best Possible Solution

Keep trusted provenance server-resolved, then make the CLI contract explicit by rejecting unsupported skill source flags or exposing clearly labeled unverified attribution outside verification and trust decisions.

Options:

- **Reject unsupported skill source fields (recommended):** Keep verified provenance exclusive to server-resolved GitHub imports and make `skill publish` fail with guidance to the supported package/import workflow.
- **Expose unverified attribution:** Persist publisher-supplied repository details separately from trusted provenance and label them unverified in API and UI surfaces.
- **Build verified CLI provenance:** Verify repository ownership, commit/path content, and uploaded artifact correspondence before writing trusted provenance.
