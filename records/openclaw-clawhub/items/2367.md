## Summary

Keep this collaborator-authored, security-sensitive publisher-identity issue open: current main still rejects dot and underscore publisher handles while enforcing scope/owner matching, and choosing an alias or canonicalization model requires explicit maintainer policy.

## What This Changes

The issue requests a safe way for npm scopes containing dots or underscores to map to ClawHub publisher identities without breaking package ownership guarantees.

## Best Possible Solution

Choose and document one canonical publisher-identity model—preferably preserving slug-safe public handles while adding a tightly verified npm-scope alias only if maintainers approve the added ownership lifecycle—and cover creation, publish, transfer, install, and URL behavior with regression tests.
