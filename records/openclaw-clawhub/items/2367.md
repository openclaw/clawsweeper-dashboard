## Summary

Keep this collaborator-authored, security-sensitive publisher-identity issue open. The reported scope/owner conflict remains a policy and authorization-boundary decision, and the related test-only pull request was closed unmerged rather than resolving the behavior.

## What This Changes

The issue requests a durable way for npm-valid scoped package names containing dots or underscores to map to ClawHub publisher identities without breaking scope-based ownership checks.

## Best Possible Solution

Adopt one explicit publisher-identity model—preferably stable slug handles plus verified, unique npm-scope aliases—and enforce it consistently across publish authorization, transfers, URLs, UI, package lookup, and regression coverage.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ClawHub preserve slug-like publisher handles and add verified npm-scope aliases, or make npm-compatible scopes canonical publisher handles?

Rationale: Both directions alter the identity used for package publishing and can affect authorization, collision handling, URLs, transfers, and existing publishers; the repository cannot safely infer that policy from validation code alone.

Likely owner: Patrick-Erichsen

Owner reason: They are the collaborator who supplied the concrete package evidence and identified the product/security tradeoff requiring an explicit decision.

Owner confidence: medium

Options:

- **Use verified scope aliases (recommended):** Keep stable slug handles as canonical publisher IDs and permit a unique, verified npm scope alias for scoped-package authorization.
- **Allow npm-compatible handles:** Expand canonical publisher-handle grammar to match npm scope grammar, with explicit URL canonicalization, collision handling, and migration rules.
- **Keep strict scope matching:** Require affected publishers to rename packages or publish under matching scopes, accepting the migration burden for existing npm identities.
