## Summary

Keep this issue open: current main still eagerly requests up to 50 skill-version records on the default detail view, so the central performance problem remains, and the item is a newly filed member-authored enhancement with concrete acceptance criteria.

## What This Changes

Defer skill version history, plugin release history, and deletion-access queries until their detail-page tabs need them, with cancellation, retry, and direct-tab navigation handling.

## Best Possible Solution

Load only the minimum two-version eligibility data on ordinary skill views, skip inapplicable archives, and lazily fetch plugin and full skill histories with abortable first-page state, explicit retry, and preserved pagination semantics.
