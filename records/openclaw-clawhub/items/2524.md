## Summary

Keep open: this collaborator-authored auth/security issue is not solved by current main; the code still delegates GitHub consent-screen identity to the OAuth App selected by production `AUTH_GITHUB_ID`/`AUTH_GITHUB_SECRET`, and no operator proof shows the production branding has been moved to official ownership.

## What This Changes

The issue asks maintainers to replace or transfer the production GitHub OAuth App credentials so ClawHub consent shows official ClawHub/OpenClaw branding.

## Best Possible Solution

A maintainer should create or transfer the production GitHub OAuth App to official OpenClaw/ClawHub ownership, rotate the Convex production GitHub OAuth credentials, keep callback/site URLs aligned, and smoke-test web plus CLI auth with private values redacted.

## Reproduction Assessment

No, not for the current live consent branding. The issue includes screenshot evidence and source confirms the env-controlled OAuth route, but a fresh/private-browser or CLI production OAuth approval check is still needed to verify current branding.

## Solution Assessment

Yes. Production OAuth App ownership plus Convex credential rotation is the narrowest maintainable solution; a source-only PR would not change GitHub's visible consent branding unless the external OAuth App selected by `AUTH_GITHUB_ID` changes too.
