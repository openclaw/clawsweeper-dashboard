## Summary

Keep open: current main still derives an organization publisher’s GitHub link from its ClawHub handle, while the publisher data model and update surface lack an independent GitHub identity field. The RFC needs a focused product decision before implementation.

Likely related people: `vyctorbrzezowski` (medium confidence, recent organization-ownership work) and `ianalloway` (low confidence, prior public-profile work).

## What This Changes

Allow organization publishers to configure a GitHub profile independently of their ClawHub handle while preserving existing package coordinates and handle-derived fallback behavior.

## Best Possible Solution

Add a nullable, normalized GitHub handle specifically for organization publishers, preserve the handle-derived fallback, authorize edits through the existing organization role model, and display verification status separately from ordinary public profile metadata.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should organization publishers receive a GitHub-specific profile override, who may edit it, and must ClawHub verify the linked GitHub organization before presenting it as verified?

Rationale: The source confirms the capability is missing, but the issue leaves the durable data contract, authorization boundary, and verification semantics open; these choices affect schema, UI language, API behavior, and future trust guarantees.

Likely owner: vyctorbrzezowski

Owner reason: The strongest available history signal is recent merged work defining organization ownership behavior and its separation from personal-account state.

Owner confidence: medium

Options:

- **Add narrow GitHub metadata (recommended):** Store an optional normalized GitHub handle, allow organization owners and admins to edit it, and treat it as unverified public metadata unless separate ownership verification exists.
- **Require verified ownership:** Add the override only after OAuth organization-membership verification can prove that an authorized ClawHub member controls the linked GitHub organization.
- **Use a general website field:** Add a broader organization website URL instead of GitHub-specific identity, accepting that this does not provide GitHub ownership semantics.

## Reproduction Assessment

Yes, at source level: current main deterministically builds the GitHub URL from the publisher handle, and the schema and mutation surfaces contain no independent override. A live browser run is unnecessary to establish that limitation.

## Solution Assessment

Unclear pending product direction. The proposed optional fallback-compatible field is narrow and migration-safe, but a GitHub handle is preferable to an unrestricted URL and verification semantics must remain distinct from provenance or trusted publishing.
