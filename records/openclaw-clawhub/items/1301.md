## Summary

Keep open. Current main and v0.23.1 have Official/community/private channels, release verification tiers, trusted publishing, package scan scheduling, and exact-release security summaries, but they still do not provide the requested public Verified or vetted-community path for community code plugin publishers.

## What This Changes

The issue asks whether ClawHub has a verified-publisher path for active community code plugin contributors and why several source-linked code plugins remained in pending scan state after more than 24 hours.

## Best Possible Solution

Resolve the community plugin verification policy in the open vetted-community RFC, document request/status semantics, and open a narrower scanner-health bug only if production inspection finds a remaining queue or freshness failure.

## Reproduction Assessment

No high-confidence current-main reproduction exists for the named pending-scan symptom from source inspection alone. The verified-publisher request is a trust-policy feature, not a deterministic failing code path.

## Solution Assessment

No direct source fix is the best next step yet. The maintainable path is maintainer-approved trust policy first, then a scoped implementation that keeps publisher status, release evidence, trusted publishing, and scan state distinct.
