## Summary

Keep open. Current main still lacks a public Verified or vetted-community path for community code-plugin publishers; the named latest plugin releases no longer show pending scans, but most still report stale trust summaries and the policy question remains open.

## What This Changes

The issue asks whether active community code-plugin publishers can get a Verified-style trust path and why several published code plugins stayed at Scan: pending.

## Best Possible Solution

Resolve the public vetted-community or Verified policy in https://github.com/openclaw/clawhub/issues/2272, document the request/status semantics, and inspect production scanner freshness only if maintainers want to answer the stale-summary part.

## Reproduction Assessment

No. Live exact-release security endpoints for the named latest plugin releases now return pending=false, so the original pending-scan symptom does not reproduce; the remaining Verified publisher path is a security/product feature request.

## Solution Assessment

No direct source fix is ready. The maintainable path is maintainer-approved trust policy in the broader RFC first, with production scanner inspection only if stale trust summaries indicate a current freshness problem.
