## Summary

Keep open. Current main and v0.23.1 still provide Official/community/private channels, source/provenance verification tiers, trusted-publisher publishing, and exact-release scan summaries, but they do not provide a public Verified or vetted-community path for community plugin publishers; the named latest releases no longer reproduce the original pending-scan symptom.

## What This Changes

The issue asks whether active community code-plugin publishers can get a Verified or vetted status and why several source-linked plugins stayed scan-pending for more than 24 hours.

## Best Possible Solution

Resolve the community-plugin verification policy in https://github.com/openclaw/clawhub/issues/2272, document the request/status semantics, and open a narrower scanner-health item only if production inspection finds a current queue or freshness bug.

## Reproduction Assessment

No. Live public security endpoints for the named latest releases now return clean or suspicious with pending=false; the remaining Verified publisher path is a trust-policy feature request rather than a runtime bug reproduction.

## Solution Assessment

No direct source fix is ready. The maintainable path is maintainer-approved trust policy first, with production scanner inspection only if the historical pending-scan symptom still matters.
