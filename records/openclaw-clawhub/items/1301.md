## Summary

Keep open. Current main and v0.23.1 have Official/community/private channels, release verification tiers, trusted-publisher publishing, package security summaries, and code-plugin scan scheduling, but they still do not provide a public Verified or vetted-community path for community plugin publishers; the named packages no longer reproduce the original pending-scan symptom on the public API.

## What This Changes

The issue asks whether ClawHub has a verified-publisher or vetted-community trust path for active community code-plugin publishers, and whether code-plugin security scans should remain pending after more than 24 hours.

## Best Possible Solution

Resolve the community-plugin verification policy in https://github.com/openclaw/clawhub/issues/2272, document the request/status semantics, and open a narrower scanner-health item only if production inspection finds a remaining queue or freshness bug.

## Reproduction Assessment

No. Live public security endpoints for the named latest releases now return clean or suspicious with pending=false; the remaining Verified publisher path is a trust-policy feature request rather than a runtime bug reproduction.

## Solution Assessment

No direct source fix is ready. The maintainable path is maintainer-approved trust policy first, with production scanner inspection only if the historical pending-scan symptom still matters.
