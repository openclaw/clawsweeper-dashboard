## Summary

Keep open. Current main has Official/community/private channels, release verification tiers, trusted publishing, package scan scheduling, and exact-release security summaries, but it still does not provide the requested public Verified or vetted-community path for community code plugin publishers.

## What This Changes

The issue asks whether community code plugin contributors can become verified publishers and why their code plugin scans stayed pending after publishing.

## Best Possible Solution

Resolve the community plugin verification policy in the open vetted-community RFC, document the request/status semantics, and open a narrower scanner-health bug only if production inspection finds a remaining queue or freshness failure.

## Reproduction Assessment

No high-confidence current-main reproduction exists for the pending-scan symptom from this review. The remaining verified-publisher request is a trust-policy feature, not a deterministic failing code path.

## Solution Assessment

No direct source fix is the best next step yet. The maintainable path is maintainer-approved trust policy first, then a scoped implementation that keeps publisher status, release evidence, trusted publishing, and scan state distinct.
