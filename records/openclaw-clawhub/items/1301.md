## Summary

Keep open. Current main and the live API still do not provide a public Verified or vetted-community path for community code-plugin publishers; the original pending-scan symptom no longer reproduces, but stale trust summaries remain for several named releases.

## What This Changes

The issue asks whether community code-plugin publishers can get a verified-publisher trust signal and why several published code plugins stayed in pending scan status.

## Best Possible Solution

Resolve the public vetted-community or Verified policy in https://github.com/openclaw/clawhub/issues/2272, document the request/status semantics, and open a narrower scanner-health issue only if production inspection finds a current queue or freshness bug.

## Reproduction Assessment

## Solution Assessment

No direct source fix is ready. The maintainable path is maintainer-approved trust policy in the broader RFC first, with production scanner inspection only if stale trust summaries point to a current scanner freshness problem.
