## Summary

Keep open: current main and the latest release still accept changelog text during publishing but provide no operation for correcting an already-published version. No canonical issue or pull request owns the same remaining capability, and implementation requires an explicit release-history policy.

## What This Changes

Add an authenticated CLI workflow for correcting the changelog of an already-published skill or package version.

## Best Possible Solution

Define audited changelog revisions in a lifecycle spec, then implement owner-authorized skill and package corrections that retain prior text, actor, timestamp, and reason while atomically updating latest-version projections.
