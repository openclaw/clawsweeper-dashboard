## Summary

Current main still accepts changelog text only during publish or sync and exposes published versions through read and deletion lifecycle operations, not metadata editing. This remains a distinct feature request, but implementation needs a maintainer decision because changing a published changelog affects authorization, historical provenance, and parallel skill/package release contracts.

## What This Changes

Add an authenticated command or equivalent workflow to correct the changelog of an already published skill or package version.

## Best Possible Solution

Define an audited correction invariant in specs, then implement equivalent owner-authorized backend operations for skill and package versions and expose them through one clear CLI workflow, retaining the prior text, actor, timestamp, and correction reason.
