## Summary

Current main still accepts changelog text only during publishing and provides no supported operation for correcting an already-published release. Keep this issue open because the requested capability requires a maintainer-owned decision about authorization, provenance, and audit history; the related report addresses publish-time generation and draft overwrites instead.

## What This Changes

Add an owner-facing command or equivalent product surface for correcting the changelog of a specific published version.

## Best Possible Solution

Adopt an append-only correction model that preserves original text and records revised text, actor, reason, and timestamp, then implement it consistently for approved release types across storage, API, CLI, web UI, tests, docs, and the durable product spec.

- **Audited owner corrections (recommended):** Let the owning user or authorized publisher role add a visible correction while preserving the original text, actor, reason, timestamp, and revision history.
- **Staff-only corrections:** Keep release metadata immutable for owners and allow guarded moderator or administrator corrections only for exceptional mistakes.
- **Immutable release records:** Require a replacement release or visible addendum rather than changing an existing version record.
