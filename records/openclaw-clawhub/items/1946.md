## Summary

Keep open: current main still accepts changelogs only during publish/sync/package publish and displays stored changelogs read-only; it does not provide a post-publish command, API, or UI to edit an existing version changelog. The related changelog issue and open PR are about publish-time preview generation, not this edit workflow.

## What This Changes

Request adding a command such as `clawhub changelog edit <version>` to edit an existing version changelog after publish.

## Best Possible Solution

Add a deliberately authorized and audited edit path for skill and package version changelogs, updating denormalized latest-version summaries consistently, or explicitly document that published changelogs are immutable and require a new release.

## Reproduction Assessment

Not applicable: this is a feature request for a new changelog editing workflow, not a bug in documented behavior. Source inspection shows current support is publish-time changelog submission plus read-only version history display.

## Solution Assessment

Unclear until maintainers choose the product policy. A CLI/API mutation is plausible, but the best solution must first define authorization, audit logging, edit history, skill/package scope, and latest-summary synchronization.
