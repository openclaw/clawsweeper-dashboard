The prior review also found that current main accepts changelog text at publishing time but did not establish a post-publication correction operation.

## What This Changes

Add a `clawhub changelog edit <version>`-style workflow for correcting changelog text after a version has been published.

## Best Possible Solution

Define a narrow, auditable correction model for published changelogs—authorized editor scope, immutable original/version provenance or revision history, visible corrected-at metadata, and CLI/API/UI behavior—then implement it with focused authorization and regression coverage.
