## Summary

Keep open: current main still accepts changelogs only at publish/sync time and renders stored version changelogs read-only; a post-publish edit command, API, or UI would be new security-sensitive product surface.

## What This Changes

Request a command such as `clawhub changelog edit <version>` to edit an existing version changelog after publication.

## Best Possible Solution

Add an explicitly owner/publisher/admin-gated and audited edit workflow for skill and package version changelogs, with latest-summary synchronization and documented immutability/edit-history rules.

## Reproduction Assessment

Not applicable: this is a feature request for a new changelog editing workflow, not a bug in documented behavior. Source inspection shows current support is publish-time changelog submission plus read-only version history display.

## Solution Assessment

Unclear until maintainers choose the product policy. A CLI/API/UI edit path is plausible, but the best solution must define authorization, audit logging, edit visibility/history, skill/package scope, and latest-summary synchronization first.
