## Summary

Keep open. The report is concrete and plausibly valid, but current ClawHub main is a registry/package catalog and still does not contain the Anthropic/OpenClaw runtime transcript serializer needed to verify or fix this provider protocol bug here.

## What This Changes

The issue reports that Anthropic rejects multi-tool turns when one assistant message has multiple tool calls but OpenClaw persists each corresponding tool result as a separate following message.

## Best Possible Solution

Route this to the OpenClaw runtime/provider tracker and fix transcript conversion there so all tool results for one assistant tool-use turn are grouped in the immediately following provider message, with regression coverage from the reported JSONL shape.

## Reproduction Assessment

No. The issue includes a concrete JSONL/error and plausible minimal repro, but current ClawHub main has no Anthropic/OpenClaw runtime provider serializer to run the failing turn against.

## Solution Assessment

Unclear. Grouping tool results in runtime transcript conversion is the likely maintainable fix; enforcing max_tool_calls=1 would be a compatibility workaround, and a ClawHub catalog change is the wrong layer.
