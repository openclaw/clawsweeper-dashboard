## Summary

Keep open: current main still does not provide an unqualified/default-skill install target for the reported names. Live ClawHub still returns ambiguity for `coding-agent` and `summarize` detail lookups, `404 Skill not found` for their unqualified `/install` routes and for `wacli`, while current source only supports single visible or owner-qualified skill resolution.

## What This Changes

The issue requests help making OpenClaw default skill names such as `coding-agent`, `summarize`, `himayala`/`himalaya`, and `wacli` installable through ClawHub instead of returning not-found or ambiguity errors.

## Best Possible Solution

Define the default-skill registry contract, then publish or alias canonical official skill targets in ClawHub or update OpenClaw/docs to use owner-qualified or local bundled resolution while preserving ambiguity for community duplicate slugs.

## Reproduction Assessment

Yes for the observable API symptoms: live ClawHub still returns ambiguity or 404 for the central reported slugs, and current main has the corresponding source paths. I did not run the full Windows OpenClaw `node openclaw.mjs skills install ...` flow with production-like registry data.

## Solution Assessment

Unclear. A source-only route change is not proven to be the best fix until maintainers choose whether default skill names should resolve through official rows, aliases, owner-qualified refs, or local bundled skills.
