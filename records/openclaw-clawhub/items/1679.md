## Summary

Keep open: current main still routes the reported short-name installs through ambiguity or not-found paths, and live ClawHub still returns `409` for `coding-agent`/`summarize` and `404` for `himayala`/`wacli`. This is a product/API contract question about official default-skill names, not a cleanup-safe implemented item.

## What This Changes

The issue reports that installing expected default skills by short slug returns `Skill not found` or otherwise fails for names such as `coding-agent`, `summarize`, `himayala`, and `wacli`.

## Best Possible Solution

Define the official default-skill install contract, then either publish or alias canonical ClawHub targets for these names or update OpenClaw CLI/docs to require owner-qualified default-skill refs.

## Reproduction Assessment

Yes for the observable API behavior: live ClawHub returns 409 or 404 for the reported short names, and current source has the same ambiguity/not-found branches. I did not run a full local OpenClaw setup against production-like registry data.

## Solution Assessment

Unclear: the code paths are known, but the best fix depends on deciding whether default skill names should resolve through official rows, aliases, owner-qualified refs, or bundled local skill resolution.
