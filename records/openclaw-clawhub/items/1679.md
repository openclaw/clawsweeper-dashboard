## Summary

Keep open: current main and live ClawHub still do not provide a settled default-skill alias/catalog contract for short names like `coding-agent`, `summarize`, `himayala`, or `wacli`, so this is not safe cleanup as implemented.

## What This Changes

The issue reports that installing default OpenClaw skills by short slug through the ClawHub skill API returns `404 Skill not found`.

## Best Possible Solution

Define the official default-skill install contract, then publish or alias canonical official skill targets in ClawHub or update the CLI/docs to require owner-qualified default skill refs.

## Reproduction Assessment

Yes from source and live API behavior: current main has the same not-found and ambiguity paths, and production still returns ambiguity or 404 for the reported short names. I did not run a full local OpenClaw setup flow with production-like registry data.

## Solution Assessment

Unclear: the narrow code paths are known, but the best fix depends on choosing whether default skill names resolve through official rows, aliases, owner-qualified refs, or bundled local skills. A source-only route change before that decision could make the slug model less predictable.
