## Summary

Current main still relies on the dedicated repair workflow when npm publishing succeeds but GitHub Release creation fails. The PR head has not changed since five prior review cycles, so the blocking recovery-path concern remains unresolved; its collaborator authorship also requires explicit maintainer handling rather than cleanup closure.

## What This Changes

The PR removes the standalone CLI GitHub Release repair workflow and deletes the corresponding recovery instructions from the deploy runbook.

## Best Possible Solution

Keep the standalone repair workflow or add an explicit, tested repair-only mode that validates the existing npm artifact and creates or updates the GitHub Release without republishing.
