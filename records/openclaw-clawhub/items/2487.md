## Summary

Current main still relies on the dedicated repair workflow, and the unchanged PR head removes the only documented no-republish recovery path after npm succeeds but GitHub Release creation fails; the prior P1 finding remains valid and requires release-owner judgment.

## What This Changes

The PR deletes the standalone ClawHub CLI GitHub Release repair workflow and removes its recovery instructions from the deploy runbook.

## Best Possible Solution

Keep the standalone repair workflow or replace it with a tested repair-only mode that can create or update the GitHub Release from an already-published npm version without republishing.
