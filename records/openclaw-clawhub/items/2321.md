## Summary

Keep this open: it is a collaborator-authored moderation/security RFC and current main only partially covers the requested policy frame. The public docs and internal spec now address broad acceptable usage, moderation states, VirusTotal telemetry, ClawScan, SkillSpector delegation, and scanner/context separation, but the category-to-consequence matrix and crypto/blockchain edge cases raised in discussion still need maintainer policy synthesis.

## What This Changes

This issue requests a clearer ClawHub content-policy taxonomy for public registry inclusion, hiding/removal, upload review, and account enforcement decisions.

## Best Possible Solution

Maintainers should publish a category-to-consequence matrix in public docs and keep scanner/enforcement invariants, private detection tactics, and reviewer-only rationale in specs/security-moderation.md.
