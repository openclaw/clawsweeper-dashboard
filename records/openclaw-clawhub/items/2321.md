## Summary

Keep this open: current main already documents behavior-based rules for spam, malicious packages, visibility, install blocking, and account enforcement, but it does not resolve the RFC’s proposed category-wide financial-content boundary. Because this is a collaborator-authored security RFC with active product and security review signals, maintainers must decide whether any crypto, trading, payment, custody, identity, registry, or reputation classes should be categorically restricted. Likely related people: Patrick-Erichsen (high confidence), superlowburn (medium confidence), and ArthurzKV (medium confidence).

## What This Changes

Define content-policy categories and their effects on discovery, registry inclusion, upload review, installability, and account enforcement.

## Best Possible Solution

Document a durable behavior-and-risk policy matrix in `specs/security-moderation.md` and `docs/acceptable-usage.md`, adding narrow categorical restrictions only where maintainers intentionally require them and including examples that distinguish trading or custody from read-only, educational, identity, registry, and reputation uses.

Question: Should ClawHub retain behavior-based financial-content rules, or categorically exclude specified crypto, trading, wallet, payment, identity, registry, or reputation subcategories from the public registry?

Rationale: Current main prohibits fraud, unsafe execution, deceptive publishing, and abusive behavior while evaluating legitimate powerful capabilities contextually; the RFC’s draft category-wide exclusion would materially change that product and security boundary.

Likely owner: Patrick-Erichsen

Owner confidence: high

Options:

- **Keep behavior-based rules (recommended):** Allow legitimate financial and on-chain tools when transparent, purpose-aligned, and safety-bounded while blocking fraud, unsafe execution, and marketplace abuse.
- **Ban narrow high-risk classes:** Categorically exclude clearly defined transaction, custody, or autonomous-spending workflows while preserving read-only, educational, identity, registry, and reputation uses.
- **Ban the full category:** Exclude crypto, blockchain, finance, and trading content from the public registry regardless of implementation details.
