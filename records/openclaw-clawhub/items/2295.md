## Summary

Keep open: current ClawHub installation remains a skill-file download flow, while OpenClaw documents hook packs as plugin installs. Bridging those flows would automatically activate executable gateway behavior, so the remaining work is a security and product-contract decision rather than a safe missing call to add.

## What This Changes

Request that `clawhub install` recognize bundled OpenClaw hook content and register it with the gateway automatically.

## Best Possible Solution

Define a versioned, auditable hook-pack contract with scanning and explicit user consent, then provide a guided ClawHub-to-OpenClaw handoff or dedicated install flow that verifies registration and explains restart/enablement state.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should installing a ClawHub skill ever activate bundled OpenClaw hooks automatically, and if so what manifest validation, scan result, consent, lifecycle, and uninstall contract is required?

Rationale: The current products deliberately separate passive skill extraction from hook-pack installation; choosing to collapse that boundary changes when third-party executable code becomes enabled and cannot be resolved safely from source behavior alone.

Likely owner: steipete

Owner reason: The decision spans the OpenClaw plugin installer and ClawHub's skill-install contract.

Owner confidence: low

Options:

- **Keep hook activation explicit (recommended):** Keep skills inert on `clawhub install` and add a clear detected-hook handoff that requires the user to invoke the supported plugin installation flow after inspection.
- **Design an approved activation contract:** Specify a signed or validated hook-pack manifest, scan/permission display, explicit consent, rollback, update, and uninstall behavior before enabling automatic registration.
- **Continue manual-only behavior:** Retain the present separation and document that hook-capable packages must be installed through OpenClaw's plugin surface.

## Reproduction Assessment

No live current-main run was established, but source and current CLI documentation provide a clear path: skill install extracts files and records metadata, while hook packs use the separate OpenClaw plugin installer.

## Solution Assessment

No: silently invoking plugin installation for arbitrary skill content is not the narrowest safe solution. An explicit, validated and consented hook-pack activation contract is safer than automatic registration.
