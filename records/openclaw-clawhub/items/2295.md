## Summary

Keep open. Current main and v0.23.1 still install or update skill files and local metadata without discovering `hooks/openclaw`, registering an OpenClaw hook bundle, or defining the needed consent, scanner disclosure, and gateway handoff contract.

## What This Changes

The issue requests that `clawhub install` detect skill-provided OpenClaw hooks and register them with the OpenClaw gateway automatically.

## Best Possible Solution

Define a consent-aware hook registration contract first, then implement discovery, scanner disclosure, explicit approval, gateway registration, docs, and tests across the ClawHub/OpenClaw boundary.

Question: Should ClawHub automatically register skill-provided OpenClaw hook bundles during install/update, and what consent, scanner disclosure, and gateway handoff contract must guard that behavior?

Rationale: The useful behavior is clear, but accepting it safely changes a security-sensitive runtime boundary for publisher-controlled hook code and requires maintainer intent before implementation.

Likely owner: Patrick-Erichsen

Owner confidence: high

Options:

- **Consent-gated hook contract (recommended):** Define hook metadata, scanner disclosure, explicit user approval, gateway targeting, restart behavior, and tests before enabling install/update registration.
- **Manual registration only:** Keep `clawhub install` as file installation and document manual `openclaw plugins install` registration until OpenClaw exposes a safer handoff surface.
- **Unconditional auto-register:** Register hooks immediately after install/update, accepting the security and trust-boundary risk of activating publisher-controlled behavior without a new consent model.

## Solution Assessment

No, not as unconditional automatic registration. The maintainable path is an explicit consent and trust-boundary design covering scanner results, event/type restrictions, gateway targeting, restart behavior, and user-visible disclosure.
