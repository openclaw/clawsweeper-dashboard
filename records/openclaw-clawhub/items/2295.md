## Summary

Current main and v0.23.1 still do not register bundled OpenClaw hooks during skill installation, and automatic activation crosses an unresolved executable-code consent boundary. Keep this issue open as the canonical request until maintainers define the declaration, scanning, disclosure, and registration contract.

## What This Changes

Add a supported installation flow that discovers and registers OpenClaw hook bundles shipped inside installed skills.

## Best Possible Solution

Define a declared hook capability with scan results and install-time permission disclosure, then use an explicit, auditable native OpenClaw registration handoff instead of silently activating nested executable code.

Question: Should skill installation support OpenClaw hook registration, and what declaration, scanner disclosure, event restrictions, and user consent must gate activation?

Rationale: The current product separates text-bundle skill installation from executable plugin installation, so hook activation expands a security boundary that repository vision requires to remain explicit and operator-controlled.

Likely owner: Patrick-Erichsen

Owner confidence: high

Options:

- **Explicit consent handoff (recommended):** Detect a declared hook capability, display its scan and permission details, and require confirmation before native OpenClaw registration.
- **Keep installs separate:** Preserve explicit plugin installation and add a clear post-install warning with the exact registration command for hook-bearing skills.
- **Trusted-tier automation:** Permit automatic registration only for a narrowly defined vetted or official package tier with documented restrictions.

## Reproduction Assessment

Yes, at source level. Current install and update code only extracts files and records metadata, while hook or plugin registration is absent and remains a separate documented OpenClaw operation.

## Solution Assessment

No, unconditional automatic registration is not the best solution because it hides an executable-code security decision. A declared capability with scanner disclosure and explicit consent is the narrowest safe direction.
