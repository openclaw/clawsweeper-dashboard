## Summary

Keep open. Current main and v0.23.1 still install or update skill files and metadata without discovering `hooks/openclaw`, registering an OpenClaw hook bundle, or defining hook-specific consent/security disclosure, so this is not conservative cleanup.

## What This Changes

The issue requests that `clawhub install` detect skill-bundled OpenClaw hook files and register them with the OpenClaw gateway after installation.

## Best Possible Solution

Define a maintainer-approved, consent-aware hook registration contract, then implement detection, scanner/disclosure checks, OpenClaw gateway handoff, docs/spec intent, and focused install/update tests together.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` write skill files and metadata without hook discovery, gateway registration, or hook-specific consent handling; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as unconditional automatic registration. The safer path is a maintainer-approved consent, scanner/disclosure, and gateway-handoff contract rather than blindly running `openclaw plugins install` after each skill install.
