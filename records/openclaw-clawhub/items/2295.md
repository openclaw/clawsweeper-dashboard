## Summary

Keep open. Current main and v0.23.1 still install or update skill files and local metadata without discovering `hooks/openclaw`, registering an OpenClaw hook bundle, or defining hook-specific consent and scanner disclosure.

## What This Changes

The issue asks for `clawhub install` to detect OpenClaw hook files inside an installed skill and register them with the OpenClaw gateway automatically.

## Best Possible Solution

Define a consent-aware hook registration contract first, then implement discovery, scanner disclosure, explicit approval, gateway registration, docs, and tests across the ClawHub/OpenClaw boundary.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` install files and metadata without hook discovery, gateway registration, or hook-specific warning/consent; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as unconditional automatic registration. The maintainable path is an explicit consent and trust-boundary design that covers scanner results, event/type restrictions, gateway targeting, restart behavior, and user-visible disclosure.
