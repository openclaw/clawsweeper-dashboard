## Summary

Keep open. Current main and v0.23.1 still install or update skill files and metadata without discovering `hooks/openclaw` or registering a hook bundle, and safe implementation needs a maintainer-approved consent, scanner disclosure, and gateway handoff contract.

## What This Changes

The issue asks `clawhub install` and `clawhub update` to discover skill-bundled OpenClaw hooks and register them with the gateway automatically.

## Best Possible Solution

Define a consent-aware hook registration contract first, then implement discovery, scanner disclosure, explicit approval, gateway registration, docs, and tests across the ClawHub/OpenClaw boundary.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should ClawHub automatically register skill-provided OpenClaw hooks during install/update, and what consent, scanner disclosure, and gateway targeting contract must be required before that happens?

Rationale: The source gap is clear, but unconditional registration would cross a security boundary by activating publisher-controlled hook behavior during install without an established policy or runtime handoff contract.

Likely owner: Patrick-Erichsen

Owner reason: Patrick-Erichsen is the strongest history match for the current CLI, metadata, and docs boundary that needs the maintainer decision.

Owner confidence: high

Options:

- **Design consent-gated registration first (recommended):** Define hook metadata, scanner disclosure, allowed event/type policy, explicit user approval, gateway target/restart behavior, and then implement install/update registration against that contract.
- **Keep manual registration for now:** Document the manual `openclaw plugins install` path and keep `clawhub install` limited to copying skills until OpenClaw owns a native ClawHub hook install API.
- **Approve unconditional auto-registration:** Install/update would register discovered hooks automatically, but this accepts the risk of activating publisher-controlled behavior without a new consent and disclosure boundary.

## Reproduction Assessment

Yes, at source level. Current `cmdInstall` and `cmdUpdate` install or update files and metadata without hook discovery, gateway registration, or hook-specific warning/consent; I did not run a live OpenClaw gateway reproduction.

## Solution Assessment

No, not as unconditional automatic registration. The maintainable path is an explicit consent and trust-boundary design covering scanner results, event/type restrictions, gateway targeting, restart behavior, and user-visible disclosure.
