## Summary

Keep open. Current main and v0.23.1 still provide relevance-ranked skill search, exact detail lookup, and bounded registry browsing, but not a deterministic slug-prefix or list-style registry enumeration path from the CLI/API.

## What This Changes

Request a registry-oriented ClawHub CLI/API discovery path for exact slug and slug-prefix or list-style skill enumeration instead of relying on ranked search.

## Best Possible Solution

Add a documented, indexed, cursor-pageable registry discovery API and expose it through explicit CLI flags or a dedicated hub-list mode while preserving ranked search semantics.

## Reproduction Assessment

Yes. Source inspection on current main shows `search` is ranked and limited, `list` is local installed-skill output, `explore` is bounded browsing, and the public API lacks exact or prefix enumeration parameters.

## Solution Assessment

Unclear until maintainers choose the stable public contract. The maintainable direction is an indexed, cursor-pageable exact/prefix registry API exposed through explicit CLI surface, not silently stretching relevance-ranked search into total listing.
