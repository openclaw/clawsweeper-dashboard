## Summary

Keep open. Current main and release v0.23.1 still lack a deterministic registry-enumeration path, and the linked implementation PR remains open; current search intent also distinguishes relevance retrieval from browse/list behavior, so the permanent API shape needs maintainer approval.

## What This Changes

Add reliable exact or prefix-based registry skill enumeration to the ClawHub CLI and public API.

## Best Possible Solution

Provide a paginated registry-list or catalog-filter surface with exact-slug and prefix filters, explicit completeness semantics, stable ordering, and CLI JSON output; reuse the existing search indexes where appropriate without redefining relevance search as a complete listing API.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should deterministic skill enumeration be added as bounded modes on `/api/v1/search`, or as a paginated prefix/exact filter on the registry list/catalog surface?

Rationale: The current durable contract says search is relevance retrieval rather than browse fallback, while the issue requires reliable enumeration and counting that a capped search response may not guarantee.

Likely owner: Peter Steinberger

Owner reason: The latest current-main search contract commit establishes the product boundary that this decision would modify.

Owner confidence: high

Options:

- **Add paginated catalog filters (recommended):** Keep ranked search intact and add exact/prefix filters to a stable, cursor-based registry listing API and CLI command.
- **Adopt bounded search modes:** Approve the linked PR's exact and prefix search modes, documenting the cap and that prefix results are not necessarily a complete registry count.
- **Retain relevance search only:** Decline enumeration guarantees and document that users must browse or resolve known slugs individually.

## Reproduction Assessment

Yes, at source level. Current main accepts a query and limit, recalls literal prefix candidates, and relevance-ranks the combined pool without providing complete prefix enumeration or pagination.

## Solution Assessment

No, the bounded search-mode proposal is not yet clearly the best solution. A paginated list/catalog filter better matches the requested completeness guarantee and preserves the repository's explicit separation between search and browse.
