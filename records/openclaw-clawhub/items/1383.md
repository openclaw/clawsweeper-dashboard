## Summary

Keep open. Current main still lacks deterministic CLI/API exact-slug or slug-prefix enumeration: `search` remains relevance-oriented, `list` is local installed skills, and `explore` is bounded sorted registry browsing. Existing exact/prefix recall helps ranked lookup but does not provide complete registry enumeration, so the request remains a valid feature/product API decision.

## What This Changes

The issue requests deterministic ClawHub CLI registry discovery by exact slug, slug prefix, list mode, pagination, or filters instead of relying only on ranked search.

## Best Possible Solution

Choose and document an indexed, cursor-pageable registry discovery contract, then implement matching CLI flags or a dedicated list mode with API/runtime tests while preserving ranked search semantics.

## Reproduction Assessment

Yes for source-level current behavior. Current main shows ranked search, installed-skill listing, and bounded registry explore, but no exact or prefix enumeration input in the CLI or public v1 API.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable direction is an explicit indexed exact/prefix registry path, not implicit total listing through relevance-ranked search.
