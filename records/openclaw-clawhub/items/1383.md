## Summary

Keep open. Current main still has relevance-ranked skill search, local installed-skill listing, and bounded registry browsing, but no deterministic exact-slug or slug-prefix enumeration surface for ClawHub CLI users.

## What This Changes

Add a registry-oriented CLI/API discovery path for exact slug and slug-prefix skill enumeration instead of relying on relevance-ranked search.

## Best Possible Solution

Expose a documented, indexed, cursor-pageable registry discovery path for exact slug lookup and slug-prefix enumeration while preserving relevance-ranked search semantics.

Options:

- **Add explicit exact/prefix discovery (recommended):** Add indexed, cursor-pageable exact and prefix filters to the public registry API and expose them through clear CLI flags or a dedicated hub-list mode.
- **Keep search relevance-only:** Document that ranked search is not an enumeration API and leave this issue open only if a separate registry-browse product task is desired.

## Reproduction Assessment

Yes. Source inspection on current main shows CLI search only sends `q` and `limit` to `/api/v1/search`, while list/explore are local or bounded browsing paths with no exact or prefix enumeration parameter.

## Solution Assessment

Unclear until maintainers choose the public contract. The maintainable direction is an indexed, cursor-pageable exact/prefix registry API exposed through explicit CLI behavior, not implicit total listing through ranked search.
