## Summary

Keep this issue open: a fresh July 10, 2026 production reproduction shows that the OAuth trust presentation remains wrong, while current main only reads externally managed GitHub client credentials and cannot establish that the production OAuth application has official OpenClaw custody or branding.

## What This Changes

Replace the personally owned and branded GitHub OAuth application used by ClawHub sign-in with an officially owned OpenClaw/ClawHub application.

## Best Possible Solution

Transfer the existing OAuth application to the official OpenClaw organization when feasible, otherwise create an official replacement, rotate the production AUTH_GITHUB_ID and AUTH_GITHUB_SECRET, verify web and CLI consent in a private browser, and record the ownership, callback, and verification invariant in the deployment specification.
