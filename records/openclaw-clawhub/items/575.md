## Summary

Current main still accepts lowercase and legacy skill metadata aliases and does not consistently reject case-insensitive path collisions before import or storage. The proof-backed pull request that directly addresses this issue remains open and conflicted, so this issue is still necessary and should stay paired with that implementation while maintainers confirm the filename compatibility policy.

## What This Changes

Reject packages containing case-insensitive filename collisions such as `SKILL.md`/`skill.md` and `PROTOCOL.md`/`protocol.md`, with an explicit policy for supported aliases.

## Best Possible Solution

Preserve explicitly supported aliases when only one variant exists, reject every package whose normalized paths collide under case-insensitive comparison before discovery or storage, and document the deterministic remediation rule across CLI, web, API, server, and GitHub import flows.
