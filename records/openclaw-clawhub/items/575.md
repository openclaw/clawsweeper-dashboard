## Summary

Keep this open: current main and v0.23.1 still document and implement lowercase/legacy skill metadata filename compatibility, duplicate-case enforcement is missing from local, web, and server publish paths, and `PROTOCOL.md` is not a defined ClawHub skill package contract.

## What This Changes

The issue requests enforcement that skill packages do not contain conflicting uppercase and lowercase metadata filenames such as `SKILL.md`/`skill.md` and `PROTOCOL.md`/`protocol.md`.

## Best Possible Solution

Maintainers should define the casing policy, likely preserve lowercase compatibility while rejecting case-colliding duplicates, decide whether `PROTOCOL.md` belongs in the package contract, then update specs, docs, validation, tests, and content-cleanup guidance consistently.

## Reproduction Assessment

Yes, at source level. Current docs and publish/import code still accept lowercase or legacy skill readme aliases, and inspected paths do not reject case-colliding duplicates; I did not run a Windows checkout of the separate `openclaw/skills` content repository.
