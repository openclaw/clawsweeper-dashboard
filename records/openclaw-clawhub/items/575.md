## Summary

Keep this open: current main still accepts lowercase and legacy skill metadata filenames, does not reject case-colliding file paths, and has no established ClawHub `PROTOCOL.md` skill-package contract to enforce yet.

## What This Changes

The issue asks ClawHub to enforce canonical uppercase `SKILL.md` and `PROTOCOL.md` naming and reject packages containing case-colliding uppercase/lowercase variants.

## Best Possible Solution

Define the skill package filename contract in specs/docs, preserve any intentional lowercase legacy support, and add normalized path-collision rejection across web publish, CLI publish/sync, GitHub import, and tests before cleaning affected catalog sources.

## Reproduction Assessment

Yes, at source level: current main accepts `skill.md`/`skills.md` and lacks a normalized duplicate-path check in the publish/import/sync surfaces inspected. I did not run a Windows checkout reproduction, but the reported failure mode is consistent with those source paths.

## Solution Assessment

Unclear: strict uppercase-only enforcement is not obviously the best first step because current docs promise lowercase compatibility. A safer solution is a maintained policy decision plus collision rejection and documented migration behavior.
