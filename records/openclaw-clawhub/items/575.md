## Summary

## What This Changes

Request to enforce canonical casing or duplicate-case rejection for `SKILL.md` and `PROTOCOL.md` package files so skill repositories do not break on case-insensitive filesystems.

## Best Possible Solution

Maintainers should choose the casing policy, define whether `PROTOCOL.md` belongs in the skill package contract, then update specs, docs, validation, tests, and any external content cleanup consistently.

## Reproduction Assessment

Yes, at source level. Current main docs and validation paths accept `skill.md`/`skills.md` aliases, and the inspected publish/import/CLI surfaces do not reject case-colliding duplicate filenames.

## Solution Assessment

Unclear until maintainers choose the format policy. The reporter's later duplicate-only enforcement would preserve compatibility better than uppercase-only enforcement, but `PROTOCOL.md` still needs a ClawHub scope decision.
