## Summary

Keep this open: current main still has adjacent env/dependency metadata and ClawScan coherence checks, but it does not implement the requested declared capability manifest for network, filesystem, external-code execution, and secret-reading boundaries. This remains a security/product RFC that needs maintainer direction before implementation.

## What This Changes

The issue proposes a machine-readable SKILL.md capability manifest for trust-boundary behavior such as network use, filesystem access, secret reads, and external code execution.

## Best Possible Solution

Define a spec-backed advisory capability schema under skill metadata, parse/store/expose it, update docs and ClawScan review output to compare declared versus observed behavior, and coordinate rollout with the adjacent security RFCs.

- **Require manifests immediately:** Make new submissions provide the capability block from day one, which gives a stronger contract but requires a sharper legacy and false-positive policy before rollout.
