## Summary

Keep this open: current main has adjacent skill runtime metadata and ClawScan coherence checks, but it still lacks the requested machine-readable capability manifest for network, filesystem, external-code execution, and secret-reading boundaries.

## What This Changes

The RFC asks ClawHub to add a standard SKILL.md frontmatter capability manifest for skill trust-boundary behavior and declared-versus-observed review.

## Best Possible Solution

Define a spec-backed advisory capability schema under skill metadata, parse/store/expose it, update docs and ClawScan review output to compare declared versus observed behavior, and coordinate rollout with the adjacent security RFCs.

- **Advisory manifest first (recommended):** Define the capability schema in specs, parse and expose it as advisory metadata, and let ClawScan flag declared-versus-observed mismatches before making it required.

- **Require manifests immediately:** Make new submissions provide the capability block from day one, which gives a stronger contract but requires a sharper legacy and false-positive policy before rollout.
