## Summary

Keep this open: current main has runtime metadata, env/dependency declarations, and ClawScan coherence checks, but it still does not implement the requested declared capability manifest for network, filesystem, external-code execution, and secret-reading boundaries. This remains a security/trust RFC that needs maintainer product and security direction.

## What This Changes

The issue requests a standard machine-readable SKILL.md capability manifest for trust-boundary behavior such as network access, filesystem access, external code execution, and secret reads.

## Best Possible Solution

Keep the RFC open for maintainer security/product design, then add a spec-backed capability schema, parser/storage/API surface, docs, and advisory review output coordinated with the existing ClawScan pipeline.

## Reproduction Assessment

Not applicable: this is an RFC for a new security/trust capability, not a broken existing behavior report. Source inspection gives high confidence that current main only partially covers the area through env/runtime metadata and scan prompts.

## Solution Assessment

Unclear until maintainers decide the manifest schema, authority model, and rollout policy. The proposed direction fits the trust problem, but the maintainable solution should be spec-backed and coordinated with adjacent review-pipeline RFCs.
