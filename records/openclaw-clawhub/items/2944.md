## Summary

Current main and v0.23.1 provide adjacent environment/install declarations and scanner coherence checks, but they do not define the requested network, filesystem, external-code, and secret-access capability contract. Keep this security RFC open for an explicit schema and compatibility decision; the earlier implementation direction was welcomed but closed with concrete mixed-manifest and v1 API regressions.

## What This Changes

Add a standard skill capability block for network, filesystem, external-code execution, and secret access so review tooling can compare declared intent with observed behavior.

## Best Possible Solution

Sponsor a versioned trust-boundary contract that preserves existing API fields, defines deterministic legacy/current manifest precedence, stores author-declared and scanner-observed capabilities separately, and begins with advisory mismatch reporting documented in a durable security spec.
