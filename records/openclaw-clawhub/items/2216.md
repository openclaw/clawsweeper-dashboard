## Summary

Keep open: current main has partial seven-day skill/plugin Trending infrastructure and package daily stats, but the shared Weekly/Monthly/All time popularity contract across publishers, skills, and plugins is still missing and needs product/data-contract decisions.

## What This Changes

The issue requests period-based popularity tabs and backing temporal popularity data for publisher, skill, and plugin browse surfaces.

## Best Possible Solution

Keep this as the canonical RFC, settle the period/scoring/attribution policy, then implement publisher rollups and snapshot-pinned weekly/monthly leaderboards before wiring the three browse UIs.

## Reproduction Assessment

Not applicable: this is an RFC for a new discovery capability, not a broken existing behavior report. Source inspection on current main confirms the shared period tabs and complete backing contract are still absent.

## Solution Assessment

Yes for now: the foundation-first RFC path is safer than UI-only tabs because current publisher data lacks temporal skill-plus-plugin aggregation. Maintainers still need to decide scoring, period semantics, ownership attribution, and backfill/retention policy.
