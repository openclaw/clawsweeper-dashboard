## Summary

Keep open: current main has partial seven-day trending for skills and plugins, plus package daily stats, but the requested Weekly/Monthly/All time period contract, publisher temporal rollups, publisher leaderboards, and snapshot-pinned cross-surface pagination are still missing.

## What This Changes

RFC requests period-based popularity tabs for publishers, skills, and plugins backed by a shared temporal popularity foundation.

## Best Possible Solution

Keep this as the canonical RFC, settle the remaining product semantics, then build on the existing package daily stats to add publisher rollups, period leaderboards, snapshot-pinned pagination, and the browse tabs together.

## Reproduction Assessment

Not applicable: this is an RFC for a new discovery capability, not a broken existing behavior report. Source inspection confirms current main still lacks the requested period tabs and shared temporal browse contract.

## Solution Assessment

Yes: keeping the visible tabs behind a shared temporal data contract remains the best path. Current one-off seven-day trending for skills/plugins is useful partial progress but too narrow for the RFC’s publisher/monthly/snapshot requirements.
