## Summary

Keep open: current main has seven-day skill/plugin trending and package daily stats, but the shared Weekly/Monthly/All time popularity contract, publisher period rollups, monthly leaderboards, snapshot-pinned period pagination, and browse-page period tabs are still missing.

## What This Changes

Add period-based popularity tabs and backing temporal ranking for publishers, skills, and plugins.

## Best Possible Solution

Keep this as the canonical RFC, settle the period/scoring/attribution policy, then implement publisher rollups and snapshot-pinned weekly/monthly leaderboards before wiring the three browse UIs.

## Reproduction Assessment

Not applicable: this is an RFC for a new discovery capability, not a broken existing behavior report. Source inspection on current main confirms the shared period tabs and backend contract are still absent.

## Solution Assessment

Yes for now: the foundation-first RFC path is safer than UI-only tabs because current publisher data lacks temporal skill-plus-plugin aggregation. Maintainers still need to decide scoring, period semantics, ownership attribution, and backfill/retention policy.
