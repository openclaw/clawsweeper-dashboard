## Summary

Keep open: current main has partial seven-day skill/plugin trending and package daily stats, but the RFC's shared Weekly/Monthly/All time popularity contract is still missing for publishers, skills, and plugins.

## What This Changes

The issue requests Weekly, Monthly, and All time popularity tabs plus a backing temporal leaderboard contract across publishers, skills, and plugins.

## Best Possible Solution

Keep this as the canonical RFC, settle period/scoring/attribution policy, then implement publisher daily rollups and snapshot-pinned weekly/monthly browse leaderboards before wiring the three UIs.

## Reproduction Assessment

Not applicable; this is an RFC for a new discovery capability, not a broken existing behavior report. Source inspection on current main shows the shared period tabs and publisher temporal contract are still absent.

## Solution Assessment

Yes for the current stage: the foundation-first RFC path is safer than adding UI-only tabs because current publisher data lacks temporal skill-plus-plugin aggregation. Maintainers still need to decide scoring, period semantics, ownership attribution, and backfill/retention policy.
