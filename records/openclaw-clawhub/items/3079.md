## Summary

Current `main` still uses the bounded temporal cohort and P95-capable classification, so this correction remains necessary. The implementation is coherent and well tested, but it is a draft member-authored PR that replaces a security-moderation cron with a new persisted Convex state machine and explicitly lacks real Convex runtime and upgrade-path validation; no conservative close reason applies.

## What This Changes

The PR benchmarks temporal abuse signals against all active skills, changes flat-install review thresholds to platform P99 plus absolute minimums, adds a resumable persisted Convex scan with seven-day cleanup, and labels platform versus legacy benchmarks in the staff UI.

## Best Possible Solution

Keep the all-active-skill, exact-percentile design, but land it only after a configured non-production run proves page continuation, percentile completion, candidate classification, atomic archival, failure and expiry guards, pruning, and both platform and legacy staff-drawer presentation across fresh and upgrade scenarios.

Likely yes: persisted bounded pages and exact indexed nearest-rank percentiles address the population and execution-limit problem without making partial scans look platform-wide. Real Convex rollout proof is still needed before treating the implementation as merge-ready.
