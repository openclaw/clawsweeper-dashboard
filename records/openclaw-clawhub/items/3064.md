## Summary

Current main includes the staged profile, membership, deletion-inventory, and catalog improvements, but the explicit completion boundary remains unmet: the GitHub-backed display-manifest path can still read the publisher’s complete active catalog. The MEMBER author confirmed after merge that this tracker should remain open until that contract is bounded, redesigned, or moved to an agreed focused follow-up.

## What This Changes

Bound publisher profile, membership, catalog, and GitHub display-manifest reads so requests avoid scanning or serializing complete publisher resource collections unnecessarily.

## Best Possible Solution

Give `getPublishedDisplayManifest` a fixed read budget and gracefully fall back to the normal indexed paginated catalog when the custom display payload exceeds it, with tests preserving visibility, official, source-backed, legacy, and soft-delete behavior.
