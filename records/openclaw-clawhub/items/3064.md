## Summary

Keep open: current main still has the reported collect-heavy publisher profile, membership, and catalog query shapes, and no merged follow-up implements the bounded-read outcome. The issue is also member-authored, so repository policy requires explicit maintainer handling rather than automated cleanup.

## What This Changes

Bound publisher profile, membership, deletion-inventory, and catalog reads so summary and paginated callers avoid collecting complete resource catalogs.

## Best Possible Solution

Introduce lightweight profile and membership summaries backed by complete denormalized counters with the legacy fallback, fetch deletion inventory only for the open destructive dialog, paginate kind-specific catalogs through the publisher index, and either bound the display manifest separately or track it as an explicit follow-up.
