## Summary

Keep open. Current main and the latest release still implement a platform-wide MIT-0/no-attribution skill-license contract, while the live reported skill API returns MIT-0 and npm reports the upstream package as MIT; the remaining decision is policy/legal, not an already-implemented fix.

## What This Changes

The issue requests that the `openclaw-workspace-sync` listing display standard MIT licensing instead of the current MIT-0/no-attribution ClawHub skill license.

## Best Possible Solution

Maintainers should choose one license model and implement it consistently across upload consent, storage, public schemas, API, UI, CLI, docs, migrations or backfills, and tests.

## Reproduction Assessment

Yes. Source inspection and live API checks reproduce that ClawHub reports MIT-0 for the skill while npm latest reports MIT for the package.

## Solution Assessment

No. A display-only MIT fix would be too narrow because current main intentionally models platform-wide MIT-0; the maintainable solution starts with a maintainer/legal decision on the license model.
