## Summary

Keep open. Current main, the latest release, and the live ClawHub version API still expose this skill through the platform MIT-0/no-attribution model, so the requested MIT display is not implemented and needs maintainer/legal product direction before code changes.

## Best Possible Solution

Maintainers should choose one license model, then implement it consistently across publish consent, Convex storage, public API schemas, listing UI, CLI output, docs, migrations or backfills, and tests.

Yes. Current-main source inspection shows ClawHub writes, validates, documents, and displays only MIT-0 for published skills, and the live version API returns MIT-0 for `openclaw-workspace-sync` v2.4.1.

## Solution Assessment

No. A narrow visible-label change is not the best fix because the current implementation intentionally models a platform-wide MIT-0 contract; the maintainable fix starts with the license-policy decision.
