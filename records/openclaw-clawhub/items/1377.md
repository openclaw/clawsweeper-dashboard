## Summary

Keep open. Current main and the latest release still use a platform-wide MIT-0/no-attribution skill-license contract, while the live reported skill API still returns MIT-0 and npm reports the upstream package as MIT; the related per-skill license metadata PRs were closed unmerged after maintainer product direction rejected heterogeneous skill licensing.

## What This Changes

The issue requests that ClawHub display the reported skill's upstream MIT license instead of the platform MIT-0/no-attribution license.

## Best Possible Solution

Maintainers should choose one license model and implement it consistently across upload consent, Convex storage, public API schemas, listing UI, CLI output, docs, migrations or backfills, and tests.

## Reproduction Assessment

Yes. Source inspection shows current main still stores and displays MIT-0, and the live ClawHub API returns MIT-0 for the reported skill while npm reports MIT for the upstream package.

## Solution Assessment

No automatic display-only fix is clearly best. Showing MIT alone would contradict the current platform license contract unless maintainers decide to support per-skill SPDX licensing and migrate the related surfaces together.
