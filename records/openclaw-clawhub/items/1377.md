## Summary

Keep open. Current main, the latest release lineage, and the live ClawHub API still expose the reported skill under the platform MIT-0/no-attribution license model, so the MIT versus MIT-0 mismatch is not cleanup-closeable and needs maintainer/legal product direction.

## What This Changes

The issue asks ClawHub to display the upstream standard MIT license for `openclaw-workspace-sync` instead of the platform MIT-0/no-attribution license.

## Best Possible Solution

Maintainers should choose one license model, then implement it consistently across publish consent, Convex storage, public API schemas, listing UI, CLI output, docs, migrations or backfills, and tests.

## Reproduction Assessment

Yes. The live ClawHub API returns `MIT-0` for `openclaw-workspace-sync`, and current main deterministically writes, validates, documents, and displays only the platform MIT-0 license.

## Solution Assessment

No. A narrow label change would be the wrong layer because current main intentionally models a platform-wide MIT-0 contract; the maintainable fix starts with the license-policy decision.
