## Summary

Keep open. Current main and the latest release still model published skill licensing as fixed MIT-0/no-attribution, while the reported skill's upstream package metadata is MIT, so the central mismatch remains unresolved and needs maintainer/legal product direction rather than cleanup closure.

## What This Changes

The issue asks ClawHub to stop displaying a published MIT-licensed skill as MIT-0/no-attribution and to show license terms that match the package's actual license.

## Best Possible Solution

Maintainers should choose one license model, then implement it consistently across publish consent, stored metadata, API/schema, UI, CLI, docs, and any migration or backfill path.

## Reproduction Assessment

Yes. Live ClawHub returns MIT-0 for `openclaw-workspace-sync`, while npm and upstream package metadata return MIT, and current main hard-codes MIT-0 in schema, publish, docs, and UI paths.

## Solution Assessment

No. A narrow label swap would be the wrong layer because current main intentionally models a platform-wide MIT-0 contract; the maintainable fix starts with the license-policy decision.
