## Summary

Keep open. Current main, the latest release, and the live ClawHub API still expose published skills through the platform MIT-0/no-attribution model, so the reported MIT-vs-MIT-0 mismatch is unresolved and needs maintainer/legal product direction rather than cleanup closure.

## What This Changes

The issue asks ClawHub to show the upstream MIT license for `openclaw-workspace-sync` instead of the platform MIT-0/no-attribution license.

## Best Possible Solution

Maintainers should choose one license model, then implement it consistently across publish consent, Convex storage, public API schemas, listing UI, CLI output, docs, migrations or backfills, and tests.

## Reproduction Assessment

Yes. The live ClawHub API returns MIT-0 for `openclaw-workspace-sync`, and current main writes, validates, documents, and displays only MIT-0 for published skills.

## Solution Assessment

No. A narrow label change would be the wrong layer because current main intentionally models a platform-wide MIT-0 contract; the maintainable fix starts with the license-policy decision.
