## Summary

Keep open: current main still renders the dashboard drift warning when frontend and Convex build SHAs both exist and differ. The related items cover the older appMeta outage or separate CLI version wording, so this still needs a maintainer deployment-policy decision rather than cleanup closure.

## What This Changes

The issue reports a persistent dashboard deployment-drift warning where the frontend build SHA and Convex app build SHA differ while the dashboard still works.

## Best Possible Solution

Define the deployment contract, then update the banner, tests, and deploy docs so coordinated deploys use the same SHA and expected partial deploys are either clearly informational or not warned as actionable drift.

Question: Should ClawHub treat frontend/Convex SHA mismatch as an actionable production error, or should expected backend-only and frontend-only deploys downgrade or suppress this dashboard warning?

Rationale: The source path is working as currently tested, and changing it without maintainer intent could either hide real skew or keep a red warning for expected partial deploys.

Likely owner: Patrick-Erichsen

Owner reason: The central banner, metadata query, deploy workflow, and deploy runbook blame to Patrick-Erichsen in current history.

Owner confidence: high

Options:

- **Keep Strict Same-SHA Warning (recommended):** Treat the red warning as correct when SHAs differ, and fix deployment stamping or release ordering when production drifts.
- **Downgrade Expected Partial Drift:** If partial deploy targets are normal, make the banner copy/severity distinguish expected partial drift from actionable skew and update tests/docs together.
- **Disable Drift Detection:** Suppressing the check would remove noisy warnings but would also lose the signal that catches real frontend/backend deployment skew.

## Reproduction Assessment

Yes at source level: current main renders the alert when both frontend and Convex SHAs are present and unequal, and tests assert that behavior. I did not establish a fresh live production dashboard reproduction in this read-only review.

## Solution Assessment

No automatic code change is proven best yet. Maintainers need to choose whether the right fix is stricter same-SHA deploy stamping or a changed banner policy for expected partial deploys.
