## Summary

Keep open: current main still contains the tested deployment-drift alert when frontend and Convex build SHAs are both present and unequal. The related closed appMeta issues fixed the dashboard outage path, not the remaining warning-policy question.

## What This Changes

The issue asks ClawHub to stop showing a persistent red dashboard deployment-drift warning when frontend and Convex build SHAs differ while the dashboard otherwise works.

## Best Possible Solution

Define the deployment contract explicitly: coordinated production deploys should carry the same SHA, and if partial deploys are normal, adjust the banner severity/copy plus tests and deploy docs together.

## Reproduction Assessment

Yes at source level: current main renders the alert when both frontend and Convex SHAs are present and unequal, and the component test asserts that behavior. I did not establish a current live dashboard reproduction because production currently appears not to expose VITE_APP_BUILD_SHA.

## Solution Assessment

Unclear for an automatic code change. The current warning is intentional and tested, so maintainers need to choose whether to enforce same-SHA deploy stamping or change the warning policy for expected partial deploys.
