## Summary

Keep open: current main and the latest release still intentionally render the dashboard drift alert when frontend and Convex build SHAs are both present and unequal, so the reported warning-policy/deploy-stamping question is not implemented away.

## What This Changes

The issue asks ClawHub to stop showing a persistent dashboard deployment-version drift warning when the dashboard otherwise works.

## Best Possible Solution

Define the deployment contract explicitly: either ensure coordinated production deploys stamp matching SHAs end to end, or change the banner severity/copy/tests/docs so expected partial deploys are distinguished from actionable skew.

## Reproduction Assessment

Yes at source level: current main renders the alert when both frontend and Convex SHAs are present and unequal, and tests assert that behavior. I did not establish a fresh live production dashboard reproduction in this read-only review.

## Solution Assessment

Unclear for an automatic fix: current code correctly detects SHA skew under the documented same-SHA deploy contract, but maintainers need to decide how expected partial deploys should be surfaced.
