## Summary

Keep open: current main still renders and tests the dashboard deployment-drift alert whenever frontend and Convex build SHAs are both present and unequal, and no merged canonical follow-up resolves the remaining deploy-policy question.

## What This Changes

The issue asks ClawHub to stop showing a persistent dashboard deployment version drift warning when the dashboard otherwise works but frontend and Convex build SHAs differ.

## Best Possible Solution

Define the deployment contract: either enforce same-SHA coordinated production deploys, or change the banner severity/copy, tests, and deploy docs so expected partial deploys do not look like actionable failures while real skew is still detectable.

## Reproduction Assessment

Yes at source level: current main renders the alert when VITE_APP_BUILD_SHA and appMeta.appBuildSha are both present and unequal, and tests assert that behavior. I did not establish a fresh live production dashboard reproduction in this read-only review.

## Solution Assessment

Unclear. Automatic suppression is not proven best because maintainers still need to decide whether this state should be treated as actionable deploy skew or as an expected partial-deploy condition with different UI/docs.
