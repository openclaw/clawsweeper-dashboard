## Summary

Keep open: current main still intentionally renders and tests the deployment-drift alert when frontend and Convex build SHAs are both present and unequal, while the deploy workflow also supports partial frontend/backend deploy targets. This needs a maintainer policy decision, not automatic cleanup.

## What This Changes

The issue reports that the dashboard keeps showing a red deployment version drift warning even though the dashboard otherwise works.

## Best Possible Solution

Maintain a clear deployment contract: coordinated production deploys should carry the same main SHA, and if partial deploys are expected, adjust the banner severity/copy, tests, and deploy docs to distinguish expected drift from actionable skew.
