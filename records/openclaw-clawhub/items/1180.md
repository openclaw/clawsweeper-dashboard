## Summary

Keep open: current main and latest release still intentionally render the dashboard drift alert when frontend and Convex build SHAs are both present and unequal, so the central warning-policy question is not implemented away. The related closed appMeta outage issues fixed the dashboard crash path, not whether a functional dashboard should show this red drift warning.

## What This Changes

The issue reports that the dashboard keeps showing a red deployment version drift warning when the frontend and Convex build SHAs differ, even though the dashboard otherwise works.

## Best Possible Solution

Maintain a clear deployment contract: coordinated production deploys should carry the same main SHA, and if partial deploys are normal, the banner severity/copy, tests, and deploy runbook should distinguish expected drift from actionable skew.

## Reproduction Assessment

Yes at source level: current main still renders the alert when frontend and Convex SHAs are both present and unequal, and tests assert that behavior. I did not establish a fresh live production dashboard reproduction.

## Solution Assessment

No automatic code change is proven best yet. Maintainers need to choose whether the right fix is stricter same-SHA deploy stamping or a changed banner policy for expected partial deploys.
