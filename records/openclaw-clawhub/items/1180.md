## Summary

Keep open: current main still contains and tests the dashboard deployment-drift alert whenever frontend and Convex build SHAs are both present and unequal, and the remaining question is the deployment-stamping and partial-deploy policy rather than an already-implemented source fix.

## What This Changes

The issue reports a persistent dashboard warning where the frontend expected one deployment SHA while Convex reported a different SHA, even though dashboard functionality still worked.

## Best Possible Solution

Define the production deploy SHA contract, then either enforce coordinated frontend/backend stamping for normal deploys or intentionally adjust the banner severity, copy, tests, and deploy docs for expected partial deploys.

## Reproduction Assessment

Yes at source level: current main renders the alert when both frontend and Convex SHAs are present and unequal, and tests assert that behavior. I did not establish a live browser reproduction because production currently omits the frontend SHA and therefore suppresses the banner.

## Solution Assessment

No automatic code-only fix is proven best yet. Maintainers should first decide whether the correct behavior is stricter same-SHA deploy stamping or a changed warning policy for expected partial deploys.
