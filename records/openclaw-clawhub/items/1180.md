## Summary

Keep open: current main still intentionally renders the deployment-drift alert when frontend and Convex SHAs are both present and unequal, while live production currently omits `VITE_APP_BUILD_SHA` from the frontend asset, which suppresses the alert rather than proving the deploy-stamping contract is fixed.

## What This Changes

The issue reports a persistent dashboard deployment-drift warning where the frontend expected one build SHA while Convex reported another.

## Best Possible Solution

Define the production deploy SHA contract, then either keep coordinated frontend/backend stamping for normal deploys or intentionally adjust the banner policy for expected partial deploys with matching tests and deploy docs.

## Reproduction Assessment

Yes at source level: current main renders the alert when frontend and Convex SHAs are both present and unequal, and component tests assert that behavior. I did not run a live authenticated dashboard session in this read-only review.

## Solution Assessment

No automatic code change is proven best yet. Maintainers need to decide whether persistent drift should be fixed by deploy stamping, by banner policy for partial deploys, or by production configuration.
