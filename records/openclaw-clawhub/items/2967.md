Full review comments:

- **[P2] Preserve the Hermit retry backoff:** `convex/crons.ts:124`
  - body: The notifier currently handles a failed Hermit POST by marking the rows `needsNotification: true` and scheduling the next retry after `PUBLISHER_ABUSE_SIGNAL_NOTIFICATION_RETRY_MS` (one hour). This new 15-minute drain calls the same claim/send action, and the claim mutation selects all `needsNotification=true` rows, so a Hermit outage will retry the same failed rows on the next cron tick instead of respecting the existing backoff. Please make the drain no more frequent than the retry window, or add an eligibility guard so recently failed rows are skipped.
