## Summary

The revised draft now uses the correct stored-publication and DSSE trust boundary, but it remains unmergeable because key rotation can expose a mismatched key-id/private-key pair and `Last-Modified` can incorrectly validate an obsolete signed representation; the only proof is a Vitest source harness, not a real deployment. citeturn0view3turn0view4

## What This Changes

The PR replaces the existing plugin-feed handler with a DSSE/Ed25519 signer over the stored `clawhub-official` publication, adds signing and conditional-request tests, refactors shared feed-response helpers, and documents signing-key operations.

## Best Possible Solution

Use one atomic signer configuration or an explicit disable-first activation protocol, make every cache validator represent the signed-envelope revision, retain the stored immutable payload boundary, and land the route only with coordinated producer/consumer key rollout and redacted live endpoint verification.
