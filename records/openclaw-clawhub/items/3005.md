Full review comments:

- **[P1] Register the signer in a Node-runtime action:** `convex/httpApiV1.ts:54`
  - body: This exported HTTP action is registered from the default `httpApiV1.ts` module while its handler imports `node:crypto` through `feedsV1.ts`. Convex actions that use Node built-ins need to live in a `"use node"` action module, so isolate the signed feed action into a Node-runtime file or remove the Node dependency before this can deploy reliably.
  - confidence: 0.9
- **[P1] Sign stored feed bytes instead of live digest rows:** `convex/httpApiV1/feedsV1.ts:544-551`
  - body: The signed compatibility endpoint calls the new live `feeds.rootFeed` query and signs a freshly built payload for each public request. Current hosted-feed intent says feeds must be refreshed into stored publications first and then served as immutable ETag-cacheable bytes, so this bypasses the availability and validation boundary that `/api/v1/feeds/plugins` already uses.
  - confidence: 0.92
- **[P1] Do not sign mutable plugin install coordinates:** `convex/httpApiV1/feedsV1.ts:309-330`
  - body: `openClawPluginEntry` falls back to `latest` when `latestVersion` is absent and the signed candidate carries no artifact `integrity`. The current hosted-feed contract requires an exact package version plus `sha256:<artifact sha256>`, so a signed feed entry could still resolve mutable or unverifiable install bytes.
  - confidence: 0.88
