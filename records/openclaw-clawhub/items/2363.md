## What This Changes

The issue reports that skill publishing still blocks same-slug publishes across different publishers by resolving `slug` globally instead of by `(ownerPublisherId, slug)`.

## Best Possible Solution

Keep the owner-scoped ClawHub publish implementation, then have a maintainer close this as fixed for ClawHub or split the installed-skill UI `skill.not_found` symptom to the OpenClaw resolver/UI owner.

## Reproduction Assessment

The original source path is no longer failing because publish lookup now starts from the owner-scoped helper and tests guard against global preflight lookup.
