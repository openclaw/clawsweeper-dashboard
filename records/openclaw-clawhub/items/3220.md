## What This Changes

Add durable ClawSweeper review-status handling so failed, expired, or blocked attempts do not repeatedly post visible `review started` placeholders for the same item.

## System Context

ClawSweeper’s review orchestration starts per-item shard work and publishes a GitHub status marker with a lease. That lifecycle should end in a completed review or a clear terminal/backoff state so issue participants receive useful status rather than repeated placeholder notifications.

## Architecture Diagram

flowchart LR
  A[Issue or PR queued] --> B[Review scheduler]
  B --> C[Lease and status marker]
  C --> D[Shard review execution]
  D --> E{Completed?}
  E -->|Yes| F[Rendered review result]
  E -->|No or expired| G[Terminal status and backoff]
  G --> B

## Best Possible Solution

Keep one durable per-item review-status comment, update it to a completed or terminal state after lease expiry, and suppress retries until a meaningful item or code change makes another review useful.
