## Summary

Keep open. Current main has partial author-side validation through `clawhub package validate`, but it still lacks a supported local plugin scanner with hosted ClawScan/static/LLM parity, and `clawhub scan` explicitly rejects local paths.

## What This Changes

Request a supported local plugin scanner or lint CLI that plugin authors can run before publishing to catch manifest, SKILL.md, and code/security findings with JSON and severity output.

## Best Possible Solution

Define a maintainer-approved local plugin scanner contract that reuses shared manifest/schema validation and safe deterministic moderation checks, documents hosted-scan parity gaps, and provides stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks, while `clawhub scan` rejects local paths and the approved scan design explicitly excludes unpublished plugin packages.

## Solution Assessment

Unclear. Extending `clawhub package validate` is a plausible surface, but maintainers first need to settle scanner parity, redaction, severity semantics, and whether LLM/static checks belong in the public CLI.
