## Summary

Keep open. Current main has useful partial coverage through `clawhub package validate` and a repo-local `clawscan:local` helper, but it still does not provide a supported public local plugin scanner with stable hosted-scan parity, severity/exit semantics, and redacted author-facing output; the public `clawhub scan` path still rejects local uploads.

## What This Changes

The issue requests a local plugin scanner or CLI subcommand that plugin authors can run before publishing to catch manifest, SKILL.md, credential, and code-scan findings.

## Best Possible Solution

Define a maintainer-approved public local plugin scanner surface that reuses shared manifest/package validation and safe deterministic scanner logic, documents hosted-scan parity gaps, and emits stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level. Current main exposes partial `clawhub package validate` coverage and a repo-local helper, while `clawhub scan` and the scan API still reject local uploads and the approved design defers unpublished plugin/package scans.

## Solution Assessment

Unclear. Extending the public ClawHub CLI around `package validate` or a new scanner command is plausible, but maintainers first need to settle scanner parity, redaction, severity, exit-code, and support-policy semantics.
