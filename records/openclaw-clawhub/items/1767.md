## Summary

Keep open. Current main and the latest release provide partial author feedback through `clawhub package validate` and a repo-local ClawScan dry-run helper, but they still do not provide the requested supported local plugin scanner/linter CLI with hosted scan parity; the public `clawhub scan` path still rejects local folders.

## What This Changes

The issue requests a supported local pre-publish plugin scanner/linter CLI that validates manifest, SKILL.md, code-scan findings, JSON output, severity levels, and nonzero exits before publishing.

## Best Possible Solution

Define a maintainer-approved local plugin scanner contract that reuses shared Plugin Inspector and safe deterministic moderation checks, documents hosted-scan parity gaps, and emits stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks while `clawhub scan` rejects local paths and the HTTP scan API returns 410 for local uploads, so the remaining supported local scanner gap is visible from source and docs.

## Solution Assessment

Unclear. Extending `clawhub package validate` is plausible, but maintainers first need to settle scanner parity, redaction, severity semantics, exit behavior, and whether LLM/static checks belong in the public author CLI.
