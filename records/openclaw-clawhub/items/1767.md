## Summary

Keep open. Current main and the latest release provide partial author feedback through `clawhub package validate` and a repo-local ClawScan helper, but they still do not provide the requested supported local plugin scanner/linter CLI with hosted scan parity; `clawhub scan` still rejects local folders.

## What This Changes

The issue requests a supported local plugin scanner or lint CLI that catches ClawHub scan and manifest findings before publishing.

## Best Possible Solution

Define and ship a maintainer-approved local plugin scanner contract that reuses shared Plugin Inspector and safe deterministic moderation checks, documents hosted-scan parity gaps, and emits stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level: current main exposes `clawhub package validate` for Plugin Inspector checks while `clawhub scan` rejects local paths, so the remaining supported local scanner gap is visible from CLI source, docs, and e2e tests.

## Solution Assessment

Unclear. Extending `clawhub package validate` is plausible, but maintainers first need to settle scanner parity, redaction, severity semantics, and whether LLM/static checks belong in the public author CLI.
