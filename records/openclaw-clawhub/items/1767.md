## Summary

Keep open. Current main has a useful partial path with `clawhub package validate`, but it still does not expose a supported local pre-publish scanner with hosted ClawScan/static/LLM parity, credential-code findings, and stable severity/output semantics.

## What This Changes

Request a local plugin scanner or lint CLI that plugin authors can run before publishing to catch manifest, SKILL.md, credential, and code-scan findings.

## Best Possible Solution

Define a maintainer-approved local scanner contract that reuses shared manifest/schema validation and deterministic static moderation where safe, documents hosted-scan parity gaps, and provides stable human and JSON output with redaction and severity rules.

## Reproduction Assessment

Yes, at source level. Current main supports Plugin Inspector validation with `clawhub package validate`, while `clawhub scan` rejects local paths and the full hosted security pipeline is not available as a supported local pre-publish plugin CLI.

## Solution Assessment

Unclear. Extending `clawhub package validate` is a plausible surface, but maintainers first need to decide scanner parity, redaction, severity semantics, and whether LLM/static checks belong in the public CLI.
