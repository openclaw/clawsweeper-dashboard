## Summary

Keep open. Current main now gives authors partial local validation through `clawhub package validate`, but it still does not provide the requested supported local plugin scanner with hosted ClawScan/static/LLM parity, and `clawhub scan` still rejects local paths.

## What This Changes

Request a local pre-publish CLI scanner for OpenClaw plugins that reports manifest, SKILL.md, code-scan, severity, exit-code, and JSON findings before publication.

## Best Possible Solution

Define a maintainer-approved local plugin scanner contract that reuses shared Plugin Inspector and safe deterministic moderation checks, documents hosted-scan parity gaps, and emits stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks while `clawhub scan` rejects local paths, so the remaining local scanner gap is visible from the CLI source and docs.

## Solution Assessment

Unclear. Extending `clawhub package validate` is a plausible surface, but maintainers first need to settle scanner parity, redaction, severity semantics, and whether LLM/static checks belong in the public CLI.
