## Summary

Keep open. Current main has a useful shipped partial path with `clawhub package validate`, but the central request is still broader than bundled Plugin Inspector validation: local `clawhub scan` still rejects unpublished folders, the repo-local ClawScan dry-run helper is not a supported public CLI/backend path, and scanner parity/severity/redaction remain product-security decisions.

## What This Changes

The issue requests a supported local pre-publish scanner for plugin authors, covering manifest/SKILL metadata validation, code/security findings, nonzero exits, JSON output, and severity levels.

## Best Possible Solution

Define a maintainer-approved local scanner contract that extends or complements `clawhub package validate`, reuses shared deterministic scanner logic where safe, documents hosted ClawScan parity gaps, and provides stable redacted human/JSON output with severity rules.

## Reproduction Assessment

Yes, at source level. Current main supports `clawhub package validate` for local Plugin Inspector checks, while `clawhub scan` still rejects local paths and the full hosted security pipeline is not exposed as a supported local plugin-author CLI.

## Solution Assessment

Unclear. Extending `clawhub package validate` is the likely narrow surface, but maintainers need to settle scanner parity, redaction, severity, and runtime/API-key policy before this should be implemented.
