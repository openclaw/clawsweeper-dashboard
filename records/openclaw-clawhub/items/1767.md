## Summary

Keep open. Current main partially addresses author preflight with `clawhub package validate`, package publish dry-run, hosted publish-time scans, and stored scan downloads, but it still does not provide the requested supported local plugin security scanner with ClawScan/static/LLM parity, SKILL metadata checks, credential/code heuristics, stable severities, and pre-publish JSON output.

## What This Changes

The issue requests a local plugin scanner CLI or dry-run publish command that validates plugin manifests, SKILL.md metadata, code security heuristics, JSON output, exit codes, and severity before publishing.

## Best Possible Solution

Define a maintainer-approved local ClawHub scanner that reuses shared package validation and deterministic static moderation logic, supports stable human and JSON output, and documents how local results relate to hosted publish-time scanning.

## Reproduction Assessment

Yes, at source level: the CLI has package validation and scan-result retrieval paths, but not a complete local ClawScan-style pre-publish scanner for plugin code and SKILL metadata. This is a missing capability rather than a runtime crash reproduction.

## Solution Assessment

Unclear. Extending `clawhub package validate` may be the right surface, but scanner parity, redaction, exit-code severity, and hosted-scan semantics need maintainer direction first.
