## Summary

Close as implemented: the released ClawHub CLI now provides the requested local pre-publish validation flow through `clawhub package validate`, including offline/static inspection, optional isolated runtime capture, JSON output, remediation guidance, and publish dry-runs.

## What This Changes

Add a supported local CLI scanner that validates a plugin package and reports pre-publish metadata, manifest, compatibility, artifact, and security-related findings.

## System Context

ClawHub's package-publishing flow accepts a local plugin folder or artifact, validates its package and OpenClaw metadata, and then publishes it to the registry. The bundled Plugin Inspector supplies local author feedback before the separate registry scan and moderation stages.

## Architecture Diagram

flowchart TD
  A[Local plugin package] --> B[clawhub package validate]
  B --> C[Bundled Plugin Inspector]
  C --> D[Static checks and optional isolated runtime capture]
  D --> E[Remediation findings and JSON output]
  E --> F[Package publish dry run]
  F --> G[Registry security scan and moderation]

## Best Possible Solution

Keep the released `clawhub package validate <path>` and `clawhub package publish <path> --dry-run` workflow as the pre-publish author path, and add only narrowly evidenced inspector rules when a concrete unsupported package pattern remains.
