## Summary

Keep open. Current main has useful partial validation through `clawhub package validate` and a repo-local `clawscan:local` script, but it still lacks a supported author-facing local plugin scanner package or CLI command with manifest, SKILL.md, static scan, LLM scan, severity, exit-code, and JSON-output contract; `clawhub scan` still rejects local paths.

## What This Changes

Request to add a local plugin scanner package, CLI subcommand, or dry-run publish mode that catches manifest, SKILL.md, and code scan findings before plugin publication.

## Best Possible Solution

Define a maintainer-approved local plugin scanner contract that reuses shared Plugin Inspector and deterministic moderation logic, clearly documents hosted-scan parity gaps, redacts sensitive evidence, and exposes stable human and JSON output through the supported ClawHub CLI or package surface.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks, while `clawhub scan` rejects local paths and the only full local ClawScan-style helper is a repo script rather than a supported author CLI/package.

## Solution Assessment

Unclear. Extending `clawhub package validate` or promoting shared scanner logic into a supported command is plausible, but maintainers first need to settle scanner parity, redaction, severity, and public CLI placement.
