## Summary

Keep open. Current main has partial author-side validation through `clawhub package validate`, but it still lacks a supported local pre-publish scanner with hosted ClawScan/static/LLM parity and settled security output semantics.

## What This Changes

The issue requests a local plugin scanner or CLI lint/dry-run command that validates manifests, SKILL metadata, suspicious code patterns, JSON output, exit codes, and severities before publishing.

## Best Possible Solution

Define a maintainer-approved local scanner contract that reuses shared manifest/schema validation and safe deterministic moderation checks, documents hosted-scan parity gaps, and provides stable redacted human and JSON output.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks, while `clawhub scan` rejects local paths and hosted static/LLM/ClawScan results remain publish-side or repo-local.

## Solution Assessment

Unclear. Extending `clawhub package validate` is a plausible surface, but maintainers first need to settle scanner parity, redaction, severity semantics, and whether LLM/static checks belong in the public CLI.
