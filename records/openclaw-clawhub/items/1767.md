## Summary

Keep open. Current main provides useful partial author feedback through `clawhub package validate` and repository-only local ClawScan tooling, but the supported public scan command still rejects local artifacts. The remaining work is a product and security-contract decision, not an already-implemented feature.

## What This Changes

Add a supported local pre-publish plugin scanner with manifest, metadata, code-risk, severity, JSON, and exit-status validation.

## Best Possible Solution

Expose a shared deterministic pre-publish validation layer through the supported CLI, with stable redacted human and JSON output, severity and exit semantics, and explicit documentation that model-backed hosted moderation may add findings unless full parity is deliberately supported.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should local pre-publish plugin validation guarantee full hosted ClawScan parity or expose a stable deterministic subset?

Rationale: Current main contains both partial public validation and fuller internal scanning, but deciding which checks, model calls, secrets, redaction rules, severities, and compatibility guarantees become public requires maintainer intent.

Likely owner: Patrick Erichsen

Owner reason: They introduced and recently maintained the closest local scanner and public validation implementations.

Owner confidence: high

Options:

- **Stable deterministic subset (recommended):** Expose shared manifest, metadata, schema, and static-risk checks locally while documenting model-backed hosted findings as supplemental.
- **Full hosted parity:** Expose model-backed scanning locally and support its credential, privacy, cost, redaction, and versioning obligations.
- **Keep scanning internal:** Retain repository-only scanning and improve upload-time diagnostics without adding a supported local scanner.

## Reproduction Assessment

Yes, at source level. Current main explicitly rejects local paths in the public scan command, while the local Plugin Inspector and repository-only ClawScan paths demonstrate partial and internal coverage rather than the requested supported workflow.

## Solution Assessment

No, full hosted parity as initially proposed is not yet the safest default. A stable deterministic shared validation core with clearly documented hosted-only gaps is the narrowest maintainable first implementation.
