## Summary

Keep open. Current main partially covers author-facing plugin validation through `clawhub package validate`, but it still does not expose the requested supported local pre-publish plugin scanner with ClawScan/static/LLM security parity, stable severity semantics, and CI-friendly JSON output.

## What This Changes

Request a local plugin pre-publish scanner or CLI linter that checks plugin manifest, SKILL.md metadata, code/credential findings, JSON output, severities, and nonzero exit behavior before publishing.

## Best Possible Solution

Define a supported local plugin pre-publish scanner contract that reuses shared package validation and scanner inputs where safe, documents redaction/parity/severity rules, and exposes stable human plus JSON output.

## Reproduction Assessment

Yes, at source level: current main has `clawhub package validate` and hosted/stored scan flows, while supported local plugin ClawScan-style pre-publish scanning is absent. This is a missing capability rather than a crash or runtime bug reproduction.

## Solution Assessment

Unclear. Extending `clawhub package validate` is a plausible user surface, but maintainers first need to decide scanner parity, secret redaction, severity semantics, and whether static/LLM checks belong in a public local CLI.
