## Summary

Keep open. Current main and the latest release now provide partial local Plugin Inspector validation through `clawhub package validate`, but they still do not provide the requested supported local pre-publish ClawScan-style plugin scanner with code/credential findings, hosted-scan parity, stable severities, and JSON semantics.

## What This Changes

Request a local pre-publish plugin scanner or lint CLI that validates plugin manifests, SKILL.md metadata, code/credential findings, JSON output, and severity-based exits before publishing.

## Best Possible Solution

Define one maintainer-approved local scanner contract that reuses shared manifest/schema and deterministic static checks, clearly documents how results relate to hosted ClawScan, and exposes stable human and JSON output with redaction rules.

## Reproduction Assessment

Yes, at source level: current main has `clawhub package validate` and stored scan downloads, while `clawhub scan` still rejects local paths. This is a missing supported capability rather than a crashing runtime bug.

## Solution Assessment

Unclear. Extending `clawhub package validate` may be the right user surface, but maintainers first need to decide scanner parity, redaction, severity, and whether LLM/static checks belong in a public local CLI.
