## Summary

Keep open. Current main now provides substantial local author feedback through `clawhub package validate` and plugin publish dry runs, but it still explicitly rejects local artifacts from the authoritative ClawScan path. The remaining credential-pattern, network/environment heuristic, and hosted-parity work needs a product and security-contract decision; the active OpenClaw plugin support work in https://github.com/openclaw/clawscan/pull/15 is useful context but does not implement the public ClawHub CLI contract.

## What This Changes

Requests a supported local CLI or package that validates plugin manifests, skill metadata, and security findings before publication.

## Best Possible Solution

Extend the existing `clawhub package validate` surface with versioned, deterministic advisory security checks and clearly distinguish them from any hosted-only authoritative scan stages.
