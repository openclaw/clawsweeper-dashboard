## Summary

Close as implemented: current ClawHub ships a supported local pre-publish validation command, with offline Plugin Inspector checks, JSON output, report artifacts, remediation guidance, and package-publish dry runs. The remaining distinction is intentional: hosted ClawScan remains the registry-owned scan authority rather than a local-path scan command.

## What This Changes

Request a supported local plugin scanner or CLI dry-run that validates plugin manifests, package metadata, and security-related findings before publication.

## Best Possible Solution

Keep `clawhub package validate <path>` as the supported local author preflight and retain ClawHub-hosted ClawScan as the authoritative post-submission security decision and report surface.
