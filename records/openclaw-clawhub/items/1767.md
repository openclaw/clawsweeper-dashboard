## Summary

Keep open. Current main has partial pre-publish help through `clawhub package validate` and a repo-local ClawScan helper, but it still does not provide the requested supported local plugin scanner/linter CLI with hosted-scan-style checks, stable severity/exit semantics, and documented JSON output.

## What This Changes

The issue requests a local plugin scanner or CLI lint/dry-run command that plugin authors can run before publishing to catch manifest, SKILL.md, credential, and code-scan findings.

## Best Possible Solution

Define and ship a maintainer-approved local plugin scanner contract that reuses shared Plugin Inspector and safe deterministic moderation checks, documents hosted-scan parity gaps, and emits stable redacted human and JSON output.

Owner confidence: high

Options:

- **Sponsor a supported scanner contract (recommended):** Expand the author-facing CLI around `package validate` or a clearly named sibling command with shared deterministic checks, documented parity limits, redacted JSON output, and stable severity/exit behavior.
- **Keep validator-only scope:** Document `package validate` as Plugin Inspector-only and leave hosted ClawScan results available only after publish or stored scan download.
- **Split a separate scanner design:** Create a narrower follow-up spec for local scanner architecture before implementing any public CLI behavior.

## Reproduction Assessment

Yes, at source level. Current main exposes `clawhub package validate` for Plugin Inspector checks while `clawhub scan` and the scan submit API reject local upload/folder scans, so the supported local scanner gap is visible from source and docs.

## Solution Assessment

Unclear. Extending `clawhub package validate` is plausible, but maintainers first need to settle scanner parity, redaction, severity semantics, and whether hosted ClawScan-style checks belong in the public author CLI.
