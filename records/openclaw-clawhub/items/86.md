## Summary

Current main and v0.23.1 do not provide a shareable scheduled-job template catalog or installation path. The request remains useful, but it requires a maintainer-owned product and security decision because ClawHub’s existing artifact families have deliberately distinct trust and runtime semantics.

## What This Changes

Add a browsable catalog of community cron-job templates with config preview, categories, and one-click installation into OpenClaw.

## Best Possible Solution

Define a cross-repository scheduled-job import contract first, then either reuse skills or bundle plugins when their semantics fit or deliberately add a moderated template family with explicit preview, consent, permissions, and lifecycle controls.

## Maintainer Decision

Rationale: Current artifact families intentionally encode different execution and installation semantics, while recurring actions add durable authority that automation cannot define safely.

Likely owner: Patrick-Erichsen

Owner confidence: high

Options:

- **Design runtime contract first (recommended):** Define OpenClaw validation, preview, consent, permissions, installation, update, disable, and uninstall semantics before choosing the ClawHub representation.
- **Use existing families:** Publish cron examples as skills or bundle plugins and avoid a new artifact family unless the existing semantics prove insufficient.
- **Add dedicated template family:** Create a fourth moderated family with distinct schema, API, UI, scanning, and installation contracts.
