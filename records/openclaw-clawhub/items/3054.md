- `impact:security`: Unverified publishers can cheaply manipulate top search placement through exact-name squatting.

## Summary

Keep open: current main still has the reported tier-first ranking behavior, and no open or merged follow-up PR currently owns the fix.

## What This Changes

Harden package and skill search ranking so zero-adoption, unverified exact-name matches do not automatically outrank adopted or verified related results.

## Best Possible Solution

Use one pure digest-based ranking policy for both catalogs: demote untrusted zero-adoption exact matches, compare a documented log-scale adoption bucket before raw relevance within each effective tier, preserve official and provenance/rebuild-verified exceptions, and record the invariant in the existing search-relevance spec.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main deterministically places every tier-0 exact match before tier-1 prefix or token matches, so adoption and verification cannot overcome the tier difference.

## Solution Assessment

Yes in principle. A shared ranking-policy helper fixes the primitive consistently across packages and skills; package-specific moderation or a one-sided comparator change would leave the underlying weakness intact.
