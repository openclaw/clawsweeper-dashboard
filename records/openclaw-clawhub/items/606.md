Keep open. Current main and the latest release still lack ClawHub app i18n: there is no `src/i18n` locale layer, the root shell metadata and `<html lang>` remain static English, and header/navigation surfaces still use English literals without a language switcher. The related app-i18n and translated-docs PRs are closed unmerged after maintainer product-direction comments pausing translation/i18n expansion, so this needs maintainer localization policy rather than cleanup closure.

## What This Changes

The issue requests a lightweight ClawHub i18n layer with English and zh-CN locale files, a header language switcher, and persisted client-side locale preference.

## Best Possible Solution

Maintainers should first decide ClawHub's localization policy; if accepted, request a fresh staged implementation with typed locale keys, en/zh-CN coverage, a persisted switcher, locale-aware shell/head behavior, fallback/parity tests, and real UI proof.
