## Summary

Keep open for maintainer direction. Neither current main nor v0.23.1 supports publisher-wide installation, and the collaborator-authored request requires a product choice because skills have a complete installer while plugins currently use a separate artifact download and verification lifecycle.

## What This Changes

Add a ClawHub CLI workflow to install every skill and plugin published by one publisher.

## Best Possible Solution

Implement publisher-wide skill installation by enumerating the publisher catalog and reusing the existing item installer, then add plugin support only after defining a first-class plugin installation lifecycle; return resumable per-artifact outcomes rather than treating the publisher as one atomic target.

## Maintainer Decision

Rationale: Skills have an established installer with moderation, overwrite, lockfile, and version behavior, while plugin packages currently stop at artifact download and verification; combining them commits the product to a new plugin lifecycle and consent model.

Likely owner: Patrick-Erichsen

Owner confidence: high

Options:

- **Start With Skills (recommended):** Add publisher-wide skill installation that preserves every per-item check and defer plugins until their installation lifecycle is defined.
- **Design Both Together:** Define plugin installation, compatibility, consent, rollback, and partial-failure behavior before exposing any publisher-wide command.
- **Discovery Only:** List all publisher artifacts and generate individual commands without performing bulk mutation.

## Reproduction Assessment

No—reproduction is not applicable because current behavior is intentionally item-scoped and the issue requests a new publisher-scoped capability. Source and release inspection confirm the requested operation does not currently exist.

Not yet. Best-fix verdict: too broad as stated; a skill-only bulk command that reuses `cmdInstall` is the narrowest maintainable first step, while plugin support should wait for a defined installation contract.
