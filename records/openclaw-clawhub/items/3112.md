## Summary

Current main still exposes both transient-failure paths: the required HTTP gate runs live GitHub-backed package dry-runs without a dedicated retry or controlled-fixture boundary, while local-auth shards request larger runners but record no schedulable-CPU diagnostics or saturation-specific failure classification. This MEMBER-authored issue should remain open for explicit CI ownership and scope decisions.

Likely related people: @jesse-merhi (recent CI stabilization, high confidence), @vyctorbrzezowski (profile/query and retry-path history, high confidence), and @odysseus0 (GitHub-backed package-publish test history, medium confidence).

## What This Changes

Harden the HTTP e2e and local-auth CI gates against transient GitHub lookup failures, Convex saturation, retry amplification, and uncertain runner capacity.

## Best Possible Solution

Deliver two coordinated tracks: make GitHub package dry-runs deterministic or retry only bounded transient failures, and separately add runner-quota diagnostics, backend readiness polling, inactive-query gating, capped reload behavior, and explicit Convex-timeout reporting before repeated isolated validation.
