## Summary

Keep this PR open for a focused repair: the retry path is intended for transient OCC failures, but the patch retries every claim exception until the claim window closes, so permanent authentication, configuration, or request errors can stall the security-scan worker instead of failing promptly. The author is also a repository collaborator, so this item requires normal maintainer handling rather than cleanup closure.

## What This Changes

The PR changes the security-scan worker to retry failed job claims after a configurable delay and adds tests for successful retry and claim-window expiration.

## Best Possible Solution

Retry only explicitly recognized transient/OCC claim errors with bounded backoff, fail permanent errors promptly, and cover both paths with focused worker tests while preserving the failed outcome when the claim window expires.

## Solution Assessment

No, not yet: retrying transient OCC failures is appropriate, but applying the policy to every exception is broader than the stated bug and can hide permanent failures. Error classification or a narrowly bounded retry policy is the safer implementation.
