## Summary

Current main has structured install, dependency, compatibility, capability, and package-verification metadata, but it does not implement the proposed routing, task-verification, advisory risk, or playbook contract. The RFC is recent, meaningfully distinct from adjacent closed RFCs, and aligned with the stated agent-harness direction, so it should remain open for a narrow product and trust-boundary decision. ([github.com](https://github.com/openclaw/clawhub/blob/main/VISION.md))

## What This Changes

Define optional skill and plugin metadata for intent-based routing, advisory risk/preflight hints, expected completion checks, and reusable-playbook discovery through ClawHub API and CLI consumers.

## Best Possible Solution

Approve a minimal, versioned, advisory metadata contract under existing skill and package namespaces; expose normalized raw fields through inspect/API output, keep author claims distinct from scanner facts, defer server-side ranking, and document the trust semantics in `specs/` plus consumer-facing behavior in `docs/`.

Options:

- **Advisory metadata v1 (recommended):** Define a small optional and versioned field set, expose normalized raw values through API and CLI, distinguish author claims from scanner facts, and defer ranking to consumers.
- **ClawHub ranking service:** Add the metadata plus a server-ranked candidate endpoint, accepting additional quality-scoring, abuse-prevention, and compatibility obligations.
- **Keep routing external:** Do not standardize new registry fields yet; require Harness-style consumers to derive candidates from descriptions, existing metadata, and their own indexes.
