## Summary

Keep open for an explicit product and trust-boundary decision. Current main has adjacent structured manifest metadata, but it does not implement routing candidates, advisory risk/preflight semantics, verification hints, or playbook metadata; the protected security-review label also requires maintainer handling.

## What This Changes

The issue proposes optional skill/plugin manifest metadata for routing, advisory risk/preflight, verification hints, and incident-playbook discovery for Harness-style consumers.

## Best Possible Solution

Define a small, versioned advisory metadata contract for candidate discovery and human-readable verification, explicitly separate it from OpenClaw execution policy and ClawHub security evidence, then implement it across schema, parser, API/CLI, docs, and tests.

Owner confidence: high

Options:

- **Adopt a narrow advisory v1 (recommended):** Standardize bounded intents/keywords plus verification descriptions, expose raw values only, and explicitly exclude risk enforcement, ranking guarantees, and runtime permission effects.
- **Include advisory risk hints:** Add a limited risk/preflight vocabulary only if it is clearly presented as untrusted publisher disclosure alongside—not instead of—ClawHub scanner and moderation evidence.
- **Defer registry metadata:** Keep existing semantic/vector discovery and revisit after a concrete Harness consumer proves which fields improve selection without creating a misleading trust signal.
