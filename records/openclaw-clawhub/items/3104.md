## Summary

Keep open for a maintainer decision on a narrow, advisory registry contract. Current main supports several structured skill requirements and trust signals, but it does not define routing candidates, publisher-supplied risk/preflight semantics, machine-readable verification checks, or playbook metadata; treating those declarations as trusted policy would cross ClawHub’s stated runtime boundary.

## What This Changes

The issue proposes optional skill and plugin manifest metadata for routing, advisory risk/preflight, verification checks, and playbook hints that external Harness-style consumers could use.

## Best Possible Solution

Define a versioned, optional advisory metadata subset for candidate discovery and post-run checks, expose raw declarations separately from ClawHub-owned scan/trust evidence, and keep authorization, enforcement, and execution decisions in OpenClaw.
