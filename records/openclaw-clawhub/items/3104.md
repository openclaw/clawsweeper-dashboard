## Summary

Keep open for a maintainer decision on a narrow advisory registry contract. Current main has structured runtime requirements, security scanning, trust envelopes, and catalog metadata, but it does not define machine-readable routing candidates, publisher-supplied preflight semantics, or verification/playbook hints; making those declarations authoritative would cross ClawHub’s runtime and trust boundary.

## What This Changes

The RFC proposes optional skill and plugin metadata for routing, risk/preflight, verification, and playbook hints that external Harness-style controllers could consume.

## Best Possible Solution

Define a small versioned advisory metadata schema for candidate discovery and evaluation, expose it as raw registry data, and keep ranking, enforcement, and runtime approvals under their existing owners until separately designed.

- **Expand registry policy signals:** Treat risk and preflight fields as a broader trust product, requiring a separate security design, validation model, and moderation ownership.
