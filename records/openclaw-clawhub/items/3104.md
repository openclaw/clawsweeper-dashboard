## Summary

Keep open: current main supports basic skill setup/platform metadata and package capability summaries, but it does not define or expose the proposed routing intents, negative matches, risk declarations, verification expectations, or playbook hints. This fresh RFC fits ClawHub’s registry direction but needs explicit product and trust-boundary decisions before implementation.

## What This Changes

Add optional skill and plugin metadata for routing, risk preflight, verification expectations, and playbook discovery, exposed through ClawHub API and CLI surfaces.

## Best Possible Solution

Adopt a small, general-purpose, backward-compatible manifest extension only after validating it with a real consumer: start with normalized routing intents and human-readable verification hints, expose raw advisory metadata through the API/CLI, keep ranking external, and explicitly separate declarations from enforced permissions, scanner findings, and moderation state.

## Risks / Open Questions

- Author-declared risk levels or preflight hints could be mistaken for authoritative permission or scanner results unless the API clearly separates advisory metadata from enforced security state.
- Free-form intents and keywords create keyword-stuffing, misleading declarations, ranking-quality, and moderation concerns without a defined trust and evaluation model.
- Designing fields around one proposed Harness consumer could create a public contract that drifts from OpenClaw or other clients before a concrete consumer and evaluation corpus validate it.
- Adding the full proposal across skill manifests, plugin manifests, storage, API schemas, CLI output, moderation, and documentation would broaden a compatibility-sensitive public interface.
