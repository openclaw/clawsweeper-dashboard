## Summary

Keep open: current main does not yet implement Codex worker artifact_coverage enforcement, but this draft PR is conflicting with newer worker/security-scan code and changes a security-sensitive fail-closed contract that needs maintainer review before merge.

## What This Changes

The PR adds an artifact_coverage field to the Codex scan output schema, prompts Codex to report submitted-file coverage, rejects benign worker results without complete coverage proof, adds worker tests, and records the invariant in specs/security-moderation.md.

## Best Possible Solution

Integrate the coverage gate into the current worker code after resolving conflicts, keep the invariant documented in specs/security-moderation.md, and require fresh runtime proof that complete benign scans pass while incomplete benign scans fail without disrupting normal scan throughput.

## Reproduction Assessment

Yes, source inspection shows current main parses and stores Codex benign results without an artifact_coverage verifier, and the PR body gives a concrete local Convex/Codex positive and controlled-negative proof path. ## Solution Assessment

Acceptable but not merge-ready: enforcing coverage before storing a clean result is the right layer, but the branch must be refreshed onto current main and maintainers must accept model-reported coverage as sufficient proof or request deterministic instrumentation.
