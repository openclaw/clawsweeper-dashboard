## Summary

Keep open: this is a meaningful new public feed API, but the patch has a blocking trust-boundary defect because client-supplied cursors can inject arbitrary feed entries, plus package-family mapping and runtime-proof gaps.

## What This Changes

The branch adds account and publisher feed schema/contracts, Convex queries, four public HTTP GET routes, OpenAPI updates, specs, and focused tests for live public account/publisher feeds.

## Best Possible Solution

Redesign feed pagination so cursors contain only server-verifiable continuation state, filter package families or model package kinds explicitly, add focused regression coverage, and provide a real Convex HTTP smoke before exposing the endpoints.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path: pass a base64 JSON cursor containing pendingEntries to a feed endpoint and the query seeds candidates from those caller-supplied entries. I did not run a live Convex smoke because this review is read-only.

## Solution Assessment

No, this is not yet the best way to solve the issue. A safer implementation should make cursors opaque or server-verifiable and derive every returned entry from current storage rather than trusting cursor-embedded entries.

## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Do not trust feed entries from the cursor:** `convex/accountFeeds.ts:168`
  - body: `cursor` is a public query parameter, but `parseFeedCursor` accepts `pendingEntries` from it and this line seeds the returned candidate list with those entries. A caller can base64-encode a cursor with arbitrary entries and no real Convex cursor, causing the public feed to return forged ClawHub-authored feed items; keep the cursor to opaque/verifiable continuation state and recompute entries from storage.
  - confidence: 0.93
- **[P2] Filter package families before emitting plugin entries:** `convex/accountFeeds.ts:118-120`
  - body: `packages.family` can be `skill`, `code-plugin`, or `bundle-plugin`, but this path maps every non-private, non-blocked package to `kind: "plugin"` and a `/plugins/...` URL. That mislabels skill-family package rows as plugin feed entries; either filter to plugin families or make the feed contract carry the actual package family/kind.
  - confidence: 0.82
