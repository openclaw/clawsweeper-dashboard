## Summary

Keep this collaborator-authored draft open for normal maintainer handling. The overall staged-publication design is useful, but the current patch can skip published skill versions during pagination, allows preview proof without binding it to an exact commit, and changes a security-sensitive scanner path without complete rollout proof or durable design documentation.

## What This Changes

The PR creates private pending skill versions and plugin releases before scanning, promotes or removes them based on TruffleHog and ClawScan results, preserves legacy publish response IDs, and updates current CLI messaging and proof automation.

## Best Possible Solution

Retain the private pending-artifact architecture and legacy-compatible IDs, but make pagination cursor-safe, bind every protected proof run to an immutable required SHA, lock the scanner execution path, document publication and deletion invariants under specs/, and capture a redacted staged rollout showing upload, public invisibility, promotion, malicious retention, and secret-positive deletion.
