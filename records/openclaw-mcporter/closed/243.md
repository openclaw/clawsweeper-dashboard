## Summary

Keep open for maintainer review: the proposed URL marker makes a pre-existing directory-backed OAuth cache with no marker look changed on its first post-upgrade use, silently clearing credentials even when the configured URL did not change. The branch otherwise targets the linked stale-registration report constructively. Likely related people: steipete (current OAuth contributor, medium confidence) and sourman (reproduction reporter, medium confidence).

## What This Changes

The branch records each configured HTTP server URL and clears shared-vault and directory OAuth state when that named server’s URL changes, with regression tests and user-facing documentation.

## System Context

mcporter builds OAuth persistence from each configured MCP server and then supplies that stored token, client-registration, PKCE, and callback state to login and transport connections. This change adds a URL binding to that persistence so a renamed server configuration cannot reuse credentials from a different endpoint.

## Best Possible Solution

Make the markerless directory-cache upgrade behavior an explicit, tested security-and-compatibility decision: either document and deliberately approve a one-time reauthentication reset, or add a safe migration that preserves state only when its endpoint binding can be proven.
