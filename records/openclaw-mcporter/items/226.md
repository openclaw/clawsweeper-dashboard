## Summary

Keep open: current main and v0.12.3 still have the reported refreshable_bearer failure path, with no invalid_grant classification, concurrent-winner reread, or token-cache clearing like the plain OAuth path.

## What This Changes

The issue requests refresh-failure recovery for refreshable_bearer token refresh so invalid_grant and concurrent refresh races do not keep replaying stale rotated refresh tokens.

## Best Possible Solution

Extend refreshable_bearer to parse OAuth error bodies and reuse the existing unrecoverable refresh recovery semantics, with focused invalid_grant and concurrent-winner regression tests.

## Reproduction Assessment

Yes, source inspection gives a high-confidence reproduction path with a mocked token endpoint returning HTTP 400 and {"error":"invalid_grant"} for an expired refreshable_bearer token. I did not execute live Notion or local tests because this review is read-only.

## Solution Assessment

Yes, porting the existing plain-OAuth error classification, reread, and cache-clear path is the narrowest maintainable fix. Full refresh serialization can stay optional or become a separate hardening follow-up.
