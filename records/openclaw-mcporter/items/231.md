A maintainer should require a current-main provider reproduction before choosing the error classification and retry boundary.

## What This Changes

Recover from a cached dynamic client registration that a provider no longer accepts, rather than replaying it until the user runs `mcporter auth <server> --reset`.

## System Context

mcporter stores OAuth discovery, dynamically registered client information, and tokens in its credential persistence layer. An authentication attempt loads that state, performs dynamic client registration when needed, then opens the MCP transport; stale client state currently appears able to stop that sequence before the user can re-authorize.

## Best Possible Solution

Reproduce the exact stale-client scenario on current main, then add one bounded retry that invalidates only client registration state when the provider response reliably proves that cached client is rejected; retain persisted state for transient registration failures and cover configuration-change behavior explicitly.
