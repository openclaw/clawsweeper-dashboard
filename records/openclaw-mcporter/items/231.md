## Summary

Keep open. Current main has recovery for structured permanent refresh failures and corrupt credential storage, but the available evidence does not establish equivalent handling for a cached dynamic-client registration rejected during DCR; the unmerged automated PR is not a safe replacement.

## What This Changes

Automatically invalidate a stale cached OAuth client registration and retry DCR once when `mcporter auth <server>` fails because that registration is no longer accepted.

## Best Possible Solution

Add a narrowly classified, once-only DCR recovery path only after a live provider trace confirms how a rejected cached client registration can be distinguished from transient registration failures; cover unchanged credentials, endpoint/config changes, successful retry, and no retry loop.

- **Retry all DCR server errors once:** Favor recovery convenience by clearing cached client information after any DCR server error, accepting additional registration churn during transient outages.
