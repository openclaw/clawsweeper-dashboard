## Summary

Keep open. The report identifies a plausible DCR-specific OAuth recovery gap that the related merged fixes do not establish as covered, and the reporter’s follow-up raises a real policy question about whether server configuration changes should invalidate cached client registration. A maintainer should choose the recovery boundary after validating a stale registration versus transient DCR failure with a real provider.

## What This Changes

Add safe automatic recovery when a cached dynamic client registration is no longer accepted by the OAuth provider.

## Best Possible Solution

Define a narrow DCR recovery contract: invalidate and retry once only when cached client information is demonstrably stale or the configured server identity has changed, preserve the existing registration for transient failures, and add focused regression coverage plus provider-backed proof.
