## Summary

Keep open. Current `main` still retries only the authorization-code redirect path after an unauthorized error; it does not invalidate cached client registration state or retry dynamic client registration after a non-unauthorized DCR failure. The related OAuth fixes address distinct refresh and corrupt-cache cases, while the only direct candidate PR was closed unmerged.

## What This Changes

Recover automatically from a stale cached OAuth dynamic-client registration that repeatedly fails DCR, rather than requiring users to run `mcporter auth <server> --reset`.

## Best Possible Solution

Reproduce the stale-registration case against the named GoTrue-backed server, then add a bounded one-time client-registration invalidation and retry only for a verified durable stale-client signal while preserving transient DCR failures.
