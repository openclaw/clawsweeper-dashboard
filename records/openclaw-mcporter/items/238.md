## What This Changes

Adds safety documentation explaining that generated CLIs need an application-owned per-call policy wrapper and that record/replay fixtures must be redacted before sharing.

## System Context

mcporter generates standalone CLIs and typed clients that invoke MCP server tools outside the client that originally configured the server. Its record/replay feature stores JSON-RPC exchanges for regression use, so the documentation needs to distinguish static tool selection from runtime authorization and safe fixture handling.

## Architecture Diagram

  C --> D[Application policy wrapper]
  D --> E[Approval and policy decision]
  E --> F[Tool execution]
  F --> G[Redacted audit record]
  C -. direct invocation bypasses .-> F

## Best Possible Solution

Revise the conceptual wrapper to emit one redacted audit outcome for every policy decision and execution result, then retain the focused generated-CLI and fixture-redaction guidance.
