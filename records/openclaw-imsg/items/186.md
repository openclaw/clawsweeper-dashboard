## Summary

This issue remains necessary: the reported RPC-only Contacts policy is a narrow availability fix, and no merged or open canonical replacement is present in the supplied context. The existing resolver already exposes a fail-open policy for an undetermined authorization state, so the RPC startup boundary can avoid blocking unrelated requests while interactive commands retain their current behavior.

## What This Changes

Use `ContactsAccessPolicy.skipIfNotDetermined` when initializing Contacts for `imsg rpc`, so headless RPC startup does not await a macOS Contacts prompt.

## Best Possible Solution

Keep interactive Contacts commands on their existing request-if-needed behavior, but initialize the RPC server with the existing skip-if-undetermined policy and add deterministic regression coverage for the no-prompt fallback.
