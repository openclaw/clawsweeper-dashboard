## Label Justifications

- `P1`: A single production RPC send can intermittently double-text recipients, breaking a real channel workflow.

## Summary

Keep open: current main and v0.12.3 still use process-local request deduplication, which cannot provide exclusive ownership when multiple injected processes observe the shared inbox. The clean candidate fix at https://github.com/openclaw/imsg/pull/159 is unmerged and deliberately awaiting physical exactly-once delivery proof.

## What This Changes

Restore exactly-once RPC bridge text delivery by ensuring only one injected process consumes and dispatches each v2 inbox request.

## Best Possible Solution

Land exclusive atomic inbox-file claiming and intended-process bridge bootstrap after direct-target and chat-guid probes confirm one handler claim, response, database row, unique GUID, and recipient-visible delivery per request, with no missing sends.
