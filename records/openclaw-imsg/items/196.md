## Summary

Keep open. The implementation is narrowly scoped and preserves existing caption behavior by default, but it introduces public CLI and RPC controls without updating the documented poll/RPC contract, and it lacks real macOS Messages behavior proof before merge.

## What This Changes

Adds an opt-in `--no-comment` flag and `suppress_comment`/`suppressComment` RPC parameter so callers can send a native Messages poll without the automatic follow-up caption, with CLI and RPC regression tests.

## System Context

The imsg poll flow accepts CLI or JSON-RPC requests, creates a native Messages poll through the bridge, then normally sends a plain-message caption. This change adds a caller-controlled decision between retaining that caption and sending only the poll balloon.

Confirm the opt-in caption-suppression contract, document both CLI and RPC forms alongside the existing caption behavior, and merge only after a redacted real Messages transcript or terminal/log proof shows the poll-only result.
