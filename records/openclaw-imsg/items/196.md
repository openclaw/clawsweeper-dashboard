## Summary

This PR is still necessary: it adds an opt-in caption-suppression path that current main does not provide. The patch preserves the existing default caption, documents both public interfaces, adds focused CLI/RPC regression coverage, and reports detailed real iMessage behavior proof; the remaining merge gate is confirming the currently failing macOS job is only the reported unrelated timing flake.

## What This Changes

Adds `imsg poll send --no-comment` and `poll.send` `suppress_comment`/`suppressComment` controls so callers can send a native Messages poll without the automatic follow-up caption.

## System Context

The iMessage CLI and JSON-RPC bridge accept poll requests, invoke the IMCore bridge to send a native poll, and then optionally send a plain-text caption because Messages does not display the stored poll title. This change lets callers that already rendered context omit that second message while retaining caption behavior for all existing callers.

  Request --> Bridge[IMCore native poll bridge]
  Bridge --> Decision{Caption suppressed?}
  Decision -->|No, default| Caption[Send plain-text caption]
  Decision -->|Yes| PollOnly[Return native poll only]
  Caption --> Result[Messages conversation]
  PollOnly --> Result

## Best Possible Solution

Accept the opt-in, default-preserving API if maintainers want callers to control duplicate poll context, then rerun the macOS job and merge once the timing failure is confirmed unrelated or passes.
