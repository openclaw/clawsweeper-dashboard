## Summary

Keep this draft PR open. The patch has a coherent, narrowly scoped queue-state design and deterministic coverage, but it lacks after-fix real behavior proof for the Messages-relaunch path; that proof is required before merge because this changes when an in-flight iMessage send is declared undeliverable.

## What This Changes

This PR detects when a Messages.app relaunch has removed an in-flight bridge request, returns a bridge-not-ready error instead of waiting for the full response timeout, and adds queue-state tests.

## System Context

The iMessage bridge writes request files for an injected Messages process and polls a response queue for completion. This change sits in that polling loop and converts a vanished request-without-response into an immediate recoverable failure for callers such as message sends.

## Best Possible Solution

Retain the narrow queue-state detection, then demonstrate on a non-production macOS setup that killing or relaunching Messages during a send produces an early discarded-request error and that a later send succeeds after bridge recovery.
