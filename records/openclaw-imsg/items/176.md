- **[P2] Use a monotonic deadline for the timeout:** `Sources/IMsgCore/AttachmentResolver.swift:139-145`
  - body: `Date()` follows the wall clock, so moving the system clock backward while conversion is running can extend this wait beyond the promised bound. Measure the timeout with `ContinuousClock` or `DispatchTime` so clock synchronization or manual clock changes cannot defeat it.
  - confidence: 0.96
- **[P2] Avoid leaking the hung converter child from the test:** `Tests/IMsgCoreTests/UtilityTests.swift:586-590`
  - body: This fixture starts `/bin/sh`, which forks `sleep 30`; the timeout code terminates only the shell PID, so the test returns successfully while `sleep` remains alive. Use a non-forking fixture such as `exec sleep 30`, or explicitly manage the process group and assert that no child remains.
  - confidence: 0.99
