## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.87

Full review comments:

- **[P1] Reject scheduled attachments before dispatch:** `Sources/imsg/Commands/BridgeMessagingCommands.swift:172-180`
  - body: `--schedule` is accepted before the `if !file.isEmpty` branch, and that branch still invokes `.sendAttachment`; the helper attachment path never reads `scheduledAt` and builds the message with a nil scheduled date. `send-rich --file --schedule` will therefore send immediately while the user asked for Send Later, so reject this combination or implement and prove scheduled attachments before passing it to the bridge.
  - confidence: 0.95
- **[P2] Make scheduled GUID lookup unique:** `Sources/IMsgCore/MessageStore+Scheduled.swift:97-101`
  - body: `scheduledMessage(chatGUID:scheduledAt:)` returns the first row for the same chat within two seconds. If a user already has another scheduled row at that time, `send-rich --schedule --json` and RPC can return the wrong GUID, which can target the wrong row for follow-up list or cancel; include text or a row/sent-time bound and fail on ambiguity.
  - confidence: 0.86
- **[P2] Do not report cancellation without verified cancellation:** `Sources/IMsgHelper/IMsgInjected.m:2776-2782`
  - body: The helper returns `cancelled=true` as soon as an unproven private selector accepts one argument, but the PR proof says no true Send Later cancel path has been identified. If one of these selectors is present but does not cancel the pending bubble, callers will stop retrying and the message can still deliver; hide/gate cancel/delete or verify the row/UI is gone before returning success.
  - confidence: 0.78
- **[P3] Remove the release-owned changelog edit:** `CHANGELOG.md:5-6`
  - body: `CHANGELOG.md` is release-owned for this repository's review flow; normal feature PRs should carry release-note context in the PR body or commit message instead of editing the unreleased changelog.
  - confidence: 0.92
