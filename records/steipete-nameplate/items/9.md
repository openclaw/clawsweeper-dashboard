## Label Justifications

- `P2`: This is a normal-priority reliability bug in a user-facing CLI alert path with limited blast radius.
- `impact:message-loss`: Concurrent attention requests can silently drop one alert message when two CLI invocations share the same handoff file.

## Summary

Keep open: current main and v0.2.2 still use one fixed `attention.json` handoff file, and the open linked pull request is the active candidate fix rather than a merged implementation.

## What This Changes

The issue asks for attention request handoffs to use queued unique files so concurrent CLI alerts are not overwritten before the app consumes them.

## Best Possible Solution

Review and land https://github.com/steipete/Nameplate/pull/13 once its proof is acceptable, then let the closing reference resolve this issue.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: two `AttentionRequest.write()` calls to the default URL before the app's first `consume()` can replace the first JSON file, after which the app reads and removes only the later request.

## Solution Assessment

Yes. A queue directory plus deterministic app-side draining is the narrow maintainable fix, and the open linked PR already owns that implementation path.
