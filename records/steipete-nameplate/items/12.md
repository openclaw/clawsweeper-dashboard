## Summary

Current main and the latest release still limit remote-only visibility to virtual-display, Apple Screen Sharing, and VNC-style signals; proprietary-client support remains a valid but unproven feature extension requiring maintainer policy and connected-versus-idle samples.

## What This Changes

Extend remote-only overlay detection to recognize active proprietary remote desktop sessions without treating installed or idle remote-control software as an active viewer.

## Best Possible Solution

Capture redacted connected and idle diagnostics for each targeted client, approve the supported heuristic scope, then add narrowly scoped active-session parsing with positive and negative NameplateCore fixtures and updated user-facing documentation.
