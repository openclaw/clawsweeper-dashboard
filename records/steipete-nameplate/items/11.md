## Summary

This issue remains necessary because the configuration round-trip mismatch is still present on current main and in v0.2.5; the exact linked fix remains open and unmerged.

## What This Changes

Align config-imported watermark opacity with the Settings UI’s 0.5 maximum so shared configurations preserve their appearance.

## Best Possible Solution

Review and land https://github.com/steipete/Nameplate/pull/15 so valid values such as 0.45 survive import and only values above the UI maximum clamp to 0.5.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: importing watermarkOpacity=0.45 deterministically passes through a 0...0.3 clamp and is then written directly into settings, although the UI accepts 0.5. Swift tests were not run because this read-only review must keep the checkout byte-for-byte clean.

## Solution Assessment

Yes. Changing the existing core clamp to 0.5 and updating focused parser tests is the narrowest maintainable fix, with no new feature, setting, or policy surface.
