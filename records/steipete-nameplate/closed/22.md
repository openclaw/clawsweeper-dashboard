## Label Justifications

- `P0`: An invisible sticky topmost panel can block the interactive approval needed to continue a core user workflow.
- `impact:ux-release-blocker`: The user has no visible in-product recovery path and currently must use a terminal command to quit Nameplate.

## Summary

Current main still exposes the reported safety failure: the sticky attention card becomes mouse-interactive before visible presentation is validated, and neither v0.2.5 nor the only later main commit adds a safeguard. This should remain the canonical P0 issue; nearby attention PRs change queueing and acknowledgement behavior but do not fix invisible hit interception.

## What This Changes

Prevent an invisible attention card panel from intercepting clicks and provide safe automatic or user-invoked recovery when presentation fails.

## Best Possible Solution

Keep the card panel click-through until finite, nonempty, onscreen geometry and successful visible ordering are confirmed, then automatically close or disable interaction for invalid, offscreen, stale, or display-reconfigured presentations while retaining normal click-to-dismiss behavior and an obvious recovery action.

## Reproduction Assessment

No, there is not yet a high-confidence live reproduction because the rendering failure is intermittent. Source inspection does establish the unsafe current-main state: mouse events are enabled before visible presentation is confirmed, and a no-duration card can remain indefinitely.

## Solution Assessment

Yes, the narrowest maintainable solution is to enforce a visible-before-interactive invariant and deterministic teardown in the existing AppKit controller. A dismiss CLI or menu action is valuable recovery, but it should supplement rather than replace the lifecycle fix.
