## Risks / Open Questions

- Trusting Tailscale identity makes tailnet ACL configuration part of the gateway authorization boundary; an incorrect or unexpectedly broad ACL could grant gateway access without an OpenClaw token.
- Browser and auth-key enrollment introduce sensitive authorization material that must remain absent from setup logs, journals, diagnostics, command lines, persisted settings, and error messages.
- Provisioning Tailscale inside a managed WSL distro expands setup and replacement lifecycle ownership, including daemon health, tailnet mismatch, MagicDNS prerequisites, Serve cleanup, and recovery from partial replacement.
