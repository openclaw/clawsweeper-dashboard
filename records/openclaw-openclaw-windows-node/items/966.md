Keep open: current main can connect to user-managed Tailscale Serve endpoints, but it does not provision Tailscale, configure Serve, or enable tailnet identity authentication for generated WSL gateways; that distinct core workflow requires an explicit product and security decision.

## What This Changes

Add an opt-in setup mode that provisions Tailscale Serve and tailnet identity authentication for generated WSL gateways.

## Best Possible Solution

If maintainers approve core ownership, implement a staged setup-pipeline mode that performs prereplacement Windows/WSL checks, uses non-persistent authorization, configures loopback Serve, registers the discovered WSS endpoint through GatewayRegistry, preserves existing device/token credentials, provides in-product recovery, and proves the complete gateway-to-Windows-node path.
