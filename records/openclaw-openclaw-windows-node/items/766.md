## Summary

Current main has a managed SSH tunnel, but it still lacks the reporter’s required non-SSH command lifecycle and does not define native OAuth2-proxy authentication. The active epic retains this issue as the specific child, and a collaborator reopened it on July 13, 2026, so it remains necessary pending an explicit security and product decision.

## What This Changes

Requests a secure non-SSH connection option, preferably configurable start/stop lifecycle commands such as `kubectl port-forward`, with OAuth2-proxy authentication as an alternative.

## Best Possible Solution

Add a constrained per-gateway managed-port-forward profile in `OpenClaw.Connection`: executable plus structured arguments without shell evaluation, explicit user consent, a readiness probe, bounded startup and stop timeouts, owned-process cleanup, redacted diagnostics, and reconnect deduplication. Handle native trusted-proxy/OAuth authentication separately only if the gateway and client define a supported header or device-flow contract.
