## Summary

Keep open: current main still has distinct WSL/Linux gateway-control paths and Windows-host node command execution, and the available docs only partially explain that split rather than proving the reported path/semantics confusion is resolved.

## What This Changes

Clarify or repair the gateway command surface so WSL-side gateway administration and Windows-node command execution do not confuse Linux and Windows shell/path semantics.

## Best Possible Solution

Define an explicit command/path contract for local WSL gateway administration versus Windows node execution, then update the relevant UI, diagnostics, docs, and tests so each command surface names the side it runs on and the path format it expects.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Source inspection gives a medium-confidence reproduction of the mixed domains: gateway setup/control runs through WSL bash while system.run is registered through the Windows node host runner, but the issue lacks a concrete command/log showing the confusing failure.

## Solution Assessment

Is this the best way to solve the issue? Current main is not a complete solution; it has primitives and partial docs, but the narrow maintainable fix needs a maintainer-approved contract and focused proof around cross-boundary command semantics.
