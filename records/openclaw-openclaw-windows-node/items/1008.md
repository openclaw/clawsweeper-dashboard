## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.94

Full review comments:

- **[P1] Contain activation failures at the frame event boundary:** `src/OpenClaw.Tray.WinUI/Windows/HubWindow.xaml.cs:1033`
  - body: Wrap this hook in the repository's catch-and-log boundary. `NavigationScopeManager` cleans up and rethrows activation/deactivation failures, so once a page is mapped a normal view-model exception escapes `Frame.Navigated` and can crash the tray instead of preserving the existing navigation UI.
  - confidence: 0.98
- **[P1] Make the provider unreachable before disposing it:** `src/OpenClaw.Tray.WinUI/App.xaml.cs:77`
  - body: `PageActivator` resolves from `_services` while shutdown disposes that provider before clearing the field. A queued navigation callback can therefore call `GetService` on a disposed provider; atomically detach or null the root first, then dispose the captured provider.
  - confidence: 0.96
- **[P2] End the navigation scope when HubWindow closes:** `src/OpenClaw.Tray.WinUI/Presentation/AppServiceRegistration.cs:39`
  - body: Registering `NavigationScopeManager` as an app-root singleton leaves its current view model alive when the Hub closes. Once mappings exist, subscriptions and timers survive until another navigation or process shutdown; add an explicit reset on window close or move scope ownership to the Hub window lifetime.
  - confidence: 0.95
- **[P2] Define truthful UI-thread navigation semantics:** `src/OpenClaw.Tray.WinUI/Presentation/INavigationService.cs:20`
  - body: The new public navigation contract returns success without establishing that underlying frame navigation succeeded and does not specify or enforce UI-thread affinity. Return the real result on the UI thread, marshal asynchronously through `IUiDispatcher`, or narrow the contract and explicitly reject off-thread use before view models depend on it.
  - confidence: 0.92
