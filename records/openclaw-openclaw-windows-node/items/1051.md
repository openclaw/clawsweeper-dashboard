## Summary

This PR should remain open. It has strong runtime proof for the new V2 path, but the final head still intentionally removes two existing upgrade contracts: raw string-form `system.run` input and persisted V1 command-text approval rules. Because it is collaborator-authored and changes a security boundary, those release semantics need explicit maintainer approval or a compatible transition before merge.

## What This Changes

This PR replaces legacy Windows command-text approval rules with a V2 executable-identity approval system, makes low-level `system.run` argv-only, and runs approved argv through the local or MXC-contained runner.

## System Context

Windows node callers reach `system.run` through the gateway or local MCP interface, where a local approval decision is made before a command is executed either directly or inside the MXC sandbox. The PR changes the persistence format, input contract, policy evaluation, prompt UI, and execution handoff in that path.

## Architecture Diagram

flowchart LR
  A[Gateway or local MCP caller] --> B[Windows node system.run]
  B --> C[Input validation]
  C --> D[V2 approval coordinator]
  D --> E[Approval store and local dialog]
  D --> F[Approved canonical argv]
  F --> G[Local or MXC runner]
  G --> H[Command result]

## Best Possible Solution

Keep canonical argv as the internal execution representation, but preserve the supported string-form boundary or explicitly deprecate it; provide a constrained migration or visible reapproval path for V1 policy users unless maintainers explicitly approve a breaking security-release contract.
