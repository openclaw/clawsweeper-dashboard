## Summary

Keep this PR open for explicit maintainer review. It deliberately retires persisted V1 approval rules and rejects the previously supported string form of `system.run`; both are merge-critical upgrade and security-boundary changes, and the previous P1 compatibility concern remains unresolved by documentation alone.

## What This Changes

This PR replaces Windows node legacy command-text approvals with a V2 executable-identity approval system, makes low-level `system.run` argv-only, and routes approved argv through local and MXC execution paths.

## System Context

Windows node `system.run` requests enter through gateway or local MCP tooling, are authorized by the local exec-approvals policy, and then run through either the host or MXC sandbox. The changed approval layer controls both what existing automation can invoke after upgrade and what a local operator is asked to approve.

## Architecture Diagram

flowchart LR

  B --> C[V2 approval coordinator]
  C --> D[Policy store and local approval dialog]
  D --> E{Approved and still current?}
  E -->|Yes| F[Local or MXC runner]
  E -->|No| G[Typed denial]
  F --> H[Command result]

## Best Possible Solution

Preserve a narrow compatibility boundary for existing callers and define an explicit, maintainer-approved V1 upgrade path that keeps prior safety constraints effective or gives users a visible, informed migration/reapproval flow before their automation changes behavior.
