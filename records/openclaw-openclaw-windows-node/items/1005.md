## Summary

The fail-closed parser and WinUI recovery path address a real setup-safety bug, with current-head CLI and UI proof reported in the PR. However, rejecting every duplicate value option replaces the established first-value-wins CLI behavior for valid existing scripts, and the discussion contains no maintainer-confirmed decision to make that compatibility break.

## What This Changes

This PR centralizes SetupEngine argument parsing, rejects malformed or unknown arguments and explicit configuration-load failures, and shows configuration errors in the tray-hosted setup window.

## Best Possible Solution

Keep malformed, unknown, positional, and missing-value input fail-closed, but preserve legacy first-value-wins handling for duplicate value options unless a setup owner explicitly adopts the breaking duplicate-rejection contract and communicates the upgrade behavior.
