## Summary

This remains a useful implementation for the linked feature issue, and current main does not provision Tailscale Serve for generated WSL gateways. Strong live proof covers the successful path, but the patch should not merge until Tailscale daemon control is removed from the gateway service account, Serve-route validation is structural, and maintainers explicitly accept Tailscale identity as a core authentication boundary.

## What This Changes

The PR adds opt-in Tailscale Serve provisioning for generated WSL gateways, including setup UI and CLI/config, browser or auth-key enrollment, private WSS registration, recovery guidance, log redaction, documentation, and tests.

## Best Possible Solution

Keep Tailscale daemon and persistent Serve administration root-owned, parse tailscale serve status --json to require the exact loopback gateway backend, preserve token/device authentication compatibility, and land only after explicit approval of the opt-in tailnet-identity trust model.
