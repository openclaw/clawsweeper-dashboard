## Summary

Keep open: current main has important client-side hardening, but it does not conclusively fix the reported remote node token scope, node approval namespace, node-role rotation, and confusing 0-capability UX. The issue is now best treated as auth/security-boundary work coordinated with the open gateway-side counterpart and the local/remote pairing tracking items.

## What This Changes

The issue asks for remote Windows Node Mode pairing to work end-to-end, including non-empty/usable node authorization, working node approval, node-role token rotation, and clear tray recovery state when capabilities remain at zero.

## Best Possible Solution

Define the remote node approval contract across gateway and Windows client first, then land the selected gateway/client/UI/docs path with security-focused live remote pairing proof and regression coverage.
