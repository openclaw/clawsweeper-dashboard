## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P2] Block failures before leaving node startup Connecting:** `src/OpenClaw.Connection/GatewayConnectionManager.cs:855-856`
  - body: The branch now emits a snapshot with `NodeState=Connecting` during handshake, before `StartNodeConnectionAsync` has finished disconnecting any previous connector. If that previous `_nodeConnector.DisconnectAsync()` times out or throws, the helper returns before `StartNodeConnectionCoreAsync` and never calls `BlockNodeStartAsync`, so snapshot consumers stay stuck in Connecting; move the Connecting publish after the old disconnect succeeds or block the node before returning.
  - confidence: 0.87
- **[P2] Expose degraded snapshot state through app status:** `src/OpenClaw.Tray.WinUI/App.CapabilityHandlers.cs:54`
  - body: `connectionStatus` still comes from `_appState.Status`, while `OnManagerStateChanged` intentionally maps a Degraded manager snapshot back to legacy `Connected`. Because the MCP `app.status` result has no `overallState` or `nodeError` field, and `app.menu` follows the same legacy status, a blocked node can still look healthy to MCP/menu consumers; expose the manager-owned overall state and update the docs/tests for that shape.
  - confidence: 0.82
