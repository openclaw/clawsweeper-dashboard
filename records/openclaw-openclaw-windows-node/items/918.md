## Summary

Keep this PR open: the manager-owned snapshot direction is useful and not already implemented on current main, but the proposed node-start path still has a concrete lifecycle hole that can leave user-facing status stuck in Connecting instead of publishing the blocked node truth.

## What This Changes

The PR makes GatewayConnectionSnapshot/OverallConnectionState the connection lifecycle source of truth across the manager, tray, hub, Command Center, MCP app status/settings, docs, and focused tests.

## Best Possible Solution

Keep the manager-owned snapshot design, but make every node-start failure path publish a terminal blocked node snapshot before merge.

## Reproduction Assessment

Yes, from source inspection for the review finding: the PR branch sets NodeState to Connecting before connector execution, and the catch path logs connector failures without blocking the node snapshot. I did not run runtime tests in this read-only review.

## Solution Assessment

Mostly yes: manager-owned snapshots are the right owner for this bug class, but the connector exception path needs the same blocked-node semantics as missing credentials and gateway context.
