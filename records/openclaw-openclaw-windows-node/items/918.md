## Summary

Keep this PR open, but it still needs changes before merge: the manager-owned snapshot direction is useful, yet source inspection shows one node-start failure path can still leave the snapshot stuck in Connecting and MCP app.status/app.menu can still present degraded node state as legacy Connected.

## What This Changes

The PR makes GatewayConnectionSnapshot and OverallConnectionState drive connection truth across the connection manager, tray UI surfaces, MCP app status/settings behavior, docs, and regression tests.

## Best Possible Solution

Land the manager-owned snapshot design only after all node-start early failures publish a blocked snapshot and MCP app.status/app.menu expose manager-owned overall state/error detail with regression coverage.

- **[P2] Block failures before leaving node startup Connecting:** `src/OpenClaw.Connection/GatewayConnectionManager.cs:855-856`
  - body: This PR publishes `NodeState=Connecting` during handshake before the old connector has been retired.   - confidence: 0.9
- **[P2] Expose degraded snapshot state through app status:** `src/OpenClaw.Tray.WinUI/App.CapabilityHandlers.cs:54-55`
  - body: `connectionStatus` still comes from `_appState.Status`, and `OnManagerStateChanged` maps a degraded manager snapshot back to legacy `Connected`. Because `app.status` and `app.menu` do not expose `overallState`, `nodeState`, or `nodeError`, MCP clients can still see a healthy status when the manager snapshot is degraded.
  - confidence: 0.86
