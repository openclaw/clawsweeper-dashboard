## Summary

The requested capability remains missing: current `main` is the base of the still-open partial implementation at https://github.com/openclaw/openclaw-windows-node/pull/997, which explicitly leaves styled islands and cross-message selection unresolved. This substantial native interaction and accessibility subsystem needs an explicit scope and ownership decision before implementation.

Likely related people: `karkarl` (high confidence, designed and implemented the adjacent RichTextBlock work), `shanselman` (medium confidence, native-app product routing), and `ranjeshj` (medium confidence, recent chat/tray work).

## What This Changes

Requests a custom WinUI selection and accessibility layer that permits continuous drag-selection across styled chat controls and potentially multiple messages.

## Best Possible Solution

Resolve the bounded baseline in https://github.com/openclaw/openclaw-windows-node/pull/997, then sponsor a per-message design spike with one logical-document owner and proof for pointer selection, keyboard and Ctrl+C behavior, UI Automation ranges, styled-island painting, scrolling, and rerender preservation before considering transcript-wide scope.

Options:

- **Prototype per-message selection (recommended):** Sponsor a narrow spike crossing styled islands within one message and require keyboard, clipboard, UIA, rerender, scrolling, and visual proof before expansion.
- **Keep native controls:** Retain native per-control selection plus the whole-message Copy affordance and avoid owning a parallel text-selection stack.
- **Build transcript-wide selection:** Treat the logical transcript, multi-message selection, custom painting, and UIA provider as a larger planned native-chat initiative.
