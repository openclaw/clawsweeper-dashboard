## Summary

Keep open: current main contains MXC proof for `system.run`, but camera capture remains in the tray process and `browser.proxy` remains a separate authenticated local-control path. This collaborator-authored, security-sensitive epic child therefore still needs an explicit containment decision.

## What This Changes

Define, test, and document secure containment for the Windows node camera and browser-control tools.

## Best Possible Solution

Define measurable least-privilege invariants separately for camera and `browser.proxy`, preserve current authorization behavior, then add only the broker or MXC integration required and prove successful and denied operations on real Windows setups.
