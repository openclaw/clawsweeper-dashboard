## Summary

Keep this PR open for human review. The direct Reactor migration is a substantial default-chat rendering change, but it still globally suppresses Reactor accessibility and theme diagnostics for the project, and the supplied evidence does not show the four current-head scrolling scenarios working in a real tray session.

## What This Changes

This PR replaces the native FunctionalUI chat host in the chat page and pop-out window with a direct Microsoft UI Reactor timeline and composer, while continuing to use the existing gateway-backed chat provider.

## System Context

The tray app receives session history, streaming updates, attachments, and tool-call state through its shared chat provider, then renders them in the native chat page and pop-out window. This PR changes that final native rendering layer from FunctionalUI to Reactor, including timeline virtualization, scrolling, composer behavior, and accessibility presentation.

## Architecture Diagram

flowchart LR
  Gateway[Gateway session and message events] --> Provider[Shared chat data provider]
  Provider --> Reactor[Reactor chat root]
  Reactor --> Timeline[Virtualized message timeline]
  Reactor --> Composer[Native message composer]
  Timeline --> Hosts[Chat page and pop-out window]
  Composer --> Gateway

## Best Possible Solution

Keep the shared provider and existing host boundaries, narrow or remove the global Reactor diagnostic suppression so the new chat tree is checked, then add redacted current-head evidence covering the four scrolling scenarios before a maintainer decides whether to adopt Reactor as the default native chat renderer.
