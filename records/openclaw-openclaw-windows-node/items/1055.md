## Summary

Keep this PR open. Its Reactor migration is still unique branch work rather than an implementation already on `main`, but it needs real current-head behavior proof and a narrower treatment of Reactor diagnostics before it is ready for merge review.

## What This Changes

This PR replaces the default native FunctionalUI chat host with a Microsoft UI Reactor chat tree for the chat timeline, composer, scrolling, and existing ChatPage and ChatWindow hosts.

## System Context

The tray application's chat pages receive gateway-backed snapshots from the shared chat data provider, then render a native conversation timeline and composer. This change swaps the default rendering layer while preserving the surrounding WinUI windows and gateway/provider model.

## Architecture Diagram

  C --> D[Reactor chat root]
  D --> E[Virtualized message timeline]
  D --> F[Composer and attachments]
  E --> G[Chat page and pop-out window]
  F --> G

## Best Possible Solution

Keep the existing gateway/provider contract, scope any necessary Reactor warning suppression to demonstrably legacy surfaces, and add redacted current-head proof covering initial tail, streaming follow, scroll-away, and return-to-tail in both native hosts before deciding whether to land the default-renderer migration.
