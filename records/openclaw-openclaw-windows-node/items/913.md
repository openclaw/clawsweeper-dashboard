## Summary

Keep open: the ARM64/run-script alignment and tray hint are useful, but this branch also emits unsupported win-x86/win-arm RIDs from the build and run scripts, which can break existing 32-bit PowerShell or ARM process setups before merge.

## What This Changes

The PR adds UTF-8 BOMs to two PowerShell scripts, changes build/run runtime identifier selection, and prints a system-tray hint after launching the tray app.

## Best Possible Solution

Keep the run script aligned with build output while preserving the supported RID contract: ARM64 should use win-arm64, supported non-ARM64 shells should use win-x64 or fail clearly, and the PR should include redacted terminal proof from the target setup.

## Reproduction Assessment

Yes by source inspection: set PROCESSOR_ARCHITECTURE to x86 or ARM and the PR switch selects win-x86/win-arm, while the current WinUI project and MXC target support only win-x64/win-arm64. I did not execute the Windows build in this read-only review.

## Solution Assessment

No: aligning run-app-local.ps1 with build.ps1 is the right direction, but the implementation should not introduce unsupported RIDs. The narrower fix is to keep both scripts on the repository’s supported x64/ARM64 contract and add current-head proof.
