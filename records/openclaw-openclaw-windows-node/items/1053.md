## Summary

Keep this PR open for maintainer review. It has convincing current-head Windows recovery proof and resolves the prior migration/architecture findings, but it still contains an upgrade-safety defect: editing a setup-managed loopback gateway to a different loopback endpoint can retain managed ownership and make that new endpoint eligible for WSL repair and strong-credential gating. ## What This Changes

This PR adds listener-provenance checks, role-specific token recovery, explicit disconnect intent, and bounded WSL recovery for setup-managed local gateway connections.

## System Context

The tray connects an operator and Windows node to a gateway record stored locally. For setup-managed WSL gateways, the connection manager and repair services now inspect the Windows listener before sending stronger credentials, then can repair a proven obsolete local listener or restart the expected WSL gateway when transport recovery is safe.

## Best Possible Solution

Preserve managed-local ownership only for the unchanged endpoint or after independently proving that the edited loopback endpoint is the same setup-managed gateway, add regression coverage for a changed localhost port, then merge only if a maintainer sponsors the bounded default-on recovery contract.
