## Summary

Keep open: current main has an extensible voice-provider catalog but no Edge TTS provider, so the requested capability remains missing. Adding another network speech backend requires maintainer direction on whether Windows Voice Mode should own a second Microsoft implementation or reuse OpenClaw's existing gateway-level Microsoft TTS path.

**Likely related people:** RBrid is the strongest feature-history owner; NichUK and shanselman are also connected through the original voice-mode and TTS capability work.

## What This Changes

Add Edge TTS as a selectable text-to-speech provider, particularly for no-key natural Chinese voice synthesis.

## Best Possible Solution

Choose one Microsoft TTS ownership path: preferably reuse the gateway's existing provider when Voice Mode can consume it, or otherwise add a catalog-backed node provider with explicit data-egress disclosure, configurable voices, graceful failure behavior, MCP documentation, focused tests, and current-head Windows playback proof.

## Maintainer Decision

Required: true

Question: Should Windows Voice Mode reuse OpenClaw's existing gateway-level Microsoft TTS provider, or own a separate node-local Edge TTS integration?

Rationale: Both approaches can provide the requested voices, but they establish different long-term provider contracts, privacy disclosures, dependency boundaries, and failure behavior; repository history does not establish which layer should own this duplication.

Likely owner: RBrid

Options:

- **Reuse Gateway Provider (recommended):** Route compatible Voice Mode synthesis through OpenClaw's existing Microsoft TTS provider and avoid maintaining a second Edge protocol implementation.
- **Add Node Provider:** Approve a node-local catalog provider when offline-independent Windows playback is required, with explicit egress disclosure and end-to-end proof.
- **Decline Bundling:** Keep the current provider set and leave unsupported Edge integration outside the bundled Windows node.

## Risks / Open Questions

- A node-local Edge implementation may duplicate OpenClaw's existing gateway-level Microsoft TTS support and create two provider contracts with different voice names, behavior, and maintenance paths.

- The existing generic cloud transport may not directly model Edge's WebSocket framing and SSML protocol, making the actual implementation boundary larger than a catalog-only addition.
