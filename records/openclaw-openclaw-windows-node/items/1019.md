## Summary

This remains a concrete current-main shutdown race: send operations are serialized while graceful close is not, and no merged fix in the supplied related work addresses this WebSocket lifecycle path. Keep it open for a focused lifecycle-policy decision and regression fix.

## What This Changes

Serialize `CloseWebSocketAsync` with in-flight `SendRawAsync` work so concurrent close/send activity does not throw or skip the graceful WebSocket close handshake.

## Best Possible Solution

Define a bounded, shutdown-safe close-wait policy, then serialize the socket state check and `CloseAsync` behind the send gate with deterministic loopback coverage for both an in-flight send and an already-cancelled lifetime path.
