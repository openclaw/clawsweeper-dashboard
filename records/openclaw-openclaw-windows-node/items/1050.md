## Summary

Keep open. Current main still treats any registered `OpenClawGateway` distro as stale and unregisters it before retrying the same direct WSL install, so it does not preserve the reporter's manual recovery path or explain this specific WSL install failure.

## What This Changes

Fix setup when direct creation of the app-owned WSL gateway distribution fails, including a safe recovery path that does not erase a manually imported target distribution.

## System Context

The Setup Engine provisions a locked-down, app-owned `OpenClawGateway` WSL distribution during first-run onboarding. The tray wizard drives the sequential setup pipeline, which cleans prior setup state, creates the distro, then configures and starts the local gateway.

## Architecture Diagram

flowchart TD
  A[Tray setup wizard] --> B[Setup pipeline]
  B --> C[WSL preflight]
  C --> D[Existing distro cleanup]
  D --> E[Direct WSL install]
  E --> F[WSL gateway configuration]
  F --> G[Local gateway and pairing]
  D --> H[Recovery or actionable failure]

## Best Possible Solution

Preserve the app-owned WSL security model while adding a non-destructive recovery flow: diagnose known direct-install failures, retain a manually imported target until explicit validation and confirmation, and only delete distributions the setup engine can prove it owns.
