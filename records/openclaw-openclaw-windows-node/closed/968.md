## Label Justifications

## Summary

The reported dead end no longer exists in the supported UI: released code provides a managed-WSL-only Settings action that reopens the gateway’s provider/model/key onboarding without reinstalling WSL. The generic tray entry remains intentionally hidden, but the dedicated replacement path solves the central recovery need while preserving gateway ownership.

## What This Changes

Requests a discoverable in-app way to reconfigure model and API credentials for a setup-managed local WSL gateway.

## Best Possible Solution

Keep Companion Settings → Local Gateway → OpenClaw Onboard as the canonical reconfiguration path, and have any future chat auth/model recovery button route to that same wizard.

## Maintainer Decision

No. Current main and released versions expose Companion Settings → Local Gateway → OpenClaw Onboard, which directly reopens the installed gateway’s configuration wizard.

## Solution Assessment

Yes. The shipped gateway-specific wizard handoff is the narrowest maintainable solution because it preserves the intentional tray policy and keeps provider credentials owned by the gateway.
