## Summary

The issue remains necessary: current main still drops the Gateway’s runtime `contextTokens` value and presents `contextWindow` as the model picker’s unqualified usable limit, while the report supplies a concrete runtime reproduction and the affected release is still the latest release.

## What This Changes

Parse and retain model `contextTokens`, show it as the effective runtime budget, optionally distinguish a differing native `contextWindow`, and preserve the existing fallback when runtime metadata is absent.

## Best Possible Solution

Add nullable `ContextTokens` throughout the models.list-to-picker data path, render the effective runtime budget first and the native window only when different, preserve the current `ContextWindow` fallback, and prove all four metadata combinations in tests plus a current-head picker capture.
