## Summary

Current main and the latest release already cover the reported chat accent/text contrast problem with Fluent text-on-accent resources and a high-contrast-aware selection path, so this issue can close as implemented.

## What This Changes

The issue reports that chat UI text can become low contrast when synchronized to the Windows accent color and asks for WCAG AA contrast enforcement or decoupling.

## Best Possible Solution

Keep the shipped native chat implementation that uses Fluent accent-on-text semantic brushes and high-contrast-aware selection colors.

## Reproduction Assessment

No current-main failing path was found. Source and tagged-release inspection show accent-tinted user bubbles now use `TextOnAccentFillColorPrimaryBrush`, with a separate high-contrast-aware selection highlight for selected user text.

## Solution Assessment

Yes. The current implementation is the narrow maintainable solution requested: keep accent syncing where appropriate, but use Fluent semantic resources intended to preserve contrast across accent, theme, and High Contrast combinations.
