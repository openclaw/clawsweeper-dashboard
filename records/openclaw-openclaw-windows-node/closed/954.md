## Summary

Keep open: current main has one chat-title disambiguation path, but the Sessions page still renders row names directly from `SessionInfo.DisplayName` or key, so two active sessions with the same display name can remain indistinguishable.

## What This Changes

The issue asks for active chat/forked session names to be unique or visually disambiguated when display names collide.

## Best Possible Solution

Use one stable session-title formatter for both native chat and the Sessions page so duplicate display names get a key-derived qualifier while action routing still uses the original session key.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse or extract the existing chat session-title qualifier and cover duplicate display-name rows with focused tests, while leaving the fork root cause to the linked issue.
