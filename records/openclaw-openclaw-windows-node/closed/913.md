## Summary

## What This Changes

The PR modifies `build.ps1` and `run-app-local.ps1` to add UTF-8 BOMs, map processor architecture to runtime identifiers, and print a tray icon hint after launching the app.

## Best Possible Solution

Keep `run-app-local.ps1` aligned with `build.ps1`, but constrain both scripts to the supported `win-arm64`/`win-x64` contract or fail clearly before build, then add redacted current-head proof.

## Reproduction Assessment

Yes by source inspection: set `PROCESSOR_ARCHITECTURE` to `x86` or `ARM` and the PR switch selects `win-x86` or `win-arm`, while current main supports only `win-x64` and `win-arm64`. I did not execute the Windows build in this read-only review.

## Solution Assessment

No: aligning `run-app-local.ps1` with `build.ps1` is the right direction, but this implementation broadens the RID contract beyond current support. The narrower maintainable fix is to keep both scripts on x64/ARM64 and add current-head proof.
