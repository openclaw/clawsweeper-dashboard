## Repair Work Prompt

Fix the Windows host exec-policy ordering bug reported in https://github.com/openclaw/openclaw-windows-node/issues/971. In `SystemCapability`'s command and nested-target approval flow, permit a recognized wrapper such as `cmd.exe /d /s /c hostname` when the outer wrapper has no explicit matching deny and every parsed nested target is allowed. Preserve fail-closed behavior for malformed or empty wrappers, explicit deny rules on the outer wrapper, explicit deny rules on any nested target, command chains, prompts, and exact outer-wrapper allows. Add focused shared regression tests for the exact Gateway argv shape and all deny invariants. Do not change the broader Windows-versus-WSL command/path product contract tracked at https://github.com/openclaw/openclaw-windows-node/issues/911, do not add a config option, and do not edit `CHANGELOG.md`. Run the required build, shared tests, tray tests, and `scripts/validate-mxc-e2e.ps1` without `-AllowSkip`; include redacted real Gateway-path proof and rubber-duck review per `AGENTS.md`.
