## Label Justifications

- `P1`: An unhandled stdin write error can terminate an active workflow run and hide the failing command's useful error output.

## Summary

Keep open for ordinary maintainer review. The PR makes a narrow reliability repair in both child-process stdin write paths, includes a focused regression test, and supplies before/after terminal evidence that the workflow now preserves the command failure instead of terminating on an unhandled `EPIPE`.

## What This Changes

The PR attaches child-stdin error listeners in workflow shell steps and the stdlib exec runner, then adds a regression test for large step output piped into a fast-exiting command.

## System Context

Lobster workflows run shell commands and built-in commands as child processes, optionally passing output from one step to the next through stdin. This change sits at that process boundary and affects whether a failed child command is reported as a normal workflow failure or crashes the enclosing run.

## Best Possible Solution

Merge this narrowly scoped stdin-error guard after the normal maintainer review, retaining the regression test so both workflow shell commands and stdlib execution continue to surface authoritative child-process failures.
