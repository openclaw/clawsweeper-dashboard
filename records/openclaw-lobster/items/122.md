## What This Changes

The PR installs `child.stdin` error listeners in workflow shell and stdlib exec spawns, then adds a workflow regression test for a large stdin payload sent to a fast-exiting command.

## Best Possible Solution

Merge the narrow guards and regression coverage after a maintainer confirms that ignoring stdin-stream errors remains aligned with the intended child-process failure semantics in both execution paths.

## Reproduction Assessment

Yes, from source and supplied real-run evidence: pipe a payload larger than the OS pipe buffer into a workflow command that exits before reading stdin; current main can emit an unhandled EPIPE instead of the command-failure rejection.

## Solution Assessment

Yes. Registering a stdin error listener before the pending write is the narrowest solution because the existing close handler remains responsible for the child’s authoritative exit code and stderr.
