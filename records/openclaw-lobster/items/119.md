## Label Justifications

## Summary

The focused process-lifecycle changes are well tested, but the previously reported P1 remains: after an in-flight Gmail send completes under cancellation, the command returns normal output, so the unchanged pipeline runner can execute later stages despite the parent signal being aborted.

## What This Changes

The PR propagates abort signals to Gmail search and GitHub monitor subprocesses, stops later Gmail drafts after cancellation, and adds process-lifecycle fixtures and regression tests.

## Best Possible Solution

Define a pipeline-level partial-success cancellation result that preserves completed Gmail send outputs, prevents every later stage from starting, and returns an unambiguous cancellation envelope with a downstream side-effect regression.

- **Allow downstream continuation:** Keep normal output semantics after the completed send and narrow the PR claim to stopping only later drafts and owned subprocesses.

## Reproduction Assessment

## Solution Assessment

No, not yet. Moving cancellation ownership into subprocess-backed commands is the right narrow direction, but the Gmail partial-result path must also halt the remaining pipeline without hiding the definitive completed send result.
