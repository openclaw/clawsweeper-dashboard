## Summary

Keep this PR open for a focused repair: the command-level cancellation changes are useful and well-proven, but the unchanged pipeline contract still permits another stage to be invoked after an in-flight Gmail send settles under cancellation. This is the same P1 blocker reported against the current head. Likely related people: steipete and vignesh07, with medium confidence from recent runtime and workflow history.

## What This Changes

The PR adds AbortSignal-aware shutdown for Gmail search and the legacy GitHub PR monitor, stops later Gmail drafts after cancellation, and adds process-level cancellation tests and fixtures.

## Best Possible Solution

Add a stage-boundary abort guard that prevents invocation of any subsequent pipeline stage while still allowing an already-completed final Gmail send to return its definitive result, then cover `gog.gmail.send` followed by a downstream marker command.
