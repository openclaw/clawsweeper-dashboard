## Summary

This PR still needs one focused repair before merge: after a completed Gmail send, cancellation can leave the command blocked awaiting the next upstream draft, so the run does not promptly surface cancellation when that iterator ignores the signal.

## What This Changes

The branch propagates cancellation through pipelines, workflow resumes, process-backed commands, and monitor-state writes, with broad cancellation regression coverage.

## Best Possible Solution

Make the Gmail send input read abortable after any completed send—race or close a pending upstream iterator read on parent abort—while preserving the intended rule that an already-started send reaches a definitive completion first.
