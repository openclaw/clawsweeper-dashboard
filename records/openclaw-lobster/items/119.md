## Summary

This PR remains necessary because current main does not own cancellation for these child processes, but the previously reported blocker persists at the unchanged head: cancellation during an in-flight send can still allow the pipeline to start its next stage.

## What This Changes

The PR adds AbortSignal-aware shutdown for Gmail search and GitHub PR monitoring, stops later Gmail drafts after cancellation, and adds process-level cancellation fixtures and regression tests.

## Best Possible Solution

Add a stage-boundary cancellation check that retains the definitive output from an already-started send but exits the pipeline before invoking any following stage, then prove it with an observable three-stage process test.
