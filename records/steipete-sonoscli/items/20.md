## Summary

This is a concrete, source-reproducible authentication bug that remains necessary: current validation rejects a response shape permitted by Sonos SMAPI and reported to work downstream with an empty key. The repair is narrow and should preserve stricter validation for refresh responses that require a new private key.

## What This Changes

Allow SMAPI device authentication and token persistence when a valid auth token is returned without the optional private key.

## Best Possible Solution

Require authToken for initial device authentication and token-store persistence, preserve privateKey when supplied, and keep refresh-specific key requirements enforced in the refresh path with focused regression tests.

## Solution Assessment
