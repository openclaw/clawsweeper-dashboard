## Summary

Keep open for security review: the current documented fallback is described as narrowly bounded, but the available evidence does not prove that `expires_at` is bounded consistently in both runtime validation and the authoritative D1 query. The issue identifies a concrete authorization-boundary concern during upstream outages.

## What This Changes

Bound historical public-repository proof reuse after expiry so outage fallback accepts only a small explicit expiry slack in both runtime checks and D1 selection.

## Best Possible Solution

Define one small historical-expiry grace constant, apply it to both runtime validation and the authoritative D1 predicate, and add boundary tests proving acceptance inside the window and rejection beyond it.
