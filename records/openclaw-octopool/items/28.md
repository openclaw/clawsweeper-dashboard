This PR has a concrete cache-semantics regression: it caches GitHub's transient `202 Accepted` statistics responses, whereas current behavior only caches `200` responses. The stated test results are useful but do not provide after-fix deployed behavior proof, so it needs both a narrow predicate repair and real runtime evidence before merge.

## Best Possible Solution
