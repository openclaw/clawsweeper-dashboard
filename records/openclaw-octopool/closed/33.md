## Summary

Keep this PR open. The focused change appears to implement the requested fail-closed expiry boundary, but it needs real after-fix Worker/relay evidence before merge and should leave release-owned changelog editing to the release process.

## What This Changes

This PR rejects exact-expiry and expired public-repository proofs during GitHub-outage fallback in both the D1 query and Worker validation, adds regression coverage, and updates the cache documentation.

## System Context

Octopool relays cached GitHub responses only after confirming the upstream repository is public. When live GitHub checks fail, the Worker may use a recently stored D1 or edge-cache visibility proof, so its expiry predicate is an authorization boundary for relay delivery.

  E --> G[Fail-closed denial]

## Best Possible Solution

Preserve the no-grace fail-closed policy, retain matching D1 and Worker predicates with boundary coverage, remove the release-owned changelog edit, and attach redacted live Worker/relay evidence showing unexpired fallback acceptance and exact-expiry denial.
