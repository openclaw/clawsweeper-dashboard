## Summary

Keep this PR open: the protected-dashboard publish fix is targeted, but it currently exposes a new status-write token to the whole dashboard-generation shell step, and the PR has not shown an after-fix protected publish run. The recent related CI work by steipete is the strongest routing signal; a shell check points to scoping the credential before merge.

## What This Changes

The PR stages generated dashboard commits on an attempt-unique branch, applies the required Default Track status to the generated SHA, then fast-forwards protected `main` and deletes the staging branch.

## Best Possible Solution

Keep the temporary-branch/status/fast-forward design, but pass the status-write token only to the single `gh api` command and provide a redacted successful protected-dashboard publish run showing the generated SHA, required context, and final `main` update.
