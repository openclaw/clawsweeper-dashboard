## Summary

Keep open: current main still uses the ESP Component Registry API token, so the OIDC migration is not already implemented, but this PR should not merge until the workflow permission blocker and live upload proof are handled.

## What This Changes

The PR changes the component upload workflow to use GitHub OIDC by granting `id-token: write` and removing the ESP Component Registry API token input.

## Best Possible Solution

Keep the OIDC migration, add `contents: read` beside `id-token: write`, and merge only after redacted proof of a successful workflow run or registry upload verifies the tokenless path.
