## Summary

Keep open: current main still lacks caller-registered scope support, and this PR is the only active candidate, but it is not merge-ready because the signed auth scope string can diverge from the transmitted scope list and no real ESP behavior proof is posted.

## What This Changes

## Best Possible Solution

Keep the scope support effort open, but require one canonical non-truncating signed/transmitted scope representation, explicit overflow validation, focused tests, real ESP proof, and maintainer confirmation of the public API.

## Reproduction Assessment

Yes for the PR-introduced defect from source inspection: register scopes whose comma-separated form exceeds 127 bytes, and the branch signs only the prefix while still sending all registered scopes in JSON. The intended successful scoped-connect behavior has not been proven in a real ESP setup.

## Solution Assessment

No in its current form. Scope support belongs in the registry/connect path, but this implementation needs a single canonical scope representation, overflow handling, tests, proof, and maintainer confirmation of the public API contract.
