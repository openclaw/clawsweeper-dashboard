## Summary

Keep open: current main still lacks caller-registered scope support, and this PR is the only active candidate, but the branch is not merge-ready because its auth signature input can diverge from the transmitted scope list and no real ESP behavior proof is posted.

## What This Changes

Adds a configurable scope registry and public registration API, then includes registered scopes in connect JSON and the device auth signature payload.

## Best Possible Solution

Keep the useful scope-support direction, but require one canonical validated scope representation for both signing and JSON, focused coverage for limits/overflow, maintainer API confirmation, and redacted real ESP connect proof before merge.

## Reproduction Assessment

Yes for the PR-introduced defect from source inspection: register scopes whose comma-separated form exceeds 127 bytes, and the branch signs only a prefix while still sending the full registry in JSON. The intended successful scoped-connect behavior has not been proven in a real ESP setup.

## Solution Assessment

No in its current form. Scope support belongs in the registry/connect path, but this implementation needs a single canonical scope representation, explicit overflow handling, tests, proof, and maintainer confirmation of the public API contract.
