## Summary

This PR remains necessary because current main still advertises empty scopes and exposes no scope-registration API, but the proposed authorization-scope implementation is not merge-ready: it can sign a truncated scope list while advertising the full list, has no real-device proof, and leaves the supported role/scope contract unclear.

## What This Changes

Adds a configurable scope registry and public registration API, then includes registered scopes in connect-request signing, JSON serialization, and documentation.

## Best Possible Solution

Define the component's supported role/scope contract, then derive the signed value and JSON array from one complete canonical representation with explicit validation, bounded failure behavior, focused tests, and a redacted real-device connection transcript.

Options:

- **Define role-aware scopes (recommended):** Document allowed scopes per supported role and reject invalid or unrepresentable registrations before any connect request is sent.
- **Keep node scopes empty:** Retain the current node-only contract and close or redesign this PR around a separate operator-client mode.
