# Coding Plan for steipete/oracle#297: Placeholder-capture detection misses 'Deep Research App' wrapper, so session --render replays junk instead of live-reattaching

Source report: [records/steipete-oracle/items/297.md](records/steipete-oracle/items/297.md)

## Summary

Keep open: current main still only treats exact tool-only Deep Research captures as recoverable, so the reported multi-line "Deep Research App" wrapper can still replay stale session output instead of triggering live reattach.

## Plan

Fix the Deep Research completed-session recovery bug where `oracle session <id> --render` replays a multi-line ChatGPT `Deep Research App` tool-call wrapper instead of live-reattaching. Broaden the shared incomplete-capture detection so deep browser sessions treat structured wrappers beginning with or containing the tool-call wrapper shape as recoverable placeholders, but preserve false-positive guards for real reports that quote tool-call text. Reuse the detector consistently from `src/cli/sessionDisplay.ts` and browser Deep Research filtering rather than adding another ad hoc predicate. Add regression coverage for a completed deep browser session whose saved log contains a multi-line `Called tool / Deep Research App / Request / Response { session_id: ... }` wrapper, plus tests proving normal reports and reports that quote wrapper text are still accepted. Do not add a config option, change the public CLI workflow, or edit unrelated release/changelog content.
