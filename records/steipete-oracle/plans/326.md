# Coding Plan for steipete/oracle#326: Browser mode loses completed Pro answer after recoverable CDP disconnect (0.16.0)

Source report: [records/steipete-oracle/items/326.md](records/steipete-oracle/items/326.md)

## Summary

Current main still handles `connection-lost` differently from assistant timeout: it preserves a submitted run as `running` and returns reattach guidance, but only the timeout path invokes automatic reattach. That matches the reported failure, and neither v0.16.0 nor the current 0.16.1 changelog records a fix for recoverable target-level CDP disconnects.

## Plan

Fix the recoverable browser `connection-lost` path described by https://github.com/steipete/oracle/issues/326. On a controlled target-level CDP client disconnect after `promptSubmitted=true`, probe whether the recorded Chrome endpoint and target remain alive; reconnect to the exact target or verified saved ChatGPT conversation, continue waiting or harvest the completed response, and reconcile session/model-run metadata to `completed`. Reuse the existing reattach and conversation URL monitor architecture from https://github.com/steipete/oracle/pull/289 and the auto-reattach flow rather than adding a config option. Preserve the underlying disconnect reason and distinguish client disconnect, missing target, and actual Chrome closure. Add regression coverage for live-target reconnect, missing conversation URL with recorded-target fallback, wrong-target rejection, completed-state reconciliation, and unrecoverable closure. Follow AGENTS.md: never click “Answer now”; run relevant browser manual smokes and include redacted forced-disconnect proof. Because this is user-visible, add one grouped 0.16.1 changelog entry. Do not weaken conversation identity checks, change unrelated browser defaults, or alter archive behavior.
