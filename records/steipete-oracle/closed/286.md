## What This Changes

The issue requests a reliable browser-mode send/commit path or clearer diagnostics for moderately structured no-file ChatGPT prompts that fail before `promptSubmitted` and conversation metadata are persisted.

## Best Possible Solution

Keep this as a narrow browser submission reliability bug: preserve stage-local send/commit diagnostics and runtime/model-selection metadata on failure, then tighten the no-file commit heuristic only where live evidence shows a false negative.
