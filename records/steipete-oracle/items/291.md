## Summary

Keep this PR open: the selector direction is useful and the PR has real after-fix smoke output, but the patch leaves another baseline path using the broad selector, which can still suppress assistant snapshots in reused browser conversations.

## What This Changes

The PR makes browser response capture prefer precise `[data-testid^="conversation-turn"]` containers before falling back to the broad conversation-turn selector.

## Best Possible Solution

Use one precise-container-first turn-counting helper across pre-submit baseline reads, prompt-commit confirmation, assistant extraction, completion checks, and markdown fallback, with regression coverage for prior-turn browser conversations.

## Reproduction Assessment

Do we have a high-confidence way to reproduce the issue? Yes from source inspection: a reused conversation with prior turns can make `verifyPromptCommitted` return a broad committed-turn count that exceeds the new precise assistant turn index.

## Solution Assessment

Is this the best way to solve the issue? No; the precise selector is the right direction, but the fix must also update the prompt-commit baseline path that feeds `minTurnIndex`.
