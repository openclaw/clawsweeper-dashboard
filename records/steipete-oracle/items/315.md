## Summary

Current main does not normalize ChatGPT Work mode before Chat-oriented browser selection and submission, the report includes concrete live DOM and outcome evidence, and no canonical PR or existing setting owns the gap. This remains a valid bounded compatibility enhancement.

## What This Changes

Add browser startup detection that switches non-resume ChatGPT Work sessions to Chat before model and effort selection while rejecting explicit resume of a Work conversation.

## Best Possible Solution

Implement one shared ChatGPT startup normalizer before model and effort selection, using trusted CDP input, a post-switch readiness wait, root navigation for attached non-resume Work conversations, and a clear fail-closed error for explicit Work resumes.

## Repair Work Prompt

Implement the ChatGPT Work-to-Chat browser startup normalization described by https://github.com/steipete/oracle/issues/315. Add a shared helper used before model and effort selection that detects the exact visible Chat and Work radio controls, switches selected Work to Chat via trusted CDP input, verifies the state change, and waits for the replacement composer. For an attached existing Work conversation in a non-resume one-shot run, navigate to the configured ChatGPT root and normalize there; for an explicit resumeConversationUrl targeting a Work conversation, fail with a clear error rather than replacing the requested conversation. Preserve compatibility by doing nothing when mode controls and Work-conversation metadata are absent. Cover ordinary navigation, existing-tab attachment, explicit resume, absent controls, switch verification failure, and post-switch readiness. Run focused browser tests, pnpm check, and the non-live suite; then perform retained-browser live smokes for a Work-selected home page and an existing Work conversation without clicking Answer now.
