## Summary

Keep this issue open for maintainer product direction. Oracle already has a deliberately scoped browser-mode path for Deep Research, while the earlier implementation explicitly excluded connected apps; expanding to Web Search, Canvas, or connectors would add new, UI-sensitive capability rather than repair a defined regression.

## What This Changes

The issue asks whether Oracle browser mode should support ChatGPT composer tools and connected apps beyond its existing Deep Research handling.

## System Context

Oracle’s browser mode drives a signed-in ChatGPT page and submits prompts through the composer. Tool selection changes what ChatGPT can do for a run, so it sits between Oracle’s CLI/browser orchestration and the resulting assistant response/session output.

## Architecture Diagram

flowchart LR
  A[Oracle CLI request] --> B[Browser-mode run]
  B --> C[Signed-in ChatGPT page]
  C --> D[Composer tool selection]
  D --> E[ChatGPT run lifecycle]
  E --> F[Captured assistant response]
  F --> G[Oracle session output]

## Best Possible Solution

Keep Deep Research capability-specific unless a maintainer sponsors one narrowly defined additional tool with a stable user workflow, explicit permission/availability behavior, and real browser smoke proof before generalizing shared selection code.
