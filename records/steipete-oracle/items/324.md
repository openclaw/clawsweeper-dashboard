## Summary

This PR remains necessary because current main still uses a resolver nameserver directly as the WSL DevTools host. The proposed change is a focused correction with convincing before-and-after WSL proof, preserved override precedence, targeted regression coverage, and no blocking correctness or security finding.

## What This Changes

Centralizes WSL resolver-host detection, routes resolver-derived 127/8 addresses through the local Chrome launcher, and updates the browser smoke helper, tests, Windows notes, and changelog.

## Best Possible Solution

Land the centralized resolver classifier and focused tests so unambiguous guest-loopback resolver addresses use local Chrome while explicit and non-loopback remote-host routes remain unchanged.

## Solution Assessment

Yes. Rejecting only resolver-derived 127/8 values is the narrowest maintainable fix because those addresses are necessarily guest loopback, while explicit overrides and non-loopback resolver behavior remain intact.
