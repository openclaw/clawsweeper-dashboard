## Summary

Keep open: the linked Deep Research recovery bug is real and this PR targets the right area, but the current diff can misclassify already-recovered auto-reattach logs and turn completed sessions into errors; it also still needs real behavior proof before merge.

## What This Changes

The PR broadens Deep Research placeholder detection in `sessionDisplay` to treat captures that start with tool-call markers as recoverable and adds focused sessionDisplay tests.

## Best Possible Solution

Broaden placeholder detection and stale-answer trimming together so multiline wrappers trigger reattach only when no later recovered answer exists, backed by regression coverage and redacted live render proof.

## Solution Assessment

No: broadening the placeholder predicate alone is not the safest fix because it does not preserve the existing recovered-answer skip for appended auto-reattach logs. The narrow solution is to update the stale-answer guard and add the missing regression case.
