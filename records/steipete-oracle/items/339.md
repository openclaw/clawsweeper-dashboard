## Summary

This PR presents a coherent resilience fix with detailed before/after real-browser evidence, but it changes the default process model for every local Pro browser consultation. Keep it open for maintainer confirmation of that lifecycle and compatibility direction rather than treating it as cleanup-ready.

## What This Changes

The branch runs local Pro browser consultations in a detached Oracle worker while the original CLI follows the session log, preserving capture when the foreground CLI receives an unexpected termination signal.

## System Context

Oracle’s browser engine drives a signed-in ChatGPT browser session and persists the resulting transcript, output file, and session metadata. This change separates browser ownership from terminal streaming so a foreground CLI interruption does not leave an in-progress Pro response uncaptured.

Adopt detached worker ownership for local Pro browser runs only if maintainers want that as the supported default, with the existing foreground-debug escape hatch preserved and focused lifecycle coverage retained for interruption, Ctrl-C, recovery, and worker failure.
