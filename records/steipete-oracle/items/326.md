## Label Justifications

- `P1`: A completed long-running Pro answer can be lost from Oracle despite the browser and conversation remaining alive, breaking a real browser workflow.
- `impact:message-loss`: Oracle fails to capture or persist an assistant answer that completed successfully in ChatGPT.
- `impact:session-state`: The affected run remains permanently marked running with insufficient conversation metadata for effective recovery.

## Summary

Keep open: current main still converts any target-level CDP client disconnect into a closed-window failure, while the session runner preserves the run without automatically reconnecting through the existing conversation recovery path. This is a distinct remaining recovery bug rather than work already completed by the earlier stale-target fixes.

Likely related people: @LeoLin990405 for the saved-conversation recovery work, Felix Huber for timeout auto-reattach, and @pdurlej for recent browser recovery hardening, all with high confidence.

## What This Changes

Recover completed browser-mode answers after a target-level CDP disconnect by reconnecting to the live target, preserving conversation identity, and reconciling the session to completed state.

## Best Possible Solution

Extend the existing saved-conversation and target re-resolution machinery with a bounded connection-loss recovery loop that probes the CDP endpoint, reconnects to the original or conversation-matched live target, resumes capture or harvest, persists the conversation URL as soon as available, and records the original disconnect reason when recovery ultimately fails.

Yes at source level: a target client `disconnect` deterministically produces the closed-window error, and the `connection-lost` session branch does not enter the existing automatic reattach loop. A live transient-CDP reproduction was not performed during this read-only review.

## Solution Assessment

Yes in direction: reusing the existing conversation monitor and target re-resolution path is narrower and safer than creating another recovery system. The reconnect attempt should be bounded and must retain distinct diagnostics for transient client loss, missing target, and actual browser closure.
