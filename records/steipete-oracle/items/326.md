## Summary

Keep open: current main still treats a target-level CDP disconnect as a closed Chrome window and does not invoke automatic reattach from the resulting `connection-lost` path. The specifically linked implementation at https://github.com/steipete/oracle/pull/327 should remain the active resolution path until it merges or is otherwise resolved.

Likely related people: @LeoLin990405 for the recent conversation recovery implementation, Peter Steinberger for extensive recent browser-path maintenance, and Felix Huber for the original auto-reattach work.

## What This Changes

Handle recoverable browser CDP client disconnects by distinguishing them from a closed target, reconnecting or harvesting the live conversation, and reconciling the saved session to completed.

## Best Possible Solution

Review and land the linked PR after a forced target-client disconnect smoke proves that Oracle reconnects to the same submitted conversation, captures the completed answer, marks the session completed, and safely retains the existing running-session fallback when recovery cannot be established.
