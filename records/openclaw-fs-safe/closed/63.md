## Summary

Keep this PR open for normal maintainer review: it directly addresses the canonical data-loss report with a focused serialization boundary, comprehensive pairing coverage, and credible packaged-runtime proof. The remaining merge consideration is the intentional 0.5 removal of a public async lock option and its changed nested-mutation behavior.

## What This Changes

The PR serializes all `jsonStore` writes and read-modify-write operations by canonical file path, removes async `allowReentrant`, documents the 0.5 migration, and adds concurrency regression tests.

## System Context

`jsonStore` persists application state through guarded JSON file operations. This change places an in-process queue ahead of the optional sidecar lock so callers in one process and writers in separate processes both serialize around the same stored file.
