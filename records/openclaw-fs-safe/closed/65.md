## Summary

Keep this PR open. The containment hardening and focused regression coverage are useful, but the branch changes the exported native `openBeneath()` contract from a file-descriptor number to an object, which would break existing direct native callers without an explicit compatibility decision and migration path.

## What This Changes

The PR validates raw root-relative path spellings before normalized I/O, strengthens macOS native containment checks, exposes containment metadata on open results, and documents platform-specific guarantees.

## System Context

`root()` is the package’s capability-style filesystem boundary: callers provide a trusted root and untrusted relative paths flow through alias validation and guarded native or JavaScript filesystem operations. The changed path-resolution and native-open layers decide whether an operation remains beneath that root, then return verified file handles and metadata to application code.

## Architecture Diagram

flowchart LR
  Input[Trusted root and untrusted path] --> Validator[Alias-aware root-path validator]
  Validator --> Decision{Path remains beneath root?}
  Decision -->|No| Rejection[Outside-workspace error]
  Decision -->|Yes| Open[Native or JavaScript open]
  Open --> NativeCheck[Platform containment check]
  NativeCheck --> Result[Verified handle and metadata]
  Result --> Consumer[Application read or write]
