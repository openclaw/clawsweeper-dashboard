## Summary

Keep open for maintainer judgment: current main and v2026.6.11 still reject ByteRover 4.0.0's unshrinkwrapped runtime dependency shape and intentionally forbid mixing `runtimePlugins`/`runtimePluginSources` with raw `plugins.load.paths`, so this is a product/packageability decision rather than a cleanup close.

## What This Changes

A user wants ByteRover 4.0.0 to install declaratively with `runtimePluginSources` alongside other runtime plugins instead of hand-wiring raw plugin load paths.

## Best Possible Solution

Keep the deterministic runtime-plugin contract and make ByteRover installable by having its package publish npm-shrinkwrap.json or bundled runtime dependencies; only change nix-openclaw if maintainers explicitly choose a broader policy for unshrinkwrapped packages or mixed raw paths.
