## Summary

Keep open for a maintainer product/packageability decision. Current main documents how `runtimePlugins` and `runtimePluginSources` compose, but ByteRover still cannot use that managed path unless its runtime dependencies are reproducible under Nix or nix-openclaw adopts a dedicated package. Likely related people: @joshp123 for the issue routing and @bjesuiter for recent runtime-plugin packaging work.

## What This Changes

The issue requests a supported declarative way to install ByteRover alongside catalog runtime plugins without manually combining raw plugin load paths.

## Best Possible Solution

Preserve the single composable managed-plugin path and support ByteRover only after it publishes replayable dependencies, unless maintainers explicitly sponsor a pinned ByteRover Nix artifact with build and gateway-startup coverage.
