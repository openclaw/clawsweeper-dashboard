## Label Justifications

- `P2`: This is a bounded but user-visible runtime compatibility change that can prevent managed Codex command execution from starting or finding expected state.
- `merge-risk: 🚨 compatibility`: The launcher replaces inherited HOME with CODEX_HOME/home and changes the native profile-bin ownership contract for existing users.
- `merge-risk: 🚨 auth-provider`: Codex authentication and related state may be located relative to the inherited HOME that this launcher no longer exposes.
- `merge-risk: 🚨 availability`: The wrapper exits when CODEX_HOME/home/.nix-profile/bin is an existing non-store symlink or non-symlink.

## Summary

Keep this PR open for explicit maintainer review. The author is a repository collaborator, which repository policy excludes from automated cleanup, and the unchanged head still needs a decision on the deliberate Codex HOME isolation plus safeguards for pre-existing native-home state.

## What This Changes

The branch separates generic OpenClaw runtime tool PATH handling from a Nix-managed Codex app-server wrapper so Codex command execution can resolve configured Nix runtime packages.

## Best Possible Solution

Keep the generic runtime-path split, but preserve or deliberately migrate required Codex state, make existing native-home profile state non-blocking, and document or reject every supported Codex plugin source form with focused upgrade coverage.
