## Summary

Current main has no proven ACPX fix: it documents a declarative runtime-plugin packaging system but does not establish ACPX as a supported dependency-closed plugin. The identical earlier discussion at https://github.com/openclaw/nix-openclaw/issues/73 was closed as not planned rather than implemented, so this issue remains useful for an explicit support decision.

## What This Changes

Add ACPX to the Nix-managed runtime-plugin packaging path with all runtime dependencies available without writes to the immutable store.

## Best Possible Solution

Either add ACPX to the generated supported runtime-plugin catalog with a reproducible dependency closure and startup check, or reject it during configuration with an actionable unsupported-plugin diagnostic before the gateway attempts any store write.
