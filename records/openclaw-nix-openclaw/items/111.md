## Summary

Current main confirms the reported path mismatch, but not the claimed functional loss: nix-openclaw exposes plugin skills as workspace symlinks that OpenClaw may reject, while independently loading the original skill directories through `skills.load.extraDirs`. Runtime inventory evidence is still needed to determine whether goplaces is unavailable or only produces a duplicate-discovery warning.

## What This Changes

Ensure Nix-managed tool-plugin skills such as goplaces load without being rejected as out-of-root workspace symlinks.

## Best Possible Solution

Keep `skills.load.extraDirs` as the authoritative declarative loading path and either remove redundant workspace skill links or narrowly trust only the exact generated targets, with regression proof that goplaces appears once and no out-of-root warning remains.
