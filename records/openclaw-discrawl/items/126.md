## Label Justifications

- `merge-risk: 🚨 message-delivery`: Merging the blanket nonfatal policy could leave Discord events unpersisted indefinitely while the tail process continues running.

## Summary

Keep open. This member-authored PR is not eligible for automated cleanup, and it has a blocking reliability gap: every handler error becomes nonfatal, including permanent store failures, so the tail can remain apparently healthy while later Discord events repeatedly fail to persist.

## What This Changes

The PR changes Discord tail processing so event-scoped handler errors, panics, and timeouts are logged with safe event metadata without stopping the tail, while queue saturation remains fatal.

## Best Possible Solution

Continue after isolated event failures, but preserve a fatal or circuit-breaker path for systemic and repeated failures, with focused tests proving both later-event continuation and bounded escalation during persistent store failure.
