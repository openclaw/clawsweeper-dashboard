## Summary

The latest head still has the previously reported delivery blocker: recovered message-handler panics continue through the ordered tail, but the durable exact-message ledger records only timeout failures. A later message can therefore advance the channel cursor and leave the panicked message permanently absent. The PR otherwise has strong automated validation, but this unchanged P1 finding should be fixed before merge.

**Likely related people**
- `hannesrudolph` — high confidence; repository member and owner of the six-commit tail recovery implementation.

## What This Changes

The PR separates recoverable Discord tail-handler failures from fatal tail failures, adds durable exact-message timeout recording and bounded replay, and exposes replay-only CLI controls with extensive regression coverage.

## Best Possible Solution

Record message-scoped panic failures transactionally through the same exact-message ledger before later ordered work can advance, and treat inability to persist that recovery identity as fatal while preserving continuation and three-failure escalation for successfully recorded panics.
