## Summary

The PR should stay open because current `main` does not solve the reported tail-loss problem, but the proposed continuation path still lacks durable recovery for message handlers that panic: the tail logs and continues while the replay recorder explicitly ignores every non-timeout failure. The recovery design is well tested and the earlier persistent-failure finding appears addressed, but this remaining message-loss path should be fixed before merge.

## What This Changes

Separates event-scoped Discord tail failures from fatal failures, adds durable exact-message replay and a replay-only CLI mode, and expands focused store, syncer, Discord client, and CLI coverage.

## Best Possible Solution

Record every message-scoped failure that escapes normal handler bookkeeping—especially recovered panics—using a content-free sentinel classification, then replay it through the same bounded exact-message path while retaining persistent-failure escalation and idempotent cursor rules.
