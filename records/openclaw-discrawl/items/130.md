## Summary

The current head is unchanged from the last completed review, so the previously reported end-of-options compatibility bug remains: help interception can consume a literal `-h` or `--help` appearing after `--` instead of letting the selected command receive it. The Kong-based help direction is useful and CI is green, but this narrow parser defect should be repaired before merge.

## What This Changes

The PR replaces static CLI usage output with Kong-generated root, command, and nested-group help handled before runtime initialization, and expands CLI help regression coverage.

## Best Possible Solution

Make the early help scan stop at the first `--`, preserve all later tokens for normal command dispatch, and add regressions for both `-h` and `--help` after the delimiter while retaining side-effect-free help paths.
