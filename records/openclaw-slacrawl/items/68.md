## Summary

Keep open: current main and v0.7.3 still append a `message_events` row for every message upsert, and purge still only removes event history for messages selected for deletion. The storage concern is real, but deduping or compacting retained event history needs maintainer policy direction because current docs describe watch as appending event history.

## What This Changes

The issue asks Slacrawl to deduplicate unchanged `message_events` snapshots during desktop watch ingestion and optionally add a purge flag that compacts retained event history.

## Best Possible Solution

Choose the event-retention policy, then implement latest-event dedupe and/or explicit purge compaction with preview/reporting and focused store plus CLI regression tests.

## Reproduction Assessment

Yes for the duplicate-insertion path: source inspection shows every successful `UpsertMessage` appends an event, and watch repeatedly upserts desktop state. The live several-GB database growth was not reproduced in this read-only review.

## Solution Assessment

Unclear until maintainers choose the retention semantics. Latest-event dedupe is a narrow candidate for preventing new duplicates, while retained-history compaction is destructive and needs an explicit product decision.
