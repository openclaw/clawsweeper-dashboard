## Summary

Keep open: current main still appends a `message_events` row on every message upsert, and purge still only removes event rows for messages selected for deletion. The storage growth is well supported by source inspection, but changing append/compaction behavior needs maintainer policy direction because the docs currently describe desktop watch as appending event history.

## What This Changes

The issue asks Slacrawl to reduce unbounded `message_events` growth from repeated desktop-watch upserts and optionally add purge-time compaction for retained message event history.

## Best Possible Solution

Choose the event-history retention policy, then implement latest-event dedupe and/or opt-in retained-event compaction with preview/reporting and focused store plus CLI regression tests.

## Reproduction Assessment

Yes for the source path: every message upsert still appends a message event, and desktop watch is documented as repeatedly upserting desktop state. The live multi-GB database growth was not rerun during this read-only review.

## Solution Assessment

Unclear until maintainers choose the retention semantics. Latest-event dedupe is a narrow candidate to prevent new duplicates, while retained-history compaction is destructive and should be explicit and previewable.
