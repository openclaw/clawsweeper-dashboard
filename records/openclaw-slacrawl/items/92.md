## Summary

Keep this collaborator-authored PR open. The merge-safe import direction is well scoped and backed by fixture coverage, but tombstoned attachment bytes can still be republished by `publish --with-media`, contradicting the new deletion semantics and potentially retaining removed content in the shared archive.

## What This Changes

The branch makes routine Git-share updates merge canonical rows by default, adds explicit `update --restore` replacement behavior, and retains source-attributed tombstones for removed message files and mentions.

## Best Possible Solution

Filter tombstoned `message_files` out of media export, retain existing canonical tombstone metadata, and add an end-to-end publish/import regression that proves deleted attachment bytes are absent while live attachments remain exportable.
