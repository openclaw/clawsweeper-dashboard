## Summary

Keep this PR open for maintainer review. It presents credible live OAuth vision evidence and a focused provider/test change, but it introduces an authentication-routing and credential-rotation contract that should be explicitly accepted before merging.

## What This Changes

This PR detects ChatGPT OAuth credentials, sends OpenAI Responses requests through the ChatGPT Codex backend with the account ID, refreshes rotated credentials, and adds OAuth vision coverage while preserving the API-key path.

## System Context

Tachikoma’s OpenAI Responses provider converts application text, image, and tool requests into streamed OpenAI responses. This change selects the request transport from the available credential type, affecting endpoint selection, request headers, and persisted OAuth credentials for downstream embedding applications such as Peekaboo.

## Architecture Diagram

    C[API key or ChatGPT OAuth credentials] --> D[Credential selection]
    D -->|API key| E[Platform Responses endpoint]
    D -->|ChatGPT OAuth| F[Token refresh and account ID]
    F --> G[Codex Responses endpoint]
    E --> H[Streamed provider response]
    G --> H

## Best Possible Solution

Adopt one documented credential-routing contract: preserve existing Platform API-key behavior, use the Codex transport only for recognized ChatGPT OAuth credentials, and retain focused tests for API-key, valid OAuth, expired OAuth refresh, and persisted-credential upgrade behavior.
