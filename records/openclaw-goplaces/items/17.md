## Summary

Current main still appears to expose the reported CLI/docs mismatch: coordinate flags are parsed directly by Kong, docs promise space-separated long flags, and no related PR owns the fix.

## What This Changes

The issue asks for negative numeric CLI flag values, especially `--lng`, to work in documented space-separated form instead of being treated as new flags.

## Best Possible Solution

Preserve the documented `--flag value` contract by normalizing negative numeric values for numeric flags before Kong parsing, then add focused regression coverage for coordinate flags across affected commands.

## Reproduction Assessment

Yes, source-reproducible: the issue gives a concrete command, current main still parses raw args through Kong, and docs still show the failing space-separated negative longitude form. I did not live-run the CLI in this read-only review.

## Solution Assessment

Yes, a narrow parser compatibility shim plus regression tests is the best maintainable fix. A docs-only equals-form warning would weaken the existing documented contract and leave surprising behavior in place.
