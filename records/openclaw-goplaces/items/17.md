## What This Changes

The issue reports that space-separated negative coordinate values such as `--lng -70.8483` are parsed as flags instead of numeric flag values.

## Best Possible Solution

Preserve the documented `--flag value` contract by normalizing negative numeric values for the affected numeric flags before Kong parsing, then add regression coverage for search, nearby, autocomplete, and directions coordinate flags.

## Reproduction Assessment

Source-reproducible: the parser path passes raw args to Kong while docs promise space-separated long flags and show negative coordinate examples; tests only prove the equals form for negative longitude. I did not run the CLI because this review is constrained to read-only inspection.

## Solution Assessment

Yes, a narrow parser compatibility shim plus regression tests is the best maintainable fix because it keeps current documentation true and avoids making users remember a special equals-only rule for western or southern coordinates.
