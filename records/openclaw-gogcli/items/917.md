## Summary

This issue remains necessary: current `main` still discards external hyperlink targets from ordinary text runs, while v0.34.0 addressed only smart-chip elements. The existing opt-in rendering and JSON sidecar framework provides a narrow compatibility-preserving fix path.

**Likely related people**
- TurboTheTurtle — high confidence; introduced the adjacent smart-chip rendering path used by `docs cat`.
- steipete — medium confidence; integrated and released the v0.34.0 Docs rendering work.

## What This Changes

Preserve external hyperlink targets on ordinary Google Docs text runs in opt-in rendered output and structured JSON instead of returning only visible anchor text.

## Best Possible Solution

Extend the existing opt-in rendered-text path to emit Markdown-style links and add per-run or sidecar link metadata to JSON, while leaving default text and `--plain` compatibility unchanged and avoiding noisy `[url](url)` rendering.
