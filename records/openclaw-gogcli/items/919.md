## Summary

Current main does not provide either remote-content mode, and the PR’s prior parseability and runaway-parser defects are fixed with strong live proof. The remaining question is deliberate product/security scope: whether core gogcli should own untrusted attachment text extraction or land only the narrower inline transport capability.

Likely related people: @steipete (high confidence, release/product boundary), @salmonumbrella (medium confidence, Gmail attachment hardening history), and @zerone0x (medium confidence, attachment output/cache behavior).

## What This Changes

Adds `--inline` base64 output and `--text` extraction to Gmail attachment downloads, with metadata fallback, bounded subprocess-isolated PDF parsing, tests, docs, and a new PDF dependency.

## Best Possible Solution

Land the bounded `--inline` mode as the narrow remote-client fix, and include `--text` only if maintainers explicitly choose to support attachment parsing in core with the dependency, subprocess, safety-profile, and untrusted-content obligations that entails.
