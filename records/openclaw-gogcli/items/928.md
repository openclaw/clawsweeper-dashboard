## Summary

Keep this issue open for maintainer product and security-boundary direction. Current `gog` Photos support is deliberately limited to app-created media, while the requested complete-library backup remains a distinct, sensitive new API/workflow surface; the current Data Portability scope catalog does not list a Google Photos resource. ([github.com](https://github.com/openclaw/gogcli?utm_source=openai))

## What This Changes

Explore a supported, automatable workflow for complete Google Photos backups through Data Portability, Takeout, or ingestion of Takeout archives delivered to Drive.

## Best Possible Solution

First publish a short feasibility decision that rules out unsupported Data Portability access for Photos and, if the repository wants to proceed, scopes a separate opt-in Drive-delivered Takeout downloader with resumable downloads, integrity checks, explicit state ownership, and no remote deletion by default.

## Risks / Open Questions

- A full-library export would handle highly sensitive personal media and potentially restricted OAuth scopes; its consent, verification, archive-storage, integrity, and default-retention behavior need an explicit security design before implementation. ([developers.google.com](https://developers.google.com/data-portability?hl=en&utm_source=openai))
