## Summary

Keep this issue open for a maintainer product decision. Current main does not support whole-library Photos export, and although Google’s Data Portability scopes exclude Photos, scheduled Takeout delivery to Drive leaves a distinct ingestion workflow worth evaluating. 

## What This Changes

Explore an official, automatable Google Photos backup workflow using Data Portability, Takeout, or Drive-delivered export archives.

## Best Possible Solution

Publish a dated feasibility document that rejects unsupported Photos portability and Takeout-creation paths, then define a narrow non-destructive Drive-delivered archive ingestion design with resumable downloads, integrity verification, protected state, and no remote deletion by default.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should gogcli own a narrow Takeout-to-Drive ingestion primitive for Photos archives, or keep complete Photos backup outside the CLI?

Rationale: The broad Data Portability route is unavailable for Photos, but Drive-delivered Takeout ingestion is technically plausible and would introduce persistent state, sensitive archives, large-file transfer, and long-running backup semantics that require maintainer sponsorship.

Likely owner: steipete

Owner confidence: high

Options:

- **Feasibility and narrow ingest (recommended):** Document the official API limits and design a non-destructive Drive-delivered Takeout downloader before sponsoring implementation.
- **Keep outside gogcli:** Document that complete Photos backup remains a user-managed Takeout workflow outside this CLI.
- **Sponsor broader backup surface:** Adopt a portability or Takeout command family and accept its verification, security, and long-running workflow obligations.
