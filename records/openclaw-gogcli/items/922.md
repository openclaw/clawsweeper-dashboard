## Summary

Current main still uses the padding-rejecting decoder in the reported command path, while the open linked pull request is the direct candidate fix; keep this issue open until that PR is reviewed and merged.

## What This Changes

Fix `gog gmail get --format raw` so valid padded base64url responses decode and emit the raw RFC822 message.

## Best Possible Solution

Use one shared decoder that accepts both padded and unpadded base64url, retain command-level regression coverage for trailing padding, and verify the corrected raw output against a real Gmail response.

## Solution Assessment

Yes. Reusing a shared decoder that tolerates both valid Gmail base64url variants is the narrowest maintainable correction and avoids divergent backup and interactive retrieval behavior.
