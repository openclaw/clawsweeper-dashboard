## Summary

This appears to be a valid, narrow Gmail output bug: the current command surface routes `gog gmail read` to thread operations, while the reported draft state is only reliably visible through underlying message labels. The requested plain-output marker fits the repository’s agent-friendly, stable-output vision and is not shown as fixed in the current v0.34.1 release.

## What This Changes

Mark draft messages prominently in human-readable Gmail thread output so an unsent reply cannot be mistaken for a sent message, without changing existing JSON or plain contracts.

## Best Possible Solution

Add a focused status suffix such as `[DRAFT — NOT SENT]` to each affected human-readable thread-message heading, derived from the exact Gmail `DRAFT` label, with regression coverage for mixed sent-and-draft threads and no change to JSON output.
