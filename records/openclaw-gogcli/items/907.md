## Summary

Keep open: current main still skips non-TextRun Google Docs paragraph elements in `docs cat`, and JSON output wraps the same lossy text. The bug is source-reproducible, but maintainers should choose the script-visible output compatibility contract before an automated fix changes plain or JSON output.

## What This Changes

`docs cat` should stop silently omitting Google Docs smart chips from plain and JSON output, or expose chip data through a compatible mode.

## Best Possible Solution

Add a shared chip-aware Docs read renderer for default, tab, all-tabs, numbered, and JSON paths, with tests for person, date, and richLink elements after maintainers choose the output contract.
