## Summary

Keep open: current main still drops non-TextRun Google Docs elements from `docs cat` text extraction, and JSON output wraps the same lossy text. The bug is source-reproducible, but maintainers should choose the compatibility shape before changing script-visible output.

## What This Changes

Request that `gog docs cat` render person/date/richLink smart chips in text output and expose structured chip data in JSON instead of requiring `--raw`.

## Best Possible Solution

Add a shared chip-aware Docs read renderer for default, tab, all-tabs, numbered, and JSON paths, with tests for person, date, and richLink elements in paragraphs and tables after maintainers choose the output contract.
