## Summary

Keep open: current main still skips Google Docs non-TextRun inline elements in `docs cat`, and JSON output wraps that same lossy text. The remaining blocker is maintainer intent on the script-visible output contract.

## What This Changes

The issue requests that `gog docs cat` render or expose Docs smart chips instead of silently omitting person, date, and richLink elements from text and JSON output.

## Best Possible Solution

Add a shared chip-aware Docs read renderer/extractor for default, tab, all-tabs, numbered, and JSON paths, with tests for person, date, and richLink elements once maintainers choose the compatibility contract.
