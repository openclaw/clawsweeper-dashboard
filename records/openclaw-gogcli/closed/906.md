## Summary

Current main and the v0.33.0 release already apply Gmail system-label `labelIds` to the top-level threads search path, with thread-specific regression coverage for unread/system-label queries.

## What This Changes

The issue requests that `gog gmail search "is:unread"` apply the unread system-label filter on the Gmail `threads.list` path, matching `gog gmail messages search`.

## Best Possible Solution

Keep the shipped shared Gmail search request helper and direct users affected on older binaries to upgrade to v0.33.0 or newer.

## Maintainer Decision

## Reproduction Assessment

No current-main failing reproduction remains: source inspection shows `gog gmail search` now sends Gmail `labelIds` on the threads path, and the checked-in httptest coverage verifies `SPAM` plus `UNREAD` for a thread search. The live report appears to describe an older v0.31.1 binary.

## Solution Assessment

Yes. The current shared request-options helper is the narrowest maintainable solution because it applies the same system-label extraction to both `threads.list` and `messages.list` without adding a new command mode or config option.
