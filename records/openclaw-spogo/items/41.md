## Summary

The implementation is focused and uses the appropriate existing error path, but the new HTTP-date display can understate Spotify’s earliest retry time; the PR also still lacks required after-fix evidence from a real Spotify 429.

## What This Changes

The PR adds Spotify `Retry-After` metadata to `APIError`, parses delta-seconds and HTTP-date header forms, displays a cooldown hint in error text, and adds focused parsing and final-retry tests.

## Best Possible Solution

Keep the existing error-path approach, format every positive earliest-retry hint with ceiling semantics, cover the fractional HTTP-date boundary, and retain the current retry policy unchanged.
