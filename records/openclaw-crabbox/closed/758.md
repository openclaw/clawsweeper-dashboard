## Label Justifications

- `P2`: The report describes a bounded authenticated artifact broker security issue with deployment-specific prerequisites and limited blast radius.
- `impact:security`: The issue concerns coordinator authorization boundaries and signed artifact upload/read grants across logical identity namespaces.

## Summary

Keep open: current main still builds brokered artifact keys by normalizing authenticated owner and caller prefix as collapsible path components, and this report covers a distinct identity-component collision that is not fully closed by the open org-namespace tracker.

## What This Changes

The issue reports a brokered artifact signing bug where slash-bearing authenticated owner values and caller-supplied artifact prefixes can normalize to the same object key.

## Best Possible Solution

Encode or otherwise delimit authenticated org and owner as separate server-side namespace components for new brokered artifact grants, preserve a deliberate compatibility path for existing artifact URLs, and add regression coverage for both org omission and owner/prefix collision cases.

## Reproduction Assessment

Yes. Source inspection shows `POST /v1/artifacts/uploads` passes only `requestOwner(request)` into `artifactUploadResponse`, and `artifactPrefix` normalizes owner and request prefix with the same slash-splitting helper, so distinct owner/prefix tuples can produce the same key prefix.

## Solution Assessment

Yes on direction, but the exact key format is compatibility-sensitive. The maintainable fix should encode or otherwise delimit authenticated identity components, include org, and deliberately handle existing owner-only artifact links.
