## Summary

Keep open: current main and v0.34.0 still let Hetzner direct cleanup and stop paths trust weak labels before destructive deletion, so the central security report remains necessary.

## What This Changes

The issue asks Crabbox to strengthen Hetzner direct-provider ownership checks before listing, resolving, releasing, or cleaning up provider servers.

## Best Possible Solution

Add a canonical Hetzner ownership predicate for list, resolve, release, and cleanup, require canonical lease identity plus slug/provider or an explicit retained-claim legacy path, and cover weak-label cleanup cases with regression tests.

## Reproduction Assessment

Yes. Source inspection shows a weakly labeled Hetzner server can enter List/Cleanup through label_selector=crabbox=true, pass validateHetznerServerOwnership with any non-empty lease label, and reach DeleteServer when cleanup rules select it.

## Solution Assessment

Yes for the boundary: the narrow fix belongs in the Hetzner adapter ownership predicate and tests. The legacy-provider-label and local-claim compatibility branch needs maintainer/security direction before implementation.
