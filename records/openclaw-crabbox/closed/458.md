## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.99

Full review comments:

- **[P1] Persist recovery state before remote Orgo creates:** `internal/providers/orgo/backend.go:346`
  - body: Both the workspace and computer are created before any lease claim is written. If Crabbox exits after either successful API call, later cleanup has no durable ID to recover, so persist mutation state before each remote create and update it as identities arrive.
  - confidence: 0.99
- **[P1] Redact credentials from Orgo HTTP error bodies:** `internal/providers/orgo/client.go:315`
  - body: The non-2xx path returns the upstream body verbatim after sending the bearer key. A service, proxy, or custom endpoint that echoes the header or raw key will disclose it in the CLI error, so redact the configured credential before constructing the error.
  - confidence: 0.99
- **[P1] Require an explicit successful Bash result:** `internal/providers/orgo/client.go:280-283`
  - body: When the response omits both exit-code fields and `success`, this path returns zero. An incomplete or changed Orgo envelope is therefore reported as a successful command; reject responses that do not explicitly prove success.
  - confidence: 0.99
- **[P1] Keep cleanup state until deletion is confirmed:** `internal/providers/orgo/backend.go:520-521`
  - body: The claim is removed as soon as delete calls return no error, without confirming the computer is absent, and a workspace response can suppress a computer-delete error. Preserve recovery state until exact remote absence is verified so asynchronous or incomplete deletion remains retryable.
  - confidence: 0.98
- **[P1] Reject redirects for bearer-authenticated requests:** `internal/providers/orgo/client.go:148-155`
  - body: The provider reuses the supplied or default HTTP client without an Orgo-specific redirect rejection policy. A redirect can carry the bearer-authenticated request beyond the validated API base; clone the client with fail-closed redirect handling.
  - confidence: 0.96
- **[P1] Validate the returned computer identity before use:** `internal/providers/orgo/backend.go:354-365`
  - body: The create response is accepted without requiring a non-empty computer ID or an exact workspace match, and a missing workspace ID is filled from the request. Fail closed unless the returned identity exactly matches the requested workspace before polling, running commands, or deleting resources.
  - confidence: 0.97
- **[P1] Remove automatic cascading workspace deletion:** `internal/providers/orgo/backend.go:511-518`
  - body: Orgo documents workspace deletion as permanently deleting every computer in that workspace, but the API has no conditional precondition. Another client can add a computer immediately before this call, so the built-in provider must never delete workspaces unless Orgo supplies an atomic safe-delete contract.
  - confidence: 0.99
