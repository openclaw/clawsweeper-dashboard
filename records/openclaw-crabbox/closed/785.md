## Label Justifications

- `P0`: The issue describes a plausible non-admin bypass of brokered provider-resource selector authorization using coordinator-held Azure credentials.
- `impact:security`: The report is about coordinator authorization boundaries, privileged cloud credentials, and protected provider resource selection.

## Summary

Keep open: current main still lets non-admin Azure broker lease requests supply Azure image and OS-disk selectors that flow into privileged Azure VM creation, while the comparable AWS and GCP selectors are admin-gated.

## What This Changes

The issue requests admin gating or explicit policy for non-admin Azure broker lease selectors such as `azureImage` and `azureOSDisk`.

## Best Possible Solution

Add an Azure `restrictedLeaseRequestFields` implementation for `azureImage` and `azureOSDisk`, decide the `azureLocation` policy, and update Worker tests plus Azure docs to match.

## Reproduction Assessment

Yes. Source inspection shows a non-admin `POST /v1/leases` request can carry `azureImage` and `azureOSDisk` through `leaseConfig` into Azure VM creation because `AzureProvider` lacks the selector restriction hook; no live Azure request was run.

## Solution Assessment

Unclear for the full field set. Admin-gating `azureImage` and `azureOSDisk` matches the existing AWS/GCP pattern, but maintainers should explicitly decide whether `azureLocation` stays user-selectable and update docs/tests accordingly.
