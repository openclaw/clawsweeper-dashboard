## Summary

Keep open: current main still lets the Lambda direct-provider cleanup path turn provider tags into destructive delete authority when no unchanged local claim exists, and the repository's security and vision docs treat that as a supported ownership boundary.

## What This Changes

The issue asks Crabbox to require an unchanged Lambda local lease claim, or equivalent unforgeable ownership proof, before Lambda direct cleanup or release terminates instances or deletes SSH keys.

## Best Possible Solution

Make Lambda tags discovery-only for destructive operations, require an exact unchanged local claim for instance and SSH-key deletion, and preserve explicit rollback/reclaim recovery paths with regression tests.

- **Keep tag-only cleanup:** Preserve current orphan-reclaim behavior but accept that provider labels remain destructive authority for Lambda resources.

Yes, the proposed fail-closed local-claim requirement is the narrowest maintainable fix because it matches VISION.md and docs/security.md. The implementation should still preserve explicit recovery or reclaim claims for approved Lambda rollback paths.
