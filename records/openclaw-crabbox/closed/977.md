## Label Justifications

- `P0`: The issue reports a destructive provider security boundary where Crabbox can delete a GCE instance it cannot prove it owns.
- `impact:security`: The affected behavior is a provider-resource ownership and destructive-authorization boundary.
- `impact:data-loss`: Deleting the wrong GCE instance can remove the running machine and its associated state or disks.

## Summary

Keep open: current main still lets direct GCP cleanup and release delete canonical labeled instances without requiring an exact local claim. Prior merged fixes addressed live read-back and related cloud ownership checks, but they do not close this remaining GCP claim-authority gap.

## What This Changes

Request exact local-claim authorization before GCP direct cleanup or release deletes a GCE instance.

## Best Possible Solution

Add exact GCP local-claim validation for cleanup and release before DeleteServer, fail closed for missing or stale claims, retain ambiguous claims, and cover the valid-claim and invalid-claim cases in provider tests.
