## Summary

Keep open: current main still has the brokered Hetzner partial-provisioning cleanup gap, and the only related closed report covers broader orphan-sweep hardening rather than this lost server-ID path.

## What This Changes

Brokered non-workspace Hetzner provisioning should roll back or persist cleanup-addressable provider IDs when post-create readiness fails.

## Best Possible Solution

Add Worker Hetzner rollback for post-POST readiness failures, or persist the allocated server ID so existing release and expiry cleanup can delete it, with regression tests for ordinary non-workspace failed brokered leases.

## Reproduction Assessment

Yes. Source inspection shows the post-create Hetzner wait failure throws after a server ID exists, while the failed lease keeps empty cloudID/serverID and release/expiry cleanup skip provider deletion; no live Hetzner allocation was run.

## Solution Assessment

Yes. The narrowest maintainable fix is to roll back the just-created Hetzner server in the provider adapter, or otherwise carry the allocated ID into existing cleanup, rather than relying first on a broad tag-only orphan sweep.
