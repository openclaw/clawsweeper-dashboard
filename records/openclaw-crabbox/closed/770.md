## Summary

Keep open for maintainer review: current main and v0.33.0 still have the artifact namespace issue, and this PR is the linked candidate fix with sufficient real behavior proof. The patch looks functionally correct, but it deliberately changes returned keys and URLs for new brokered artifact grants.

## What This Changes

The branch changes the Worker artifact broker to sign new uploads under v2 base64url-encoded org/owner namespaces, updates docs/changelog, and adds Worker regression coverage.

## Best Possible Solution

Land the v2 new-write-only org/owner namespace if maintainers accept the returned key/URL compatibility impact, while preserving existing objects and URLs without legacy rewrites.

## Reproduction Assessment

Yes. Source inspection on current main shows two authenticated POST /v1/artifacts/uploads requests with the same owner, prefix, and file name can reach an owner-only key builder and derive the same key across orgs.

## Solution Assessment

Mostly yes. The v2 base64url org/owner namespace preserves exact identity bytes and covers both collision classes; compatibility handling only needs to expand if maintainers reject the documented new-write-only contract.
