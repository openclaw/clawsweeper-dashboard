## Summary

Keep open: current main still lacks External-provider SSH credential-destination provenance validation, and the reported path remains source-reproducible against the current External lifecycle and SSH target code.

## What This Changes

The issue reports that repository-sourced External provider SSH host/key configuration is not checked by the credential-destination provenance guard before Crabbox uses inherited or ambient SSH authentication.

## Best Possible Solution

Extend the existing source-bound credential-destination model to External SSH host/key/proxy fields, preserving repository-contained same-source keys and trusted approval, with focused docs and regression tests.
