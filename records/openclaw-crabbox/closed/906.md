## Summary

Keep open. Current main still has the Go shared provider redactor gap described here; the merged provider-error fix at https://github.com/openclaw/crabbox/pull/823 added exact/common redaction, and the Worker fix at https://github.com/openclaw/crabbox/pull/883 added broader pattern coverage, but that broader coverage has not been carried into `RedactErrorSecrets`.

## What This Changes

The issue requests broader Go provider diagnostic redaction for PEM keys, URL credentials, credential query parameters, and additional common credential JSON/header names.

## Best Possible Solution

Extend `internal/providers/shared.RedactErrorSecrets` with the missing Worker-equivalent credential pattern families and table-driven Go regressions, while keeping the documented scope limited to Crabbox-generated provider diagnostics.

## Reproduction Assessment

Yes. A table-driven test that passes PEM blocks, URL userinfo, credential query parameters, and the missing JSON/header names into `RedactErrorSecrets` should currently show the reported values remain visible.

## Solution Assessment

Yes. Reusing the Worker’s established diagnostic redaction pattern set in the shared Go helper is the narrowest maintainable fix because the affected provider clients already call that helper.
