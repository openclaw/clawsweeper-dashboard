## Summary

The authentication-availability concern remains on current main: Node requests still fall back to the direct peer when trusted proxy CIDRs are absent, causing users behind one reverse proxy to share the low-capacity OAuth source bucket. The earlier global-queue fix introduced this partitioning but did not resolve unconfigured proxy aggregation, and the appropriate fail-closed or aggregation-safe policy needs maintainer security judgment. citeturn5search0turn5search2

## What This Changes

Harden Node/PostgreSQL GitHub OAuth admission so an unconfigured reverse proxy cannot place all downstream clients in one ten-attempt pending-login bucket.

## Best Possible Solution

Keep forwarding headers untrusted, but make untrusted-proxy aggregation an explicit safe state: detect proxy evidence where practical, provide startup/doctor and runtime diagnostics, and implement a maintainer-approved admission policy that prevents one anonymous client from monopolizing every downstream user's login bucket, with end-to-end Node proxy tests.
