## Summary

Keep open: current main still converts the portal session cookie into bearer auth and dispatches cookie-authenticated state-changing portal POSTs without a CSRF token or general request-intent check. Related Code-origin hardening is adjacent but does not cover this same-site sibling-origin POST path.

## What This Changes

The issue requests CSRF or equivalent request-intent validation for cookie-authenticated portal POST endpoints that mutate lease sharing, release, VNC, and related portal state.

## Best Possible Solution

Add a server-validated request-intent control for unsafe cookie-authenticated portal methods, render it into portal forms and fetch calls, and cover missing-token and valid-token cases in Worker tests.

## Reproduction Assessment

Yes. Source inspection shows cookie-backed portal authentication reaching POST handlers that mutate lease sharing, release, and VNC state without a token or general portal Origin check; a deployed same-site browser setup was not exercised.

## Solution Assessment

Yes. The narrow maintainable fix is a CSRF/request-intent layer for cookie-authenticated unsafe portal methods, with API bearer-token routes kept separate and focused Worker regression tests added.
