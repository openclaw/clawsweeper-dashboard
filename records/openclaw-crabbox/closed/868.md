## Summary

This issue should stay open: current `main` and latest `v0.35.0` still contain the unguarded portal cookie decoder, so malformed `crabbox_session` percent-encoding can throw before normal unauthenticated handling.

## What This Changes

The issue reports that malformed percent-encoding in the `crabbox_session` portal cookie can abort coordinator request preparation before authentication.

## Best Possible Solution

Catch malformed percent-decoding in the coordinator portal cookie parser, treat invalid cookie values like absent cookies, and add focused Worker regression coverage for safe portal GET, unsafe portal mutation, and unauthenticated API-style paths.

## Reproduction Assessment

Yes from source: a `/portal` request with `Cookie: crabbox_session=%ZZ` reaches `cookieValue`, and JavaScript `decodeURIComponent` throws on malformed percent-encoding. I did not run a full runtime request because this was a read-only cleanup review.

## Solution Assessment

Yes. Catching decode failures inside the coordinator cookie parser and treating the cookie as missing is the narrowest maintainable fix, and it matches the existing guarded parser pattern in `worker/src/fleet.ts`.
