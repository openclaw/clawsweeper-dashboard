## Summary

Keep open. Current main revalidates GitHub user tokens for new requests, but live non-admin WebVNC and egress bridge sessions still carry only setup-time principal data and are not closed by portal logout or non-admin grant revalidation.

## What This Changes

Request to make user-token revocation, GitHub membership loss, and portal logout invalidate active non-admin WebVNC and egress bridge sessions.

## Best Possible Solution

Bind non-admin WebVNC and egress attachments to revocable portal or GitHub identity, close those bridge types when the identity is revoked, and add focused Worker coverage for live and restored bridge sessions.

- **Fix live bridge revocation (recommended):** Store revocable session or GitHub identity metadata for non-admin WebVNC and egress bridges and close them when that identity is no longer authorized.

- **Fold into broader bridge auth redesign:** Keep this issue open under a larger WebSocket authorization pass covering Code, WebVNC, egress, control, restored sockets, and token revocation consistently.

## Solution Assessment

Unclear until maintainers confirm the security boundary. The maintainable direction is to reuse the current GitHub/session revocation model for live non-admin bridges rather than add route-specific special cases.
