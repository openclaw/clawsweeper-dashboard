## Label Justifications

- `impact:security`: The issue concerns potential disclosure of provider credential material in Crabbox-generated diagnostic output.
- `impact:auth-provider`: The affected values are provider endpoint URLs that may carry authentication material in query or fragment components.

## Summary

Keep open. Current main still preserves URL query strings and fragments in `redactedConfigURL`, and existing tests intentionally preserve harmless query strings, so this needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

The issue asks Crabbox to stop exposing credential-looking URL query and fragment material in `crabbox config show` diagnostics.

## Best Possible Solution

Make the URL display contract explicit, then update `redactedConfigURL` to protect secret-looking query and fragment material or intentionally strip those components, with focused text and JSON config-show regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a configured endpoint such as `https://api.example.test/v1?token=query-secret#fragment-secret` reaches `redactedConfigURL`, which returns it unchanged when no userinfo is present and preserves query/fragment data when userinfo is redacted.

## Solution Assessment

Unclear. The issue identifies the right helper boundary, but maintainers should choose whether to strip all query/fragment output or redact only secret-looking components because current regression tests preserve harmless query strings.
