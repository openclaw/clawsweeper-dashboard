## Label Justifications

- `P2`: This is a concrete medium-severity local confidentiality issue in a bounded CLI feature, with clear code paths but no evidence of a broad runtime outage.
- `impact:security`: The report concerns sensitive CI log and manifest data becoming readable by other local OS users through Crabbox-created artifact permissions.

## Summary

Keep open: current main and v0.35.0 still create capsule log and manifest artifacts with public read bits, while the capsule docs acknowledge these artifacts can contain sensitive CI data and adjacent run outputs already use owner-only permissions.

## What This Changes

The issue asks Crabbox to make `capsule from-actions` local log and manifest artifacts owner-only because failed Actions logs can contain secrets.

## Best Possible Solution

Use the existing private local-output pattern for capsule directories, failed logs, and manifests, with focused Unix permission regression tests and a short docs note for capsule confidentiality.

## Reproduction Assessment

Yes. Source inspection on current main shows `capsule from-actions` requests `0755` directories and `0644` files for the failed log and manifest; I did not execute the CLI because this review is read-only.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse the existing private local-output helpers or equivalent `0700`/`0600` behavior for capsule artifacts, then add a permissive-umask regression test.
