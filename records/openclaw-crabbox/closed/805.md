## Summary

Keep this open: current main still uses ordinary string equality for the static coordinator bearer-token paths, while the repository security policy treats coordinator authentication as a supported product boundary.

## What This Changes

The issue asks Crabbox to replace static coordinator bearer-token equality checks with timing-safe comparisons and add regression coverage.

## Best Possible Solution

Use one timing-safe comparison helper for every static coordinator bearer secret, keep the existing auth semantics and precedence, and add focused Worker auth tests or a guard against reintroducing direct CRABBOX_* token equality.

## Reproduction Assessment

Yes from source inspection: current main still compares static bearer credentials with `===`/`!==` on authenticated coordinator paths that return 401 for invalid credentials. I did not reproduce the full remote timing exploit.

## Solution Assessment

Yes, the recommended remediation is the narrow maintainable path: reuse or export a timing-safe comparison for static bearer-token checks and cover the admin, shared, and runtime-adapter paths without changing auth semantics.
