## Label Justifications

- `P2`: This is a source-reproducible artifact credential disclosure and integrity risk with redirect preconditions and limited blast radius.
- `impact:security`: The issue concerns Crabbox sending a trusted presigned artifact credential to a redirect-selected destination outside the intended storage origin.

## Summary

Keep open: current main still uploads brokered presigned artifact grants through Go's default redirect policy while the Worker emits SigV4 query-signed URLs and Crabbox already documents stricter credential-destination handling elsewhere.

## What This Changes

The issue asks Crabbox to stop brokered artifact upload redirects from disclosing presigned S3/R2 upload URLs to cross-origin redirect targets.

## Best Possible Solution

Add a dedicated artifact transfer HTTP client that refuses cross-origin redirects, or disables redirects entirely, before any follow-up can send a Referer, then cover presigned upload and read/download paths with focused regression tests.

## Reproduction Assessment

Yes. Source inspection shows brokered upload grants are sent through http.DefaultClient without CheckRedirect while the Worker issues SigV4 query-signed PUT URLs; I did not run a live S3/R2 redirect test in this read-only review.

## Solution Assessment

Yes on direction, with one maintainer/security choice left. The narrow fix is an artifact transfer redirect policy, either no redirects or same-origin only, plus upload and pull regression tests.
