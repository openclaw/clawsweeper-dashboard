## Summary

Keep open: current main and v0.34.0 still let the Hetzner release path delete after generic Crabbox label validation without proving the server lease label matches the LeaseTarget being released.

## What This Changes

Require Hetzner release deletion to verify that the target server's lease label matches the LeaseTarget lease ID before deleting the server or removing local claim state.

## Best Possible Solution

Patch the Hetzner release helper to fail closed when server.Labels["lease"] does not equal the release LeaseID, preserve legacy provider-label compatibility separately, and add a regression test for the mismatched lease/server case.

## Reproduction Assessment

Yes, by source inspection: a LeaseTarget can carry one LeaseID while its Hetzner server has a different non-empty lease label, and current ReleaseLease never compares the two before deletion.

## Solution Assessment

Yes, the narrow maintainable fix is to compare the expected lease ID with the server lease label before DeleteServer; broader canonical-label hardening can remain separate.
