## Summary

Keep open: current main still has a source-reproducible security issue where GCP ReleaseLease deletes the stored CloudID without re-fetching the live instance and revalidating canonical ownership plus the matching lease ID.

## What This Changes

The issue requests hardening GCP direct-provider release so it revalidates live Crabbox ownership and matching lease identity before deleting a GCP instance.

## Best Possible Solution

Update the GCP provider adapter to fetch the live instance in the selected zone, require canonical GCP ownership plus matching lease ID and CloudID before DeleteServer, preserve the claim on refusal, and add fake-client regression tests for wrong-lease, noncanonical, missing, and valid release cases.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: pass GCP ReleaseLease a LeaseTarget whose stored CloudID names a noncanonical or wrong-lease instance, and the current code calls DeleteServer without a live ownership check.

## Solution Assessment

Yes. The narrow maintainable fix is provider-local re-fetch and canonical ownership/lease matching before deletion; moving GCP-specific checks into core would conflict with the repository’s provider-boundary guidance.
