## Summary

Keep open: current main still has the reported direct Azure provider ownership gap, and the merged Worker Azure selector fix does not touch the direct `internal/providers/azure` release, cleanup, or delete path.

## What This Changes

The issue reports that direct Azure stop and cleanup can delete non-Crabbox VMs that carry weak Crabbox-looking tags instead of canonical ownership labels.

## Best Possible Solution

Require canonical Azure ownership labels and a matching lease ID before Azure inventory, resolve, release, delete, or cleanup can treat a VM as Crabbox-managed.

## Reproduction Assessment

Yes. Source inspection on current main shows weak-tagged Azure VMs can enter inventory/resolve paths and reach the release or cleanup delete sink without a canonical ownership re-check.

## Solution Assessment

Yes. The narrow maintainable fix is to apply the existing AWS-style canonical ownership predicate and lease-match check in Azure provider-owned list, resolve, release, cleanup, and delete boundaries.
