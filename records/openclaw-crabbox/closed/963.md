## Label Justifications

- `P1`: The issue is a reproduced SSH credential-boundary gap that can expose a local SSH agent capability during normal Crabbox lease connections.
- `impact:security`: The report concerns credential boundary hardening and exposure of sensitive local SSH-agent authority to remote lease processes.
- `impact:auth-provider`: The affected behavior is SSH authentication and credential routing for provider lease targets.

## Summary

Keep open: current main still lacks forwarding-deny options in the SSH, VNC tunnel, rsync, and SCP argument builders, and an `ssh -G` check confirms Crabbox-equivalent options can inherit local `ForwardAgent` and X11 forwarding settings.

## What This Changes

The issue requests that Crabbox's SSH-backed transports stop inheriting local OpenSSH agent and X11 forwarding by default despite per-lease key scoping.

## Best Possible Solution

Add default `ForwardAgent=no`, `ForwardX11=no`, and `ForwardX11Trusted=no` to the shared SSH, VNC tunnel, and SCP builders, with any opt-in restricted to trusted operator configuration and covered by focused tests and docs.

## Solution Assessment

Yes, with one maintainer security-boundary choice still needed. The narrow maintainable fix is to deny inherited forwarding in every Crabbox-managed OpenSSH path and decide whether a trusted operator opt-in should exist.
