## Label Justifications

- `P2`: This is a source-reproducible medium-severity credential diagnostic leak with limited preconditions and no evidence of active exploitation or broader runtime failure.
- `impact:security`: Credential-bearing URL userinfo can be copied into Crabbox-generated diagnostics and failure artifacts.
- `impact:auth-provider`: The affected values are provider API routing endpoints that may carry authentication material in URL userinfo.

## Summary

Keep open. Current main still appends the affected provider API URLs directly into the generated stop command that is printed or stored in run diagnostics, while neighboring Namespace Instance and XCP-ng routing paths already strip URL userinfo.

## What This Changes

The issue asks Crabbox to strip URL userinfo from generated stop-command provider API URL arguments for Proxmox, Daytona, Sprites, Morph, and Hostinger diagnostics and add regression coverage.

## Best Possible Solution

Apply routingSafeURL to every provider API URL inserted into generated stop/failure routing commands, then add table-driven runStopCommand coverage for the affected providers with userinfo-bearing URLs.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence path: a Config for Proxmox, Daytona, Sprites, Morph, or Hostinger with APIURL like https://user:secret@host is passed through runStopCommand and appended without routingSafeURL.

## Solution Assessment

Yes. The narrow maintainable fix is to reuse the existing routingSafeURL helper on the affected stop-routing URL fields and add regression coverage beside the existing runStopCommand tests.
