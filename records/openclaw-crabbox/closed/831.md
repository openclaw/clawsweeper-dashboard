## Label Justifications

- `impact:security`: The affected behavior copies generated VNC access material into a human-shareable URL.

## Summary

Keep open: current main still copies WebVNC fragment credentials into the manager-facing share link, and the linked older fixes do not cover this share-copy sink. The impact is bounded by portal lease/share authorization, but it remains a concrete generated-credential exposure path that needs maintainer security/product review.

## What This Changes

The issue asks Crabbox to stop including generated VNC username/password values in copied WebVNC share links.

## Best Possible Solution

Keep existing fragment consumption for compatible CLI/browser launches, but make copied WebVNC share links credential-free or ticket-backed and add Worker regression coverage that share-copy URLs omit raw VNC credentials.

## Reproduction Assessment

Yes. Source inspection on current main shows WebVNC reads username/password from the URL fragment, shareableWebVNCURL() writes those values back into a copied URL, and the copy button writes that URL to the clipboard.

## Solution Assessment

Yes for the narrow repair: stop copying raw credentials into share links while preserving existing fragment consumption for compatible one-click launches. A broader ticket handoff may be cleaner, but that needs maintainer product/security direction.
