## Label Justifications

- `P2`: The issue is a bounded confidentiality disclosure requiring opt-in public reads and possession or recording of a generated URL, without cross-owner artifact access or credential exposure.
- `impact:security`: Artifact URLs expose authenticated organization and owner identities, including verified email addresses, outside the authenticated coordinator boundary.

## Summary

Current main and v0.38.0 still expose exact authenticated organization and owner values through reversible artifact-path segments. This is a distinct, source-reproducible confidentiality gap, but remediation needs an explicit decision about pseudonym key lifecycle and compatibility for already published v2 URLs.

## What This Changes

Replace reversible authenticated owner and organization segments in artifact URLs with non-reversible deployment-scoped namespaces while preserving identity isolation and defining compatibility for existing object keys.

## Best Possible Solution

Mint future grants under a versioned, deployment-keyed pseudonymous identity namespace, retain existing v2 URLs, document secret rotation and public-link metadata, and add confidentiality plus identity-isolation regression coverage.

## Solution Assessment

Yes in direction, but the narrowest maintainable solution is a new versioned keyed-pseudonym namespace for future grants rather than silently changing or rewriting existing v2 keys. The secret source and rotation contract require maintainer approval.
