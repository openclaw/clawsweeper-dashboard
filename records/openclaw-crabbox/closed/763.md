- `impact:security`: The report concerns sending a provider API key to unsafe or ambiguous configured destinations.

## Summary

This issue is still necessary: current main and the latest release both accept the ASCII Box base URL with only whitespace/trailing-slash trimming before passing it to the token-bearing Box CLI path.

## What This Changes

The issue asks Crabbox to validate ASCII Box base URL override destinations before attaching the provider API key.

## Best Possible Solution

Add a small ASCII Box base URL validator matching adjacent credentialed providers, with regression tests for unsafe public HTTP, userinfo, query, fragment, opaque or malformed URLs, HTTPS normalization, and loopback HTTP allowance.

## Reproduction Assessment

Yes. Source inspection shows that setting `asciiBox.baseUrl` or the matching env/flag to an unsafe URL reaches `newAPI`, then the value is written with the token and passed to `box --api-url`; no runtime test was run under the read-only review contract.

## Solution Assessment

Yes. A focused validator before constructing the ASCII Box client is the narrowest maintainable fix, and it should reuse the established provider pattern rather than adding new configuration surface.
