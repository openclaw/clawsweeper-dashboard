## Summary

Current main already blocks the reported Freestyle repository-config credential-destination path, and the guard shipped before this issue was filed; the missing Freestyle case in `validateProviderCredentialDestination` does not create the described bypass because repository config cannot persist `Freestyle.APIURL`.

## What This Changes

The issue asks Crabbox to reject repository-sourced `freestyle.apiUrl` when a higher-trust Freestyle API key is inherited.

## Best Possible Solution

Keep the shipped Freestyle load-time destination guard and regression test; add Freestyle provenance fields only if maintainers later refactor all provider destination checks into the shared provenance switch.

## Maintainer Decision

## Reproduction Assessment

No: current main restores `Freestyle.APIURL` after repository config is applied and before environment keys are read. Existing regression coverage also asserts repository config cannot override the Freestyle API URL.

## Solution Assessment

Yes: the existing load-order guard is the narrowest shipped solution for this exact Freestyle path. Adding duplicate Freestyle provenance fields would be optional refactoring unless a new bypass path is demonstrated.
