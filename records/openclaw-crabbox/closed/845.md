## Label Justifications

- `P2`: The report describes a medium-severity generated credential exposure with a short race window and lease-scoped blast radius.
- `impact:security`: The affected flow exposes a Crabbox-generated Code viewer credential through a URL-bearing redirect surface.
- `impact:auth-provider`: The bootstrap ticket is used as bearer authentication material for the isolated Code viewer session.
- `impact:session-state`: A copied bootstrap ticket can mint a longer-lived stored Code viewer session for the affected lease.

## Summary

Current main still implements the reported URL-borne Code viewer bootstrap credential flow, and the latest release contains the same behavior. This should stay open for maintainer security/design review rather than being closed as already fixed or merged into a canonical replacement.

## What This Changes

Report that isolated browser Code bootstrapping puts a short-lived `code_view_...` ticket in the cross-origin redirect URL and treats that URL value as sufficient to mint a longer-lived `crabbox_code_session`.

## Best Possible Solution

Move Code viewer bootstrap authority out of URL-bearing redirects, or bind the redirect to non-URL proof, while preserving single-use expiry, logout revocation, isolated origins, and regression coverage proving a copied bootstrap URL alone cannot mint a session.

## Reproduction Assessment

Yes for source reproduction: current Worker code places the Code viewer ticket into the redirect URL, and current tests assert that fetching that URL creates a `crabbox_code_session`. I did not execute live replay because this review is read-only.

## Solution Assessment

Yes directionally: removing URL-borne bearer authority is the right security boundary. The exact handoff mechanism still needs maintainer design review because it must work across isolated Code origins without breaking existing portal behavior.
