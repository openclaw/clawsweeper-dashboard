## Label Justifications

- `P1`: An unauthenticated network caller can make GitHub OAuth login unavailable for legitimate users behind an affected Node reverse-proxy deployment.
- `impact:security`: The report concerns unauthenticated traffic affecting the coordinator authentication availability boundary.
- `impact:auth-provider`: The affected surface is GitHub OAuth login for CLI and portal users.

## Summary

Keep open: current main still lets the Node runtime collapse OAuth pending-login source buckets to the reverse-proxy socket peer when `CRABBOX_TRUSTED_PROXY_CIDRS` is unset or invalid, and the existing docs describe that requirement rather than removing the security-sensitive availability concern.

## What This Changes

Harden Node/PostgreSQL GitHub OAuth pending-login admission so unconfigured reverse proxies do not collapse all clients into one low-capacity source bucket.

## Best Possible Solution

Keep the trusted-forwarded-header boundary, but add a security-reviewed OAuth admission, diagnostic, or operator-visible policy for Node reverse-proxy deployments so one unconfigured ingress peer cannot quietly starve legitimate GitHub login starts.
