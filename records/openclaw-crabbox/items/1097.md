## Summary

Keep this PR open. The revised branch resolves the prior unbounded-drain finding with idle and absolute limits, but the idle detector can still close pipes while a copier is blocked on a slow synchronous response write, silently truncating unread direct-child output. The submitted live comparison also reports complete output on both base and head, so it does not demonstrate the claimed real-world improvement.

## What This Changes

The PR replaces `StdoutPipe` and `StderrPipe` with explicitly owned pipes, adds an idle-aware and absolutely bounded post-exit drain, and adds subprocess lifecycle regression tests.

## Best Possible Solution

Keep explicit pipe ownership, but distinguish an in-flight response write from true pipe idleness—or decouple pipe reads from response streaming—then add a regression whose response writer blocks beyond the idle interval and provide a throttled live base-versus-head capture.

- **[P1] Do not close pipes while a response write is in flight:** `worker/cloudflare-container-runner/main.go:56`
  - body: The idle loop treats an unchanged copied-byte counter as evidence that pipe output is finished, but `copyPipe` writes synchronously to the HTTP response.
