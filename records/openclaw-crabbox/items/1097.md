## Summary

The updated head addresses the prior descendant-pipe hang finding, but it is not merge-ready: the idle signal cannot distinguish a quiet inherited writer from downstream backpressure, and the submitted live output does not demonstrate an observed base-versus-head improvement.

## What This Changes

The PR replaces `StdoutPipe` and `StderrPipe` with runner-owned pipes, adds an idle-aware bounded drain after `cmd.Wait`, and expands subprocess regression coverage for output delivery and inherited descriptors.

## Best Possible Solution

Decouple pipe draining from downstream HTTP writes using a bounded spool or queue, safely capture all direct-child bytes first, and apply descendant idle or cap policy only after foreground output is buffered; cover this with a response write that exceeds the idle threshold.

## Solution Assessment

No. Owning the pipe ends is a sound direction, but using completed downstream-copy progress as the idle signal conflates a quiet inherited writer with a backpressured response writer.
