## Summary

Keep open: current main still has the Worker-side OAuth callback-origin fallback described in the report, and the nearby closed CLI callback-origin fix does not remove this portal/server path.

## What This Changes

The issue asks Crabbox to prevent GitHub OAuth portal callbacks from being rebound through the request host when `CRABBOX_PUBLIC_URL` is unset.

## Best Possible Solution

Bind GitHub OAuth to a configured canonical public origin before authorization and callback exchange, with any same-deployment alias support explicit, trusted, and covered by regression tests.

## Reproduction Assessment

Yes. Source inspection shows `GET /portal/login` reaches `githubPortalLogin`, authorization and callback exchange both use `githubRedirectURI`, and that helper is request-origin-derived when `CRABBOX_PUBLIC_URL` is unset.

## Solution Assessment

Unclear. Requiring `CRABBOX_PUBLIC_URL` before GitHub OAuth is the safest narrow fix, but maintainers should choose the compatibility policy for trusted aliases or existing unset-public-url deployments.
