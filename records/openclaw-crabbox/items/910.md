## Label Justifications

- `P1`: The source trace supports a provider credential disclosure boundary issue requiring security follow-up, even though exploitation has local/user-interaction preconditions.
- `impact:security`: The report concerns a trusted provider credential being sent to a destination selected by lower-trust repository configuration.
- `impact:auth-provider`: The affected path combines provider endpoint routing with inherited provider API keys such as Morph credentials.

## Summary

Keep open: current main still has the reported credential-destination provenance gap when `CRABBOX_CONFIG` points at a repository-local file, and no open PR or canonical issue appears to own this exact bypass.

## What This Changes

The issue asks Crabbox to prevent a repository-controlled `CRABBOX_CONFIG` file from making inherited provider credentials flow to repository-selected provider endpoints.

## Best Possible Solution

Keep this issue open for a security-reviewed, compatibility-preserving fix that treats explicit repo-local config as repository-sourced for credential destinations or otherwise rejects inherited credentials from non-user trusted endpoint files.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: set `CRABBOX_CONFIG` to a repo-local config with `morph.apiUrl`, inherit `MORPH_API_KEY`, and the endpoint is trusted-file rather than repository provenance before validation.

## Solution Assessment

Yes. The recommended direction is the narrow maintainable fix: preserve the existing destination-approval model and correct the trust classification or validation rule instead of adding a new config surface.
