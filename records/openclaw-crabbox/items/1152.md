## Summary

Keep this PR open: the coordinator-side tombstone design addresses the reported resurrection path, but the persisted active-session record lacks the principal needed by revocation flows, so an offline active session can remain reusable after its owner loses access. The supplied live transcript convincingly covers the CLI close-code mapping, not the new Worker persistence and revocation behavior.

## What This Changes

The branch persists per-lease tombstones for replaced egress sessions in the Worker and maps matching egress bridge close frames to a fatal daemon-supervisor exit in the CLI.

## Best Possible Solution

Persist enough authenticated bridge-principal data with each active egress-session record, or conservatively clear and tombstone persisted active state during access revocation, then prove restart and revocation flows in a real Worker deployment.

## Solution Assessment

No. Durable tombstones are the right direction, but the active persisted record must carry revocation-relevant identity or be conservatively invalidated during access changes; otherwise the new state cannot be safely revoked.
