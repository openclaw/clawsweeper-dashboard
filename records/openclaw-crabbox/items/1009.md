## Label Justifications

- `P0`: The issue describes a current coordinator authorization bypass where a revoked manager can keep backend bridge infrastructure available for another owner's lease.
- `impact:security`: The report concerns stale bridge authority after revocation of the grant that authorized the backend agent.
- `impact:session-state`: The stale authority lives in long-lived WebSocket backend-agent attachment state after the creating grant changes.
- `impact:auth-provider`: The affected behavior is tied to GitHub, shared-token, and admin grant revocation for bridge authentication.

## Summary

Keep open: current main still stores accepted WebVNC and Code backend agents as lease-level attachments without the grant material needed to close them when the creating manager's authority is revoked.

## What This Changes

The issue reports that WebVNC and Code backend-agent sockets remain available after the manager grant that created them is revoked.

## Best Possible Solution

Bind accepted WebVNC and Code backend agents to the same revocable grant/principal that authorized their tickets, revalidate that binding on revocation and traffic paths, close stale agents, and add Worker regression tests for idle WebVNC and Code backend agents.

Options:

- **Close backend agents on any relevant revocation:** Use a broader but more disruptive revocation rule that clears lease backend agents when manager/share/token state shrinks and attribution is incomplete.
- **Document lease-level backend agents:** Keep backend agents as lease infrastructure after ticket acceptance and document that manager revocation does not close already accepted backend bridges.

## Solution Assessment
