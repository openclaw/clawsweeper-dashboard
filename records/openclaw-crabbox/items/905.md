## Summary

Keep open: current main still has a credentialed tag-push release path where the default-branch/tag ancestry guard is limited to manual dispatch, so the central release-source trust problem is not already implemented or superseded.

## What This Changes

The issue reports that `v*` tag-push releases can run GoReleaser with tag-controlled configuration outside the reviewed default-branch ancestry checks used by manual releases.

## Best Possible Solution

Update the release workflow so both tag-push and manual releases resolve an exact stable tag, prove it is in reviewed default-branch history before any release secret is used, and keep the GoReleaser config pinned to reviewed workflow state, with regression coverage for both triggers.

## Reproduction Assessment

Yes. Source inspection of current main reproduces the issue: the `v*` tag-push trigger reaches the config stash and credentialed GoReleaser path while the default-branch/tag ancestry guard is manual-dispatch-only.

## Solution Assessment

Yes for the core direction. Applying the same reviewed-source invariant to tag-push releases is the narrow maintainable fix; protected tags or GitHub rulesets can be additional operational defense rather than the only control.
