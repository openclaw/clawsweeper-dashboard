## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Reject duplicate keys before verifying receipts:** `internal/cli/attest.go:168`
  - body: `json.Unmarshal` accepts duplicate object names and keeps the last value. That means someone can edit a receipt by prepending a duplicate `command` or `exit_code` for humans to see while leaving the signed value later in the file, and `crabbox verify` will still canonicalize the map and print PASS. Reject duplicate top-level keys before signature verification or otherwise require an unambiguous canonical receipt.
  - confidence: 0.91
- **[P2] Preflight receipt paths against other outputs:** `internal/cli/run.go:408`
  - body: This only checks whether the receipt path itself is writable. If a user passes the same path to `--attest` and `--emit-proof`, `--capture-stdout`, `--capture-stderr`, `--download`, or `--lease-output`, the successful run can write that artifact and then overwrite it with the receipt. Mirror the existing proof collision checks before starting the run.
  - confidence: 0.9
- **[P2] Block receipt paths in watch and shard forwarding:** `internal/cli/run.go:230-231`
  - body: Adding `--attest` as a run flag also makes it pass through `crabbox watch` and `crabbox shard` because their forbidden flag maps were not updated. `shard --attest receipt.json` can have multiple parallel runs racing to replace one local receipt, and `watch --attest` overwrites the same file on each rerun, unlike `--emit-proof` which these wrappers reject.
  - confidence: 0.86
- **[P3] Leave the changelog to release ownership:** `CHANGELOG.md:8`
  - body: The review policy treats `CHANGELOG.md` as release-owned, and the PR body already carries the user-visible release-note context. Please remove this changelog edit and let the release process add the final note.
  - confidence: 0.84
