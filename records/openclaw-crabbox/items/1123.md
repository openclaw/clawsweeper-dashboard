## Summary

Keep this tracking issue open: Crabbox’s lifecycle contract requires exact ownership proof before destructive operations, and current main still shows the Blacksmith failed-warmup path starting cleanup from a pre-operation inventory snapshot; the provided context identifies no merged fix covering all three providers.

## What This Changes

Harden Tart, Firecracker, and Blacksmith cleanup paths against cross-process check-to-act races by revalidating the current lease claim before deleting or stopping resources.

## Best Possible Solution

Keep provider-specific reconciliation inside each adapter, use compare-and-remove claim semantics for Tart and Firecracker, skip Blacksmith failed-warmup candidates with a current live claim, and retain deterministic interleaving regression tests until all three fixes merge.
