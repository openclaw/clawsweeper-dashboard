## Summary

Keep open: the patch targets the right W&B ownership boundary, but it still authorizes Exec/Get/Stop from bare `crabbox` tag-filtered inventory, which does not satisfy the exact ownership policy or the PR body's tagged-but-unowned deny gate. Exact-head live W&B proof is also still absent.

## What This Changes

The branch adds a W&B tag-filtered ownership check before existing-ID run/status/stop, updates W&B docs/tests, and adds an Unreleased changelog entry.

## Best Possible Solution

Land a W&B guard based on exact local claim or exact provider ownership metadata, or an explicit maintainer-approved tag contract, with redacted live allow/deny/cleanup proof; leave release notes to the release flow.

## Reproduction Assessment

Yes. Current main has a high-confidence source-level path: W&B `run --id`, `status --id`, and `stop --id` forward caller-supplied IDs to Exec/Get/Stop without first proving Crabbox ownership.

## Solution Assessment

No. Tag-filtered inventory is aimed at the right boundary, but it is not exact ownership proof and does not establish the PR body's tagged-but-unowned deny requirement.
