## Summary

Current main does not solve the requested workflow: `crabbox cp` is explicitly limited to provider-native delegated-sandbox copying, while Static SSH only exposes its resolved transport to other core workflows. The feature fits Crabbox’s provider-neutral architecture, but command semantics and cross-platform safety need maintainer direction before implementation. Likely related person: steipete, with low-confidence routing based on broad repository stewardship because file-level authorship could not be established.

## What This Changes

Requests extending the existing `cp` command to transfer files for leases whose resolved transport is SSH, including Static SSH leases.

## Best Possible Solution

Add a provider-neutral SSH-lease copy path in core that reuses the resolved lease target and existing SSH policy, while retaining provider-native copy adapters for delegated sandboxes and documenting explicit cross-platform path and symlink semantics.

Options:

- **Support all SSH targets immediately:** Define and implement one release covering POSIX, native Windows, WSL2, local-container, and proxy-backed SSH transports, accepting a larger compatibility and validation surface.
- **Keep cp provider-native:** Retain the delegated-provider-only contract and require callers to use printed SSH commands or external transfer tools for SSH-backed leases.
