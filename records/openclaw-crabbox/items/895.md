## Summary

Keep open: current main still skips incomplete-principal Code viewer attachments during share-shrink revocation, and the checked-in Worker test still expects a legacy Code viewer to remain connected after the revoked share closes the complete-principal viewer. No linked closing PR owns this Code viewer security fix yet.

## What This Changes

The issue asks Crabbox to fail closed for legacy or restored Code viewer WebSocket attachments without a complete principal when lease sharing is revoked.

## Best Possible Solution

Close incomplete-principal Code viewers for the affected lease during share-revocation and restored-socket reconciliation, preserving deserialization only long enough to identify and clean them up, with focused Worker regressions for legacy, retained user, owner, and admin cases.

## Reproduction Assessment

Yes. Current source shows incomplete-principal Code viewers are skipped before authorization, and the existing Worker test constructs code-legacy without a full principal and expects it to stay open after share removal.

## Solution Assessment

Yes, with maintainer security review for compatibility. Treating incomplete Code viewer principals as unauthorized is the narrowest maintainable fix; legacy deserialization should remain only for cleanup and close notification.
