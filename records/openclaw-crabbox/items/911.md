## Label Justifications

- `P2`: The report describes an authenticated cross-org usage metadata leak with a same-owner precondition and limited blast radius.
- `impact:security`: The issue concerns a documented coordinator authorization boundary for owner/org-scoped usage data.

## Summary

Keep open: current main still routes non-admin usage requests through a user-scope predicate that checks owner but not org, while the docs describe user tokens as scoped to their own owner/org identity. The related OAuth security report is adjacent, not a fix or canonical replacement for this usage-filter gap.

## What This Changes

Require user-scoped usage aggregation to exclude same-owner leases from other orgs for non-admin callers.

## Best Possible Solution

Update the user-scope usage predicate to require the authenticated org when `filter.org` is present, preserve admin `all`/`org` behavior and owner-only quota accounting, and add focused `usageSummary` plus `/v1/usage` route regression tests.

## Reproduction Assessment

Yes. Source inspection gives a high-confidence reproduction path: seed two managed leases with the same owner in different orgs, call `/v1/usage?scope=user` as one org, and the current predicate can include both because it checks only owner.

## Solution Assessment

Yes. Matching `lease.org` when user scope receives an org is the narrowest maintainable fix, as long as the existing owner-only quota path is preserved or explicitly covered.
