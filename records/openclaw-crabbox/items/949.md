## Summary

Keep open: current main and v0.36.0 still return per-side egress connection booleans to visibility-only use-share callers while the documented model separates visible `use` access from `manage` access. The older related issue and merged PR redacted profile/allow and WebVNC diagnostics, but this narrower egress status disclosure remains.

## What This Changes

The issue requests that non-manage lease-share recipients stop receiving `hostConnected` and `clientConnected` details from `GET /v1/leases/{id}/egress/status`.

## Best Possible Solution

Gate per-side egress connection state behind manage access, or replace it with a documented coarse use-role status, with Worker regression tests for owner, manage share, explicit use share, and org use share callers.
