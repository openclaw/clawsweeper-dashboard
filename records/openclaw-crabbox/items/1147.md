## Label Justifications

- `P1`: Concurrent normal same-scope local-container runs can lose the credentials needed to use a live lease.
- `merge-risk: 🚨 session-state`: The patch changes atomic handling of persisted lease claims and their associated per-lease key state.
- `merge-risk: 🚨 availability`: Deleting a key prepared by a concurrent Acquire can make the resulting live container unreachable over SSH.

## Summary

The snapshot and compare-and-delete direction is sound, but stored-key deletion is not fully fenced against an Acquire that prepares the key before publishing its replacement claim; real local-container proof is also absent.

## What This Changes

The PR snapshots local-container orphan candidates before container enumeration, conditionally deletes unchanged claims and stored keys, and adds deterministic regressions for fresh-claim and rebind interleavings.

## Best Possible Solution

Retain stored keys during missing-container orphan sweeping unless acquisition and key creation share a broader fence, then add a regression for key preparation before replacement-claim publication and redacted real Docker or Podman proof.

## Solution Assessment

No, not yet: pre-snapshotting candidates and compare-and-delete are appropriate, but deleting the key inside only the claim-removal fence is not a complete acquisition fence; retaining keys is the safer narrow solution.
