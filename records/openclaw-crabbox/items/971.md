## Summary

Keep open: current main and the latest release still print generated managed VNC credentials in default `crabbox vnc` output, and changing that documented behavior needs maintainer security and compatibility signoff.

## What This Changes

The issue asks Crabbox to stop printing generated managed-desktop VNC and OS passwords in default `crabbox vnc` stdout and require an explicit reveal or handoff path.

## Best Possible Solution

Adopt a WebVNC-style secure default for `crabbox vnc`: print connection details without generated credentials, keep private reveal or native handoff explicit with a warning, and add focused CLI/docs regression coverage.
