- `impact:security`: The reported behavior can disclose an authenticated provider token and replay sensitive provider request data across an unintended redirect.

## Summary

Keep this security report open: the supplied current-main source trace identifies authenticated Semaphore requests without redirect confinement, while Crabbox documents credentialed redirects as confined to the configured origin. The report is narrowly scoped to a realistic redirect prerequisite and includes a concrete remediation and validation design; it needs security-owner review rather than cleanup closure.

## What This Changes

Add same-origin redirect confinement to the Semaphore provider’s authenticated HTTP client so redirects cannot replay request bodies or forward the Semaphore API token to a different origin.

## Best Possible Solution

Clone the effective Semaphore HTTP client inside the provider, compose a strict configured-origin redirect check with any caller policy, return a stable redacted rejection, and add focused transport-level regression coverage for both denied and allowed hops.
