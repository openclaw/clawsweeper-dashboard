## Label Justifications

- `P1`: A supported AWS Tailscale workflow times out and tears down an otherwise reachable lease for EC2-based operators.
- `impact:other`: The issue blocks remote lease bootstrap for a concrete cloud-network topology, a meaningful provider connectivity failure outside the narrower impact categories.

## Summary

Current main still waits on the AWS public IPv4 inside provider acquisition before the documented `--network tailscale` selector can choose the tailnet endpoint, so the reported EC2-operator topology remains broken and no canonical PR owns the fix.

## What This Changes

Make AWS Tailscale lease bootstrap readiness use a reachable tailnet endpoint when the operator cannot reach the leased instance’s public IP.

## Best Possible Solution

Apply the existing network-mode contract during direct-provider bootstrap: strict Tailscale should wait on the deterministically rendered tailnet hostname, public should remain public, and auto should retain a compatibility-safe public fallback, all through provider-neutral helpers with AWS regression and live cleanup proof.
