## Summary

Keep this PR open, but do not merge it as-is: the compare-and-delete direction is appropriate, yet the newly added empty-snapshot fallback preserves a blocking concurrent-claim deletion path, and the PR provides only test-based proof rather than real Firecracker-host evidence.

## What This Changes

The PR changes both Firecracker cleanup claim removals to use snapshot-aware deletion where possible and adds a deterministic concurrent-reclaim regression test.

## Best Possible Solution

Make claim deletion atomic for both present and absent cleanup snapshots—either by preserving claims absent from the snapshot or adding an explicit compare-against-absence primitive—then cover both interleavings and demonstrate the result on a real Firecracker host.
