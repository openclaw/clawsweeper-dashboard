## Summary

The feature is not present on current main, but this PR is not merge-ready: it adds an unbounded remote artifact read, silently ignores unsupported validation constraints, and provides no real CLI/provider proof.

## What This Changes

The PR adds `--require-artifact-schema remote=schema.json` for SSH-backed runs, implements a dependency-free JSON Schema subset validator, records timing evidence, and adds tests and documentation.

## Best Possible Solution

Keep validation local and provider-neutral, but cap fetched bytes, fail preflight on unsupported validation keywords or explicitly use a Crabbox-specific schema format, and prove valid, invalid, missing, and oversized artifacts through the real SSH-backed CLI path.

  - body: This gate fetches and base64-decodes the entire remote file with no byte limit; the PR even defers a cap as follow-up.
