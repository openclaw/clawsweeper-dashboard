## Label Justifications

- `P1`: The report identifies a default sync optimization that can send credential material into a remote execution environment.
- `impact:security`: Credential-bearing Git remote userinfo can be exposed to lease-runner process arguments and remote Git configuration.

## Summary

Keep open: current main and the latest release still pass the raw Git remote URL into git-seed clone commands, and no open PR or canonical issue appears to own the remediation. This is a source-reproducible credential-boundary issue, but the exact fail-closed versus skip-seed behavior should be maintainer-owned.

## What This Changes

The issue requests preventing git seed from sending credential-bearing Git remote URLs to lease runners.

## Best Possible Solution

Reject or disable git seed for remotes with URL userinfo before constructing Linux, Windows, or local Actions seed commands, with redacted diagnostics and regression coverage proving the credential never reaches argv or remote Git config.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Crabbox fail closed or skip git seed when the local Git remote URL contains userinfo?

Rationale: Both choices protect the credential boundary, but they have different operator impact: fail-closed makes the unsafe remote explicit, while skip-and-overlay preserves run progress with less visibility.

Likely owner: steipete

Owner reason: The central git-seed and security-boundary paths are most strongly tied to this owner in current-main history.

Owner confidence: high

Options:

- **Fail closed with redacted diagnostic (recommended):** Return a clear error before any lease-runner command is constructed and identify only that the remote contains URL userinfo.
- **Skip git seed and continue overlay sync:** Disable git seed for that run and rely on rsync/archive overlay, emitting a redacted warning so credentials are not sent to the lease.
- **Design explicit private seed credentials:** Keep private-repo seeding only behind a separate scoped delivery mechanism that avoids argv and persisted remote config.

## Reproduction Assessment

Yes. Source inspection shows the raw origin remote is stored, the git-seed gate does not reject URL userinfo, and both Linux and Windows seed builders pass the normalized URL to `git clone`; I did not run a live lease in this read-only review.

## Solution Assessment

Yes on the boundary, pending maintainer policy. The narrow fix should treat URL userinfo as credential material before command construction across Linux SSH sync, native Windows sync, and local Actions hydration; maintainers should choose fail-closed versus skip-seed UX.
