## Label Justifications

- `P0`: The PR addresses irreversible force-deletion of a container and its local writable state without established ownership.
- `merge-risk: 🚨 security-boundary`: The proposed authorization is snapshot-based, so a changed claim can leave destructive cleanup acting on stale ownership proof.
- `merge-risk: 🚨 compatibility`: The fail-closed behavior intentionally stops label-only cleanup of stopped containers, changing existing operator reclamation workflows.

## Summary

The exact-claim gate fixes the reported unconditional deletion path, but the patch still relies on a claim snapshot rather than proving the binding remains unchanged at the destructive call site. Real Apple-container proof is also absent.

## What This Changes

Requires Apple-container cleanup to match provider, lease ID, and container ID against a local claim before deleting stopped or expired containers, with regression tests, provider documentation, and a changelog entry.

## Best Possible Solution

Keep the provider-local exact-claim gate, add an unchanged-claim check immediately before force deletion, preserve an explicit reclaim or adoption path for intentionally lost state, and leave the changelog entry to release tooling.
