## Label Justifications

- `P1`: The PR addresses a security-boundary issue where Git seed can forward credential-bearing origin URLs into lease-runner command arguments and remote Git config.
- `merge-risk: 🚨 compatibility`: Merging changes the default behavior for credential-bearing HTTP(S) remotes from seeded clone to file-sync fallback, which can affect large or timeout-sensitive existing workflows.

## Summary

Keep open: this is a focused candidate fix for the linked security issue, and I found no line-level correctness regression, but it still needs contributor-visible runtime proof and maintainer acceptance of the skip-and-warn policy before merge.

## What This Changes

The branch disables Git seeding for HTTP(S) origin URLs with userinfo across Linux, native Windows, and local Actions sync, adds redacted warnings, defense-in-depth command blocking, regression tests, docs, and a changelog note.

## Best Possible Solution

Land one vetted fix that blocks credential-bearing HTTP(S) git seed before any Linux, Windows, or local Actions seed command is built, keeps diagnostics redacted, and preserves file-sync fallback unless maintainers explicitly choose fail-closed behavior.
