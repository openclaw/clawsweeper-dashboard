## What This Changes

Requests a deterministic performance-evidence and budget-gating capability for Crabbox runs, initially using reproducible WASM fuel or instruction counts.

## Best Possible Solution

Ship this only as a staged, provider-neutral evidence contract backed by one committed deterministic workload, a pinned and isolated metering runtime, strict provenance and comparability checks, and focused fresh-run and budget-failure proof.

## Risks / Open Questions

- An embedded runtime for untrusted modules would add a new host-process security boundary around CPU limits, memory, filesystem preopens, environment variables, and host imports.
- Fuel or instruction values are not comparable unless the engine, version, module identity, configuration, input, and determinism assumptions are pinned and validated.
- Adding budget flags before proving one real workload could create a permanent CLI and evidence-schema contract around a metric that does not correlate with the intended regression signal.
