## Summary

Keep open: current Crabbox synchronization is explicitly Git-manifest and Git-HEAD based, so it does not yet solve the reported Jujutsu workspace behavior. A July 28, 2026 scope decision welcomes contributions but limits an initial change to safe Jujutsu-workspace detection, a clear colocated-Git recovery path, and documentation; native revision adaptation needs a minimized reproduction first.

## What This Changes

Add safe Jujutsu (`jj`) workspace handling so remote runs do not synchronize an unintended working-tree diff.

## System Context

Crabbox’s CLI prepares a remote runner by deriving a local file manifest, optionally seeding a remote Git checkout, then transferring the selected working set before running the requested command. The requested behavior affects the local synchronization boundary that determines what code reaches the remote test environment.

## Best Possible Solution

Add a narrow Jujutsu-workspace detection guard with a clear colocated-Git recovery message and sync documentation, then design any native revision adapter only from a minimized multi-parent reproduction that defines the expected remote tree.
