## Summary

Keep open: current main still has no External-provider credential-destination validation, while repository-sourced External SSH connection fields can become the SSH target used by Crabbox with inherited key or ambient SSH authentication.

## What This Changes

The issue requests provenance tracking and validation for External provider SSH destinations so repository config cannot silently select where inherited SSH credentials are used.

## Best Possible Solution

Add External SSH destination/key provenance, reject repository-selected External SSH destinations when auth is inherited or ambient unless the destination is approved from a trusted source, and document/test the same-source and explicit-approval cases.
