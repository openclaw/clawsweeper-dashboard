## Summary

This PR should stay open: it addresses a real banner-loss race, and the prior changelog concern is fixed, but the new readiness wait can block the bridge’s single inbound websocket reader behind one unfinished local handshake, pausing unrelated multiplexed traffic; live after-fix proof is also still absent. Likely related people: `steipete` is the clearest routing candidate with medium confidence because he requested review and managed the PR’s merge state.

## What This Changes

The branch registers egress connections before remote-open completion, gates inbound bytes until the local CONNECT response is written, preserves rejected-open HTTP responses, and adds three focused `net.Pipe` regression scenarios.

## Best Possible Solution

Keep early connection registration, but replace the shared-reader condition wait with per-connection staging or asynchronous ordered delivery so one opening stream cannot block other ids, then prove a live SSH or SMTP CONNECT transcript plus the rejected-open path.
