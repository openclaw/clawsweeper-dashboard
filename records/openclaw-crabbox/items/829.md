## Summary

Keep open: current main still lets the Hetzner release path delete a Crabbox-labeled server without checking that the server lease label matches the LeaseTarget being released. The report is source-reproducible and aligned with the repository’s lifecycle-safety policy.

## What This Changes

The issue requests a Hetzner release guard that refuses to delete a server unless its provider lease label matches the lease ID being released.

## Best Possible Solution

Add a provider-local Hetzner release check that binds req.Lease.LeaseID to server.Labels["lease"] before DeleteServer, preserving legacy provider-label compatibility unless maintainers choose broader hardening.

## Reproduction Assessment

Yes by source inspection: a LeaseTarget can carry one LeaseID while its Hetzner server has a different non-empty lease label, and current ReleaseLease never compares the two before deletion. I did not run a dynamic test because this review is read-only.

## Solution Assessment

Yes. The narrowest maintainable fix is to pass or check the expected lease ID in the Hetzner release/delete path before the provider delete call, matching the AWS and Azure release guards without broadening provider-label policy.
