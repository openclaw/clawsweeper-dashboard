## Summary

Keep open. Current main still stores request-time admin state on long-lived bridge/control WebSocket attachments and later treats that cached bit as owner-equivalent authorization without re-checking the current GitHub admin allowlist.

## What This Changes

The issue reports that GitHub admin revocation does not invalidate already-established coordinator bridge/control WebSockets whose attachments cached admin authority.

## Best Possible Solution

Define current-admin revalidation for long-lived bridge principals, then close or downgrade stale admin control, WebVNC, Code, and egress sockets with focused Worker regression tests.

## Reproduction Assessment

Yes. Source inspection shows new GitHub requests derive admin from current config while existing bridge/control attachments keep a cached admin bit that restored-socket and share-revocation paths do not revalidate.

## Solution Assessment

Unclear until maintainers choose the durable revocation model. Revalidating or versioning admin status for long-lived bridge principals is the right direction, but the exact identity data and fail-closed behavior need security review.
