- `impact:security`: The issue concerns possible exposure of configured provider credentials in Crabbox-generated diagnostics.

## Summary

Keep open: current main still returns Sprites non-2xx API response bodies in generated errors without credential redaction, and no merged or open PR appears to own this specific fix.

## What This Changes

The issue requests redaction of configured Sprites provider credentials and token-like values from Sprites API error diagnostics.

## Best Possible Solution

Patch the Sprites client to run non-2xx response text through `shared.RedactErrorSecrets` with the configured Sprites token, then add focused regression coverage for reflected token, Bearer, authorization field, and token-like JSON-field cases.

## Reproduction Assessment

Yes from source: a local httptest-style non-2xx Sprites response containing the token would flow through `summarizeSpritesBody` into `spritesAPIError.Error` after the client sends `Authorization: Bearer <token>`. I did not run a live Sprites deployment reproduction.

## Solution Assessment

Yes: reusing the existing shared provider redaction helper in the Sprites error-body path is the narrowest maintainable fix and matches adjacent provider behavior.
