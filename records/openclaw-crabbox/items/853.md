## Summary

Keep open: the PR addresses real Hetzner destructive-ownership gaps, but the new exact-claim release gate can strand a freshly acquired server when local claim persistence fails before cleanup, and the PR has only fake-client proof so far.

## What This Changes

The PR tightens Hetzner release and cleanup ownership checks around canonical labels, exact server-bound local claims, explicit reclaim, retryable claim retention, and related docs/tests.

## Best Possible Solution

Land a version that keeps strict destructive ownership for existing/adopted resources while preserving trusted fresh-acquire rollback before local claims exist, with regression coverage and redacted live Hetzner proof or maintainer override.

## Reproduction Assessment

Yes, by source inspection: run and warmup cleanup can call ReleaseLease after Acquire but before local claim persistence succeeds, while the PR rejects release without an exact persisted claim. I did not execute a live Hetzner path.

## Solution Assessment

No. Exact local claims are appropriate for existing, adopted, or stale resources, but fresh in-process acquisition cleanup needs a narrow trusted rollback path or earlier claim persistence so failed local state writes do not leave cloud resources running.

  - body: This new gate makes `ReleaseLease` require a persisted local claim before it will delete the Hetzner server.
