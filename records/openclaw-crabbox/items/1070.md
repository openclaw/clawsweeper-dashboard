## Summary

Current main still documents artifact requirements as existence-only and leaves schema validation to repository commands. The linked open pull request is the active implementation candidate, so this issue should remain open until maintainers decide whether schema validation belongs in Crabbox core and then merge or close that PR.

## What This Changes

Add a repeatable `--require-artifact-schema REMOTE=SCHEMA` post-run gate that validates bounded JSON artifacts against a fail-closed schema subset.

## Best Possible Solution

Adopt a single clearly documented validation contract only after maintainers confirm core ownership; if approved, land the bounded fail-closed gate with live SSH proof and explicit subset semantics, otherwise retain repository-owned validation and close the linked proposal consistently.
