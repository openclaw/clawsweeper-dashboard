## Summary

Keep open: current main still has Daytona as direct-only, and this PR adds the missing brokered path, but the proposed Worker response path has a blocking security-boundary issue for shared leases.

## What This Changes

The PR adds brokered Daytona coordinator support across the CLI, Worker, docs, config, and tests, including Worker-held API key use, sandbox lifecycle, SSH-token refresh, redaction, and readiness handling.

## Best Possible Solution

Keep the brokered Daytona design, but split secret-bearing lease resolution from read-only/shared lease visibility and make the routing migration explicit for existing direct Daytona users.
