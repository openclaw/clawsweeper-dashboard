## Summary

Keep open: current main still stores active WebVNC handoff credentials as raw `username` and `password` fields in coordinator storage, so the central security concern remains valid and needs a maintainer security-boundary decision.

## What This Changes

The issue reports that WebVNC share handoff records persist generated VNC usernames and passwords as plaintext Durable Object values during the active ticket window.

## Best Possible Solution

Keep the issue open until maintainers choose the WebVNC handoff credential-sealing boundary and land a Worker fix with regression coverage proving stored handoff records and keys do not expose the submitted VNC username or password.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Which secret boundary should WebVNC credential handoff storage use so Durable Object storage readers cannot recover active VNC credentials without the handoff ticket?

Rationale: The source-confirmed issue is security-sensitive, and choosing ticket-bound sealing versus a deployment or broker secret changes Crabbox's supported threat model and operational behavior.

Likely owner: steipete

Owner reason: The current handoff implementation and recent WebVNC hardening history both trace to this owner candidate.

Owner confidence: high

Options:

- **Ticket-bound sealing (recommended):** Make the random handoff ticket necessary to decrypt the stored credential payload while preserving one-time consume and TTL semantics.
- **Deployment-secret sealing:** Encrypt the handoff payload with a coordinator secret outside Durable Object storage, accepting that broker runtime secret access remains sufficient to decrypt.
- **Document TTL-only storage:** Treat plaintext five-minute storage as accepted hardening debt and document that storage readers are inside the broker trust boundary.

## Reproduction Assessment

Yes. Source inspection on current main shows `issue()` stores the submitted `username` and `password` directly, and `consume()` returns those same stored fields after ticket validation.

## Solution Assessment

Unclear until maintainers pick the security boundary. The narrow fix should preserve manager-only issuance, visible-user redemption, TTL, replay rejection, and no-store responses while changing only the persisted credential representation and tests.
