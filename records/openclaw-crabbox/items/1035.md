## Summary

Keep open: current main still lets exact-ID REST/control heartbeats revive past-expiry live leases without rerunning active-cap admission, while create-time cap accounting excludes those same leases. The issue is security-sensitive and needs a maintainer choice on fail-closed versus cap-rechecked revival semantics.

## What This Changes

The issue asks Crabbox to prevent past-expiry live leases from being revived by heartbeat in a way that bypasses configured active-lease limits.

## Best Possible Solution

Keep coordinator active-lease caps as an enforceable resource boundary by counting live cleanup-pending leases until terminal cleanup and rejecting or cap-checking any expired-lease heartbeat revival under the same state lock, with regression tests for REST heartbeat, control heartbeat, and cleanup-retry windows.
