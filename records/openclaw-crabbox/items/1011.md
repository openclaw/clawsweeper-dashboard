## Summary

Keep open: current main still normalizes authenticated org identifiers with a lossy underscore replacement before lease sharing, run attribution, and usage checks use the value. The report is source-reproducible, security-sensitive, and not owned by a merged fix or canonical duplicate.

## What This Changes

The issue reports that coordinator org IDs are lossy-normalized before storage and authorization, allowing distinct raw org identifiers to collide for org-shared leases, runs, and usage accounting.

## Best Possible Solution

Store and compare a collision-resistant authorization org identity while keeping display labels separate, then add regression coverage for colliding org pairs across requestOrg, lease sharing, run visibility, and usage accounting.
