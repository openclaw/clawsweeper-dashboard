## Label Justifications

- `P1`: The report describes a documented mediated-egress boundary bypass that can turn an allowlisted hostname into operator-network SSRF under realistic opt-in preconditions.
- `impact:security`: The issue concerns egress allowlist enforcement, private-address reachability, and the operator-network security boundary.

## Summary

Keep open: current main still enforces mediated-egress allowlists with a pre-resolution hostname string check, then dials the original hostname, so the reported DNS-rebinding/private-address bypass remains a credible security issue.

## What This Changes

The issue requests hardening mediated egress so allowlisted hostnames cannot resolve to loopback, private, link-local, multicast, unspecified, or other reserved destinations unless maintainers explicitly allow that policy.

## Best Possible Solution

Add host-side resolved-address validation before opening the TCP connection, block unsafe reserved/private destinations by default, and make any private-network egress support explicit and visible to the operator.

## Reproduction Assessment

Yes at source level: an allowlisted host from the lease-side proxy reaches hostOpen, passes egressHostAllowed, and is dialed by net.Dialer without resolved-address policy. A runtime proof would map an allowed test hostname to loopback/private space and observe the host agent attempt the connection.

## Solution Assessment

Unclear as a final product decision: resolved-address validation before dialing is the narrow repair, but maintainers should decide the compatibility policy for legitimate private-network egress.
