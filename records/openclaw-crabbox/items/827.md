## Summary

Keep open: current main still accepts restored org-less WebVNC viewer attachments and keeps the owner-only legacy authorization fallback, so the central security report is not implemented or superseded.

## What This Changes

The issue reports that restored legacy WebVNC viewer attachments without organization metadata can remain authorized by owner alone after coordinator WebSocket restoration.

## Best Possible Solution

Fail closed for restored WebVNC viewer attachments that lack org metadata unless a trusted current-state reconstruction can prove the same owner/org principal, and add focused regression coverage for the legacy restored case.

## Reproduction Assessment

Yes, at source level: current main accepts an org-less restored webvnc-viewer and leaseViewerAuthorized returns true on owner-only fallback. I did not run a live runtime harness in this read-only review.

## Solution Assessment

Yes, fail-closed restored authorization is the narrowest maintainable security direction unless maintainers explicitly choose a bounded legacy compatibility policy.
