## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.88

Full review comments:

- **[P1] Send raw JSON to CubeSandbox envd process start:** `internal/providers/cubesandbox/client.go:371-375`
  - body: CubeSandbox’s SDK marshals the process-start payload to raw JSON and sends that directly to `/process.Process/Start`; only the response is a Connect stream. This wraps the request with `encodeConnectJSONEnvelope`, so real envd process starts can reject the body and make `crabbox run --provider cubesandbox` fail before the user command runs.
  - confidence: 0.9
- **[P1] Handle CubeSandbox snake_case exit codes:** `internal/providers/cubesandbox/client.go:506`
  - body: CubeSandbox’s SDK accepts both `exitCode` and `exit_code` and errors if neither is present. This struct only decodes `exitCode`, so a real `exit_code: 7` end event is decoded as the zero value and the provider can report a failing command as success.
  - confidence: 0.86
- **[P2] Preserve the sandbox virtual host for proxy routing:** `internal/providers/cubesandbox/client.go:483`
  - body: When `CUBE_PROXY_NODE_IP` is set, this builds the request URL with the node/IP as the host and only overrides `Host`. The CubeSandbox SDK keeps `49999-<sandbox>.<domain>` as the URL host and overrides `DialContext` to the node, which preserves virtual-host routing and TLS/SNI behavior; HTTPS proxy mode can fail with this URL shape.
  - confidence: 0.82
