## Label Justifications

- `P2`: The report describes a bounded authenticated artifact broker security issue with deployment-specific prerequisites and limited blast radius.
- `impact:security`: The issue concerns coordinator authorization boundaries and signed artifact upload/read grants across logical identity namespaces.

## Summary

Keep open: current main still normalizes the authenticated owner and caller prefix as collapsible path components before signing brokered artifact URLs, and the open org-namespace item does not fully cover this slash-bearing owner/prefix collision.

## What This Changes

The issue reports that brokered artifact object keys can collapse slash-bearing authenticated owner values and caller-supplied prefixes into the same storage namespace.

## Best Possible Solution

Define an encoded or versioned org/owner namespace for new brokered artifact grants, preserve a deliberate compatibility path for legacy artifact URLs, and add regression tests for both org omission and owner/prefix collisions.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main passes only `requestOwner(request)` into the brokered artifact signer and then normalizes owner and caller prefix with the same slash-splitting helper, so `alice/team` plus `run-1` collides with `alice` plus `team/run-1`.

## Solution Assessment

Yes on direction, but the exact key format needs maintainer judgment. Encoding or otherwise delimiting authenticated org and owner components is the narrow maintainable fix, with explicit handling for existing owner-only keys.
