- `P2`: The report describes a bounded authenticated artifact broker security issue with deployment-specific prerequisites.
- `impact:security`: The issue concerns coordinator authorization boundaries and signed artifact upload/read grants across logical identity namespaces.

## Summary

Keep open: current main still builds brokered artifact keys by normalizing authenticated owner and caller prefix as collapsible path components, and this report adds a distinct identity-component collision that is not fully closed by the open org-namespace tracker.

## What This Changes

The issue reports that brokered artifact object keys can collide when slash-bearing authenticated owner values and caller-supplied artifact prefixes normalize to the same path.

## Best Possible Solution

Track this with the artifact namespace security work and implement a server-side namespace format that encodes or otherwise delimits authenticated identity components, includes org, and preserves expected behavior for existing brokered artifact links through a documented compatibility path.

## Reproduction Assessment

Yes. Source inspection shows `POST /v1/artifacts/uploads` passes only `requestOwner(request)` into `artifactUploadResponse`, and `artifactPrefix` normalizes owner and request prefix with the same slash-splitting helper, so `owner=alice/team,prefix=run-1` and `owner=alice,prefix=team/run-1` produce the same key prefix.

## Solution Assessment

Yes on direction, but the final key format is compatibility-sensitive. The maintainable fix should encode or otherwise delimit authenticated identity components and include org, with deliberate handling for existing owner-only artifact keys.
