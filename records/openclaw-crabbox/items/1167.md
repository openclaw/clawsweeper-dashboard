- `impact:security`: The affected path can disclose Orgo Bearer credentials and remotely executed command content, including explicitly forwarded environment values.

## Summary

Keep open for security triage: the report identifies a concrete current-main Orgo request path where default Go redirect handling can replay authenticated command requests, while the repository’s documented trust boundary says credentialed redirects must remain confined to their configured origin.

## What This Changes

Add an Orgo-provider redirect guard that blocks cross-origin redirects before command bodies or Bearer credentials can be replayed outside the configured API origin.

## Best Possible Solution

Implement a cloned, provider-local Orgo HTTP client whose redirect callback permits only the configured scheme, canonical hostname, and effective port; preserve caller policy and Go’s default hop limit, redact rejected destinations, and add negative transport tests proving no body or Authorization reaches rejected targets.
