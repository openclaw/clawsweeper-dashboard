## Summary

Keep this PR open: current main still has the request-origin OAuth callback fallback, and this branch appears to be the focused candidate fix with sufficient live proof; the remaining question is maintainer acceptance of the fail-closed OAuth upgrade behavior.

## What This Changes

The PR makes Worker GitHub OAuth require `CRABBOX_PUBLIC_URL`, stores the configured callback URI in pending login state, rejects wrong-origin callbacks before code exchange, and updates Worker tests plus OAuth docs/changelog text.

## Best Possible Solution

Land the fail-closed OAuth binding after a maintainer accepts the upgrade requirement and the release/docs path clearly tells operators to set `CRABBOX_PUBLIC_URL` before GitHub OAuth use.

## Reproduction Assessment

Yes, source-reproducible: current main routes `/portal/login` into GitHub OAuth and `githubRedirectURI` falls back to the request origin when `CRABBOX_PUBLIC_URL` is unset. I did not run a live exploit path in this read-only review.

## Solution Assessment

Yes, the implementation shape matches the linked remediation: require a canonical public origin, store the callback URI with pending state, and use it for authorization and code exchange. The remaining choice is policy/rollout acceptance for the fail-closed upgrade behavior.
