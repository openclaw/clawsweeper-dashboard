## What This Changes

The branch makes Worker GitHub OAuth require `CRABBOX_PUBLIC_URL`, stores the configured callback URI with pending logins, rejects callbacks from other origins, and adds Worker regression coverage and docs notes.

## Best Possible Solution

Land the fail-closed OAuth callback-binding fix after public setup docs all say `CRABBOX_PUBLIC_URL` is required, release notes stay release-owned, and maintainers accept the auth compatibility tradeoff.

## Reproduction Assessment

Yes. Source inspection on current main shows portal/CLI GitHub OAuth deriving the callback from the request origin when `CRABBOX_PUBLIC_URL` is unset, and the PR adds targeted regression coverage for the proposed fix.

## Solution Assessment

Mostly yes. Requiring a configured public origin and binding pending login callbacks is the narrow security fix, but the remaining docs inconsistency, release-owned changelog edit, and fail-closed upgrade decision need resolution before merge.
