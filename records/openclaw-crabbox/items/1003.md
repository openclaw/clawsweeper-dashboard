- `P2`: This is a concrete security-boundary bug with generated credential exposure, but the impact is bounded by provider metadata read access, workspace lifetime, and later network positioning.
- `impact:security`: The issue concerns generated SSH host private key material and the integrity of workspace SSH host-key verification.

## Summary

Keep open: current `main` still carries a generated workspace SSH host private key into Linux cloud-init and then into provider bootstrap metadata, so the reported security boundary issue remains live.

## What This Changes

The issue reports that generated workspace SSH host private keys are copied into provider user-data/customData/metadata during workspace provisioning.

## Best Possible Solution

Keep workspace host-key pinning, but stop placing generated host private keys in provider-retained metadata and add regression coverage for cloud-init, AWS user-data, Azure customData, and GCP metadata.

Question: Should workspace host identity be generated in the guest with an authenticated public-key readiness handoff, or should Crabbox keep coordinator-side generation but deliver the private key through a non-retained channel?

Rationale: The unsafe dataflow is clear, but the fix changes the coordinator/provider trust boundary, workspace readiness protocol, and host-key pinning behavior.

Likely owner: steipete

Owner confidence: high

Options:

- **Generate in guest and hand back public identity (recommended):** Have first boot generate the host key, report only public identity/fingerprint over an authenticated readiness channel, and keep private key material out of provider metadata.
- **Use a non-retained secret channel:** Keep coordinator-side generation only if maintainers can provide a provider-independent delivery path that is not persisted in launch metadata.
- **Document provider metadata as trusted:** Accept the current exposure model only if maintainers decide provider user-data readers are inside the workspace trust boundary.

## Solution Assessment

Yes on direction: keeping host-key pinning while removing private key material from retained provider metadata is the right security boundary. The exact handoff mechanism needs maintainer security design before implementation.
