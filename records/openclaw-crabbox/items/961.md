## Summary

Keep open: current main still disables SSH host-key checking for the three reported provider targets, and the report remains a source-reproducible security-boundary issue.

## What This Changes

Restore SSH server host-key verification for Namespace Instance, Phala, and Islo SSH targets instead of using `DisableHostKeyChecking`.

## Best Possible Solution

Restore server authentication by default for all three providers using per-lease/provider-scoped `known_hosts` or provider-supplied verified fingerprints, with an explicit trusted opt-in or warning only where stable host identity is unavailable.
