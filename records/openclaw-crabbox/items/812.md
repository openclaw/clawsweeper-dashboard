## What This Changes

This PR makes RunPod release/reclaim paths require exact resource-bound local claims, rechecks provider id/name before deletion, preserves created-pod identity during failed-acquire cleanup, and updates tests and docs.

## Best Possible Solution

Land the exact-claim RunPod hardening after a credentialed exact-head live gate proves create, SSH, exact-claim stop, and zero-residue cleanup, with the documented --reclaim path as the supported recovery behavior.

## Reproduction Assessment

Yes. Current main has a source-visible path where stop uses ReleaseOnly, RunPod accepts a raw GetPod result, and ReleaseLease terminates the resulting CloudID without a final claim check; no live RunPod mutation was run in this read-only review.

## Solution Assessment

Yes, with a proof gate. Requiring exact resource-bound RunPod claims and rechecking id/name under the claim lock is the narrow maintainable fix; authenticated exact-head provider proof should precede merge.
