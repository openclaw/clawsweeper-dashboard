## Summary

Keep open. Current main still lacks a Flue provider, and the only direct implementation candidate closed unmerged rather than being replaced by a shipped implementation. The delegated-run design fits Crabbox’s provider architecture, but adopting and maintaining a Flue-specific protocol remains an explicit product decision.

## What This Changes

Add a first-class delegated-run `flue` provider that invokes a configured Flue workflow for one-shot Linux jobs with archive-based workspace staging and a versioned JSON protocol.

## Best Possible Solution

If maintainers sponsor the integration, define a narrow v1 limited to local Node-target one-shot runs, keep Flue-specific behavior inside `internal/providers/flue`, and require redacted live proof against a real Flue project plus archive-traversal, secret-handling, protocol-framing, failure-classification, and cleanup coverage before merge.
