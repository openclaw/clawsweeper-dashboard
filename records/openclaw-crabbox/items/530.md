## Label Justifications

## Summary

Current main deliberately defines this as a future Station phase rather than shipping the requested runtime. The focused bridge request remains useful and distinct, but implementation depends on maintainer approval of the Station sequence and initial security scope.

## What This Changes

Add a provider-neutral mode that launches a coding-agent harness inside a leased box and exposes its HTTP/SSE API through Crabbox-managed bridging.

## Best Possible Solution

Implement this as a narrow post-Station phase for one SSH-backed provider, with a pinned harness artifact, loopback-only daemon, scoped bridge tickets, explicit unsupported-provider behavior, no implicit model credentials, and live start/use/stop/cleanup evidence.
