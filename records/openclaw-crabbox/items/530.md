## Summary

Keep open: current main documents a future agent-runtime bridge but does not implement the requested generic harness daemon, HTTP/SSE bridge, or supported agent-runtime mode. This is a large, security-sensitive product direction that belongs under the broader Station roadmap rather than a narrow autonomous fix.

## What This Changes

The issue requests a provider-neutral mode that runs an external coding-agent harness in a leased box and exposes its HTTP/SSE API through Crabbox bridge plumbing.

## Best Possible Solution

Extend the open Station direction with a phased, provider-neutral supervised-workload implementation first, then add a loopback-only external-harness bridge with scoped tickets and no model credentials by default; keep individual harness adapters outside core until that contract is proven.
