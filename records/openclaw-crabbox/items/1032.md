## Summary

Keep open: current main still lacks an OVH redirect guard, and source plus Go stdlib inspection supports the credential-forwarding path; this needs maintainer security review rather than cleanup closure.

## What This Changes

The issue reports that the OVH provider signs requests and then follows cross-origin redirects without preventing `X-Ovh-*` credential headers from reaching a different origin.

## Best Possible Solution

Add an OVH adapter-local secure HTTP client that refuses signed cross-origin redirects, preserves caller redirect policy and default redirect limits, and covers same-origin plus cross-origin signed-request cases.
