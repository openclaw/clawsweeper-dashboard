## Label Justifications

- `P1`: The issue affects a documented runner path that can execute before workflows carrying repository secrets, OIDC material, and build authority.
- `impact:security`: The report concerns supply-chain integrity for executable artifacts Crabbox downloads and installs as part of a supported workflow.

## Summary

Keep open: current main and the latest release still download and extract GitHub Actions runner archives without a runner archive digest or signature check, and the documented path can handle repository secrets/OIDC on self-hosted runners.

## What This Changes

Require integrity or authenticity verification before GitHub Actions self-hosted runner archives are extracted or executed during runner hydration.

## Best Possible Solution

Add fail-closed Linux and Windows runner archive verification before extraction, with a maintained trusted metadata path for `latest` and pinned versions plus focused regression tests for missing and mismatched metadata.

## Reproduction Assessment

Yes at source level: current main’s Linux and Windows install scripts download runner archives and extract them without any digest or signature check. I did not run a live remote hydration because the source path is sufficient to confirm the missing guard.

## Solution Assessment

Yes, fail-closed archive verification before extraction is the right direction. The exact trusted metadata source and unsupported-version behavior need maintainer/security policy before an automated implementation should proceed.
