## Summary

Keep open: current main still treats brokered GCP as static service-account-key only, and the docs/readiness checks also require the key pair. The request is a valid bounded provider-auth feature, but it changes credential acquisition and should get maintainer/security direction before implementation.

## What This Changes

The issue requests keyless brokered GCP auth via the Google metadata server or Workload Identity while preserving the existing service-account-key flow, partial-env errors, project requirements, readiness checks, and docs.

## Best Possible Solution

Implement a GCP-provider-local token source that uses service-account JWT auth when both key variables are set, metadata-server OAuth tokens when neither is set in a supported runtime, explicit partial-env errors, and matching readiness/docs/tests without changing direct ADC or core fleet behavior.
