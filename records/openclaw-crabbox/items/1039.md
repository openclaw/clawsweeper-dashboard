## Summary

Keep open: current main still filters monthly usage by lease `createdAt` month before adding reserved USD, so live managed leases that cross a UTC month boundary can be omitted from current-month cap enforcement. The report is source-reproducible and security-sensitive, but maintainers should choose the permanent monthly-cap accounting semantics before repair.

## What This Changes

The issue reports that monthly reserved-USD caps exclude still-live managed leases created in a prior UTC month.

## Best Possible Solution

Define monthly cap enforcement as a supported coordinator guardrail, separate enforcement accounting from historical reporting if needed, and add regression coverage for live month-spanning leases across fleet, owner, and org caps.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should monthly reserved-USD enforcement count a live managed lease's full reservation in the current month after it crosses a UTC month boundary, or should Crabbox implement a documented pro-rated reservation model?

Rationale: Both choices can repair the bypass, but they encode different operator-facing budget semantics and security/cost boundary behavior, so maintainer intent should set the permanent policy before implementation.

Likely owner: steipete

Owner reason: This handle introduced the usage/cost-control surface and is the clearest owner for the budget-boundary policy choice.

Owner confidence: high

Options:

- **Count full live reservations (recommended):** Treat any currently live managed lease as consuming its full reserved USD for admission control until release, expiry cleanup, or terminalization, while keeping creation-month reporting separate if desired.
- **Implement pro-rated enforcement:** Prorate month-spanning reservations into the active month and document the exact accounting model so operators know how caps behave near month boundaries.
- **Keep creation-month semantics:** Document monthly caps as creation-month-only reporting/admission and accept that live prior-month reservations do not block new current-month reservations.

Yes by source review: a live managed lease created in the prior UTC month fails the `createdAt` month filter before its `reservedUSD` can contribute to current-month enforcement. I did not run a runtime reproduction because this was a read-only cleanup review.

## Solution Assessment

Unclear until maintainers confirm enforcement semantics; the report's live-reservation accounting approach is narrow, but pro-rating versus full reservation carryover is a policy choice.
