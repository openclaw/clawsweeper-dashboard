## Summary

Keep open: current main still has no CUA backend, and the linked implementation remains open with a concrete upstream blocker that prevents Crabbox from proving ownership of a newly created sandbox after an ambiguous create result. The issue should remain paired with that pull request while maintainers decide whether to defer mutating support or sponsor a narrower non-mutating experiment.

## What This Changes

Add CUA as a first-class delegated-run provider supporting cloud Linux sandbox execution, archive synchronization, lifecycle commands, configuration, credentials, claims, documentation, and validation.

## Best Possible Solution

Land mutating CUA support only after the upstream API exposes a live-proven idempotency key, client-assigned identity, or echoed nonce that Crabbox can bind durably to create intent, then rebase the linked pull request and prove a credentialed zero-residue lifecycle; a separately sponsored doctor-only experiment may remain strictly non-mutating.
