## Label Justifications

- `P1`: A credential-bearing provider workflow may disclose a reusable lifecycle API token when a configured endpoint serves a qualifying redirect.
- `impact:security`: The report concerns cross-origin credential disclosure and replay of authenticated Proxmox API requests.

## Summary

Keep this security report open for explicit maintainer triage: the supplied current-main source tracing identifies an authenticated Proxmox client with no redirect boundary, while the documented provider-client policy requires preserving scheme, canonical hostname, and effective port.

## What This Changes

Add a strict initiating-origin redirect policy to authenticated Proxmox API requests and regression coverage preventing credential or replayed-form disclosure.

## Best Possible Solution

Reject any redirect whose scheme, canonical hostname, or effective port differs from the origin that initiated the request, retain safe same-origin behavior only if Proxmox requires it, and add focused regression tests for token and body forwarding.
