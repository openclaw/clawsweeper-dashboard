- `impact:security`: The affected HTTP redirect boundary can expose temporary session-token headers and secret-bearing cloud-init content.

## Summary

Keep open for security triage: the report identifies a specific current-main Tencent Cloud HTTP-client path that can follow 307/308 redirects with signed request data and temporary-token headers, while the exploit prerequisite requires control of a trusted API endpoint response and is not shown to be presently exploitable against Tencent Cloud.

## What This Changes

Add Tencent Cloud–specific same-origin redirect confinement so redirected API requests cannot replay credentials or cloud-init payloads to a different scheme, hostname, or effective port.

## Best Possible Solution

Implement a Tencent-provider-local cloned HTTP client that rejects redirects unless the initiating origin’s scheme, canonical host, and effective port match, then add redacted-error and credential/body non-delivery regression tests for cross-origin, subdomain, port-change, and cross-service redirects.
