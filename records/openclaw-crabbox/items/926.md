## Label Justifications

- `P1`: The issue describes a destructive provider-resource ownership boundary problem that can delete unrelated exe-dev VMs, but it requires local operator credentials rather than remote unauthenticated access.
- `impact:security`: The affected path can cross Crabbox's provider-resource ownership boundary before a destructive provider action.
- `impact:data-loss`: The reported failure mode can delete unrelated VM state from a shared exe.dev account or automation profile.

## Summary

Keep open: current main and the latest release still allow exe-dev raw VM name or SSH-host resolution to flow into the destructive `exe.dev rm` path without a proven Crabbox ownership predicate.

## What This Changes

The issue asks Crabbox to prevent `crabbox stop --provider exe-dev` from deleting exe.dev VMs unless Crabbox can prove the target belongs to the current lease or an explicit adoption flow.

## Best Possible Solution

Make exe-dev release prove an exact local claim or matching Crabbox ownership tags immediately before `rm`; keep raw name/host discovery read-only unless an explicit reclaim/adoption path first persists a binding.
