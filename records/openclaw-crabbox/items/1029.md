## Label Justifications

- `P1`: The issue describes a default sync optimization that can forward source-control credential material into a remote lease environment.
- `impact:security`: The affected path concerns credential forwarding, command arguments, and sensitive Git remote material crossing a trust boundary.

## Summary

Keep open: current main still detects credential-bearing git-seed origins only for HTTP(S), so password-bearing non-HTTP URL-style remotes can still pass into the POSIX and Windows clone commands. The closed related report and merged fix covered the earlier HTTP(S) case, but they do not supersede this narrower remaining security gap.

## What This Changes

Extend the remote git-seed credential guard so password-bearing non-HTTP URL-style origin remotes are not forwarded into lease clone commands.

## Best Possible Solution

Extend the existing skip-and-warn git-seed guard to password-bearing URL-style remotes across Linux, Windows, and local Actions, while preserving passwordless SSH remotes and adding regression tests.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: Should Crabbox extend the existing git-seed credential guard to password-bearing non-HTTP URL-style remotes while keeping passwordless SSH remotes seedable?

Rationale: The security boundary is clear, but the detector must distinguish password-bearing URL userinfo from ordinary SSH usernames without breaking established seedable SSH remotes.

Likely owner: steipete

Owner reason: This handle owns the merged HTTP(S) guard and most current history in the git-seed security boundary.

Owner confidence: high

Options:

- **Extend password-bearing URL detection (recommended):** Treat non-HTTP URL userinfo with a password or token as credential-bearing, skip git seed with a redacted warning, and keep passwordless SSH forms seedable.
- **Block all URL userinfo:** Treat any URL-style userinfo as unsafe, which is simpler but may break common ssh://git@host/repo.git workflows.
- **Defer for private seed credentials:** Pause this fix until Crabbox has an explicit scoped private-repository seed credential mechanism that avoids argv and persisted remote config.

## Reproduction Assessment

Yes. Source inspection on current main shows the credential detector returns false before parsing non-HTTP URL schemes, and the enabled seed path then passes the normalized remote into POSIX or Windows git clone command construction.

## Solution Assessment

Unclear until the maintainer security-boundary choice is confirmed. The narrow maintainable solution is to extend credential detection scheme-independently for password-bearing URL-style remotes, not to disable ordinary passwordless SSH remotes.
