## Summary

Keep open: current main still returns unsigned, non-expiring public read URLs whenever `CRABBOX_ARTIFACTS_BASE_URL` is configured, while the security guide still describes brokered artifact credentials as signing short-lived read URLs. The issue is source-reproducible and needs a maintainer security/product decision rather than cleanup closure.

## What This Changes

The issue asks Crabbox to stop brokered artifact base URLs from acting as unsigned permanent read links, or make that public-link mode explicit and safer.

## Best Possible Solution

Choose an explicit artifact read policy: either return bounded signed/proxied reads for brokered artifacts, or document `CRABBOX_ARTIFACTS_BASE_URL` as public non-expiring mode and add safer public-mode namespace/tests.

## Reproduction Assessment

Yes, as a source-level reproduction. Current main directly returns `baseURL + key` for brokered artifact reads when `CRABBOX_ARTIFACTS_BASE_URL` is set, while the fallback without a base URL signs a bounded GET URL.

## Solution Assessment

Unclear until maintainers choose the intended policy. The narrow secure fix is signed/proxied reads, but a public publishing mode may be acceptable if it is explicit, documented, and tested as public.
