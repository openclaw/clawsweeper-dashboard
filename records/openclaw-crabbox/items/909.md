## What This Changes

The PR changes Worker coordinator restore, run-history, lease-detail, Azure orphan-sweep, and terminal-run pruning paths to use exact lease reads, paged scans, and a configurable 30-day run-retention setting, with docs/config/tests and a changelog edit.

## Best Possible Solution

Land a version that makes every production CoordinatorStorage backend honor pagination, removes full lease/workspace namespace scans from recovery alarms, makes run retention opt-in or explicitly approved for upgrades, and leaves release notes to release owners.

## Reproduction Assessment

Yes for the PR defects from source: the new paged scan helper requires limit/startAfter, Postgres ignores those options, alarm still has full lease/workspace scans, and the default retention path deletes old terminal runs. I did not run a live deployment in this read-only review.

## Solution Assessment

No, not as-is: exact reads, paged scans, and bounded pruning are the right direction, but the implementation must cover the production Postgres backend, the recovery alarm path, and upgrade-safe retention semantics before merge.

  - body: Adding `pruneTerminalRuns()` here does not make the recovery alarm bounded: `expireLeases()` still runs first and `scheduleAlarm()` still runs later, and both load complete `lease:` and `workspace:` namespaces. A deployment whose backlog includes historical leases/workspaces can still reset before the run pruning drains state. This was visible in the previous reviewed head; raising it now after comparing the current head to `93980fbc`.
  - late: true
  - confidence: 0.84
- **[P1] Teach Postgres storage to honor scan pagination:** `worker/src/fleet.ts:11266-11270`
  - body: This helper now depends on `CoordinatorStorage.list` honoring `limit` and `startAfter`, but the Node runtime still uses `PostgresCoordinatorStorage`, whose `list` only reads `prefix`. With enough matching records, Node/Postgres scans return an unbounded or non-advancing page and can throw before completing run-history or orphan-sweep work; update the Postgres query and tests with the new pagination contract.
  - confidence: 0.93
- **[P1] Make run pruning opt-in for existing deployments:** `worker/src/fleet.ts:11426`
  - body: On upgrade this default starts deleting terminal run records, logs, chunks, and events older than 30 days even though existing deployments previously retained them indefinitely and expose them through run history and lease detail pages. Preserve existing history until retention is configured, or add an explicit maintainer-approved migration/upgrade path.
