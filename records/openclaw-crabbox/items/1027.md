## Summary

Keep open: current main and the latest v0.36.0 release still use a Worker URL-userinfo redaction regex that requires `user:password@`, so passwordless userinfo can remain visible in documented coordinator diagnostic paths.

## What This Changes

The issue reports that Worker diagnostics leave `https://TOKEN@host/path` userinfo visible even though Crabbox docs and the Go CLI redactor treat URL userinfo as credential material.

## Best Possible Solution

Align the Worker URL-userinfo redactor with the Go CLI behavior, preserve already-redacted placeholders, and add Worker regression coverage for passwordless userinfo in the helper and a diagnostic response path.
