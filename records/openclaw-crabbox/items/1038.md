## Label Justifications

- `P0`: The report describes a credential-boundary failure where a Nomad ACL token can be replayed to a cross-origin redirect target.
- `impact:security`: The affected behavior can disclose a provider credential outside the operator-selected Nomad origin.
- `impact:auth-provider`: The bug is in provider credential routing for Nomad ACL token authentication.

## Summary

Keep open: current main and v0.36.0 still build the Nomad SDK client with a token-backed `SecretID` and no same-origin redirect guard, while the repository security guide says credential-bearing provider clients with custom endpoints should reject cross-origin redirects.

## What This Changes

The issue asks Crabbox to prevent the Nomad delegated-run provider from forwarding Nomad ACL tokens to cross-origin redirect targets.

## Best Possible Solution

Add a Nomad-provider HTTP client wrapper that permits only same scheme, hostname, and effective port redirects, preserves same-origin redirects and caller redirect limits, and adds regression coverage for `X-Nomad-Token` leakage plus the existing provenance guard.
