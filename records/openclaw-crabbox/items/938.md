## Summary

Keep open for maintainer merge review. The patch appears to fix the linked Islo credential-redirect boundary with sanitized errors and sufficient live proof, but it intentionally changes custom-endpoint redirect compatibility and needs maintainer acceptance before merge.

## What This Changes

The PR adds an Islo same-origin redirect guard around the token, raw HTTP, and SDK clients, plus provider tests for allowed same-origin redirects, refused cross-origin redirects, and sanitized redirect errors.

## Best Possible Solution

Land same-origin redirect confinement as the default security boundary once maintainers accept the compatibility tradeoff; add a trusted-origin opt-in only if supported Islo deployments require cross-origin aliases.
