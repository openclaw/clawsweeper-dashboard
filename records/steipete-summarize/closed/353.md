## Summary

Current main and v0.21.3 do not recognize Loom recordings for transcript routing, and the generic yt-dlp audio selector can fall back to video-only formats. The issue should remain open because the mergeable, proof-positive implementation at https://github.com/steipete/summarize/pull/355 explicitly owns this work and has not merged yet.

## What This Changes

Add transcript extraction for public Loom share and embed URLs through the existing yt-dlp and transcription pipeline, including audio-capable format selection.

## Best Possible Solution

Land a reviewed implementation that recognizes strict Loom recording URLs, preserves the original Loom identity through yt-dlp, requires audio-capable transcription formats, and avoids changing implicit daemon or non-Loom auto-routing behavior.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes. Current main has no Loom URL classification in the generic media transcript route, and its source path deterministically reaches generic/not_implemented for a normal Loom share page without usable embedded media; the reporter also identified the audio-only selection failure.

## Solution Assessment

Yes in direction. Reusing the existing generic yt-dlp and transcriber pipeline with strict Loom URL identity and audio-capable selection is preferable to a bespoke Loom API, while the broader linked patch should receive compatibility review before merge.
