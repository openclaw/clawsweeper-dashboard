## Summary

The previous P2 blocker remains on the unchanged head: the deep-link query stays authoritative on every Options initialization, so it can override a user’s later persisted tab choice after reload. The main diagnostic change is well-proven and security-clean, but this compatibility defect should be repaired before merge.

## What This Changes

The PR deep-links the Chrome side-panel daemon Connect hint to Options → Runtime, adds state-specific daemon and native-host diagnostics, and updates documentation plus unit and packaged-extension browser tests.

## Best Possible Solution

Use the URL target only for initial navigation, remove the consumed `tab` query or hash with `history.replaceState` while preserving unrelated URL state, and add a switch-then-reload regression proving stored tab selection resumes.
