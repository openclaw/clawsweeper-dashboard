## Summary

Keep open: current main still routes MiniMax through the Chrome extension's generic OpenAI-compatible direct-provider path, which does not request separated MiniMax reasoning and streams any `delta.content` into the visible summary. The merged MiniMax CLI/daemon work in https://github.com/steipete/summarize/pull/250 is useful context, but it does not cover the later browser-extension direct-provider path from https://github.com/steipete/summarize/pull/307.

## What This Changes

The issue reports that Chrome extension direct mode leaves MiniMax `<think></think>` reasoning tags visible in the summary output.

## Best Possible Solution

Align the Chrome extension MiniMax direct-provider path with the core MiniMax behavior by requesting separated reasoning and adding a focused regression that proves MiniMax reasoning never reaches visible summary text.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes, source-level reproduction is high confidence: a MiniMax SSE response with `<think>` in `delta.content` will be yielded directly by the current extension parser, and the reporter screenshot shows that exact user-visible failure in v0.21.3. I did not run a live MiniMax account during this review.

## Solution Assessment

Yes, the narrow maintainable fix is to make the extension direct MiniMax path follow the existing core MiniMax separated-reasoning contract, with a regression test for the extension parser/request body. A broad output sanitizer across all providers would be riskier and less aligned with the existing provider-specific design.
