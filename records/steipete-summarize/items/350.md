## Summary

Keep open: this is an OWNER-authored draft PR, current main does not already contain the change, and source review found no blocking line-level defect. The patch appears to narrow the standard extension permission boundary, but merging intentionally moves debugger-backed automation out of the standard Chrome build, so that compatibility boundary needs maintainer-owned acceptance.

## What This Changes

The PR moves Chrome userScripts to optional permissions, gates debugger access behind a separate automation build, hides debugger-backed tools when unavailable, and updates extension docs/tests around that split.

## Best Possible Solution

Land the least-privilege standard Web Store build after maintainer acceptance that debugger-backed automation belongs only in the explicitly separate automation build and release packaging cannot mix the two artifacts.
