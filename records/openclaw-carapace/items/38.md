## Summary

Keep this issue open. The report identifies an established shared-token contract failure on current `main`: light status foregrounds are named and used as the text color for their matching status backgrounds, yet the documented reproduction reports sub-AA contrast for every light status role. The reporter is a repository member, so this needs explicit maintainer handling rather than automated cleanup.

## What This Changes

Fix the light-theme status foreground and matching background token pairings so status text meets WCAG AA when consumers use the named foreground on its corresponding status background.

## System Context

Carapace provides framework-neutral design tokens that consumer applications use for themed UI states. Product theme tokens feed candidate CSS such as badges, which then renders status text and backgrounds in downstream applications.

## Architecture Diagram

flowchart LR
  A[Product theme tokens] --> B[Light and dark themes]
  B --> C[Status foreground and background pairs]
  C --> D[Candidate badge styles]
  D --> E[Consumer application UI]
  E --> F[Legible status text]

## Best Possible Solution

Choose darker light-theme status foregrounds that clear AA after the translucent status backgrounds are composited over the documented light surface, then add regression assertions for every status role and keep the candidate badge specimens using the canonical tokens.
