## Summary

Keep this draft open: the immutable snapshot design is promising, but the current head still conflates completed staged state with active reader state, causing normal publication after `--stage-only` to re-ingest or conflict instead of cutting over the completed snapshot. Live cross-service and sanitized-artifact proof is also still absent.

## What This Changes

The PR adds content-addressed sanitized cloud snapshots, staged publication and later reader cutover, strict remote writer/reader contract validation, expanded review datasets and coverage, and crawlkit v0.14.0.

## Best Possible Solution

Represent completed inactive snapshot state separately from the active reader snapshot, skip ingestion only after exact digest, schema, capability, source-hash, and coverage validation, and prove stage, resume, cutover, reader refresh, and sanitized output against compatible deployed services.
