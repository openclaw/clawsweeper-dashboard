## Summary

This member-authored draft must remain open, and the patch has a merge-blocking staged-resume defect: it only recognizes the target snapshot as complete when that digest is already active, even though `--stage-only` intentionally leaves the prior snapshot active. Real remote behavior proof is also still missing.

## What This Changes

The branch adds sanitized content-addressed cloud snapshots with nine synchronized datasets, strict enrichment coverage, resumable staging, atomic reader cutover, and Crawlkit v0.14.0 integration.

## Best Possible Solution

Recognize complete staged snapshot metadata independently of the active reader digest, preserve the previous active snapshot until explicit cutover, cover distinct active and staged digests in regression tests, and prove the sanitized stage-to-cutover flow against the compatible remote deployment.
