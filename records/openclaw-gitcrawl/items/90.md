## Summary

The change is useful, cleanly scoped, and backed by convincing live CLI proof, but it should not merge until portable-store handling is defined: the new ledger currently falls outside the declared portable-v2 contract and can carry full hydration error messages into published archives. The persistent schema and CLI JSON contract also need explicit maintainer approval.

## What This Changes

The PR adds a SQLite ledger for failed PR-detail hydration attempts, resolves entries after successful retries, exposes them through `sync-failures`, and includes unresolved counts in coverage output.

## Best Possible Solution

Keep the ledger local by dropping `sync_attempt_failures` during portable-v2 pruning, add a regression test proving it is absent, and then approve the tested v5 migration and CLI JSON contract for release.
