## Summary

Keep this member-authored PR open. The source-generation cache change appears to address the reported data-loss path, but its new SHA-only cache gate regresses older or manually altered portable stores without a manifest by rerunning SQLite integrity checks on every reopen.

## What This Changes

The PR separates immutable portable-source validation from writable runtime-mirror health checks, updates doctor schema diagnostics, and adds persistence regression coverage.

## Best Possible Solution

Retain the new source-hash generation key when a manifest is available, while preserving the existing manifest timestamp-and-size cache fallback when it is unavailable; add coverage for reopening a legacy manifest-less portable mirror.
