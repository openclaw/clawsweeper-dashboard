## What This Changes

This PR reports portable runtime-mirror redirects in CLI and JSON output, then makes `portable prune` validate and publish the pruned database and manifest back to the portable checkout by default, with `--no-publish` for mirror-only pruning.

## System Context

Portable stores use a checked-out published database as their source while writable commands operate on a separate runtime mirror. `portable prune` is the handoff from mirror data to the checkout artifact that users subsequently commit and publish.
