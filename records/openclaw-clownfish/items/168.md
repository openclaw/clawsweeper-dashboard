## Summary

Keep open: current main uses cached package stores and parallel hosted runners, but each execute/autonomous worker still creates an ordinary target clone and the fix executor installs target dependencies separately. The warmed snapshot-fork pool remains a substantial execution-platform decision rather than already implemented cleanup.

## What This Changes

Requests a warmed per-repository workspace that can be snapshot-forked into isolated per-issue agent checkouts.

## Best Possible Solution

Define and benchmark a provider-neutral warmed-workspace lease contract, including isolation, freshness, cleanup, fallback, and cost acceptance criteria, before selecting a snapshot backend.
