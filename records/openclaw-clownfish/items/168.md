## Summary

Keep open: the merged checkout, worker-burst, and preflight improvements address adjacent setup and concurrency costs, but none establishes the proposed warmed snapshot-fork lifecycle with isolated per-issue workspaces. This remains a cross-cutting product and operational architecture decision rather than already-implemented cleanup.

## What This Changes

The issue proposes warming one repository environment and snapshot-forking an isolated prepared workspace for every issue worker.

## Best Possible Solution

Define an opt-in warmed-workspace backend with explicit snapshot creation, per-worker isolation, credential/cache boundaries, teardown, failure fallback, and rollout metrics before implementing it behind a narrowly scoped runner abstraction.
