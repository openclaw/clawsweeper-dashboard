## Summary

Keep open: the available context shows adjacent improvements to worker artifact handling and parallel preflights, but not the proposed warmed snapshot-fork lifecycle. This remains a cross-cutting runtime and isolation design choice that needs maintainer direction before implementation.

## What This Changes

Add a warmed-repository runtime that snapshot-forks an isolated prepared workspace for each issue worker instead of repeating clone, dependency setup, cache warming, and build work.

## Best Possible Solution

Define a supported prepared-workspace lease interface with disposable per-job copies, explicit cleanup and secret/cache isolation, bounded capacity, and a measured fallback to the existing provisioning path before implementing a backend-specific integration.
