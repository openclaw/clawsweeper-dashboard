## Summary

Keep open: current main still creates ordinary target checkouts for individual workflow and fix-executor runs, while caching package/tool downloads rather than a warmed workspace image. No same-repository PR implements snapshot-fork fan-out, and the related Crabbox primitive remains an open product direction, so the central request is still necessary but requires architectural approval.

## What This Changes

Add a reusable warmed repository environment that can snapshot-fork isolated workspaces for parallel per-issue agents.

## Best Possible Solution

Introduce an opt-in workspace-provider interface, canary one warmed snapshot-fork backend with explicit image freshness and credential boundaries, retain ordinary checkout fallback, and require benchmark plus isolation/cleanup proof before making it a default.
