## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.86

Full review comments:

- **[P1] Await the active turn before releasing the lease:** `src/cli/session/queue-owner-runtime.ts:377`
  - body: The new signal path passes `doShutdown` directly to `withInterrupt`, but `withInterrupt` rejects after `onInterrupt` completes while the `run()` callback can still be inside `runQueuedTask`. Because `doShutdown` releases the owner lease, a SIGTERM during a prompt can let a replacement owner start before the original turn has flushed/checkpointed session state and sent its final queue response. Keep the bridge-kill behavior, but wait for the active turn cleanup before releasing the lease or returning from the owner process.
  - confidence: 0.87
- **[P2] Preserve pending shutdown errors before destroying sockets:** `src/cli/queue/ipc-server.ts:207`
  - body: `close()` still sends `QUEUE_OWNER_SHUTTING_DOWN` for pending `waitForCompletion` prompts, but this new loop immediately destroys every tracked socket after `task.close()` only calls `socket.end()`. A forced destroy can tear down the socket before buffered writes drain, turning the existing typed retryable error contract into a generic disconnect. Drain or selectively destroy sockets so pending shutdown responses remain reliable.
  - confidence: 0.76
