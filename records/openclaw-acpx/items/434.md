## Label Justifications

- `P1`: The default built-in Codex workflow consistently fails at initialization on affected macOS hosts, blocking a primary agent path with a demonstrated workaround.
- `impact:crash-loop`: The selected Codex child exits during every initialization attempt, making the built-in agent unavailable on affected hosts.
- `impact:ux-friction`: The failure originally surfaced as an opaque exit code and recovery still requires discovering and exporting `CODEX_PATH` or overriding the adapter manually.

## Summary

Keep open: current main and v0.12.0 still select `@agentclientprotocol/codex-acp@^0.0.44`, so the independently reproduced macOS startup failure remains. Current main now preserves startup stderr, but it neither upgrades the affected adapter nor documents the proven `CODEX_PATH` workaround.

## What This Changes

Fix the built-in Codex agent startup failure caused by the pinned adapter launching an OS-rejected bundled Codex binary, with appropriate diagnostics and recovery guidance.

## Best Possible Solution

Compatibility-test and update the built-in Codex adapter to a non-revoked release, retain the new startup-stderr diagnostics, and document `CODEX_PATH` in `agents/Codex.md` and `skills/acpx/SKILL.md`; add automatic PATH fallback only if maintainers explicitly approve that trust policy.
