## Summary

Keep open: current v0.12.0 still routes the built-in Codex agent through the owned codex-acp package path and has no documented CODEX_PATH workaround or automatic system Codex fallback; existing startup-stderr handling only covers adapter-process stderr/exit paths, not a nested Codex binary failure returned by codex-acp as an initialize error.

## What This Changes

The issue asks acpx to make Codex adapter startup failures diagnosable, document CODEX_PATH, and possibly fall back to a working system codex binary when the bundled Codex binary is missing.

## Best Possible Solution

Keep this open and land the narrowest maintainer-approved path: a Codex-specific diagnostic and CODEX_PATH documentation first, with any automatic fallback handled as an explicit launcher policy decision.
