## Summary

This issue remains necessary: current main and v0.12.0 still pin the built-in Codex adapter to `@agentclientprotocol/codex-acp@^0.0.44`, whose dependency resolves to the reported `@openai/codex@^0.128.0` line. Startup stderr is now included in `AgentStartupError`, but the affected adapter pin and documented recovery remain unresolved; automatic PATH fallback also conflicts with prior direction that built-in adapter versions stay acpx-owned and global commands remain explicit overrides.

## What This Changes

Update the built-in Codex adapter to avoid the XProtect-affected bundled executable, retain actionable startup diagnostics, document explicit recovery, and decide whether system-Codex fallback belongs in acpx.

## Best Possible Solution

Select a current supported codex-acp version, validate its initialize, session, model, permission, and reconnect behavior plus the affected macOS launch, update the registry and synchronized Codex docs, retain the released stderr diagnostics, and keep recovery explicit unless maintainers approve a narrowly defined fallback contract.
