## Summary

Current main and v0.12.0 still launch the built-in Codex agent through `@agentclientprotocol/codex-acp@^0.0.44`, so the affected-host startup failure remains possible. The shipped startup-stderr summary addresses the opaque-error portion, but the adapter version, documented recovery path, and fallback policy remain unresolved; automatic PATH fallback also conflicts with prior maintainer direction favoring acpx-owned pinned built-ins.

## What This Changes

Address the macOS Codex startup failure by updating the implicated adapter path, improving diagnostics, documenting `CODEX_PATH`, and deciding whether a system-Codex fallback belongs in acpx.

## Best Possible Solution

Retain the shipped generic startup diagnostics, independently validate the affected native artifact, compatibility-test and upgrade the pinned Codex adapter, and document `CODEX_PATH` as the explicit recovery path; add automatic fallback only if maintainers intentionally revise the deterministic built-in launch contract.
