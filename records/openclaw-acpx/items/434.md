## What This Changes

The issue asks acpx to recover from Codex startup failure caused by macOS XProtect deleting the bundled `@openai/codex@0.128.0` binary by bumping `codex-acp`, improving diagnostics, documenting `CODEX_PATH`, and possibly falling back to a system Codex binary.

## Best Possible Solution

Compatibility-test a newer Codex adapter pin, update the registry/tests/Codex docs/skill notes, and add a guarded `CODEX_PATH` system-binary fallback only if maintainers accept that launcher policy.
