## Summary

Keep open: current main and v0.12.0 still select the adapter version implicated by two live macOS reproductions, so the built-in Codex startup regression remains unresolved. Generic startup-stderr reporting is already present, but the adapter update and fallback policy still require maintainer handling.

## What This Changes

Resolve the built-in Codex startup failure on affected macOS hosts by moving off the rejected bundled Codex build while retaining useful startup diagnostics and documenting recovery.

## Best Possible Solution

Ship a focused, compatibility-tested Codex adapter update, preserve the generic startup-stderr diagnostic, and synchronize `agents/Codex.md` with `skills/acpx/SKILL.md`; document the explicit `CODEX_PATH` override and add automatic PATH fallback only if maintainers deliberately adopt that precedence policy.
