## Summary

Keep this PR open for normal maintainer review. The final head is a focused fix that centralizes timer conversion across flags and config, but intentionally changes the upgrade behavior for oversized accepted values from Node’s historical near-immediate clamp to a CLI validation error.

## What This Changes

The PR shares timeout and TTL conversion across CLI flags and config, floors positive sub-millisecond inputs to 1 ms, preserves TTL zero as its sentinel, and rejects delays above Node’s supported timer maximum.

## System Context

The CLI receives timeout and queue TTL settings from flags and configuration, converts them to milliseconds, and passes them into prompt cancellation and queue-owner lifecycle logic. The resulting timer values determine whether a prompt times out and whether an idle queue session exits or remains available for resumption.

## Best Possible Solution

Merge the shared conversion boundary only after explicitly accepting the oversized-value validation behavior, retaining zero solely for the documented TTL sentinel and keeping flag/config semantics identical.
