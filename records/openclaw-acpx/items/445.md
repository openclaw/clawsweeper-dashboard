## Summary

Current main still discards detached queue-owner startup diagnostics and eventually reports a generic polling timeout. The bug remains necessary, but an open closing PR already owns the implementation, so this issue should remain open until that candidate is safely reviewed and merged.

## What This Changes

Surface the queue owner’s early exit, signal, stderr, and queue-directory preparation error instead of reporting only a generic startup timeout.

## Best Possible Solution

Land a corrected version of https://github.com/openclaw/acpx/pull/448 that observes early spawn or exit failure, retains only bounded cold-start stderr, stops retention at first IPC acceptance, safely drains later stderr, and reports queue-directory operation, path, and errno details.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes at source level: force queue-directory preparation to fail before socket binding, and current main discards the detached child’s stderr and exit state before exhausting the startup poll. The reporter supplied a concrete EPERM path observed on both acpx 0.10.0 and v0.12.0.

## Solution Assessment

Yes in direction, but only with safe detached-process lifecycle handling. Bounded early diagnostics and specific queue-directory errors are the narrow fix; retained capture must end at IPC acceptance without closing the child-facing stderr pipe.
