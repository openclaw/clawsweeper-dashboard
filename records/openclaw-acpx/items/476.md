## Summary

Keep this PR open for normal merge review. The current atomic-write helper on `main` extends the destination basename with its collision suffix, so a valid long session filename can exceed a 255-byte filesystem-component limit; this focused patch moves that suffix into a bounded sibling temporary name while preserving same-directory atomic rename behavior and UUID uniqueness.

## What This Changes

The PR gives atomic session writes a bounded hidden temporary basename in the destination directory and adds a regression test for long valid session filenames.

## System Context

ACPX persists CLI session records through the file session store. Each save writes a temporary file beside the destination and renames it atomically, so the temporary-path helper must avoid filename-length failures without weakening concurrent-save isolation.

## Architecture Diagram

flowchart LR
  A[Session record] --> B[File session store]
  B --> C[Destination JSON path]
  C --> D[Bounded temporary sibling]
  D --> E[Atomic rename]
  E --> F[Persisted session record]

## Best Possible Solution

Merge the bounded sibling-name approach with the regression test so valid long session identifiers remain writable while atomic saves keep unique same-directory temporary files.

## Solution Assessment

Yes. A fixed-shape temporary basename in the destination directory is the narrowest maintainable fix because it preserves the existing atomic rename boundary, diagnostic fields, and per-write UUID isolation without changing session IDs or destination names.
