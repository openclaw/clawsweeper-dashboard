## Label Justifications

- `P1`: The PR targets orphaned bridge descendants that can accumulate until sessions hang, which is a broken agent workflow affecting real users.
- `merge-risk: 🚨 compatibility`: Moving POSIX bridges into detached process groups changes how existing setups receive terminal or supervisor process-group signals.
- `merge-risk: 🚨 availability`: When the optional lifeline helper is unavailable, the detached bridge can survive abrupt owner shutdown and recreate the orphan-process availability failure.

## Summary

Keep open: the PR addresses a real orphan-process availability class and includes usable live-output proof, but the helper-unavailable path still detaches POSIX bridges, so the promised silent fallback is not current behavior and can worsen abrupt-shutdown orphaning.

## What This Changes

The branch adds POSIX bridge process-group reaping, a native pipe-based lifeline helper with lazy compile/cache resolution, package build changes, and real-process tests for cooperative close and abrupt queue-owner death.

## Best Possible Solution

Preserve current non-detached behavior when the lifeline helper cannot be resolved or compiled, and enable detached process-group mode only when a working lifeline or equivalent parent-death coverage is present.

## Reproduction Assessment

Yes, at source level. Current main has no parent-death handler and only signals the bridge PID during close; the PR body also includes live-output proof for the intended lifeline path.

## Solution Assessment

No, not yet. The pipe lifeline is a plausible narrow solution, but the helper-unavailable fallback must preserve current spawn/signal behavior before this is the safest implementation.
