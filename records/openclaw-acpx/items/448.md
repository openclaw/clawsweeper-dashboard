## Label Justifications

## Summary

Keep this PR open: the diagnostic design and proof are strong, but the current head still leaves the drain-only child stderr pipe referenced after IPC acceptance, which can prevent the invoking process from terminating while a long-lived detached owner remains active.

## What This Changes

The branch adds bounded cold-start queue-owner stderr and exit diagnostics, clearer queue-directory errors, IPC-accept capture shutdown, lifecycle tests, and a changelog entry.

## Best Possible Solution

Retain the bounded stderr tail until first IPC acceptance, then keep draining to avoid EPIPE while unrefing the pipe so the caller can exit; add a regression that proves parent termination while the owner remains alive and writes post-accept stderr.
