## Label Justifications

- `P1`: The new pipe can hang normal no-wait or completed session invocations for the owner's full lifetime, including indefinitely with `--ttl 0`.
- `merge-risk: 🚨 availability`: Merging the retained parent-child stderr connection could prevent the invoking CLI process from terminating independently of the long-lived detached owner.

## Summary

The latest commit resolves both prior lifecycle findings, but the new always-drained parent-side stderr pipe creates a separate P1 risk: the submitter can remain alive as long as the detached queue owner, including indefinitely with `--ttl 0`.

## What This Changes

The branch adds bounded cold-start queue-owner stderr and exit-state diagnostics, stops retaining bytes on IPC acceptance while continuing to drain stderr, improves queue-directory errors, and adds focused tests and a changelog entry.

## Best Possible Solution

Keep bounded actionable startup diagnostics, but transport them without a parent-referenced stdio handle after IPC acceptance and prove the submitter exits while a detached `--ttl 0` owner remains available.

No in its current form. Bounded startup diagnostics and the IPC-acceptance boundary are appropriate, but the parent must still be able to exit independently after retained capture ends.
