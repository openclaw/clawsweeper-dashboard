## Summary

This PR remains useful and directly addresses the linked current-main diagnostics bug, but the current head still leaves the drained queue-owner stderr pipe referenced, so a submitter can remain alive until the detached owner exits; this is especially serious for `--ttl 0`.

## What This Changes

The branch adds bounded cold-start queue-owner stderr and exit diagnostics, clearer queue-directory failures, an IPC-accept capture boundary, lifecycle tests, and a changelog entry.

## Best Possible Solution

Keep the bounded startup diagnostics and IPC-accept boundary, then unref the stderr pipe while continuing to drain it and add subprocess-level coverage proving the submitter exits promptly while a detached owner remains alive and can still write stderr.

## Solution Assessment

No in its current form. Bounded startup-only capture with an IPC-accept boundary is the right design, but the drain must also be detached from the submitter event loop and covered by an independent-exit test.
