## Label Justifications

- `P1`: The current patch can hang a session caller indefinitely in an existing queue workflow when a long-lived owner keeps the referenced stderr pipe open.
- `merge-risk: 🚨 availability`: The added stderr pipe can prevent the parent CLI from terminating even though the queue owner was deliberately detached and unrefed.

## Summary

Keep this PR open but do not merge its current head. The earlier capture-retention and EPIPE concerns are addressed, but the remaining referenced stderr pipe can keep a no-wait CLI process alive for the lifetime of a long-running queue owner, including an owner configured with `--ttl 0`.

## What This Changes

The branch adds bounded cold-start stderr and exit diagnostics for detached queue owners, clearer queue-directory preparation errors, an IPC-accept lifecycle callback, and focused tests.

## Best Possible Solution

Keep bounded stderr capture through the first IPC acceptance, then continue draining without retaining diagnostics while also unrefing the stderr pipe or its underlying handle; add a subprocess regression proving the CLI exits while a long-lived owner remains active and writes post-bind stderr.
