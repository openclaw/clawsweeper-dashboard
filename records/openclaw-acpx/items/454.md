## Label Justifications

- `P2`: This is a normal-priority feature proposal with meaningful but bounded compatibility, session, and output-safety blockers rather than an active production regression.
- `merge-risk: 🚨 compatibility`: The two new reserved verbs can intercept existing custom agents named `agents` or `models` and change established invocation behavior.
- `merge-risk: 🚨 session-state`: A nominally read-only model query uses the persistent session ensure path, which may create state or return model metadata from an existing session.
- `merge-risk: 🚨 security-boundary`: Agent discovery can emit arbitrary configured launch commands that may embed credentials or private endpoint information.

## Summary

This is a useful, vision-aligned discovery concept, but the current patch is not merge-ready: it reserves valid custom-agent names, can expose configured command secrets, does not guarantee fresh model discovery, adds an undocumented Devin built-in, and lacks captured real-runtime proof.

## What This Changes

Adds top-level agent enumeration and per-agent runtime model-list commands, plus a built-in Devin registry entry and focused agent-list tests.

## Best Possible Solution

Place discovery under a deliberate collision-resistant namespace, obtain model capabilities through an ephemeral non-persistent ACP initialization path, omit or safely redact launch commands, cover fresh and existing-session behavior, and either remove the unrelated Devin addition or synchronize its harness docs and skill guidance.
