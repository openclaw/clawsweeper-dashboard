## Summary

This hardening remains necessary because current main contains the newly merged structured ledger without persistence-boundary redaction. However, the PR still has a merge-blocking archive-repair defect: an active-session legacy replay can sanitize D1 while a recent same-count R2 archive continues serving the credential-bearing copy. The earlier Codex review raised this at `1c17db5d21f7022f035d69ee6b544b147e2ede84`; subsequent commits only add CI, so the finding remains unresolved.

## What This Changes

The PR restricts terminal structured events to exact replay, redacts credential-shaped event data before persistence, repairs legacy rows and archives, preserves legacy summary semantics, expands tests and docs, and adds a Worker pull-request CI workflow.

## Best Possible Solution

Carry an explicit force-refresh signal for legacy credential repairs so active and terminal repairs deterministically replace R2 objects, while preserving normal archive cadence for ordinary appends and exact side-effect-free terminal replay semantics.
