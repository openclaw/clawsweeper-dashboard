## Summary

The current head still changes two upgrade-sensitive persistence contracts: it can reject pre-existing private artifact directories owned by a different UID, and it replaces the stable readiness `recorderPath` with a generation-scoped snapshot path. These may be intentional hardening choices, but they need a maintainer-owned compatibility decision and migration/versioning proof before merge; the release-owned changelog edit should also be removed.

## What This Changes

Hardens artifact and recorder persistence by recovering interrupted removals, snapshotting recorder output, enforcing private-directory ownership and durability, repairing recorder tails, and strengthening lock recovery with expanded tests.

## Best Possible Solution

Preserve the stable readiness contract by adding a separately named or versioned immutable snapshot field, and handle mismatched existing ownership through an explicit migration or compatibility mode while retaining strict same-UID creation for new artifact trees.
