## Summary

This draft member-authored PR contains useful provider-fidelity hardening, but it should not merge while the new Mattermost environment-variable precedence can silently redirect authenticated traffic away from an existing configured endpoint; the accompanying setup documentation and release-owned changelog handling also need correction.

## What This Changes

The PR hardens authentication, native identifier validation, configuration resolution, diagnostic redaction, and webhook lifecycle behavior across Discord, Feishu, Google Chat, Matrix, Mattermost, script, Telegram, and WhatsApp adapters.

## Best Possible Solution

Preserve explicit config first and the established MATTERMOST_BASE_URL behavior during upgrades, add MATTERMOST_URL only as a lower-priority fallback or introduce a documented migration, update channel setup documentation and compatibility tests, and leave the changelog entry to the release process.
