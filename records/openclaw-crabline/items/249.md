## Summary

Keep this draft open. The forward-only parser is a promising availability hardening, but the new 1 MiB pre-parse Markdown source ceiling changes Telegram-compatible behavior before the existing post-parse semantic limits are applied; that compatibility boundary needs maintainer approval or a provider-backed limit before merge.

## What This Changes

This PR replaces potentially expensive Telegram Markdown link handling with a forward-only scan, rejects oversized Markdown sources before entity parsing, makes Slack bearer-header parsing linear over whitespace, and adds focused regression tests.

## System Context

Crabline’s Telegram and Slack provider servers receive provider-shaped client requests, parse authentication and message content, then return provider-compatible API responses. This PR changes the early request-processing stage for untrusted authorization headers and Telegram Markdown before normal message validation and delivery.

## Best Possible Solution

Retain the linear parsing hardening, but remove the arbitrary source-size rejection unless a Telegram-compatible limit is verified; otherwise document and explicitly approve the compatibility change, then validate normal and malformed Markdown behavior against a real compatible client.
