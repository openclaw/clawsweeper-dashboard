## Summary

The current head contains substantial, test-backed persistence hardening, but it still introduces two merge-blocking upgrade regressions: existing artifact directories can fail solely because their POSIX owner UID differs, and the published `recorderPath` contract is silently changed from the stable recorder to an immutable generation snapshot. The release-owned changelog edit also remains. Because this is a member-authored draft, it should stay open for the author and maintainers to resolve the compatibility policy rather than be cleanup-closed.

## What This Changes

Hardens OpenClaw artifact publication, private-directory durability, smoke-lock recovery, and provider/server recorder persistence, with expanded concurrency and interruption tests.

## Best Possible Solution

Preserve the stable readiness contract while publishing the immutable snapshot under a separately named, versioned field, add an explicit safe recovery or migration path for legacy mismatched-UID artifact trees, remove the changelog edit, and prove both fresh-install and upgrade behavior.
