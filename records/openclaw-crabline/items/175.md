## Summary

This repository-member draft should remain open. The provider-fidelity direction is coherent, but the new Zalo fail-closed startup behavior can break existing deployments that export an empty placeholder secret and requires an explicit compatibility decision before merge.

## Best Possible Solution

Keep the provider-native and bridge-isolation changes, but land the Zalo fail-closed rule only with an explicit upgrade contract and focused proof for blank, absent, overridden, and valid secrets, plus compatible-client evidence for the message-normalization changes.
