## Summary

This PR is not merge-ready: the new recorder index has a blocking durability defect that can suppress a webhook retry after a failed write. The previously reported release-owned changelog edit also remains, and the PR provides automated checks but no after-fix real-client proof.

## What This Changes

The branch canonicalizes WhatsApp identities, adds retry-idempotent webhook recording, changes Zalo polling to commit updates after response delivery, hardens provider protocol and lifecycle handling, and updates related tests and documentation.

## Best Possible Solution

Make batch deduplication transactional by updating the identity index only after durable append success and invalidating or rebuilding it after failed or partial writes; add failed-append-then-retry coverage, remove the changelog edit, refresh against main, and provide redacted live-client proof for both providers.

## Solution Assessment

No in its current form. Atomic batch recording is the correct ownership boundary, but deduplication state must follow durable storage rather than being committed before it.
