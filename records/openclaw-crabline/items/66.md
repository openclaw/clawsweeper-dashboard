## Summary

Keep this draft open: the provider hardening is useful and CI is green, but the WhatsApp change introduces a merge-blocking configuration migration gap because previously valid configurations—and the repository’s primary example—lack the two credentials now required at adapter construction.

The PR adds WhatsApp webhook verification and signature authentication, channel-scoped Slack thread handling, Telegram command-entity validation, script watcher cancellation and secret redaction, plus related tests and setup documentation.

## Best Possible Solution

Keep provider-native WhatsApp verification and raw-body signature authentication, but explicitly choose and test the upgrade contract, align every shipped example and setup statement with that choice, and verify both fresh and existing configurations before merge.
