## Summary

This PR addresses a real background-prompt problem, but it should not merge as written because it silently changes the established Chromium import default from interactive recovery to fail-closed behavior for every existing host, and the proposed loop can still perform more than one interactive lookup after a single opt-in. The PR also lacks real Keychain behavior proof, so maintainer product direction and contributor runtime evidence are still needed.

## What This Changes

The PR makes Chromium Safe Storage reads non-interactive by default, adds a host-scoped TaskLocal opt-in for interactive Keychain access, and adds injected-lookup regression tests.

## Best Possible Solution

Expose an explicit prompt policy while preserving the released interactive behavior by default, or land the fail-closed default only as a clearly approved breaking release; in either design, consume a one-shot interaction allowance after the first interactive attempt and cover both fresh adoption and upgrade behavior.
