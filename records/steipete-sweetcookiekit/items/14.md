## Summary

The earlier fallback blocker remains at the reviewed head: the new loop stops on the first alias requiring interaction instead of checking later aliases for a no-UI success. The PR also still needs live macOS Keychain proof, and the repository owner should confirm the new public host-scoped policy API before merge.

## What This Changes

The PR adds a host-scoped policy to suppress interactive Chromium Keychain recovery, limits allowed imports to one interactive lookup, and adds injected lookup regression tests.

## Best Possible Solution

Use a two-phase lookup that scans every candidate without UI, remembers at most one interaction-required candidate, then performs one approved interactive lookup; retain the compatibility default, cover later-alias success, document the public scope if accepted, and prove both modes on macOS.
