## Summary

Keep open: current main still uses the pnpm global release-install path that matches the unsafe plugin manifest errors, and no merged same-repo fix proves fresh onboarding is safe. The related issue at https://github.com/openclaw/openclaw-ansible/issues/36 is the same root cause, while https://github.com/openclaw/openclaw-ansible/pull/50 is an open partial mitigation rather than a merged default-path fix.

## What This Changes

A fresh Ubuntu 24.04 release-mode install reaches onboarding and fails config validation because bundled plugin manifests resolve from the pnpm global OpenClaw package path.

## Best Possible Solution

Choose a release-install policy that keeps bundled plugin manifests in a trusted OpenClaw location or pins a known-good release while preserving unsafe-path validation, then prove a fresh Ubuntu 24.04 onboarding run succeeds.
