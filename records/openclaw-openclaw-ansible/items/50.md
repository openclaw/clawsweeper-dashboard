## Summary

Keep open for maintainer product-direction review: the PR is a well-scoped, proof-backed opt-in configuration feature, but current main intentionally documents rolling `@latest` installs and does not yet establish version pinning as a supported installer contract. ([raw.githubusercontent.com](https://raw.githubusercontent.com/openclaw/openclaw-ansible/main/roles/openclaw/tasks/openclaw-release.yml))

## What This Changes

Adds an `openclaw_version` release-mode variable, validates exact versions or dist-tags, skips reinstalling an already-installed exact version, cleans up development-mode binary shadows, and documents the new behavior.

## Best Possible Solution

If maintainers want reproducible fleet deployments, adopt this as an opt-in `openclaw_version` contract with `latest` preserved as the default and document the development-to-release transition; otherwise retain the existing rolling-release policy and close the PR as an unsponsored direction.
