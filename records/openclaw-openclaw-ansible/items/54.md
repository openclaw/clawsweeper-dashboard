## Summary

Keep this PR open because current main still has the documented Tailscale auth-key auto-connect gap, but latest head is not merge-ready: it reuses auth keys for `Stopped` nodes, adds default-on Tailscale SSH, and still lacks inspectable real behavior proof.

## What This Changes

The branch parses Tailscale `BackendState`, joins with `tailscale up --authkey` plus optional `--ssh` when not connected, adds `tailscale_ssh`, and hides manual join instructions when an auth key is provided.

## Best Possible Solution

Keep the auth-key auto-connect fix, make Tailscale SSH opt-in or maintainer-approved, branch reconnect behavior by `BackendState`, and require redacted current-head terminal proof before merge.

Yes from source inspection: current main documents `tailscale_authkey` for auto-connect but the Linux task never consumes it and gates manual instructions only on a nonzero `tailscale status --json` rc. I did not run a disposable Debian host locally.

## Solution Assessment

No. Parsing `BackendState` is the right direction, but the branch should avoid reusing auth keys for `Stopped` nodes, keep Tailscale SSH opt-in or explicitly approved, and add current-head real behavior proof.
