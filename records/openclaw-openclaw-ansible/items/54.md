## Summary

Keep open: current main still lacks the documented Tailscale auth-key auto-connect behavior, but this PR has merge-blocking proof, compatibility, and security-boundary gaps before it is safe to land.

## What This Changes

The branch changes the Linux Tailscale role to parse `BackendState`, auto-run `tailscale up` with an auth key when disconnected, hide manual join instructions when an auth key is set, and add a default-on `tailscale_ssh` option.

## Best Possible Solution

Keep the auth-key auto-connect fix, make Tailscale SSH opt-in or explicitly maintainer-approved, branch reconnect behavior by `BackendState`, and require redacted current-head terminal proof before merge.

## Reproduction Assessment

Yes from source inspection: current main documents `tailscale_authkey` for auto-connect but never consumes it in the Linux Tailscale task. I did not run a disposable Debian host in this read-only review.

## Solution Assessment

No. Parsing `BackendState` and using `no_log` for auth-key joins is the right direction, but this branch should avoid auth-key reuse for stopped nodes, keep SSH opt-in or approved, and add current-head real behavior proof.
