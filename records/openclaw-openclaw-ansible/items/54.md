## Label Justifications

- `merge-risk: 🚨 compatibility`: Existing authorized nodes left in `Stopped` state may no longer reconnect reliably when an old auth key is reused.

## Summary

Keep this PR open. Current `main` still leaves `tailscale_authkey` unused and bases the manual prompt on the command exit code, so the central auto-connect bug remains; however, the branch still default-enables a new remote-access surface and reuses an auth key for stopped-but-authorized nodes. Likely related people: olsonale (low-confidence routing candidate from the current task-file history).

## What This Changes

This PR changes Linux Tailscale provisioning to read `BackendState`, join with `tailscale_authkey` when needed, and add a `tailscale_ssh` setting that passes `--ssh` during joining.

## System Context

The installer’s Tailscale role prepares the host VPN before the OpenClaw service runs. It starts `tailscaled`, checks its backend state, then either connects the host to the tailnet or prints manual connection guidance.

## Architecture Diagram

  E -->|Stopped| G[Restore existing connection]

## Best Possible Solution

Keep auth-key joining focused on `NeedsLogin`, restore `Stopped` nodes with a keyless `tailscale up` path, and make Tailscale SSH opt-in unless a maintainer explicitly approves changing the installer’s remote-access default.
