## Summary

Keep open. The linked auth-key bug is still present on current main, but this PR is not merge-ready because it adds default-on Tailscale SSH, can reuse auth keys for non-login reconnect states, and lacks inspectable current-head behavior proof.

## What This Changes

The branch parses Linux Tailscale `BackendState`, joins with `tailscale_authkey` under `no_log` when disconnected, suppresses manual join instructions when an auth key is set, and adds default-on `tailscale_ssh` for `tailscale up --ssh`.

## Best Possible Solution

Keep the BackendState/no-log auth-key join fix, make Tailscale SSH opt-in or explicitly maintainer-approved, handle stopped-node reconnect without unnecessary auth-key reuse, and require redacted current-head VM proof before merge.

## Reproduction Assessment

Yes from source inspection: current main documents `tailscale_authkey` for auto-connect but never consumes it in the Linux Tailscale task. I did not run a disposable Debian host in this read-only review.

## Solution Assessment

No. Parsing `BackendState` and using `no_log` for auth-key joins is the right direction, but this branch should avoid auth-key reuse for stopped nodes, keep SSH opt-in or approved, and add current-head real behavior proof.
