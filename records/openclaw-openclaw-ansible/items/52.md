## Summary

Keep this PR open: current main still lacks both the documented auth-key join behavior and the operator grant needed for non-root serve mode, but the proposed operator task overwrites any existing Tailscale operator and the submitted evidence still lacks a live Linux Tailnet run.

## What This Changes

The branch parses Tailscale BackendState, uses tailscale_authkey for unattended joining, grants the OpenClaw user Tailscale operator mode after user creation, and adds narrowly scoped serve sudoers entries.

## Best Possible Solution

Preserve a non-empty existing OperatorUser by default, grant openclaw only when no operator is configured, and require an explicit maintainer-approved override path before replacing an existing operator; validate that behavior on a live Linux Tailnet.

Rationale: OperatorUser controls a privileged Tailnet boundary. The correct upgrade policy determines whether the PR must preserve existing setup, add an explicit override setting, or intentionally force a migration.

Likely owner: olsonale

Options:

- **Preserve existing operator (recommended):** Set openclaw only when OperatorUser is empty and leave a non-empty value untouched; this is the safest upgrade default.
- **Add explicit override:** Preserve existing operators by default but add a clearly documented opt-in variable for administrators who want the role to replace it.
- **Force migration to openclaw:** Always replace the operator and document the breaking upgrade behavior, accepting that existing non-root operators lose access.

## Reproduction Assessment

No live current-main reproduction was run here, but source inspection gives a high-confidence path: main does not consume tailscale_authkey and its non-root service cannot use sudo because NoNewPrivileges is enabled.

## Solution Assessment

No. Parsing BackendState and joining with the documented key are appropriate, but unconditional replacement of an existing OperatorUser is not a safe upgrade solution; preserve it by default or require an explicit override.
