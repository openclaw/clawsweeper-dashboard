## Summary

Keep open: the PR addresses the main Tailscale auth-key and serve-operator gaps, but it still has an upgrade-safety blocker because it can replace an existing Tailscale operator user, and the current proof is mock-only rather than a live Debian/Ubuntu Tailnet run.

## What This Changes

The PR updates the Tailscale Ansible tasks to consume `tailscale_authkey`, derive `BackendState`, grant the OpenClaw service user as Tailscale operator after user creation, and narrow serve-related sudoers entries.

## Best Possible Solution

Land a narrow Tailscale fix that wires auth keys, preserves or explicitly conflict-detects existing non-empty operators, and includes maintainer-approved live Debian/Ubuntu Tailnet proof for the operator and serve path.

## Reproduction Assessment

Yes, by source inspection. Current main lacks the documented auth-key join and operator grant, and the PR blocker is reproducible from the condition that runs `tailscale set --operator=openclaw` whenever an existing `OperatorUser` is anything else.

## Solution Assessment

No as-is. The auth-key and first-run operator ordering are close, but the operator replacement policy needs an upgrade-safe guard or explicit maintainer decision plus live Tailnet proof.
