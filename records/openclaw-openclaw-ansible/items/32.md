## Summary

Keep this P0 security issue open. The supplied prior source review reports that current main still grants the service account access to a rootful Docker daemon, and no current-main remediation or merged replacement is identified; resolving it requires an explicit supported trust-model decision.

## What This Changes

The issue requests removal or redesign of the OpenClaw service account’s rootful Docker group access because it can confer host-root-equivalent control.

## Best Possible Solution

Adopt and document one supported deployment trust model that prevents the application identity from controlling a rootful Docker daemon—preferably rootless Docker or a narrowly privileged deployment broker—and validate fresh installs, upgrades, container networking, and service management under that model.
