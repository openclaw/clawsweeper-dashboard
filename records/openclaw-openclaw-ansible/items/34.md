## Summary

Keep open. Current main still lacks both the documented `tailscale_authkey` auto-connect path and the Tailscale operator/serve permission needed for the reported OpenClaw service-user failure, and https://github.com/openclaw/openclaw-ansible/pull/52 is an open linked candidate fix rather than a merged implementation.

## What This Changes

The issue reports that the OpenClaw service user cannot run `tailscale serve` until `tailscale set --operator=openclaw` is applied, and also notes that `tailscale_authkey` does not auto-enroll the node.

## Best Possible Solution

Review and either land or close https://github.com/openclaw/openclaw-ansible/pull/52 as the focused candidate, with a guarded operator policy, redacted auth-key handling, and validation for both fresh install and upgrade behavior.
