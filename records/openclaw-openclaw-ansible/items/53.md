## Summary

Keep open. Current main still has the reported Tailscale auth-key gap, and the issue is paired with an open linked implementation pull request that should be reviewed or closed before the issue is resolved.

## What This Changes

The issue reports that Linux Tailscale setup documents unattended auth-key connection but current tasks never consume `tailscale_authkey` and misread `NeedsLogin` as connected.

## Best Possible Solution

Land a focused Tailscale role fix that derives connection state from `BackendState`, uses the documented auth key with `no_log`, and keeps manual join messaging for unauthenticated installs.

## Reproduction Assessment

Yes from source inspection: current main documents `tailscale_authkey` for auto-connect but has no task using it, and the only Linux connected check is the exit code of `tailscale status --json`. I did not run a live Tailscale VM reproduction in this read-only review.

## Solution Assessment

Yes for the issue boundary: the narrow repair is to parse `BackendState == "Running"`, run `tailscale up --authkey` only when disconnected and an auth key is present, and keep the manual instructions for no-key installs.
