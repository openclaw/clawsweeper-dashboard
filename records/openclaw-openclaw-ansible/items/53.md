## Summary

Keep open. Current main still has the reported Tailscale auth-key gap, and the issue is paired with an open linked fix PR, so it should stay open until a candidate PR merges.

## What This Changes

The issue reports that Linux installs with `tailscale_enabled: true` and `tailscale_authkey` never run an unattended Tailscale join because connection state is inferred from `tailscale status --json` exit status instead of `BackendState`.

## Best Possible Solution

Land one focused Tailscale fix that parses `BackendState`, consumes `tailscale_authkey` under `no_log`, and preserves manual join instructions when no auth key is configured.

## Reproduction Assessment

Yes from source inspection: current main documents `tailscale_authkey` for auto-connect, but the Linux Tailscale task only checks `tailscale status --json` return code and never runs `tailscale up --authkey`. I did not run a real Debian host install in this read-only review.

## Solution Assessment

Yes for the central bug: deriving connected state from `BackendState`, joining only when an auth key is present, and keeping no-key manual instructions is the narrow maintainable fix. Maintainers still need to choose among the overlapping open PRs.
